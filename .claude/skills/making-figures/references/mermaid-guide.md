# Mermaid 그림 만들기 (mermaid-guide)

M 그림(Mermaid 흐름도)을 원본 `.mmd`에서 출간용 SVG까지 만드는 절차입니다. 원본을 쓰기 직전에 한 번, 렌더링 경고가 나왔을 때 한 번 펼쳐 봅니다. 설정의 정본은 `docs/style-guide.md` 9.8절과 `assets/mermaid/README.md`이고, 이 문서는 "지금 무엇을 어떻게 쓰나"로 압축했습니다. 값이 다르면 그 두 문서가 맞고, 이 문서를 고칩니다.

배치 요령(8장)과 수치 상한(5, 6장)은 2026-10-14에 실제로 렌더링해서 확인한 것만 적었습니다. 시험 원본은 스크래치패드에서 돌렸고 저장소에는 남기지 않았어요. M으로 할지 S로 다시 그릴지는 `choose-type.md` 3.4절, 디자인 공통 규칙은 `design-rules.md`가 맡습니다.

## 목차

1. 렌더링 파이프라인과 실행 명령
2. 원본 파일 머리 형식
3. 공통 설정 적용법
4. 클래스 표
5. 노드 문구 규칙
6. 방향 선택: LR과 TB

8. 자동 배치 보정 요령
9. 경고 문구별 대처표
10. 자주 하는 실수
11. 점검 명령

## 1. 렌더링 파이프라인과 실행 명령

```
X.mmd ──(1) classdefs.mmd 이어 붙임──▶ (2) Chrome + 저장소 Pretendard + config.json으로 mermaid 렌더(ELK)
      ──▶ raw SVG ──(3) postprocess.mjs: 상자, 띠, 화살표, 머리줄, 바탕 다시 씀──▶ X.svg + 경고 목록
```

| 단계 | 하는 일 | 파일 |
|---|---|---|
| 1 | 원본 끝에 `classDef` 모음을 붙임. 첫 문장이 `flowchart`나 `graph`일 때만 | `assets/mermaid/classdefs.mmd` |
| 2 | 저장소 woff2를 `@font-face`로 건 페이지에서 글자 폭을 재고 배치 | `_build/render.mjs`, `fontpage.mjs`, `config.json` |
| 3 | 상자 크기, 글자 위치, 연결선, 화살표 머리를 B 규칙으로 다시 쓰고 경고를 출력 | `_build/postprocess.mjs`, `decor.json` |

실행 명령은 저장소 뿌리에서 돌립니다(2026-10-14 실행 확인, 한 장 약 2초).

```bash
# 본문 폭 640
assets/mermaid/_build/render.sh vol1-llm/ch04/figures/1-4-3.mmd vol1-llm/ch04/figures/1-4-3.svg
# EPUB 세로 변형 360 (원본 이름이 X.v.mmd면 --width 없이도 360)
assets/mermaid/_build/render.sh X.mmd X.v.svg --width 360
# 뒤 처리 전 SVG도 남겨 비교
KEEP_RAW=1 assets/mermaid/_build/render.sh X.mmd X.svg
# 생성 파일 3개가 colors.json과 맞는지 (다르면 종료 코드 1)
.venv/bin/python assets/mermaid/_build/gen.py --check
# 미리보기와 흑백 확인 (PNG는 소스 옆이 아니라 _render/qa/에, qa-checklist.md 2.3절)
Q=vol1-llm/ch04/figures/_render/qa; mkdir -p "$Q"   # figures/ 밖 시안은 ${TMPDIR:-/tmp}/figqa
node scripts/svg_to_png.mjs vol1-llm/ch04/figures/1-4-3.svg "$Q/1-4-3.png"
node scripts/svg_to_png.mjs vol1-llm/ch04/figures/1-4-3.svg "$Q/1-4-3.gray.png" --gray
```

- 성공하면 `출력.svg  (640 × 480, 노드 4, 연결선 3)` 한 줄이 나오고, 경고는 그 아래 `  경고: ...`로 나옵니다.
- 경고가 있어도 종료 코드는 0입니다. 그러니 출력을 꼭 눈으로 읽거나 `grep 경고`로 거릅니다.
- 문법 오류(`Parse error on line n`)는 종료 코드 1이고 SVG가 생기지 않습니다.
- `docs/style-board/final/1-4-3.mmd`를 다시 렌더링하면 승인본 `1-4-3.svg`와 바이트 단위로 같습니다(`deterministicIds`). 판이 바뀌었는지 볼 때 이 비교를 씁니다.
- 뒤 처리 인자로 `--fig`, `--subject`, `--id`, `--align left`를 줄 수 있지만, 보통은 머리 주석(2장)으로 넘깁니다.
- `MMDC=1`은 mmdc 경로인데, 운영체제에 Pretendard를 설치해야 글자 폭이 맞습니다. 기본 경로를 쓰세요.

## 2. 원본 파일 머리 형식

승인 시안 `docs/style-board/final/1-4-3.mmd`의 관례를 따릅니다. 머리 주석은 `%%`로 시작하고 `flowchart` 줄보다 앞에 둡니다. 아래는 그 시안을 옮겨 4장 원고에 맞춘 `vol1-llm/ch04/figures/1-4-3.mmd`(노드 7개, 연결선 6개, 2026-10-17 검수 반영)이고, P1 단계 흐름을 Mermaid로 쓸 때의 본보기입니다. 시안과 다른 곳은 단계 이름과 연산 문구 세 곳(02 나누기, q와 k의 내적, 가중치 × v의 합)과 강조 표현(밑줄 대신 굵기 600)이에요. 머리의 `design:` 줄은 설계 판단 기록이라 줄였습니다.

```
%% canon: N4-2
%% fig: 1-4-3
%% subject: 어텐션 계산 4단계
%% message: '안'은 '왔어요'의 정보를 가장 많이 가져옵니다
%% column: s1 s2 s3 s4
%% row: q k
%% row: s3 v
flowchart TB
  accTitle: 그림 1-4-3 어텐션 계산 4단계
  accDescr: 토큰 '안'의 어텐션 계산을 점수, 나누기, softmax, 가중합의 네 단계 흐름도로 나타냈습니다. 가정한 키와 값으로 계산하면 쿼리와 각 키의 내적인 점수 1, 2, 3은 루트 2로 나눠 0.707, 1.414, 2.121이 됩니다. softmax 뒤 가중치는 상자가 0.140, 안 0.284, 왔어요 0.576입니다. 출력은 0.428과 0.572로, '안'은 '왔어요'의 정보를 가장 많이 가져옵니다.
  q["`**쿼리 q** (안)
  [1, 2]`"]:::c-query
  k["`**키 k** (상자가, 안, 왔어요)
  [1, 0]  [0, 1]  [1, 1]`"]:::c-key
  s1["`**01 점수** q와 k의 내적
  [1, 2, 3]`"]
  s2["`**02 나누기** ÷ √d, d = 2
  [0.707, 1.414, 2.121]`"]
  s3["`**03 가중치** softmax, 합 = 1
  [0.140, 0.284, **0.576**]`"]:::msg
  v["`**값 v** (상자가, 안, 왔어요)
  [1, 0]  [0, 1]  [0.5, 0.5]`"]:::c-value
  s4["`**04 가중합** 가중치 × v의 합
  [0.428, 0.572]`"]
  q --> s1
  k --> s1
  s1 --> s2 --> s3 --> s4
  v --> s4
```

본보기에서 볼 점
- 단계 노드는 세 층입니다. 첫 줄은 `**번호 이름**`과 보통 굵기의 연산 문구(`q와 k의 내적`, `÷ √d, d = 2`), 둘째 줄은 정본 값 묶음이에요. 이 구성이 상자 폭 240을 만듭니다(5장 "패턴 기준 폭과 문구").
- 단계 이름과 연산 문구는 원고 4.2절 본문과 설계서 절 목차의 말을 그대로 씁니다(점수, 나누기, 가중치, 가중합). 승인 시안은 "02 크기 조정", "q × k", "Σ 가중치 × v"였으나, 원고가 "나누기"와 "내적"이라 부르고 본문이 ×를 행렬곱과 수 곱셈에만 써서 4장 검수(R1-G04, R2-P1-03)에서 바꿨습니다. `accDescr` 첫 문장은 이 순서대로 "점수, 나누기, softmax, 가중합"으로 읽습니다. 새 그림도 정본 행과 원고에 있는 말을 먼저 쓰고, 한 번 정한 이름은 노드, alt, 캡션에서 바꾸지 않습니다.
- 입력 노드(q, k, v)는 개념 클래스, 단계 노드는 클래스 없음, 메시지 단계 하나만 `msg`, 강조 숫자 하나만 `**0.576**`(600 굵기)입니다. `*0.576*`(강조색 밑줄)은 웹과 EPUB에서 링크처럼 보여 쓰지 않아요(5장 "줄바꿈과 굵기", 강조 한계).
- `%% column:`은 단계 넷, `%% row:`는 같은 행에 놓인 입력 둘(q, k)과 03 단계 옆의 v에만 걸었습니다(8.6절).

| 주석 | 뒤 처리가 읽나 | 쓰는 법 |
|---|---|---|
| `canon:` | 아니요(기록용) | 정본 ID. `figures.yml`의 `source.canon`과 같게 |
| `fig:` | 예, 머리줄 왼쪽 | 그림 ID. 없으면 파일 이름 |
| `subject:` | 예, 머리줄 오른쪽 | 대상 이름 16자 이하 명사구(6.8절) |
| `message:` | 아니요(기록용) | 메시지 문장. `figures.yml`의 `message`와 같은 문장 |
| `column:`, `row:` | 예 | 한 열은 왼쪽 끝과 폭, 한 행은 위 끝과 높이를 맞춤(5.4절). 여러 줄 가능 |
| `width:` | 예 | 800(펼침 폭)이나 360일 때만 씀 |
| `header:`, `id:` | 예 | 견본용. 책 그림에서는 쓰지 않음 |

- `accTitle`은 "그림 ID + 대상 이름", `accDescr`는 `figures.yml`의 `alt`와 같은 문장으로 씁니다. SVG의 `<title>`, `<desc>`가 돼요. 빼면 제목이 "그림 1-4-3"뿐이고 `<desc>`가 생기지 않습니다. 서식은 `caption-alt.md`가 정합니다.
- 노드 선언을 먼저, 연결선을 뒤에 몰아 씁니다. 선언 순서가 곧 배치 순서이기 때문입니다(8.1절).

## 3. 공통 설정 적용법

원본에는 그림 내용만 씁니다. 테마, 글꼴, 간격, 배치 엔진, 색은 모두 렌더러가 붙여요.

- 파일마다 `%%{init: ...}%%`나 머리말 `---` `config:` 블록을 쓰지 않습니다(style-guide 9.8절 금지 사항). 공통 설정은 `colors.json`에서 생성한 `config.json` 하나라서, 파일마다 덮어쓰면 237장 가운데 일부만 색과 간격이 어긋납니다. 렌더러도 init을 막지 않으므로 검사로 거릅니다(11장).
- 원본 안에 `classDef`, `style`, `linkStyle`로 색을 쓰지 않습니다. HEX를 손으로 쓰면 팔레트 검사(`scripts/check_palette.py`)와 흑백 표지가 깨집니다(9.8절 금지 사항).
- 색을 바꿔야 하면 `assets/tokens/colors.json`을 고치고 `gen.py`로 세 파일을 다시 만듭니다. 생성 파일은 손대지 않습니다.
- 설정의 주요 값은 테마 `base`, Pretendard 16px, `htmlLabels: false`입니다.
- 배치 엔진은 ELK이고 `forceNodeModelOrder: true`, 고정폭 숫자를 켭니다. 근거는 `assets/mermaid/README.md` "설정에서 정한 것" 표에 있습니다.

## 4. 클래스 표

`classdefs.mmd`와 `decor.json`의 실제 내용입니다. 클래스가 없는 노드는 단계 상자가 돼요.

상자 역할

| 클래스 | 모양 | 쓰는 곳 | 흑백에서 남는 것 |
|---|---|---|---|
| (없음), `step` | 1px ink-600, paper | 단계 상자 | 테두리 |
| `input` | 1px ink-200, paper | 입력 상자 | 옅은 테두리 |
| `msg` | 1.5px ink-900, paper-warm | 메시지 상자 | 굵은 테두리와 면 |
| `accent` | 1.5px accent, paper-warm | 강조색이 꼭 필요한 메시지 대상 | 굵은 테두리와 면 |
| `warning` | 1px 경고색, 빗금 면, 흰 글자판, 경고 아이콘 | 오류, 위험(2.3절) | 빗금과 아이콘 |
| `muted` | 1px ink-400, 글자 ink-600 | 지난 단계, 반복 패턴(6.7절) | 옅은 선과 글자 |
| `exit` | 1px ink-400 파선(4 3), 글자 ink-600 | 다음 장 출구(6.9절) | 파선 |
| `panel` | paper-warm 면, 테두리 없음 | 묶음 패널(subgraph 기본과 같음) | 면 |

개념 상자(띠는 왼쪽 4px, 흑백 표지는 띠의 선 종류)

| 클래스 | 개념 | 흑백 표지 |
|---|---|---|
| `c-query` | 쿼리(Q) | 실선 띠 |
| `c-key` | 키(K) | 파선 띠 |
| `c-value` | 값(V) | 점선 띠 |
| `c-token-text` | 텍스트 토큰 | 띠 없음, ink-50 면 |
| `c-token-image` | 이미지 토큰 | 이중선 띠 |
| `c-token-action` | 액션 토큰 | 쇄선 띠 |
| `c-chunk` | 검색된 문서 조각 | 실선 띠 |
| `c-tool` | 도구 호출과 결과 | 파선 띠 |
| `c-memory` | 메모리 | 이중선 띠 |
| `c-robot-state` | 로봇 상태 | 이점쇄선 띠 |
| `c-layer` | 계층 P0~P4 | 실선 띠 |
| `c-untrusted` | 신뢰할 수 없는 외부 입력 | 띠 + 빗금 면 + 경고 아이콘 |
| `c-sim` | 시뮬레이션 | 파선 테두리 + 격자 면 |
| `c-agent` | 에이전트 | 1.5px ink-800 테두리 |
| `c-human`, `c-demo` | 사람의 개입, 사람 시연 | 1.5px 테두리 + 사람 아이콘 |

연결선

| 클래스 | 모양 | 쓰는 곳 |
|---|---|---|
| (없음) | 1px ink-600 + `arr` | 기본 흐름 |
| `e-accent` | 1.5px accent + `arr-accent` | 메시지 연결선 1개 |
| `e-strong` (`==>`와 같음) | 1.5px ink-900 | 강조 흐름 |
| `e-muted` | 1px ink-400 | 지난 단계 연결선 |
| `e-cost` | 2.5px 파선(8 4) ink-600 | 비용, 지연 |
| `e-protocol` | 2.5px ink-800 | 표준 연결(MCP, A2A) |
| (`-.->`) | 1px ink-600 파선(4 3) | 선택 흐름 |

쓰는 법과 제한
- 노드는 `a["..."]:::c-tool`, 연결선은 `a e1@--> b` 뒤에 `class e1 e-accent`로 붙입니다.
- 강조 수단(`msg`, `accent`, `e-accent`, 값 줄의 `**굵게**`)은 메시지 한 덩어리에만 씁니다. `*강조*`(밑줄)는 쓰지 않습니다(5장). `msg` 상자는 그림당 1개, `msg`와 `accent`는 함께 쓰지 않아요(6.2절).
- 한 그림의 개념색은 3개 + 강조까지입니다(design-rules.md 3장). 개념 클래스를 장식으로 붙이지 않습니다.
- c-cost와 c-protocol은 노드 클래스 없이 연결선 클래스(`e-cost`, `e-protocol`)로 씁니다.
- c-robot-body, c-imagined, c-safety는 Mermaid 클래스가 없습니다. SVG로 그립니다(`choose-type.md` 3.3절).

## 5. 노드 문구 규칙

뒤 처리는 상자 폭을 "가장 긴 줄의 글자 폭 + 32"를 8 배수로 올린 값(최소 120)으로, 높이를 1줄 48, 2줄 64, 3줄 88로 다시 잡습니다(9.8절). 그래서 문구 길이가 곧 배치 폭입니다.

| 항목 | 상한 | 근거 |
|---|---|---|
| 줄 수 | 2줄 기본(제목 + 설명이나 숫자), 3줄 최대 | 뒤 처리 높이 단계, 4.4절 |
| 제목 줄 | 3어절 12자 | 6.3절, design-rules.md 3장 |
| 숫자 줄 | 정본 숫자 묶음 한 덩어리(1-4-3은 21자) | 대괄호 묶음은 끊지 않음(4.4절) |
| LR 한 행에 상자 3개일 때 | 가장 긴 줄 공백 포함 11자 이하 | 실측: 11자 통과, 14자는 내용 폭 677 |
| 최소 길이 | 가장 긴 줄이 한글 5자 이상이거나 2줄 | 실측: 3자는 상자 사이 16 미만 경고 5건, 5자는 0건 |

최소 길이가 필요한 이유는 이렇습니다. Mermaid는 상자를 "글자 폭 + 24"로 배치하고, 뒤 처리가 중심을 그대로 둔 채 최소 120으로 넓힙니다. 그래서 짧은 상자끼리는 넓어지면서 서로 겹쳐요.

패턴 기준 폭과 문구
- 패턴 표가 상자 폭을 정한 그림(P1 세로 주 열 240 등)은 문구로 그 폭을 맞춥니다. Mermaid에는 폭을 직접 주는 설정이 없어서, 이름을 줄이거나 연산 문구를 빼면 상자가 그만큼 좁아지고 패턴 열에서 벗어나요.
- 같은 열의 단계 노드는 같은 층 구성(번호와 이름, 연산 문구, 값 줄)을 씁니다. 한 단계만 연산 문구가 없으면 그 상자만 폭이 달라집니다.
- 노드와 단계 이름은 설계서 명세 행, 원고, 정본 손계산 행, 승인 시안 예에 이미 있는 용어를 그대로 씁니다. 바꿔야 하면 `figures.yml`의 `note`에 사유를 적어요. 노드 이름은 `accDescr`과 캡션으로 그대로 옮겨 가므로, 여기서 바꾼 말이 대체 텍스트까지 번집니다.
- 렌더링 뒤 11장 명령 6으로 상자 폭을 읽어 패턴 표와 비교합니다. 16 넘게 다르면 문구를 먼저 고칩니다.

줄바꿈과 굵기
- 마크다운 문자열(`` "`...`" ``)을 기본으로 씁니다. 문자열 안의 줄바꿈이 그대로 줄이 됩니다.
- 굵기가 필요 없는 일반 문자열(`"..."`)에서는 `<br/>`로 줄을 나눕니다. 렌더링해 보니 두 줄로 나뉘었어요. 한 원본 안에서는 한 방식으로 통일합니다.
- 줄은 어절 경계에서만 손으로 끊습니다. 숫자와 단위, 대괄호 묶음, 수식 한 덩어리는 끊지 않습니다(4.4절).
- `**굵게**`는 600 굵기로 제목 줄에 씁니다. 메시지 숫자 한 곳은 `msg` 상자 안 값 줄에서 `**0.576**`처럼 굵게 해 강조합니다.
- `*강조*`는 뒤 처리(`assets/mermaid/_build/postprocess.mjs`)가 강조색 600에 밑줄로만 그립니다. 4장 1-4-3에서 이 밑줄이 웹과 EPUB에서 링크처럼 읽혔고(R1-G04, 제2색약에서 더 심함), 칩(흰 면 + 테두리) 모양으로 바꿀 수단이 없었어요. 그래서 메시지 숫자 강조에는 `*강조*`를 쓰지 않습니다.
- 강조 한계와 대안: Mermaid 노드 안에서는 숫자 칩을 그릴 수 없습니다. 칩이 꼭 필요하면 D3 3.3절 "숫자 칩 필요" 신호로 S 재작도를 판단하고(`choose-type.md`), 그렇지 않으면 `msg` 상자 + 굵기 600으로 둡니다. 뒤 처리의 `*강조*`를 칩 모양(흰 면, 1px 테두리, 강조는 accent 1.5)으로 바꾸는 안은 공통 도구 수정이라 제안으로만 올렸어요(`docs/skill-trial-3.8.md` 7.2절). 반영 전에는 공통 도구를 고치지 않습니다.
- 숫자와 괄호만 있는 줄은 자동으로 500 굵기가 됩니다.
- 공백 두 칸은 한 칸이 됩니다. 강조 낱말 뒤 조사는 강조 안에 넣습니다(`*0.576을*`).

숫자, 따옴표, 기호
- 숫자 표기는 design-rules.md 6장 표를 따릅니다. 빼기는 −(U+2212), 연산자 앞뒤 공백, 합 기호는 Σ, 범위는 물결표입니다.
- 작은따옴표는 그대로 씁니다(`'안'`). 1-4-3에서 확인한 방식이에요.
- 큰따옴표는 마크다운 문자열 안에서 “ ”(U+201C, U+201D)를 직접 씁니다. `#quot;`는 마크다운 문자열 안에서 `&quot;` 글자 그대로 찍혀 나왔습니다(실측). 일반 문자열에서만 `#quot;`가 `"`로 바뀝니다.
- 금지 기호 7종은 라벨, 연결선 라벨, `accDescr`에서도 0건입니다. 목록은 design-rules.md 11장에 있습니다.
- 라벨은 명사구, 마침표 없음. 연결선 라벨(`-->|도구 결과|`)은 1~2어절로 씁니다.

## 6. 방향 선택: LR과 TB

아래 표는 2줄 상자("**01 단계**" + "설명 문구")로 직선 흐름을 렌더링해 잰 값입니다. 문구가 길면 상한이 줄어요.

| 캔버스 | 방향 | 실측 상한 | 넘으면 나오는 경고 |
|---|---|---|---|
| 본문 640 | LR | 한 줄 4개(5개는 내용 폭 709) | 내용 폭 초과 |
| 본문 640 | TB | 세로 5단(6단은 높이 647) | 높이 단계 상한 초과 |
| 본문 640 | TB 한 행 | 4개까지 들어감 | 없음 |
| 세로 변형 360 | LR | 한 줄 2개(3개는 내용 폭 414) | 내용 폭 초과 |
| 세로 변형 360 | TB | 세로 6단(7단은 높이 744) | 720 초과 |

들어간다고 다 써도 되는 것은 아닙니다. 규칙 상한이 더 좁아요.
- 본문 폭 한 행 상자는 3개까지입니다(5.12절). TB 한 행 4개는 렌더링은 되지만 쓰지 않습니다.
- LR 한 줄에 노드가 4개 이상이면 EPUB 세로 변형이 반드시 필요합니다(5.11절).
- 노드 7개, 연결선 8개가 본문 폭 상한입니다. 뒤 처리가 세어 경고해요.

결정표

| 상황 | 방향 | 이유 |
|---|---|---|
| 직선 단계 3개 이하 | LR | 216 높이에 들어가 쪽을 아낌. 세로 변형 불필요 |
| 직선 단계 4~5개 | TB | LR이면 세로 변형이 필요. TB면 본문 하나로 끝남 |
| 직선 단계 6개 이상 | 나누기 | TB 640에서 높이 초과. 그림을 나누거나 덜어 냄 |
| 입력 2~3개가 한 단계로 모임 | TB | LR에서는 모이는 선의 곧은 부분이 16 미만이 됨(8.5절) |
| 숫자 줄이 11자를 넘음 | TB | LR 한 행 폭(11자)에 안 들어감. 1-4-3 선례 |
| 바깥에서 묶음으로 들어오는 선 | LR | TB에서는 묶음 이름과 선이 겹침(8.4절) |
| 되먹임 루프 | 루프 펼치기 | 어느 방향이든 되돌아가는 선이 4회 꺾임(8.2절) |

세로 변형은 `LR`을 `TB`로만 바꿔 360 경고가 0건이면 `auto`입니다. 판단 기준은 `choose-type.md` 5장이에요.

## 7. 지원하는 다이어그램 종류

| 종류 | 공통 테마 | 판정 |
|---|---|---|
| `flowchart`, `graph` | 클래스, 띠, 화살표, 머리줄 모두 적용 | 씀 |
| `sequenceDiagram` | 글꼴과 색 변수만. 뒤 처리는 바탕, 머리줄, filter 제거만 | 쓰지 않음 |
| `stateDiagram-v2` 등 그 밖 | 같음. 클래스가 붙지 않음 | 쓰지 않음 |

flowchart가 아니면 경고 "flowchart가 아님"이 나옵니다(실측). 시퀀스는 TB flowchart의 단계 상자와 연결선 라벨로 바꾸고, 시간축이 의미면 S로 그립니다(`choose-type.md` 3.3절).

flowchart 안에서도 쓰지 않는 것
- 둥근 `( )`, 알약 `([ ])`, 원 `(( ))`, 마름모 `{ }` 같은 직각이 아닌 노드. 경고 "직각 노드 [ ]가 아님"이 나옵니다.
- `htmlLabels: true`, 아이콘 글꼴(`fa:`), `click` 같은 상호작용, 이모지.
- 주석 지시선, 숫자 칩, 물결 테두리, 줄무늬 면. Mermaid로 그릴 수 없으니 S로 갑니다(9.8절).

## 8. 자동 배치 보정 요령

모두 스크래치패드에서 렌더링해 경고 수로 효과를 확인한 것입니다. 위에서부터 차례로 시도하고, 두 번 고쳐도 경고가 남으면 9장 끝 규칙대로 S로 넘어갑니다.

### 8.1 노드 선언 순서 바꾸기

ELK에 `forceNodeModelOrder`가 켜져 있어 같은 단 안의 위아래(LR)나 왼오른(TB) 순서는 선언 순서를 따릅니다. 교차가 보이면 선을 고치지 말고 노드 선언 줄의 순서를 바꿉니다. 1-4-3에서 `q`를 `k`보다 먼저 선언해 쿼리가 왼쪽에 온 것이 이 방식이에요.

### 8.2 되먹임 루프는 펼친다

```
전: o --> t --> a      후: o --> t --> a
    a --> o                o2["`**관찰**
                           다음 회차`"]:::muted
                           a e1@--> o2
                           class e1 e-muted
```

전은 LR과 TB 모두 "꺾임 4회" 경고가 났고, 노드 순서를 바꿔도 같았습니다. 후는 경고 0건입니다. 다음 회차를 `muted`로 낮추는 것은 6.7절 반복 패턴과 같은 표현이에요. 펼치면 노드가 하나 늘어 LR 4개가 되므로 세로 변형을 챙깁니다. 루프 모양 자체가 메시지면 S로 그립니다.

### 8.3 보이지 않는 연결 `~~~`

`b ~~~ c`는 선을 그리지 않고 c를 b 다음 단에 둡니다. 연결선 수에도 세지 않아요(실측). 다만 흐름 방향으로 미는 것이라, 서로 관계없는 두 줄을 LR에서 잇자 한 줄로 늘어서 내용 폭 621로 넘쳤습니다. 관계없는 두 흐름은 `~~~` 없이 두면 ELK가 위아래로 쌓아 줍니다. 쓸 곳은 TB에서 떨어진 노드를 특정 단 아래로 내릴 때뿐이에요.

### 8.4 subgraph로 묶기

- 묶음은 `subgraph env["에이전트 실행 환경"]`으로 쓰고 이름은 명사구로 둡니다. 모양은 `panel`과 같아요.
- 바깥 노드와 연결된 묶음에서는 안쪽 `direction LR`이 무시됩니다. 넣은 원본과 뺀 원본의 출력이 같았습니다.
- TB에서 바깥 노드가 위에서 묶음으로 들어오면 경고 "묶음 이름 ... 연결선과 겹침"이 납니다. 같은 원본을 LR로 바꾸자 경고가 사라졌어요. 선이 옆으로 들어가 이름(위 왼쪽)을 비켜 가기 때문입니다.

### 8.5 방향 바꾸기

LR에서 입력 둘이 한 상자로 모이면, 아래쪽 선이 상자 왼쪽 면에 닿기 직전에 꺾여 "화살표 앞 곧은 선 12.5px" 경고가 났습니다. TB로 바꾸자 0건이었어요. 모이는 흐름은 TB, 갈라지는 흐름은 LR가 대체로 깔끔합니다.

### 8.6 정렬 힌트 `%% row:`, `%% column:`

- `row`는 실제로 한 행에 나란히 놓인 상자(TB의 입력들), `column`은 한 열로 쌓인 상자(TB의 단계들)에만 씁니다.
- LR에서 위아래로 쌓인 두 입력에 `row`를 걸자 두 상자가 한 자리로 겹쳐 "사이가 −120px" 경고가 났습니다. 위치가 다른 상자를 억지로 맞추는 기능이 아니에요.

### 8.7 효과가 없는 것

- 링크 길이 `--->`, `---->`: ELK에서는 무시됩니다. `-->`와 출력이 바이트 단위로 같았습니다.
- `nodeSpacing`, `rankSpacing`: ELK에는 적용되지 않습니다(간격 40 고정, 9.8절). 원본에서 바꾸려 하지 않아요.
- 빈칸이나 공백으로 상자 넓히기: 공백 두 칸이 한 칸으로 줄어 효과가 없습니다.

## 9. 경고 문구별 대처표

| 경고 문구(앞부분) | 원인 | 먼저 할 일 | 그다음 |
|---|---|---|---|
| 내용 폭 ...px가 캔버스 내용 폭 ...px를 넘음 | 한 행이 넓음 | 가장 긴 줄 줄이기(5장) | LR을 TB로(6장) |
| 필요 높이 ...px가 높이 단계 상한을 넘음 | 세로 단이 많음 | 덜어 내기, 단계 합치기 | 그림 나누기(설계서 수정안) |
| 세로 변형 높이 ...px가 720 초과 | 360에서 단이 많음 | 줄 수 2줄로 | `.v.build.py`로 S 재작도 |
| 화살표 앞 곧은 선 ...px(16 미만) | 모이는 선, 짧은 상자 | 방향 바꾸기(8.5절) | 노드 순서(8.1절) |
| 꺾임 n회(2회 초과) | 되돌아가는 선, 교차 | 루프 펼치기(8.2절), 노드 순서 | S 재작도 |
| A와 B 사이가 ...px(16 미만) | 짧은 문구 상자가 넓어짐, 잘못된 정렬 힌트 | 최소 길이 지키기(5장), 힌트 확인(8.6절) | 방향 바꾸기 |
| 라벨 "..." 자리가 좁음 | 연결선 라벨이 김 | 라벨 1~2어절로 | 라벨을 캡션으로 |
| 묶음 이름 "..."이 연결선과 겹침 | TB에서 위로 들어오는 선 | LR로(8.4절) | 묶음 빼고 `msg`나 캡션으로 |
| 노드 n개(본문 폭 상한 7) | 내용이 많음 | 덜어 내기, 나누기 | S로 옮겨도 사라지지 않음 |
| 연결선 n개(본문 폭 상한 8) | 내용이 많음 | 같음 | 같음 |
| 직각 노드 [ ]가 아님 | `( )`, `{ }` 등 | `[ ]`로 바꾸기 | 없음 |
| flowchart가 아님 | sequence 등 | flowchart로 다시 씀(7장) | S |
| ... 묶음 ...: 찾은 노드 n개 | `row`, `column`의 ID 오타 | ID 확인 | 없음 |

두 번 고쳐도 배치 경고(곧은 선, 꺾임, 겹침, 폭, 높이)가 남으면 S로 다시 그립니다. 사유는 경고 문구 그대로 `figures.yml`의 `note`에 적어요. 기준과 기록 방법은 `choose-type.md` 3.4, 3.5절입니다. 요소 수 경고는 종류 문제가 아니라 내용 문제라서 S로 옮겨도 남습니다.

경고가 0건이어도 끝이 아닙니다. 폭 640 PNG를 눈으로 보고 교차, 상자 관통, 메시지 상자의 시선 순서를 확인합니다(choose-type.md 3.4절 표). 1-4-3은 본문 640에서 0건이었지만 360에서는 내용 폭 458로 넘쳐 세로 변형을 S로 다시 그렸습니다.

| 링크 길이로 간격을 벌리려 함 | 아무 변화 없음 | 8.7절. 순서, 방향, 문구로 |
| 루프를 되돌아가는 선으로 그림 | 꺾임 4회 | 펼치거나 S |
| 마크다운 문자열 안에 `#quot;` | `&quot;`가 글자로 찍힘 | “ ”를 직접 씀 |
| `accTitle`, `accDescr`를 빠뜨림 | 대체 텍스트가 SVG에 없음 | `figures.yml`의 `alt`를 옮겨 씀 |
| 360 렌더링을 안 해 봄 | 세로 변형 필요 여부를 놓침 | `--width 360`으로 한 번 더 |

## 11. 점검 명령

```bash
F=vol1-llm/ch04/figures/1-4-3.mmd

# 1. 렌더링하고 경고 수 세기 (0이 목표, 요약 줄에 경고 건수도 나옴)
bash scripts/render_mermaid.sh "$F" 2>&1 | tee /dev/stderr | grep -c '경고:'

# 2. 원본 안 금지 항목: 파일별 설정, 손으로 쓴 색, 둥근 노드 (출력 없음 = 통과)
grep -nE '%%\{init|^---|classDef|^ *style |linkStyle|#[0-9A-Fa-f]{6}' "$F"
grep -nE '[a-z0-9_]+(\(\(|\(\[|\(|\{)"' "$F"

# 3. 금지 기호 7종 (design-rules.md 12장 명령 1과 같음)
python3 -c 'import sys
B={0x2014,0x2015,0x2013,0xB7,0x318D,0x30FB,0x2022}
for i,l in enumerate(open(sys.argv[1],encoding="utf-8"),1):
    h=sorted({"U+%04X"%ord(c) for c in l if ord(c) in B})
    if h: print(i,h,l.strip()[:60])' "$F"

# 4. 강조 수단이 한 덩어리인지 (msg와 accent 합 1 이하, *강조* 밑줄 0)
grep -cE ':::(msg|accent)\b' "$F"
grep -oE '(^|[^*])\*[^* ][^*]*\*([^*]|$)' "$F" | wc -l

# 5. 세로 변형 필요 여부(임시 폴더)와 흑백 미리보기(_render/qa, qa-checklist.md 2.3절)
T=$(mktemp -d); Q="${F%/*}/_render/qa"; mkdir -p "$Q"
bash scripts/render_mermaid.sh --variant --out-dir "$T" "$F"
node scripts/svg_to_png.mjs "${F%.mmd}.svg" "$Q/$(basename "${F%.mmd}").gray.png" --gray

# 6. 열마다 상자 크기(테두리 바깥 끝). 패턴 표의 폭(P1 주 열 240 x 64)과 비교 (patterns.md 9.2절과 같음)
python3 -c 'import sys,re,collections
s=open(sys.argv[1],encoding="utf-8").read(); c=collections.defaultdict(list)
for r in re.findall(r"<rect[^>]*stroke-width=\"[\d.]+\"[^>]*>",s):
    g=lambda a:float(re.search(a+r"=\"([\d.]+)\"",r).group(1)); sw=g("stroke-width")
    if g("width")<590 and g("height")>32: c[round(g("x")-sw/2)].append("%g x %g"%(g("width")+sw,g("height")+sw))
for x in sorted(c): print(x, c[x])' "${F%.mmd}.svg"
```

명령 2의 `#[0-9A-Fa-f]{6}`는 `accDescr` 안의 문장에도 걸릴 수 있으니 결과는 후보로 보고 사람이 확인해요.

`render_mermaid.sh` 옵션(정본은 `bash scripts/render_mermaid.sh --help`)

| 옵션 | 하는 일 |
|---|---|
| (없음) | 장 폴더, 권 폴더, `figures-part/`, 개별 `.mmd`를 받아 원본 옆 `X.svg`로 렌더링. `X.v.mmd`는 `X.v.svg`가 됨 |
| `--check` | 렌더링하지 않고 원본이 SVG보다 새롭거나 SVG가 없는 파일만 보고(종료 코드 1) |
| `--png` | 렌더링 뒤 `_render/qa/X.png` 미리보기도 만듦(시각 검수 묶음은 `figure_qa.py`) |
| `--variant` | `X.v.mmd`가 없는 그림에서 방향만 TB로 바꾼 세로 변형 `X.v.svg`도 만듦(`epub_variant: auto`) |
| `--out-dir DIR` | 출력 SVG와 PNG를 DIR에 씀(시험, 시안 비교용) |

스크립트를 못 쓸 때의 예비 명령은 `assets/mermaid/_build/render.sh "$F" "${F%.mmd}.svg"`(세로 변형은 `--width 360`)입니다.
