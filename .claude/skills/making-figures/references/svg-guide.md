# SVG 그림 그리기 (svg-guide)

S 그림(직접 그리는 SVG)과 T 그림(표 생성기)을 만드는 작업 안내서입니다. build 스크립트를 어떤 골격으로 쓰고, 어느 순서로 어떤 figkit 함수를 부르고, 부품과 로봇과 표를 어떻게 가져오는지 정리했습니다. 도구의 정본은 `assets/svg-parts/_build/`의 `figkit.py`(독스트링), `table.py`, `README.md`입니다. 규칙의 정본은 `docs/style-guide.md`예요. 이 문서와 값이 다르면 그쪽이 맞고, 이 문서를 고칩니다.

S 그림의 표준 도구는 figkit입니다. 좌표 격자, 글자 넘침, 연결선 꺾임 같은 규칙을 그리는 순간 함수가 막아 주므로, 손으로 `<rect>`를 적는 것보다 실수가 훨씬 적어요.

## 목차

1. 이 문서의 쓰임과 경계
2. 작업 순서 한눈에
3. build 스크립트 골격과 최소 예제
4. 캔버스와 머리줄
5. 격자와 정렬
6. 상자, 글자, 강조, 칩, 연결선, 지시선
7. 부품 재사용: `<use>`와 함수
8. 로봇과 데모 장면
9. T 그림: table.py
10. 세로 변형 만들기
11. 글자 처리: 편집용과 출간용
12. lint, 미리보기, 오류 고치기
13. 자주 하는 실수

## 1. 이 문서의 쓰임과 경계

| 언제 | 볼 곳 |
|---|---|
| 스크립트를 만들고 좌표를 정할 때 | 3장 골격과 예제, 4장 캔버스, 5장 격자 |
| 요소를 하나씩 그릴 때 | 6장(작업 순서대로) |
| 부품, 로봇, 표를 넣을 때 | 7장, 8장, 9장 |
| 저장하고 오류를 볼 때 | 12장 |

메시지 한 문장, 강조 하나, 요소 수 상한, 색과 글자 위계 같은 도구 공통 규칙은 `design-rules.md` 2~8장에 있습니다. S로 그릴지, 세로 변형이 필요한지, 파일 이름은 무엇인지는 `choose-type.md` 3~6장이 정합니다. `<title>`, `<desc>`, 캡션은 `caption-alt.md` 3.4절이 맡습니다. 시각 검수는 `qa-checklist.md`, 반복 레이아웃 꼴은 `patterns.md`에 있어요. 이 문서는 그 규칙을 SVG 코드로 옮기는 방법만 씁니다.

## 2. 작업 순서 한눈에

1. 메시지 한 문장, 정본 ID와 문자열, 강조 대상 하나를 정합니다(`design-rules.md` 2장).
2. 종이나 머릿속에서 상자 개수와 행, 열을 정하고 캔버스를 고릅니다(4장).
3. `vol*/chNN/figures/X.build.py`를 3장 골격으로 만들고 상수 블록부터 채웁니다.
4. 좌표를 `columns`, `stack`으로 계산하고 상자를 그립니다(5장, 6.1절).
5. 글자, 강조, 칩, 연결선, 지시선 순서로 얹습니다(6.2~6.6절).
6. `save(..., preview=폴더)`로 저장하고 lint 결과와 PNG 세 장을 봅니다(12장).
7. 세로 변형이 필요하면 `LAYOUT['v']`만 채워 같은 스크립트로 뽑습니다(10장).

## 3. build 스크립트 골격과 최소 예제

스크립트 하나가 그림 하나와 그 세로 변형을 만듭니다. 확장자는 `.build.py`이고 출력은 같은 폴더의 `X.svg`, `X.v.svg`입니다(`choose-type.md` 6장).

### 3.1 골격 다섯 칸

| 칸 | 내용 | 왜 |
|---|---|---|
| 머리 docstring | 그림 ID와 대상 이름, 설계서 명세 원문, 메시지, 정본 ID와 문자열, 설계 판단, 실행 명령 | 검수자가 소스만 열어도 숫자 출처와 배치 이유를 대조할 수 있음 |
| 상수 블록 | 정본 문자열, 메시지, `DESC`(=`figures.yml`의 `alt`) | 숫자와 글이 한 곳에만 있어 두 판이 어긋나지 않음 |
| `LAYOUT` dict | `body`, `v`(필요하면 `spread`)마다 달라지는 배치 값 | 세로 변형을 복사본 없이 만듦 |
| `build(variant)` | `Figure` 생성, 그리기, `save` | 판마다 같은 순서로 그림 |
| 실행 블록 | `for v in LAYOUT: build(v, 미리보기폴더)` | 명령 한 번에 두 판 |

docstring 칸 구성은 시안 `docs/style-board/final/1-4-4.build.py` 머리와 `chart-guide.md` 2.1절에 맞춘 **제안**입니다. 설계 판단 칸에는 "왜 이 배치인가"를 씁니다. 1-4-4의 "선 굵기 대신 띠 폭 = 가중치" 같은 결정이 여기 남아야 다음 사람이 되돌리지 않아요.

### 3.2 최소 예제

아래는 정본 1권 N4-2로 만든 연습용 그림입니다(실제 1-4-3은 M 그림). 저장소와 같은 폴더 구조에서 실행해 두 판 모두 `lint: OK`를 얻었고, 컬러, 흑백, 폭 328 PNG를 열어 확인했습니다(640 × 216, 360 × 360).

```python
"""그림 1-4-3 연습판: 어텐션 가중치 3단계 (svg-guide 최소 예제. 실제 1-4-3은 M 그림)

명세: 1권 설계서 4장 그림 1-4-3(M)을 S 연습용 3단계로 줄임
메시지: '안'은 '왔어요'를 가장 많이 봅니다
정본: 1권 N4-2. 점수 [1, 2, 3], 가중치 왔어요 0.576(문자열 그대로)
설계 판단: 가로 3상자(6.3절 상한 안). 강조는 03 메시지 상자와 0.576 밑줄 한 덩어리.
          세로 변형은 같은 상자를 위에서 아래로 쌓고 척추(L + 24)로 잇는다.
실행: .venv/bin/python vol1-llm/ch04/figures/1-4-3.build.py [미리보기폴더]
"""
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[3]          # vol*/chNN/figures/ 에서 저장소 루트
sys.path.insert(0, str(ROOT / 'assets/svg-parts/_build'))
import figkit as fk  # noqa: E402
from figkit import b, m, em  # noqa: E402

# ---- 정본 문자열(설계서 7장 그대로, float로 바꾸지 않음)
SCORE = '[1, 2, 3]'
DIV = '÷ √d, d = 2'
W_MSG = '0.576'
MSG = "'안'은 '왔어요'를 가장 많이 봅니다"
DESC = ("토큰 '안'의 점수 1, 2, 3이 루트 2로 나뉘어 0.707, 1.414, 2.121이 되고, "
        "softmax를 거쳐 '왔어요'의 가중치가 0.576으로 가장 큽니다.")

# ---- 배치: 판마다 다른 값은 여기에만
LAYOUT = {
    'body': dict(flow='row', gap=32, side='left'),
    'v':    dict(flow='col', gap=32, side='right'),
}


def build(variant, preview=None):
    L = LAYOUT[variant]
    fig = fk.Figure('1-4-3', '어텐션 가중치', variant=variant, height='auto', desc=DESC)
    specs = [('step', [b('01 점수'), m(SCORE)]),
             ('step', [b('02 나누기'), DIV]),
             ('message', [b('03 가중치'), [m('왔어요 '), em(W_MSG)]])]
    boxes = []
    with fig.group(canon='N4-2'):
        if L['flow'] == 'row':
            for (kind, lines), (x, w) in zip(specs, fk.columns(3, fig.L, fig.R, gap=L['gap'])):
                boxes.append(fig.box(x, fig.top, w, 64, kind, lines=lines))
            fk.check_row(boxes)
            for a, c in zip(boxes, boxes[1:]):
                fig.connect(a, c, 'right', 'left')
        else:
            for (kind, lines), y in zip(specs, fk.stack(fig.top, [64] * 3, gap=L['gap'])):
                boxes.append(fig.box(fig.L, y, fig.content_w, 64, kind, lines=lines))
            fk.check_col(boxes)
            for a, c in zip(boxes, boxes[1:]):
                fig.connect(a, c, 'bottom', 'top', a_at=24, b_at=24)   # 척추 x = L + 24
        fig.leader(boxes[-1].port('bottom', 32), 'down', 24, MSG, message=True, side=L['side'])
    out = Path(__file__).with_name('1-4-3.v.svg' if variant == 'v' else '1-4-3.svg')
    probs = fig.save(out, preview=preview)
    print(out.name, f'{fig.W} x {fig.H}', 'lint:', probs or 'OK')


if __name__ == '__main__':
    for v in LAYOUT:
        build(v, sys.argv[1] if len(sys.argv) > 1 else None)
```

처음 판에서는 02 상자 값에 `[0.707, 1.414, 2.121]`을 넣었습니다. 그러자 `상자 안 글자가 넘칩니다(폭 158 > 144)`로 멈췄어요. 3등분 상자(176)의 안쪽 폭이 144라서입니다. 글자를 줄이지 않고 값 대신 연산(`÷ √d, d = 2`)을 쓰는 쪽으로 문구를 바꿨습니다. figkit 오류는 이렇게 "배치나 문구를 다시 정하라"는 신호로 읽으면 돼요.

더 긴 실제 견본은 `docs/style-board/figkit-sample.build.py`입니다. 1-4-3 세로 변형을 노드 7개, 척추, 합류선까지 figkit으로 다시 만든 것입니다.

## 4. 캔버스와 머리줄

| 캔버스 | `variant` | 폭 | 여백 | 허용 높이 | 근거 |
|---|---|---|---|---|---|
| 본문 폭 | `'body'` | 640 | 24 | 216, 320, 480, 640 | style-guide 5.1 |
| 펼침 폭 | `'spread'` | 800 | 24 | 264, 400, 600 | 5.1 |
| 세로 변형 | `'v'` | 360(`width=`로 400까지 8 단위) | 16 | 8의 배수, 720 이하 | 5.1, 5.11 |

- `height='auto'`를 기본으로 씁니다. `save()` 때 내용 아래 끝 + 여백이 들어가는 가장 작은 허용 높이를 고르고, 남는 공간은 본문을 8 단위로 내려 위아래로 나눕니다(5.1절). 내용이 가장 큰 높이를 넘으면 `FigkitError`이고, 그때는 그림을 나눕니다.
- 높이를 숫자로 고정하면 내용이 아래 여백을 넘을 때 오류가 납니다. 같은 장의 그림끼리 높이를 맞춰야 할 때만 고정해요.
- 머리줄(그림 번호, 대상 이름, 괘선 y 32.5)과 흰 바탕, `<title>`, `<desc>`, 루트 글꼴과 `tnum`은 `Figure`가 만듭니다. 직접 그리지 않습니다.
- 대상 이름은 본문 16자, 세로 변형 14자 이하이고, 정본 ID를 넣으면 오류입니다(5.2절, 6.8절).
- 그리기 영역은 `fig.L`, `fig.R`(좌우 여백 안쪽 끝), `fig.top`(= 56, 본문 시작), `fig.content_w`입니다. 좌표는 이 네 값에서 출발합니다.

## 5. 격자와 정렬

규칙은 style-guide 5.3절(8 격자, 간격표), 5.4절(정렬)입니다. figkit은 이 규칙을 도우미 함수와 그리는 순간의 검사로 구현해요.

| 함수 | 하는 일 | 쓰는 때 |
|---|---|---|
| `fk.columns(n, x0, x1, gap=32)` | 같은 폭 상자 n개의 `[(x, 폭)]`. 폭은 8 단위로 내리고 남는 폭은 양옆에 나눔. 폭이 120 미만이면 오류 | 한 행 배치 |
| `fk.stack(y0, [높이...], gap=32)` | 위에서 아래로 쌓을 때 각 y | 한 열 배치, 세로 변형 |
| `fk.snap(v)`, `snap_up`, `snap_down` | 8(또는 `unit=4`) 격자 값으로 맞춤 | 계산한 좌표를 격자에 얹을 때 |
| `fk.center_in(크기, 시작, 길이)` | 구간 가운데에 놓는 시작 좌표(격자 단위) | 묶음 하나를 가운데 둘 때 |
| `fk.check_row(boxes)` | 위 끝, 높이, 간격이 모두 같은지 | 행을 그린 직후 |
| `fk.check_col(boxes)` | 왼쪽 끝과 폭이 같은지 | 열을 그린 직후 |

- `gap`은 간격표 값(4, 8, 16, 24, 32, 48, 64)만 줍니다. 다른 값이면 경고가 나요. 화살표로 잇는 상자 사이는 32, 화살표 없는 상자 사이는 24, 묶음 사이는 48입니다.
- 부르는 쪽은 격자 정수만 넘깁니다. 선 굵기 반만큼 안쪽으로 들이는 0.5 처리는 함수가 합니다.
- `check_row`, `check_col`은 오류를 내기만 하고 고쳐 주지 않습니다. 같은 역할 상자는 같은 크기로 그리는 습관을 지키는 장치예요.

lint의 격자 규칙은 이렇게 나뉩니다.

| 대상 | 단위 | 판정 |
|---|---|---|
| 테두리나 면이 보이는 `<rect>`(높이 32 초과) | 바깥 끝 x, y, 폭, 높이 8 | 어기면 경고 |
| 칩(높이 32 이하, `num-chip` 묶음 안) | 4 | 어기면 경고 |
| 표(`t-table` 묶음 안) | 검사 안 함 | 행 높이 40, 기준선 +26이 9.5절 표 예외라서 |
| 글자 기준선 | 검사 안 함 | 아래 설명 |

글자 기준선은 5.3절이 "4의 배수"라고 하지만, 상자 안 글자는 5.9절의 오프셋을 따릅니다. 한 줄 상자는 위 끝 + 30이고, 두 줄 16 글자를 64 상자에 넣으면 +27과 +49가 나와요. 이 값들은 4의 배수가 아니라서 기준선을 격자로 검사하면 맞게 그린 그림이 모두 걸립니다. 그래서 lint는 기준선을 보지 않고, `box()`, `step_box()`가 5.9절 값으로 직접 계산합니다. 상자 밖 글자(`fig.text`)의 기준선만 손으로 4의 배수에 둡니다.

## 6. 상자, 글자, 강조, 칩, 연결선, 지시선

작업 순서대로 적었습니다. 척추와 합류선처럼 선 끝이 상자 테두리에 묻혀야 하면 선을 먼저 그립니다. 상자를 나중에 그려 테두리가 선 끝을 덮게 해요(`figkit-sample.build.py`).

### 6.1 상자

`fig.box(x, y, w, h=None, kind='step', band=None, lines=None)`가 상자와 안의 글자를 함께 그리고 `Box`를 돌려줍니다. `Box`의 `.left`, `.right`, `.top`, `.bottom`, `.port(변, at)`이 다음 단계 좌표의 출발점이에요.

| `kind` | 5.9절 종류 | 쓰는 곳 |
|---|---|---|
| `input` | 입력 상자(1px ink-200) | 입력 값, 데이터 묶음, 출발점과 도착점, 참조 대상처럼 처리 단계가 아닌 상자(1-4-4 쿼리와 키 상자) |
| `step` | 단계 상자(1px ink-600) | 흐름의 처리 단계(기본) |
| `message` | 메시지 상자(1.5px ink-900, paper-warm) | 메시지를 증명하는 대상 1개 |
| `accent` | accent 1.5px, tint 면 | 메시지 대상이 강조색이어야 할 때만 |
| `exit` | 1px ink-400 파선 | 흐름 밖으로 빠지는 출구 |
| `panel`, `panel-line` | 묶음 패널(테두리 없음 또는 ink-100) | 여러 상자를 한 묶음으로. 패널 안 패널 금지 |

- 기본값 `kind='step'`은 ink-600 테두리라 단계가 아닌 상자에 그대로 쓰면 비강조 요소가 한 단계 진해집니다. 상자마다 종류를 먼저 정해요(`design-rules.md` 9장 5번 아래 표).
- `h`를 비우면 한 줄 48, 두 줄 64입니다. 같은 열의 같은 종류 상자는 줄 수를 맞춥니다. 한 상자만 둘째 줄을 더하면 높이가 달라져 lint가 "같은 종류 상자 크기 다름"으로 경고해요. 단계 번호와 이름, 값이 있는 72 상자는 `fig.step_box(x, y, w, '01', '점수', value=..., right='q와 k의 내적')`로 그립니다.
- `band='c-query'`처럼 개념 토큰을 주면 왼쪽에 폭 4 개념 띠가 붙습니다. 글자 위치는 그대로입니다. 개념색 면은 칠하지 않아요(`design-rules.md` 9장 기준 11).
- `baselines=(24, 50)`로 기준선을 직접 줄 수 있습니다. 5.9절 "이름 14 + 값 16" 두 줄 상자처럼 줄마다 크기가 다를 때 씁니다.

### 6.2 글자와 줄바꿈

한 줄은 문자열 또는 조각 리스트입니다. 조각 함수는 다섯 개예요.

| 조각 | 모양 | 쓰는 곳 |
|---|---|---|
| `b('01 점수')` | 600 | 상자 첫 줄 이름 |
| `m('[1, 2]')` | 500 | 숫자, 벡터 값(4.1절) |
| `em('0.576')` | accent 600 + 밑줄 | 그림당 한 곳의 강조 |
| `sub('i')`, `sup('T')` | 14, 기준선 이동 | 첨자(4.7절). 유니코드 첨자 글자 대신 |

- 상자 안에서는 `lines=[[b('쿼리 q'), ' (안)'], m('[1, 2]')]`처럼 줄 리스트를 줍니다. 문자열 하나를 주면 안쪽 폭(상자 폭 − 32)에 맞춰 어절에서 자동으로 나눕니다.
- 상자 밖 글자는 `fig.text(x, y, 줄, size, weight, fill, anchor, max_w)`, 여러 줄은 `fig.lines(...)`입니다. `max_w`를 주면 넘칠 때 멈춰요.
- 크기는 14, 16, 20, 굵기는 400, 500, 600만 받습니다. 다른 값을 주면 바로 오류입니다(4.1, 4.2절).
- 줄 수 상한은 20이 1줄, 16이 2줄, 14가 3줄입니다(4.4절). 넘치면 `wrap`이 멈춥니다. 글자 크기를 줄이지 말고 문구를 줄이거나 상자를 넓힙니다.
- 글자 폭은 `fk.measure(줄, size, weight)`로 미리 잴 수 있습니다. Pretendard 실측 폭이고 숫자는 tnum 폭으로 잡아요.

### 6.3 강조

강조는 한 덩어리입니다(`design-rules.md` 2장). S 그림에서 쓸 수 있는 수단은 셋이고, 보통 둘을 묶어 한 덩어리로 만듭니다.

| 수단 | 함수 | 예 |
|---|---|---|
| 메시지 상자 | `kind='message'` | 03 가중치 상자 |
| 강조 글자 | `em(...)` | 0.576 밑줄 |
| 강조 칩, 강조 화살표 | `chip(..., emph=True)`, `tone='arr-accent'` | 1-4-4 칩 열의 0.576 |

- 숫자 하나를 강조할 때는 강조 칩을 먼저 고릅니다. `em(...)` 밑줄을 숫자에 걸면 웹과 EPUB에서 링크처럼 읽힐 수 있어요. 4장 1-4-3(M)에서 reviewer가 이 점을 짚어(R1-G04) Mermaid 판은 굵기 600으로 바꿨습니다. 이름 아래 밑줄(P5, P6 현재 단 표시)은 승인된 표현이라 그대로 씁니다.

lint는 강조색이 쓰인 곳을 세어 3곳(칩 포함)을 넘으면 경고합니다. 지시선 점과 화살표 머리는 세지 않아요.

### 6.4 숫자 칩

```python
w = fig.chip_w('0.576')                                   # 칩 폭을 먼저 재서
fig.chip(box.right - 16 - w, box.bottom + 16, '0.576', emph=True, canon='N4-2')
```

- 칩은 정본 숫자에만 답니다. `canon`을 빼면 경고, 저장된 SVG에 `data-canon`이 없으면 lint 오류입니다(6.5절).
- 칩 좌표는 4의 배수이고, 오른쪽 정렬은 `chip_w`로 폭을 재서 x를 정합니다. 단위는 `unit='ms'`처럼 따로 줘요(9.6절).
- 텍스트 토큰(낱말)은 칩이 아니라 `fig.token(x, y, '상자가')`입니다. 숫자 칩에 낱말을, 토큰 칩에 숫자를 넣지 않습니다.

### 6.5 연결선

| 함수 | 쓰는 때 |
|---|---|
| `fig.connect(a, b, a_side, b_side, a_at, b_at, mid, tone, check=True)` | 두 상자를 잇는 기본 방법 |
| `fig.wire([(x, y), ...], end, start, tone)` | 척추, 합류선처럼 점을 직접 정할 때 |

`connect`가 경로를 고르는 규칙입니다.
- 같은 축의 두 변(`bottom`과 `top`, `right`와 `left`): 연결점이 일직선이면 곧은 선, 아니면 가운데 `mid`(4 단위)에서 꺾임 2회.
- 서로 수직인 변(`bottom`과 `left` 등): 꺾임 1회.
- 끝은 도착 테두리 6 앞에서 멈추고 꺾쇠가 붙습니다. 머리 앞 곧은 선이 16보다 짧으면 경고예요.
- `check=True`(기본)면 경로가 다른 상자를 지나갈 때 오류입니다. 척추가 합류선과 만나는 경우처럼 의도한 겹침에만 `check=False`를 씁니다.
- `a_at`, `b_at`이 1 이하면 변 길이의 비율, 1보다 크면 변 시작에서 잰 거리입니다. 척추에 맞추려면 `a_at=24, b_at=24`를 줍니다.

`wire`는 가로, 세로 선분만 받고 꺾임 3회부터 오류입니다. `end='join'`은 머리 없이 다른 선의 가운데까지 이어 합류선을 만들어요. `tone`은 `'arr'`(기본, ink-600), `'arr-ink900'`(강조 흐름), `'arr-accent'`(메시지 1곳) 셋입니다. marker 정의는 `save()`가 그림 id 접두어(`f143-arr`)를 붙여 넣습니다.

화살표 라벨은 선에서 8 떨어진 곳에 `fig.text`로 16 크기, 가로로 씁니다. 흰 바탕을 깔아 선을 가리지 않아요(5.7절).

### 6.6 주석 지시선

```python
fig.leader(box.port('bottom', 32), 'down', 24, MSG, message=True, side='left')
```

- 대상 테두리 위 점에서 `direction`으로 `length`(16~48)만큼 뻗습니다. 끝에 반지름 3 점을 찍고, 점 중심에서 11 떨어진 곳에 14 글자를 둡니다(5.8절).
- `message=True`는 메시지 지시선(점 accent, 글자 ink-900 600)이고 그림당 1개입니다. 보조 지시선은 `False`예요.
- 문장은 30자 이내이고, 24자를 넘으면 두 줄로 나뉩니다. 오른쪽에 자리가 없으면 `side='left'`로 글자를 점 왼쪽에 끝 정렬합니다. 최소 예제 본문 판이 그 경우예요.
- 대상이 연결선 자체면 `on_line=True`로 선 없이 점만 찍습니다.

## 7. 부품 재사용: `<use>`와 함수

부품은 두 가지 방법으로 가져옵니다. 글자 길이나 칸 수가 바뀌는 부품은 함수로, 모양이 고정된 부품은 기호(`<symbol>`)로 씁니다.

| 부품 | 방법 | 이유 |
|---|---|---|
| 개념 부품 `cp-`(토큰, 칩, 문서 조각, 도구, 에이전트, 메모리, 행렬, 벡터) | `concepts.py` 함수. figkit의 `chip`, `token`, `box(band=)`가 감싼 것은 그쪽으로 | 스프라이트 기호는 기본 글자 견본이라 늘리면 선과 글자도 늘어남(9.6절) |
| 로봇 `rb-` | 기호를 `<defs>`에 복사하고 `<use>` | 모양이 고정이고 스크립트로만 다시 만듦(9.4절) |
| 데모 칩 `demo-`(값이 정해진 칩) | 기호 복사 + `<use>` | 9.3절 |
| 데모 칩(3배속, 시도 수처럼 값이 바뀌는 칩) | `demo-strip-template`의 칸 묶음을 복사해 글자만 바꿈 | 9.3절 쓰는 법 2 |
| 위치 표시 `pos-` | 기호 복사 + `<use>` | 9.2절 |
| 화살표, 흑백 무늬 | 손대지 않음. `save()`가 쓰인 것만 `<defs>`에 넣음 | 5.7절, 3.4절 |
| 장 아이콘 `ic-` | 그림 안에 쓰지 않음. 단 `ic-human`은 c-human, c-demo의 사람 개입 표지로 기호 복사 + `<use>`(24 크기) | 원고 박스 머리용, `ic-human`만 예외(9.1절). `Figure.use`가 다른 `ic-`는 막음 |

종류별 대표 id입니다. 전체 목록은 style-guide 9장 각 절의 id 표를 봅니다.

| 스프라이트 | 대표 id |
|---|---|
| `concepts.svg` | `cp-token-text`, `cp-num-chip`, `cp-chunk`, `cp-tool`, `cp-agent`, `cp-memory`, `cp-mcp`, `cp-untrusted-badge` |
| `robots.svg` | `rb-r1`, `rb-r2`, `rb-r3`, `rb-r3-sil`, `rb-r3-dof-panel`, `rb-joint-revolute`, `rb-sn-camera` |
| `demo.svg` | `demo-op-teleop`, `demo-op-auto`, `demo-speed-1x`, `demo-speed-2x`, `demo-na`, `demo-gen-g0`~`demo-gen-g5` |
| `position.svg` | `pos-L0`~`pos-L5` 꼴(L, G, P 척도별 76개) |

기호는 `fig.use(id, x, y)`로 놓습니다. id 머리(`cp-`, `rb-`, `demo-`, `pos-`, `ic-`)로 스프라이트를 찾아(`ic-`는 `assets/icons/icons.svg`), 기호 정의를 이 그림의 `<defs>`에 한 번만 복사하고 `<use>`를 둬요. 같은 기호를 여러 번 놓아도 정의는 하나입니다.

```python
r = fig.use('rb-r2', fig.L + 8, fig.top)              # 로봇, viewBox 크기 그대로(1:1)
for i, sid in enumerate(['demo-op-auto', 'demo-speed-1x', 'demo-na']):
    fig.use(sid, 304, fig.top + 40 + i * 32)          # 데모 표시 칸, 칸 사이 8
```

- 좌표는 4의 배수이고, 기호가 바깥 여백을 넘으면 그리는 순간 `FigkitError`가 납니다. 돌려받은 Box로 연결선과 지시선 자리를 잡아요.
- 자동 높이 계산에 기호 아래 끝이 들어가므로 `bottom=`을 따로 넘기지 않습니다.
- `scale`은 기본 1.0입니다. 바꾸면 기호 안의 선 굵기와 글자 크기가 함께 변하므로 figkit이 경고합니다.
- 외부 참조(`href="robots.svg#rb-r2"`)는 쓰지 않습니다. `<img>`로 넣은 SVG는 외부 파일을 읽지 못해 웹북과 EPUB에서 빈칸이 되므로, 복사 방식이 표준이에요(style-guide 9.4절 쓰는 법, 9.2, 9.3절도 같음).
- lint는 `<defs>`와 `<symbol>` 안의 글자와 선을 배치 검사(격자, 겹침, 여백, 선 굵기)에서 뺍니다. `<use>`로 놓인 기호의 바깥 상자만 여백, 격자, 부품 수 검사에 들어가요. 금지 기호와 팔레트 밖 HEX는 기호 안도 그대로 검사합니다.

## 8. 로봇과 데모 장면

로봇은 `rb-` 부품만 씁니다. 새로 그리지 않고, 다른 형태가 필요하면 `build_robots.py`에 같은 규칙으로 추가를 제안합니다(9.4절).

- 크기: 1:1이 기본입니다. 0.5배까지만 관절 있는 형태를 쓰고, 더 작으면 `-sil`로 바꿔 높이 64 이상으로 둡니다.
- 관절 원은 위치 표시일 뿐 자유도 수가 아닙니다. 자유도 숫자는 `rb-r3-dof-panel`에만 씁니다.
- 센서 이름, 관절 이름은 주석 지시선으로 붙입니다. 바닥선, 작업대는 부품에 없으니 `fig.rule(..., tone='ink-600')`으로 그립니다.
- 금지 사항(얼굴, 눈, 화면, 로고, 몸체 개념색, 둥근 외피 등)은 style-guide 9.4절 "금지 사항"을 그대로 따릅니다. 비율을 바꿔 특정 제품을 닮게 만들지 않아요.
- 새 장면을 만들면 9.4절 "닮음 점검표"로 스스로 한 번 보고, 저자 확인 항목으로 `figures.yml`의 `note`에 남깁니다.

데모 장면(로봇이 실제로 한 일을 보여 주는 그림)에는 장면 아래 16에 표시 줄을 반드시 둡니다(CLAUDE.md 10장, 9.3절).

| 순서 | 칸 | 필수 | 값이 없으면 |
|---|---|---|---|
| 1 | 조작 방식 | 필수 | `demo-na` |
| 2 | 재생 속도 | 필수 | `demo-na` |
| 3 | 시도 수 | 권장 | `demo-na`, 뺄 때는 오른쪽부터 |
| 4 | 일반화 칸 | 권장 | `demo-na`, 뺄 때는 오른쪽부터 |

- 열 폭 136, 열 사이 16으로 네 칸이 내용 폭 592를 채웁니다. 칸 이름(14, ink-500)은 줄 위 끝 + 16, 칩은 + 24에 둡니다.
- 값은 출처에 있는 것만 씁니다. 출처에 없으면 짐작하지 않고 `demo-na`입니다.
- 세로 변형에서는 2칸 × 2줄로 접습니다(열 폭 156, 열 사이 16, 줄 사이 8).

## 9. T 그림: table.py

표 그림은 손으로 그리지 않고 YAML 명세 하나에서 생성합니다. 서식 규칙 전체는 style-guide 9.5절이고, 견본 명세는 `assets/svg-parts/_build/table-samples/2-4-2.yml`입니다. 명세 파일은 `vol*/chNN/figures/X.yml`에 둡니다.

```yaml
figure: 2-4-2                    # 머리줄 왼쪽 "그림 2-4-2"
subject: RRF 계산표              # 머리줄 오른쪽(16자 이하)
canon: [N4-2]                    # data-canon으로만. 그림에 글자로 쓰지 않음
title: 그림 2-4-2 RRF 계산표
desc: 문서 A, B, C, D의 ... 순서는 A, B, C, D입니다.   # figures.yml alt와 같은 글
columns:                         # 첫 열은 행 이름. kind: label, num, note
  - {key: doc, label: 문서}
  - {key: rrf, label: RRF 점수, kind: num}
rows:                            # 값은 정본 문자열을 따옴표로 감싸 그대로
  - {doc: 문서 A, rrf: "0.03252"}
emphasis: {row: 0, col: rrf}     # 강조 칸 1곳. col을 빼면 행 전체
message: 두 검색 모두 상위인 문서 A가 1위입니다
notes:                           # 바닥 괘선 아래 주석, 2줄 이하
  - 행 순서가 최종 순위입니다
```

```bash
.venv/bin/python assets/svg-parts/_build/table.py vol2-agent/ch04/figures/2-4-2.yml -o vol2-agent/ch04/figures/2-4-2.svg
.venv/bin/python assets/svg-parts/_build/table.py vol2-agent/ch04/figures/2-4-2.yml -o vol2-agent/ch04/figures/2-4-2.v.svg --variant v
.venv/bin/python assets/svg-parts/_build/figkit.py lint vol2-agent/ch04/figures/2-4-2*.svg
```

- 행마다 다른 개념이면 행에 `_band: c-chunk`를 줍니다. 모든 행이 같은 개념이면 띠를 두지 않아요.
- 강조 칸은 그림당 한 곳이고, 숫자 칩을 대신합니다. 표 안 숫자에 칩을 따로 달지 않습니다.
- 메시지 지시선은 강조 칸이 마지막 열일 때 칸 오른쪽으로 나갑니다. 그 밖에는 바닥 괘선 아래 첫 줄로 내려가요(9.5절 예외).
- 세로 변형은 `--mode auto`(기본)가 고릅니다. 열 최소 폭 합이 328 이하면 같은 표를 다시 배치하고, 넘으면 행마다 카드 하나로 쌓습니다. 전치는 쓰지 않습니다.
- 세로 변형이 필요한지는 T 그림도 `choose-type.md` 5장 필요 여부로 정합니다. 만들면 `epub_variant: manual`, 아니면 `none`으로 적어요.
- 생성기는 금지 기호, 글꼴에 없는 글자, 6 × 4 상한, 줄 수 초과, 높이 초과에서 멈춥니다. `--force`는 미리보기 시트용이라 책 그림에는 쓰지 않습니다.
- 견본 명세로 두 판을 만들어 lint를 돌리면 둘 다 OK입니다(640 × 320, 360 × 360).

## 10. 세로 변형 만들기

세로 변형이 필요한지는 `choose-type.md` 5장이 정합니다. 만들기로 했다면 같은 스크립트의 `LAYOUT['v']`를 채웁니다. 별도 스크립트로 복사하면 정본 숫자가 두 곳에 생겨요.

재배치 원칙(5.11절)
1. 노드, 글자, 정본 숫자, 메시지, 강조 위치는 원본과 같습니다. 바꾸는 것은 좌표뿐입니다.
2. 흐름은 위에서 아래로 쌓습니다(`fk.stack`). 단계 상자는 내용 폭 전체(`fig.content_w`)로 넓혀 글자 자리를 얻어요.
3. 연결선은 왼쪽 척추 하나로 모읍니다. `fig.spine_x`(= L + 24)이고, `connect(..., a_at=24, b_at=24)`가 그 선 위로 지나갑니다.
4. 입력은 처음 쓰이는 단계 바로 위로 옮겨도 됩니다. 입력 상자는 척추 오른쪽 16에서 시작합니다(`figkit-sample.build.py`의 `X_IN`).
5. 지시선은 척추 오른쪽으로 글자를 넓게 씁니다. 최소 예제가 본문 판은 `side='left'`, 세로 판은 `'right'`로 나눈 이유예요.
6. 원본 문구가 360에 들어가지 않으면 두 판 모두 문구를 고칩니다. 세로 판만 다른 말을 쓰지 않습니다.

- `<title>` 끝의 "(EPUB 세로 변형)"과 id 접두어 `v`(`f143v`)는 `Figure(variant='v')`가 붙입니다. `desc`는 원본과 같은 상수를 넘깁니다.
- 폭은 360이 기본입니다. `width=400`은 끊을 수 없는 정본 숫자 묶음 한 덩어리(대괄호 벡터, 수식, 숫자와 단위)가 내용 폭 328에 들어가지 않을 때만 씁니다. 지시선 글, 라벨, 부연이 길어서는 400으로 넓히지 않고 문장을 줄이거나, 줄을 나누거나, 상자 안 라벨로 옮깁니다. 400을 쓰면 그 숫자 묶음을 `note`에 적어요. 높이가 720을 넘으면 오류이니 그림을 나누는 것부터 검토합니다.
- 모듈이 둘인 블록(P9 두 단)은 `patterns.md` P9 "모듈 둘 세로 변형" 와이어프레임대로 입력 행과 모듈을 번갈아 쌓습니다. 입력이 옆이나 아래에서 들어오면 읽는 방향이 본문과 뒤집혀요.
- `LAYOUT`에는 판마다 다른 값(흐름 방향, 열 x, 상자 폭, 지시선 방향과 쪽)만 둡니다. 숫자와 글은 상수 블록에 둡니다.

## 11. 글자 처리: 편집용과 출간용

편집용 원본(저장소의 `X.svg`)은 글자를 `<text>`로 둡니다. 고치기 쉽고, 검색과 정본 숫자 대조가 되기 때문입니다(4.9절).

| 단계 | 글자 | 도구 | 상태 |
|---|---|---|---|
| 편집용 `X.svg`, `X.v.svg` | `<text>`, 루트에 Pretendard와 `tnum` | figkit, table.py | 지금 씀 |
| 출간용 사본 | 윤곽선(path) | tnum을 적용하는 변환 도구 | 아직 없음. tasks.md 11.2절(8단계 빌드) "SVG 글자 윤곽선 변환본" 작업 |

출간용 변환이 지킬 조건은 4.9절에 있습니다. 변환 도구가 생기기 전까지 그림 작업자가 할 일은 셋입니다.
- 편집용 SVG에 `@font-face`나 글꼴 데이터를 넣지 않습니다. 예약 글꼴명 조건에 걸려요.
- 변환을 염두에 두고 글자를 path로 손수 바꾸지 않습니다. 편집용은 언제나 글자입니다.
- `<desc>`와 캡션은 변환과 상관없이 글자로 남습니다. 대체 텍스트를 그림 글자에 기대지 않아요(`caption-alt.md` 3장).

글꼴에 없는 글리프
- figkit은 Pretendard에 없는 기호(⋅, ∙, ᵀ, ∝, ∇, ∈, ⊂ 등)를 만나면 그리는 순간 멈춥니다. lint도 같은 목록을 오류로 잡아요.
- 바꾸는 표기는 style-guide 4.7절 표를 따릅니다. 내적 점은 ×나 말로, 전치는 `sup('T')`, 비례는 "비례"로 씁니다.
- 대체 글꼴로 채우지 않습니다. 렌더러마다 다른 글꼴이 끼어들고, 윤곽선 변환본에서 빈 상자로 남을 수 있습니다.
- 음수는 붙임표가 아니라 U+2212(−)입니다. 붙임표로 쓰면 lint가 경고합니다(4.5절).
- `svg_to_png.mjs` 미리보기는 tnum을 적용하지 않아 숫자가 Chrome보다 조금 좁게 보입니다. 숫자 칩이 빽빽한 그림은 Chrome으로도 한 번 엽니다.

## 12. lint, 미리보기, 오류 고치기

생성된 SVG는 손으로 고치지 않습니다. 스크립트, 명세, `colors.json`을 고치고 다시 실행합니다. 손으로 고친 값은 다음 실행에서 사라지고, 정본 숫자를 대조할 곳이 둘로 갈라지기 때문이에요.

```bash
.venv/bin/python vol1-llm/ch04/figures/1-4-3.build.py 미리보기폴더                     # 저장 + lint + PNG 세 장
.venv/bin/python -W error::UserWarning vol1-llm/ch04/figures/1-4-3.build.py 미리보기폴더  # 경고도 멈춤
.venv/bin/python assets/svg-parts/_build/figkit.py lint vol1-llm/ch04/figures/*.svg      # 다른 도구 결과도 됨
.venv/bin/python assets/svg-parts/_build/figkit.py preview 그림.svg -o 미리보기폴더
.venv/bin/python assets/svg-parts/_build/test_figkit.py                                  # figkit 자기 시험 19건
```

- `save()`는 lint 오류가 있으면 `FigkitError`로 멈춥니다. "경고:"로 시작하는 항목은 저장을 막지 않으니 실행 출력을 꼭 읽어요.
- 미리보기는 `X.png`(2배), `X.gray.png`(흑백), `X.w328.png`(휴대폰 표시 폭) 세 장입니다. node와 `scripts/svg_to_png.mjs`를 씁니다. 미리보기폴더는 `figures/_render/qa/`이고 소스 옆에는 만들지 않아요(`qa-checklist.md` 2.3절).
- 스타일 보드 시안 10개에 lint를 돌리면 오류 0, 경고는 격자 이탈 6건입니다(Mermaid 배치 3, 요약 그림 3). 경고가 남은 채 넘길 때는 이유를 `figures.yml`의 `note`에 적습니다.

자주 나는 오류와 고치는 법

| 메시지 | 원인 | 고치는 법 |
|---|---|---|
| `상자 x 4가 8의 배수가 아닙니다` | 계산한 좌표를 그대로 넘김 | `fk.snap()`이나 `columns`, `stack` 결과를 씀 |
| `상자 안 글자가 넘칩니다(폭 158 > 144)` | 안쪽 폭(상자 폭 − 32)보다 긴 줄 | 문구를 줄이거나 상자 수를 줄여 폭을 얻음. 글자 크기는 그대로 |
| `16 글자는 2줄까지입니다` | 자동 줄바꿈 결과가 상한 초과 | 문구 줄이기. 긴 설명은 캡션으로 |
| `글자가 바깥 여백을 넘습니다` | 지시선 글이나 오른쪽 끝 라벨이 여백 밖 | 지시선 `side='left'`, 대상 쪽 바꾸기 |
| `연결선이 상자(…)를 지나갑니다` | 직각 경로가 다른 상자를 가로지름 | 연결점 `a_at`, `b_at`, `mid`를 바꾸거나 배치 변경. 의도한 척추면 `check=False` |
| `꺾임 3회` | 경로 점이 너무 많음 | 상자 배치를 바꿔 2회 이하로 |
| `지시선 길이 56는 16~48입니다` | 대상과 글 자리가 멀다 | 글 자리를 대상 가까이로, 또는 꺾지 말고 방향 바꾸기 |
| `금지 기호 U+00B7 중간점` | 라벨, `desc`의 나열 | 쉼표, "와/과", "/" |
| `Pretendard에 없는 기호` | ⋅, ᵀ 등 | 11장 대체 표기 |
| `data-canon 없는 숫자 칩` | `chip`에 `canon` 빠짐 | 정본 ID를 넘김. 정본이 아니면 칩 대신 보통 글자 |
| `팔레트 밖 색 #…` | HEX를 손으로 적음 | `fk.color('ink-600')` 등 토큰 |
| `머리줄에 정본 ID를 넣지 않습니다` | 대상 이름에 N4-2 등 | 정본 ID는 `group(canon=)`, `chip(canon=)`으로만 |
| `desc(대체 텍스트)가 없습니다` | `Figure(desc=)` 빠짐 | alt 초안을 넣어 저장. 확정 alt는 시각 검수 뒤에 옮겨 다시 빌드(`caption-alt.md` 6.1절) |

자주 나는 경고: 독립 부품 7개 초과, 개념색 3개 초과, 지시선 3개 초과, 강조색 3곳 초과는 `design-rules.md` 3장 상한을 넘은 것입니다. 덜어 내는 것이 먼저고, 설계서 명세가 이미 넘으면 명세 수정안을 올립니다.

## 13. 자주 하는 실수

- 정본 숫자를 `f'{v:.3f}'`로 만드는 것. 끝자리 0이나 U+2212가 바뀌어도 lint는 잡지 못합니다. 상수 블록의 문자열을 그대로 넘깁니다.
- 글자가 넘친다고 크기를 14로 내리거나 간격을 24에서 20으로 줄이는 것. 크기와 간격은 고정이고, 문구나 배치를 바꿉니다(5.12절).
- 같은 역할 상자를 글자 길이에 맞춰 다른 폭으로 그리는 것. `columns`로 같은 폭을 받고 `check_row`로 확인합니다.
- `connect`가 오류를 낸다고 습관처럼 `check=False`를 켜는 것. 선이 상자를 가로지르는 그림이 그대로 나갑니다.
- 연결선을 상자보다 나중에 그려 선 끝이 테두리 위로 올라오는 것. 합류선과 척추는 먼저 그립니다.
- 세로 변형을 따로 복사한 스크립트로 만드는 것. 한 스크립트의 `LAYOUT`으로 나눕니다.
- 개념 부품 기호(`cp-`)를 `<use width=...>`로 늘려 쓰는 것. 선과 글자가 함께 늘어나요. 함수로 다시 그립니다.
- 로봇을 직접 그리거나 `rb-` 부품의 비율을 바꾸는 것, 데모 장면에 표시 줄을 빼는 것.
- 생성된 `X.svg`를 열어 좌표 하나를 손으로 고치는 것. 다음 실행에서 되돌아갑니다.
- `fig.add()`로 넣은 조각에 `bottom=`을 주지 않는 것. 자동 높이가 그 조각을 모르고 캔버스를 낮게 잡아 잘립니다.
- lint OK를 완료로 여기는 것. PNG 세 장을 열어 강조가 하나인지, 폭 328에서 메시지가 읽히는지 봅니다(`qa-checklist.md`).
