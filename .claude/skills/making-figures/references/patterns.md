# 레이아웃 패턴 (patterns)

설계서 그림 명세 238개(2026-10-19 1장 그림 추가 뒤)에서 되풀이되는 레이아웃 꼴을 16개 패턴과 "기타"로 묶은 문서입니다. 패턴마다 격자 치수, 강조 자리, 세로 변형 재배치 규칙, 반복 시리즈 규칙을 하나의 서식으로 적었어요.
목적은 하나입니다. 같은 꼴의 그림이 권과 장을 넘어 같은 치수와 구도로 나오게 하는 것이에요. 2권 5장의 루프와 3권 9장의 루프가 나란히 놓였을 때 같은 손이 그린 것처럼 보여야 합니다.

종류(M, S, C, T) 선택은 `choose-type.md`, 선 굵기와 색과 글자 같은 공통 규칙은 `design-rules.md`가 맡습니다. 이 문서는 "어디에, 몇 칸으로, 얼마 크기로 놓나"만 다룹니다.

## 목차

1. 쓰는 법과 공통 틀
2. 패턴 한눈에 보기
3. 흐름 계열: P1 단계 흐름, P2 루프, P3 분기 판단
4. 비교와 위치 계열: P4 전후 비교, P5 사다리, P6 계층 지도, P7 시간축
5. 구조 계열: P8 가중치 띠, P9 입출력 블록, P10 중심과 주변, P11 해부 띠, P12 카드 격자, P13 2축 배치
6. 값 계열: P14 계산표와 행렬, P15 차트 판
7. P16 한 장 요약과 기타 장면도
8. 표지 안쪽 세트(1-9-6, 2-0-2, 3-0-2) 공통 틀
9. 검증 기록과 점검 명령

부록 A. 패턴별 그림 ID 전체 목록

---

## 1. 쓰는 법과 공통 틀

그림을 맡으면 이 순서로 씁니다.
1. 부록 A에서 그림 ID를 찾아 패턴을 확인합니다. 패턴이 맞지 않아 보이면 바꾸기 전에 사유를 `figures.yml`의 `note`에 남겨요.
2. 해당 패턴 절의 격자표에서 캔버스와 열 치수를 고릅니다. 표에 없는 치수를 새로 만들지 않습니다.
3. 와이어프레임대로 빈 상자를 먼저 놓고 렌더링해 균형을 본 뒤 글자와 숫자를 채웁니다.
4. 강조 자리와 지시선 방향은 패턴이 정한 자리를 따릅니다. 메시지가 그 자리에 맞지 않으면 그림의 메시지부터 다시 봐요.

모든 패턴이 공유하는 값입니다. 근거와 자세한 값은 style-guide 5장(레이아웃)과 `design-rules.md` 7장입니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 캔버스 | 본문 640(높이 216, 320, 480, 640), 펼침 800(264, 400, 600), 세로 변형 360(높이 8의 배수, 720 이하) | 5.1 |
| 내용 영역 | 640은 x 24~616(592), 800은 x 24~776(752), 360은 x 16~344(328) | 5.1 |
| 머리줄 | 기준선 24, 괘선 y 32.5, 본문 시작 y 56 | 5.2 |
| 간격 | 4, 8, 16, 24, 32, 48, 64만. 화살표로 이은 상자 사이 32 | 5.3 |
| 상자 높이 | 한 줄 48, 두 줄(이름 + 값) 64, 단계 상자(머리 + 값) 72 | 5.9 |
| 척추 | 내용 왼쪽 끝 + 24(640은 x 48, 360은 x 40) | 5.4, 5.11 |
| 표준 열 3칸 | 폭 176, 사이 32: x 24, 232, 440. 여러 패턴이 이 열을 공유합니다 | 제안(5.12절 3칸 상한에서 계산) |
| 표준 열 2칸 | 폭 280, 사이 32: x 24, 336 | 제안 |

표준 열 두 가지가 이 문서의 뼈대예요. 단계 흐름, 루프, 행 비교, 카드 격자가 모두 x 24, 232, 440을 씁니다. 그래서 서로 다른 장의 그림이 나란히 놓여도 상자 모서리가 같은 세로선에 섭니다.

치수 표의 "실측"은 저자 승인 시안(`docs/style-board/final/`)에서 읽은 값입니다. "제안"은 이 문서가 새로 정하고 9장의 와이어프레임 렌더링으로 확인한 값이에요.

## 3. 흐름 계열

### P1. 단계 흐름

순서대로 처리되는 3~7단계를 한 방향으로 잇는 그림입니다. 19개, 대표 1-4-3, 2-3-2, 3-3-2.

- 종류와 도구: M이 기본입니다. 단계 3개 이하는 `flowchart LR`, 4개 이상은 처음부터 `flowchart TB`로 그려 세로 변형이 필요 없게 합니다(`choose-type.md` 5장). Mermaid에서는 간격을 설정으로 맞추지 않습니다. ELK가 `rankSpacing`, `nodeSpacing`을 무시하고 간격 40으로 배치하기 때문이에요(`mermaid-guide.md` 8.7절). 아래 간격 표는 렌더링 결과를 확인하고 S로 다시 그릴 때의 기준입니다(1-4-3 출력 실측 48). S로 다시 그릴 때는 figkit.py의 `box`, `step_box`, `connect`, `columns`, `stack`을 씁니다(`svg-guide.md` 6장).
- 시퀀스 변형(2-1-1, 2-5-1, 2-7-3)도 이 패턴입니다. 생명선을 3~4개로 줄이고 메시지 화살표를 위에서 아래로 쌓아요.

```
세로(TB) 640 x 640           x 24   48   88            328 360        552   616
y  56  입력 행                       [입력 A 240x64]      [입력 B 192x64]
y 152  01 단계                  |    [01 단계 240x64]
y 248  02 단계                  |    [02 단계 240x64]
y 344  03 단계                척추   [03 단계 240x64]
y 440  04 단계(메시지)          |    [## 04 메시지 상자 ##]---o 지시선 글
y 536  05 단계                       [05 단계 240x64]
가로(LR) 640 x 216            [01 176x72] -> [02 176x72] -> [## 03 ##]   x 24, 232, 440
```

| 항목 | 값 |
|---|---|
| 캔버스 | 가로 3단계 640 x 216(지시선이 있으면 320). 세로 4~5단계 640 x 640, 6~7단계 640 x 640에 상자 높이 48 |
| 열 | 세로: 주 열 x 88, 폭 240(실측 1-4-3). 옆 입력 열 x 360, 폭 192. 척추 x 48. Mermaid는 폭을 문구가 정하므로(가장 긴 줄 + 32, `mermaid-guide.md` 5장) 240은 "이름 + 연산" 머리 줄과 정본 값 줄을 함께 둘 때 나옵니다 |
| 상자 | 세로 240 x 64(이름 + 값), 가로 176 x 72(단계 상자). 단계마다 같은 층(번호와 이름 굵게, 연산 보통, 값 줄)을 써서 폭을 맞춤 |
| 간격 | 단계 사이 32(피치 96), 입력과 첫 단계 사이 32. 4단계 이하는 48까지 허용(1-4-3 실측 48) |
| 요소 상한 | 노드 7, 가로 한 줄 3, 연결선 8(style-guide 6.3절) |
| 강조 | 흐름의 결과 단계 1개를 메시지 상자로. 1-4-3은 03 가중치 상자와 0.576(시안은 밑줄, 4장 원고판은 굵기 600. `mermaid-guide.md` 5장) |
| 지시선 | 메시지 상자 오른쪽 변에서 수평으로 32, 글자는 x 371부터. 옆 입력 열과 같은 행이면 쓰지 않음 |

- 세로 변형(360): 단계 상자는 x 16, 폭 328로 넓히고 피치 96을 유지합니다. 입력 상자는 x 56, 폭 288로 들여 쓰고 척추 x 40을 따라 내려 단계에 꽂아요(1-4-3.v 실측). 입력은 처음 쓰이는 단계 바로 위로 옮겨도 됩니다.
- 단계 이름: 설계서 명세 행, 원고, 정본 손계산 행, 승인 시안 예(1-4-3은 점수, 나누기, softmax, 가중합. 시안의 "크기 조정"은 4장 원고 말 "나누기"로 바꿈)에 이미 있는 용어를 그대로 씁니다. 상자를 줄이려고 이름을 바꾸거나 연산 문구를 빼지 않습니다. 이름이 대체 텍스트와 캡션으로 그대로 옮겨 가기 때문이에요. 꼭 바꿔야 하면 사유를 `note`에 적습니다.
- 폭 확인: 렌더링 뒤 9.2절 명령으로 주 열 상자의 폭을 읽어 240과 비교합니다. 16 넘게 좁거나 넓으면 문구부터 되돌립니다.
- 허용: 화살표 라벨(16, 선에서 8). 두 갈래 흐름(2-3-2)은 두 열을 나란히 세워 끝에서 합칩니다. 하지 말 것: 4단계 이상 가로 한 줄, ㄹ자 배치, 단계마다 다른 폭.
- 반복 시리즈: 같은 흐름을 단계별로 강조하려면 밑그림 좌표를 고정하고 현재 단계만 ink-900 선과 600 라벨로 올립니다. 머리줄 대상 이름 끝에 "3/4"를 붙여요(style-guide 6.7절).

### P2. 루프

마지막 단계가 첫 단계로 돌아가는 순환입니다. 11개, 대표 1-5-4, 2-5-3, 3-9-6.

- 종류와 도구: M이 기본(`flowchart TB` + 되돌림 연결선 하나). 되돌림이 교차를 만들면 S로 다시 그립니다(`choose-type.md` 3.4절).

```
640 x 320          x 24             200 232            408 440            616
y  88  윗줄         [단계 1 176x64] --> [단계 2 176x64] --> [출구 176x64(입력 상자)]
                         ^ 반복              |
y 200  아랫줄       [단계 4 176x64] <-- [## 단계 3 ##]
```

| 항목 | 값 |
|---|---|
| 캔버스 | 4단계 + 출구 640 x 320. 5~6단계는 세 열을 다 쓰고 출구를 아래로 내려 640 x 480 |
| 열 | 표준 3열 x 24, 232, 440. 4단계 루프는 앞 두 열, 셋째 열은 출구와 지시선 자리 |
| 상자 | 176 x 64 |
| 간격 | 가로 32, 윗줄과 아랫줄 사이 48(y 88, 200) |
| 방향 | 시계 방향 고정: 윗줄 왼쪽에서 오른쪽, 오른쪽 열 아래로, 아랫줄 오른쪽에서 왼쪽, 왼쪽 열 위로 |
| 요소 상한 | 루프 안 노드 6 + 출구 1 |
| 강조 | 루프가 "배우는" 자리(갱신, 보상, 재학습) 1개. 보통 아랫줄 오른쪽 |
| 라벨 | 되돌림 화살표 옆 8에 "반복" 또는 횟수(14, ink-600) |

- 세로 변형(360): 단계를 x 56, 폭 288로 한 줄로 쌓고(피치 96), 되돌림은 척추 x 40을 타고 올라가 첫 단계 왼쪽 변에 꽂습니다. 꺾임 2회입니다.
- 허용: 출구 없는 순환(3-9-6). 셋째 열은 지시선 글자에 씁니다. 하지 말 것: 원형 배치와 곡선 화살표(5.7절), 시계 반대 방향, 되돌림 둘 이상.
- 반복 시리즈: 2-5-3과 2-6-4처럼 같은 장에서 루프가 확장되면 앞 그림의 상자 자리를 그대로 두고 새 상자만 더합니다.

### P3. 분기 판단

질문을 위에서 아래로 차례로 묻고 "예"면 오른쪽 결과로 빠지는 선택 흐름입니다. 6개, 대표 1-7-6, 2-4-6, 2-12-4.

- 종류와 도구: M(`flowchart TB`). 마름모 대신 "?"로 끝나는 직각 상자(style-guide 5.6절).

```
640 x 480       x 24              296   344              616
y  72           [질문 1? 272x64] -예-> [결과 1 272x64]
                     | 아니요
y 168           [질문 2? 272x64] -예-> [## 결과 2 ##]
y 264           [질문 3? 272x64] -예-> [결과 3]
y 360           [그 외 결과 272x64]
```

| 항목 | 값 |
|---|---|
| 캔버스 | 질문 3개 640 x 480, 질문 4개 640 x 640 |
| 열 | 질문 열 x 24, 폭 272. 결과 열 x 344, 폭 272(사이 48에 "예" 라벨) |
| 상자 | 272 x 64 |
| 간격 | 행 피치 96(사이 32에 "아니요" 라벨이 화살표 오른쪽 8) |
| 요소 상한 | 질문 4, 결과 5 |
| 강조 | 본문 사례(보상 문의 예문)가 도착하는 결과 1개 |

- 세로 변형: 가로 노드가 2개라 만들지 않습니다(`epub_variant: none`). 하지 말 것: 결과에서 질문으로 돌아가는 화살표(루프면 P2), 한 질문에 결과 셋 이상.
- 반복 시리즈: 2-4-6은 1-7-6의 확장판입니다. 1-7-6의 질문 행을 같은 자리에 두고 새 질문을 아래에 더합니다.

## 4. 비교와 위치 계열

### P4. 전후 비교

같은 대상을 두 방식(또는 세 방식)으로 나란히 놓아 차이 한 곳을 보이는 그림입니다. 27개로 S 그림 중 가장 많아요. 대표 1-4-1, 2-3-1, 3-3-4.

```
두 열 640 x 320     x 24                 304 336                 616
y  76  열 머리       전(기준) 16/600            후(메시지) 16/600
y  88  괘선          ------------------         ------------------
y 104  같은 자리     [요소 280x64]              [요소 280x64]
y 184  같은 자리     [요소 280x64]              [## 다른 한 곳 ##]
두 행 640 x 320     방식 A(14/500, y 72)   [입력 176] -> [규칙 176] -> [출력 176]
                   방식 B(y 200)          [입력]     -> [규칙]     -> [## 출력 ##]
```

| 항목 | 값 |
|---|---|
| 캔버스 | 640 x 320 기본, 요소가 3행 이상이면 480 |
| 두 열 | 표준 2열 x 24, 336, 폭 280. 열 머리 기준선 76, 1px ink-900 괘선 y 88.5, 내용 시작 104 |
| 세 열 | 표준 3열 176(2-3-4 청크 세 가지) |
| 두 행 | 행 이름 14/500 ink-600을 상자 위 8에. 상자는 표준 3열, 행 피치 128(y 80, 208) |

### 9.2 점검 명령

새 그림의 상자 좌표가 패턴 열에 서 있는지 봅니다. 출력된 x 값이 패턴 표의 열(예: 24, 232, 440)과 다르면 이유가 있어야 해요.

```bash
F=vol2-agent/ch05/figures/2-5-3.svg
# 상자의 왼쪽 끝 x 값과 개수 (반 굵기 보정은 내림으로 제거)
python3 -c 'import sys,re,collections
s=open(sys.argv[1],encoding="utf-8").read()
xs=[int(float(x)) for x,w in re.findall(r"<rect[^>]* x=\"([\d.]+)\"[^>]* width=\"([\d.]+)\"",s) if float(w)<590]
print(sorted(collections.Counter(xs).items()))' "$F"
# 열마다 상자 크기(테두리 바깥 끝): 패턴 표의 폭, 높이와 비교 (예: P1 주 열 x 88은 240 x 64)
python3 -c 'import sys,re,collections
s=open(sys.argv[1],encoding="utf-8").read(); c=collections.defaultdict(list)
for r in re.findall(r"<rect[^>]*stroke-width=\"[\d.]+\"[^>]*>",s):
    g=lambda a:float(re.search(a+r"=\"([\d.]+)\"",r).group(1)); sw=g("stroke-width")
    if g("width")<590 and g("height")>32: c[round(g("x")-sw/2)].append("%g x %g"%(g("width")+sw,g("height")+sw))
for x in sorted(c): print(x, c[x])' "$F"
```

두 번째 명령에서 같은 열에 크기가 둘 이상 나오면 `design-rules.md` 9장 3번(같은 역할은 같은 크기)을 다시 봅니다. figkit lint도 같은 종류 상자끼리 크기가 다르면 경고합니다. 검수 기록의 치수는 이 출력에서 옮겨 적습니다(`qa-checklist.md` 5.3절).

부록 A의 분류를 다시 셀 때는 설계서 명세 행을 뽑아(`choose-type.md` 부록 B 명령 1) 아래 목록과 대조합니다. 238개가 모두 한 번씩 나오면 됩니다.
