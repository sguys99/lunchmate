# 디자인 규칙 (design-rules)

도구(M Mermaid, S SVG, C 차트, T 표 그림)와 상관없이 모든 그림에 적용하는 디자인 규칙의 한 장짜리 요약입니다. 그리기 직전에 한 번, 렌더링한 뒤 시각 검수 때 한 번 펼쳐 봅니다. 정본은 `docs/style-guide.md`이고, 이 문서는 그 2~6장을 "그릴 때 무엇을 고르고 무엇을 하지 않나"로 압축했습니다. 값이 다르면 style-guide가 맞고, 이 문서를 고칩니다.

목표는 237개 그림이 한 사람이 그린 것처럼 보이는 것입니다. 그래서 "세련되게"를 감으로 두지 않았어요. 저자가 승인한 최종 시안 5장(`docs/style-board/final/`)에서 실제로 쓰인 결정을 확인 가능한 기준으로 옮겼습니다(9장). 표의 근거 칸은 style-guide 절 번호입니다.

## 2. 메시지 한 문장과 강조 하나

그림 한 장은 문장 하나를 증명하는 장치입니다. 문장이 없으면 강조할 곳도, 덜어 낼 것도 정할 수 없어요.

| 규칙 | 값 | 근거 |
|---|---|---|
| 메시지 서식 | "[무엇]은 [조건]일 때 [어떻게 된다]", 습니다체 한 문장, 40자 이하 | 6.1 |
| 메시지 시험 | 그림을 가려도, 문장을 가려도 같은 말이 됨. 그림만 보고 3초 안에 말할 수 있음 | 6.1 |
| 메시지가 둘이면 | 그림을 둘로 나누거나 하나를 캡션, 본문으로 보냄 | 6.1 |
| 기록 위치 | `figures.yml`의 `message`와 `accent`. 설계서 그림 명세와 다르면 설계서 수정안 먼저 | 6.1 |
| 강조색 범위 | 메시지를 증명하는 대상 1개 + 거기 붙은 숫자 칩. 합쳐 3군데 이하(지시선 점은 세지 않음) | 6.2 |
| 메시지 지시선 | 그림당 1개. 선 ink-600, 점 accent, 글자 ink-900 600(글자는 강조색으로 칠하지 않음) | 6.2, 5.8 |
| 보조 지시선 | 2개까지. 점 ink-900, 글자 ink-600 400. 메시지 지시선보다 눈에 띄면 다시 짬 | 6.2 |
| 강조 아닌 것 낮추기 | 나머지 선은 ink-400이나 ink-200 면, 라벨은 ink-600 | 6.2, 6.7 |
| 반복 그림 | 밑그림 좌표 고정, 지금 단계만 ink-900 선과 600 라벨, 강조는 지금 단계 결과 하나 | 6.7 |
| 반복 그림 머리줄 | 대상 이름 끝에 단계 번호("어텐션 계산 3/4") | 6.7 |

좋은 메시지와 나쁜 메시지는 이렇게 갈립니다.

| 예 | 판정 |
|---|---|
| "온도를 올리면 1위 후보의 확률이 줄어듭니다"(1-5-5) | 좋음. 주장이 하나이고 그림이 그것을 증명함 |
| "온도별 확률 분포" | 나쁨. 주제일 뿐 주장이 없음 |
| "온도는 확률을 바꾸고 top-p는 후보를 자릅니다" | 나쁨. 메시지가 둘 |

경고색은 강조 수단이 아니에요. "주목", "최고!" 같은 빨간 표시는 쓰지 않습니다(6.2절).

### 2.1 패턴 그림의 오독 점검 (2026-10-17, 4장 1-4-5)

선 굵기, 거리, 배치 같은 모양 자체가 뜻을 나르는 그림(헤드별 연결 패턴, 굵기 = 세기, 비유 장면)은 그 모양이 엉뚱한 뜻으로 읽히지 않는지 따로 봅니다. 메시지 가리기 시험(Q12)을 통과해도, 패턴 하나가 다른 말을 할 수 있기 때문이에요.

| 4장에서 걸린 것 | 잘못 읽힌 뜻 | 고친 방향 |
|---|---|---|
| 1-4-5 첫 판, 둘째 헤드의 수평 띠 | "토큰이 자기 자신만 본다" | 토큰 사이를 잇는 호로 바꿔, 연결이 늘 두 토큰 사이에 있게 함 |
| 1-4-5 R1 판, 둘째 헤드 강조 호가 이웃 쌍(안과 왔어요) | 첫째 헤드(이웃 연결)와 구별되지 않음(R1-G03) | 떨어진 쌍(상자가와 왔어요)으로 옮겨 헤드마다 모양이 갈리게 함 |
| 1-4-5 R1 판, 한 헤드만 강조 | "이 헤드가 중요한 헤드" | 강조를 본문 계산과 잇는 닻으로 쓰고, 저자 확인으로 올림 |

- 점검 방법: 메시지를 보지 않고 패턴마다 "이 모양이 말하는 것"을 한 줄씩 적고, 본문과 캡션의 뜻과 대조합니다. 두 칸(헤드, 조건)을 비교하는 그림이면 칸끼리 모양이 실제로 다른지도 적어요.
- 비유 그림은 "비유가 틀리는 지점"(비유 고정표)과 그림이 부딪치지 않는지 봅니다. 예: 1-4-2는 책 한 권만 꺼내는 장면이 아니라 세 책 모두에서 띠가 나옵니다.

## 3. 요소 수 상한과 밀도

작업 기억이 한 번에 붙잡는 덩어리는 4개 안팎이고, 폭 640 그림은 휴대폰에서 0.51배로 줄어듭니다. 그래서 상한이 빡빡합니다(6.3절).

| 종류 | 항목 | 본문 폭 640 | 펼침 폭 800 |
|---|---|---|---|
| M 흐름도 | 노드 / 연결선 | 7 / 8 | 10 / 12 |
| M 흐름도 | 가로 한 줄 노드 | 3(4 이상이면 EPUB 세로 변형) | 5 |
| S 개념도 | 독립 부품 / 개념색 | 7 / 3 + 강조 | 10 / 4 + 강조 |
| C 차트 | 계열 / 범주 / 값 라벨 | 3 / 6 / 6 | 4 / 10 / 9 |
| T 표 그림 | 행 × 열 | 6 × 4 | 8 × 6 |
| 공통 | 숫자 칩 / 지시선(메시지 포함) | 3 / 3 | 3 / 4 |
| 공통 | 라벨 하나 / 주석 문장 하나 | 3어절 12자 / 30자 | 4어절 16자 / 40자 |

공간 쪽 한계(5.12절)도 같이 지킵니다.

- 관계없는 두 요소 사이 16 이상, 글자와 선 사이 8 이상, 글자와 글자 사이 8 이상입니다. 4는 밑줄 같은 붙은 장식에만 씁니다.
- 본문 폭 한 행의 상자는 3개까지입니다.
- 넘치면 순서대로 고칩니다. 덜어 내기(캡션, 대체 텍스트로 옮김) → 문구 줄이기 → 높이 단계 올리기 → 그림 나누기.
- 글자 크기나 간격을 줄여서 맞추지 않습니다. 이것이 가장 흔한 실패예요.
- 그림 수를 늘려야 하면 설계서 수정안을 먼저 냅니다.

밀도와 무아레 (2026-10-17, 4장 1-4-5)
- 요소 수가 상한 안이어도, 가는 선이나 띠가 한곳에 촘촘히 엇갈리면 무아레(그물 무늬)가 생겨 패턴이 읽히지 않습니다. 1-4-5 첫 판은 셋째 헤드의 q, k 띠 15쌍이 그물처럼 엉켰어요.
- 선과 선 사이도 위 간격 규칙을 따릅니다. 평행하거나 거의 평행한 두 선을 4 미만으로 붙이지 않습니다(붙은 장식 예외 밖).
- 많은 연결을 한꺼번에 보여야 하면 순서대로 고칩니다. ① 가는 연결은 가장 옅은 회색(ink-300 안팎) 한 굵기로 낮추고, 가는 선에는 흰 틈을 두지 않음(1-4-5에서 흰 틈이 두 겹 선으로 보였음) ② 대표 연결만 남기고 나머지는 캡션으로 ③ 칸을 나눔.
- 가는 선의 계조가 굵은 띠보다 진하면 위계가 뒤집힙니다(1-4-5 2회차, ink-400 가는 호가 굵은 띠보다 진해 보여 ink-300으로 낮춤).

빈 여백 (2026-10-17, 4장 1-4-5, 1-4-8)
- 9장 7번의 "빈 곳 남기기"는 지시선 글 자리나 오른쪽 열 비우기입니다. 캔버스 아래가 통째로 비거나(1-4-5 첫 판) 그림 영역 오른쪽 1/3이 비면(1-4-8 1회차) 높이 단계를 낮추거나 영역을 넓혀 고칩니다.
- 판단 기준: 빈 띠가 높이 단계 차이(예: 480과 320의 차 160)보다 크면 한 단계 낮춘 판을 먼저 시도해요.

## 4. 직접 라벨과 숫자 칩

### 4.1 범례 대신 직접 라벨 (6.4절)

| 대상 | 라벨 자리 |
|---|---|
| 선 그래프 | 선 오른쪽 끝, 끝점에서 8 띄우고 같은 높이. 라벨 기준선끼리 24 이상 |
| 세로 막대 | 값은 막대 끝 8 위, 범주는 축 아래. 범주 이름이 6자를 넘으면 가로 막대로 |
| 가로 막대 | 범주는 왼쪽, 값은 오른쪽 끝 |
| 상자, 노드 | 상자 안. 작은 아이콘만 오른쪽이나 아래 |
| 점 | 점 옆. 붐비면 짧은 지시선 |

- 라벨 색은 세 가지입니다. 개념 대상은 그 개념색 main, 강조 대상은 ink-900 600, 나머지는 ink-600이에요.
- 범례는 네 경우에만 씁니다. 연속 색 척도, 선 끝이 몰려 24 간격이 안 될 때, 흑백 무늬가 여러 곳에 반복될 때, 장 첫 그림에서 정의하는 기호 약속입니다.
- 범례를 쓰면 데이터 순서대로, 그림 영역 왼쪽 위 안쪽에, 테두리 없이 둡니다.

### 4.2 숫자 칩 (6.5절)

| 항목 | 기본 칩 | 강조 칩(메시지의 숫자) |
|---|---|---|
| 모양 | 직각, 높이 24, 좌우 여백 8 | 같음 |
| 면 / 테두리 | paper / 1px ink-900 | accent tint / 1.5px accent |
| 숫자 | 14, 600, ink-900, tnum | 같음 |
| 단위 | 칩 안 숫자 뒤, 14 400 ink-500 | 같음 |
| 개수 | 그림당 3개 이하 | 그중 2개 이하 |

- 칩은 해당 권 설계서 7장 정본 "결과" 값 가운데 메시지가 기대는 값에만 답니다. 입력값, 중간값, 축 눈금은 보통 글자로 써요.
- 🔄 관리표 값과 출처 있는 외부 수치에는 칩을 달지 않습니다.
- 정본 문자열을 글자 그대로 옮깁니다. 0.140의 끝 0, 천 단위 쉼표, 빼기 기호 −(U+2212)를 바꾸지 않습니다.
- 칩은 가리키는 대상 바로 옆에 붙이고 지시선을 따로 달지 않습니다.
- 정본 ID(N4-2)는 그림에 보이지 않게 두고 메타데이터로 잇습니다. S와 C는 `data-canon`, M은 첫 줄 `%% canon:`, 공통은 `figures.yml`의 `source.canon`이에요.
- 가정값은 칩 바로 왼쪽에 "가정"이나 "가상 단가"를 ink-600 보통 글자로 둡니다.
- 숫자 칩(흰 면, 진한 테두리)과 텍스트 토큰 칩(ink-50 면, ink-200 테두리)을 섞지 않습니다.
- 칩과 대상의 거리: 칩의 가장 가까운 변에서 가리키는 점 중심이나 상자 테두리까지 16 이하입니다(차트는 `chart-guide.md` 4.2절과 같은 값, figlib `chip`이 경고). 4장 1-4-8 1회차에서 칩이 점에서 떨어져 떠 보였고, 세로축 눈금 "100만" 옆에 붙은 칩은 눈금 글자처럼 읽혔어요. 칩은 눈금 글자와 16 넘게 떨어뜨리고, 같은 값이 눈금에도 있으면 칩을 빼거나 눈금을 옮깁니다.
- 칩 안 글자 폭: 칩 폭은 숫자 폭 + 좌우 여백 8입니다. 단위 tspan은 렌더러마다 폭이 달라 칩 테두리에 닿거나 넘칠 수 있어요(1-4-9 "약 164억쌍"). 단위가 두 글자 이상이거나 한글이면 칩에는 숫자만 두고 단위는 칩 오른쪽 8에 보통 글자(14, ink-600)로 둡니다. `figure_qa.py`가 Pretendard 실측으로 안쪽 여백 4 미만을 FQ-CHIP 경고로 냅니다. 경고가 없어도 2배 PNG에서 칩을 잘라 열어 봅니다(`qa-checklist.md` 1장 명령).

## 5. 색

색은 HEX를 손으로 적지 않고 토큰 이름으로 고르며, 값은 `assets/tokens/colors.json`에서 읽습니다(1장).

| 규칙 | 내용 | 근거 |
|---|---|---|
| 개념색 고정 | 같은 개념은 시리즈 어디서나 같은 토큰. 개념이 아닌 축(온도, 단계)에 개념색을 빌리지 않음 | 2.1, 6.2 |
| 개념색 쓰는 법 | 4px 세로 띠, 1px 선, 옅은 tint 면만. 큰 면을 진한 main으로 채우지 않음 | 2.1 |
| 강조 1개 | accent는 메시지 한 덩어리에만. 굵기(600)나 1.5px 밑줄, 테두리를 함께 씀 | 2.3, 3.5 |
| 경고 1종 | warning은 오류, 위험, 신뢰할 수 없는 입력에만. 경고 아이콘과 45도 빗금을 늘 함께 | 2.3, 3.5 |
| 그림 바탕 | 흰색 `<rect>` 하나(paper). 투명 금지 | 2.2, 5.2 |
| 새 색 금지 | 새 색, 새 무늬, 새 dasharray를 즉석에서 만들지 않음. `colors.json` 추가를 먼저 제안 | 3.5 |

중립 단계는 쓰임새가 정해져 있습니다(2.2절).

| 토큰 | 글자 | 선과 면 |
|---|---|---|
| ink-900 | 제목, 라벨, 숫자, 강조 글자 | 머리줄 괘선, 메시지 상자 테두리, 표 위아래 괘선 |
| ink-600 | 주석, 낮춘 라벨 | 연결선, 화살표, 지시선, 단계 상자 테두리 |
| ink-500 | 그림 번호 머리줄, 단위, 축 눈금, 다단 그림의 열 머리(가장 옅은 글자, 2.2절) | |
| ink-400 | 글자 금지 | 낮춘 차트 선, 비활성 요소, 출구 행 파선 |
| ink-300 | 글자 금지 | 격자 무늬, 차트 보조선 |
| ink-200, ink-100 | 글자 금지 | 입력 상자 테두리 / 표 행 구분선. 사라져도 정보가 남는 곳에만 |
| ink-50, paper-warm | | 텍스트 토큰 면 / 메시지 상자와 묶음 패널 면 |

색 하나에만 기대지 않습니다(3.5절).

- 그림 안 개념 쌍은 색 말고도 명도(L* 10 이상), 면 무늬, 선 종류, 모양 표지, 직접 라벨 가운데 하나로 갈립니다.
- 근접 쌍(`exemptions`)이 한 그림에 나오면 거기 적힌 구분 수단을 생략하지 않아요. 청크와 사람이 같이 나오면 접힌 문서 모양과 사람 아이콘을 둘 다 그립니다.
- 사람의 개입과 사람 시연은 아이콘을 뺄 수 없습니다. 계층과 사다리 계조에는 단계 번호(P0, L3, G2)를 늘 적습니다.
- 흑백 무늬는 `assets/svg-parts/patterns.svg`의 `fill-<토큰>`, 선 종류는 3.4절 dasharray 표 값만 씁니다.
- 휴대폰 변형에서는 선 종류만으로 개념을 가르지 않습니다. 2배 축소에서 쇄선끼리 비슷해지기 때문이에요(3.4절).

## 6. 글자

| 단계 | 크기 | 굵기 | 줄 간격 | 한 줄 / 줄 수 | 쓰는 곳 |
|---|---|---|---|---|---|
| 제목 | 20 | 600 | 26 | 16자 / 1줄 | 상자 제목, 단계 이름, 핵심 숫자 한 줄 |
| 라벨 | 16 | 400(숫자 500) | 22 | 12자 / 2줄 | 상자 안 글자, 화살표 라벨, 벡터 값, 수식 |
| 주석 | 14 | 400 | 20 | 24자 / 3줄 | 지시선 글, 칩 글자, 축 눈금, 단위, 머리줄 |

근거는 4.1, 4.2, 4.4절입니다.

- 크기는 20, 16, 14 셋뿐입니다. 14가 최소이고 첨자도 14예요. 15, 18 같은 중간값은 만들지 않습니다.
- 굵기는 400, 500, 600 셋뿐입니다. 300 이하, 700 이상, 기울임은 쓰지 않습니다.
- 글꼴은 Pretendard 하나입니다. 영문, 숫자, 그리스 문자, 벡터 값도 같은 글꼴로 씁니다(4.6절).
- 숫자는 tnum을 켜고(SVG 루트 `style` 속성 안에), 숫자 열은 오른쪽 정렬합니다(4.5절).
- 줄은 손으로 나누고 어절 경계에서만 끊습니다. 숫자와 단위, 대괄호 묶음, 수식 한 덩어리는 끊지 않아요(4.4절).
- 넘치면 글자를 줄이거나 자간을 좁히지 말고 문구를 줄입니다.

숫자와 기호 표기의 핵심만 옮깁니다(4.5, 4.7절).

| 경우 | 쓰는 표기 |
|---|---|
| 음수, 빼기 | −(U+2212). 하이픈은 "top-p", "그림 1-4-3" 안에서만 |
| 연산자, 등호 | 앞뒤 공백 하나(T = 0.5) |
| SI 단위 | 숫자 뒤 줄바꿈 없는 공백(`&#160;`) + 단위(20 cm) |
| 한글 단위, %, ° | 붙여 씀(3달러, 0.39%, 90°) |
| 범위 | 물결표(15~25%) |
| 내적 점 ⋅ | × 또는 말로("q와 k의 내적") |
| 전치 ᵀ | 대문자 T를 위첨자 `<tspan>`(baseline-shift 숫자 값) |
| ∝, ∇, ∈ 등 글꼴에 없는 기호 | "비례", "기울기"처럼 말로 |
| 합 기호 | Σ(U+03A3). ∑(U+2211)는 쓰지 않음 |
| 유니코드 첨자 ¹⁰, ᵢ | 그림에서는 쓰지 않음(14보다 작게 그려짐). 캡션에서는 가능 |

## 11. 그림 안 글자의 문체와 분담

그림 안 글자도 원고와 같은 문체 규칙을 따릅니다(6.8절, CLAUDE.md 6장).

- 라벨은 명사구이고 마침표를 찍지 않습니다.
- 문장은 메시지 지시선 1개와 보조 주석 2개까지이고, 습니다체 한 문장에 마침표 없이 씁니다.
- 금지 기호는 그림 안에서도 0건입니다. 줄표 U+2014, U+2015, 문장 부호로 쓴 U+2013, 중간점 U+00B7, U+318D, U+30FB, 나열용 U+2022예요.
- 용어는 용어집 표기를 쓰고 한국어 낱말을 먼저 둡니다. 영문은 영문 유지 용어와 수식 기호에만 씁니다.
- 변수 이름은 코드식 `W_Q`가 아니라 W에 아래첨자 Q로 씁니다(4.6절).
- 라벨은 설계서 명세 행과 정본에 있는 말까지만 씁니다. 명세가 "고속 센서 입력"이라고만 적었으면 센서가 무엇인지(관절, 카메라 등) 괄호나 둘째 줄로 붙이지 않아요. 하위 구성이 필요해 보이면 명세 수정안을 먼저 냅니다.
- 노드, 단계, 입력 이름은 설계서, 원고, 정본 행, 승인 시안 예의 용어를 그대로 씁니다. 상자를 줄이려고 이름을 바꾸지 않고, 바꿔야 하면 `note`에 사유를 적습니다. 이름은 대체 텍스트와 캡션으로 그대로 옮겨 갑니다.

무엇을 어디에 둘지는 이 표로 정합니다(6.8절). 캡션과 대체 텍스트의 서식은 `caption-alt.md`가 맡아요.

| 내용 | 그림 안 | 머리줄 | 캡션 | 대체 텍스트 |
|---|---|---|---|---|
| 그림 번호 | | 왼쪽 | | |

## 12. 렌더링 전 빠른 점검

전체 점검표는 style-guide 6.11절(13항목)이고, 렌더링 뒤 시각 검수는 `qa-checklist.md`입니다. 이 문서 관점에서는 아래 8줄만 확인하면 돼요.

1. `message`가 40자 한 문장이고, 강조가 그 문장을 증명하는 한 덩어리(3군데 이하)에만 있는가
2. 노드, 계열, 칩, 지시선, 라벨 길이가 3장 상한 안인가
3. 범례 없이 직접 라벨인가. 칩 숫자가 정본 문자열과 같은가
4. 글자 크기 20, 16, 14와 굵기 400, 500, 600만 썼고, 숫자 열이 오른쪽 정렬인가
5. 좌표와 간격이 8 격자 위이고, 선 굵기가 1, 1.5, 2.5, 4 가운데 하나인가
6. 8장의 쓰지 않는 표현과 팔레트 밖 HEX가 소스에 없는가
7. 그림 안 글자에 금지 기호가 없고, 라벨은 명사구, 문장은 습니다체 한 문장인가
8. 9장 판정 기준에서 어긋난 줄이 없는가(특히 2, 4, 7번)

검사 명령입니다. 출력 SVG 검사의 정본은 2번 figkit lint이고, 도구와 상관없이 M, C, T 출력에도 그대로 씁니다. 금지 표현, 금지 기호, 팔레트 밖 HEX, 글자 크기와 굵기, 선 굵기를 모두 봐요. 1번은 lint가 보지 않는 렌더링 전 소스 파일용이고, 3번은 미리보기입니다. 출력이 없거나 `OK`면 통과예요.

```bash
S=vol1-llm/ch04/figures/1-4-4.build.py   # 소스(.mmd, .build.py, .py, .yml)
F=vol1-llm/ch04/figures/1-4-4.svg        # 출력

# 1. 소스의 금지 기호 (U+2014, U+2015, U+2013, U+00B7, U+318D, U+30FB, U+2022)
python3 -c 'import sys
B={0x2014,0x2015,0x2013,0xB7,0x318D,0x30FB,0x2022}
for i,l in enumerate(open(sys.argv[1],encoding="utf-8"),1):
    h=sorted({"U+%04X"%ord(c) for c in l if ord(c) in B})
    if h: print(i,h)' "$S"

# 2. 출력 SVG lint (세로 변형이 있으면 함께)
.venv/bin/python assets/svg-parts/_build/figkit.py lint "$F"

# 3. 컬러, 흑백, 휴대폰 폭 미리보기 (PNG 위치는 qa-checklist.md 2.3절)
case "$F" in */figures/*) Q="${F%/*}/_render/qa" ;; *) Q="${TMPDIR:-/tmp}/figqa" ;; esac
mkdir -p "$Q"; N=$(basename "${F%.svg}")
node scripts/svg_to_png.mjs "$F" "$Q/$N.png"
node scripts/svg_to_png.mjs "$F" "$Q/$N.gray.png" --gray
node scripts/svg_to_png.mjs "$F" "$Q/$N.w328.png" --width 328
```

- 1번은 소스에서 바로 고칠 줄 번호를 줍니다. 출력 SVG의 금지 기호는 2번이 다시 잡아요.
- 2번의 "경고:" 줄은 종료를 막지 않으니 출력을 꼭 읽습니다. 오류와 경고를 고치는 법은 `svg-guide.md` 12장 표에 있어요.
- matplotlib 출력처럼 `style` 속성에 쓴 크기도 2번이 읽지만, 실제 모습은 렌더링 PNG로 확인합니다.
- 미리보기 세 장에서 강조가 여전히 한 곳으로 보이는지, 개념마다 무엇으로 갈리는지 말로 설명할 수 있는지 확인합니다(3.5절 8번, 6.11절).
