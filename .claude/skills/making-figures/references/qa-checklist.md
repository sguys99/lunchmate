# 시각 검수 점검표 (qa-checklist)

렌더링을 마친 그림을 PNG로 직접 열어 보고 "통과, 고침, 저자 확인" 가운데 하나로 판정하는 절차입니다. 렌더링 전 소스 점검은 design-rules.md 12장, 캡션과 대체 텍스트의 글 점검은 caption-alt.md 7장이 맡습니다. 이 문서는 그 사이의 "눈으로 보는 단계"만 다룹니다. 기준값의 정본은 `docs/style-guide.md`이고, 여기서는 절 번호로 가리켜요.

예시와 명령 결과는 저자가 승인한 최종 시안(`docs/style-board/final/`)에 2026-10-14에 실제로 돌린 것입니다.

## 목차

1. 검수 순서와 "PNG를 직접 연다" 원칙
2. 미리보기 묶음 만들기
3. 점검표 Q1~Q27
4. 세련됨 최종 판정
5. 판정 등급, figures.yml status, 검수 기록
6. reviewer가 이 점검표를 쓸 때
7. 자주 놓치는 것

## 1. 검수 순서와 "PNG를 직접 연다" 원칙

| 단계 | 하는 일 | 도구 | 끝나는 조건 |
|---|---|---|---|
| ① 자동 lint | 출력 SVG의 형식 오류를 기계로 거름 | `figkit.py lint`(C는 `figlib.py lint`도) | 오류 0건, 경고는 사유를 적을 수 있음 |
| ② 미리보기 묶음 | 컬러, 흑백, 색약 2종, 휴대폰 폭, 다크 카드 PNG 생성 | 2장 명령 | 2.3절 이름표의 파일이 모두 있음 |
| ③ 눈으로 보기 | PNG를 한 장씩 열어 3장 Q 항목을 확인 | Read 도구(사람은 이미지 뷰어) | 모든 Q에 예/아니요가 붙음 |
| ④ 판정 | 고침이 0이 될 때까지 소스를 고치고 ①부터 다시 | 5.1절 등급표 | 통과 또는 저자 확인만 남음 |
| ⑤ 기록 | 판정과 근거를 notes.md와 `figures.yml`에 적음 | 5.3절 서식 | `status` 갱신 |

에이전트는 PNG를 만든 뒤 반드시 Read 도구로 파일을 하나씩 엽니다. 만들기만 하고 열지 않은 검수는 검수로 치지 않아요. 이유는 lint가 원리적으로 볼 수 없는 것이 그림의 품질을 대부분 정하기 때문입니다.

- lint는 속성 값을 읽습니다. 실제 글꼴로 그린 글자 폭, Mermaid와 matplotlib이 자동 배치한 결과, 선과 글자의 겹침은 픽셀에서만 드러납니다.
- "강조가 하나로 보이는가", "흑백에서 두 개념이 갈리는가"는 지각의 문제입니다. 색 값이 규칙 안이어도 면적과 굵기 때문에 다른 곳이 먼저 눈에 들어올 수 있어요.
- 기록에는 PNG마다 본 것을 한 줄로 남깁니다(5.3절). "열어 봤다"를 나중에 확인할 수 있는 유일한 근거입니다.

Read 도구는 큰 이미지를 줄여 보여 줍니다. 2배 컬러 PNG(폭 1280)에서 칩 글자나 화살표 끝처럼 작은 곳이 의심되면 그 부분만 잘라 다시 엽니다.

```bash
.venv/bin/python -c 'import sys;from PIL import Image
x,y,w,h=map(int,sys.argv[2:6]);Image.open(sys.argv[1]).crop((x,y,x+w,y+h)).save(sys.argv[1][:-4]+".crop.png")' "$Q/1-4-4.png" 1000 400 280 160
```

## 2. 미리보기 묶음 만들기

### 2.1 출력 SVG까지: 도구별 명령

미리보기는 언제나 최종 출력 SVG에서 만듭니다. 도구마다 SVG를 만드는 명령만 다르고, 그다음은 2.2절 묶음 명령 하나로 같아요.

| 종류 | 출력 SVG 만들기 | 근거 |
|---|---|---|
| M | `assets/mermaid/_build/render.sh X.mmd X.svg`, 세로 변형 auto는 `--width 360`으로 `X.v.svg` | assets/mermaid/README.md |
| S | `.venv/bin/python X.build.py` (`fig.save(..., preview=폴더)`로 묶음의 앞 세 장도 바로 생김) | figkit.py 머리 설명 |
| C | `.venv/bin/python -W error::UserWarning X.py 폴더`(경고까지 오류로) | chart-guide.md 7장 |
| T | `.venv/bin/python assets/svg-parts/_build/table.py X.yml -o X.svg`, 세로 변형은 `--variant v -o X.v.svg` | style-guide 9.5절 |

### 2.2 묶음 명령

`scripts/figure_qa.py`가 정본입니다. 그림 하나, 장 폴더, 권 폴더를 받고, 같은 ID의 세로 변형 `X.v.svg`가 있으면 함께 처리합니다. 출력 위치는 2.3절 표 그대로입니다.

```bash
.venv/bin/python scripts/figure_qa.py vol1-llm/ch04/figures/1-4-4.svg --sheet   # 그림 하나(+ 세로 변형)
.venv/bin/python scripts/figure_qa.py vol1-llm/ch04 --sheet                     # 장의 figures/*.svg 전부
.venv/bin/python scripts/figure_qa.py X.svg --sheet --tritan                    # 제3색약본까지(6.11절 기본은 제외)
```

`--sheet`는 변환본을 한 장에 붙인 `X.sheet.png`를 더 만듭니다. 시트로 먼저 훑고 의심 가는 변환본을 따로 엽니다. 기계 점검 경고는 FQ-FONT(글자 14 미만), FQ-W328(휴대폰 폭 환산 글자 크기 미달)이고, FQ-V(세로 변형 없음)는 참고 정보입니다. lint는 figure_qa가 하지 않으므로 아래 예비 블록의 1번 줄(`figkit.py lint`)은 따로 돌려요.

스크립트를 못 쓸 때의 예비 명령은 아래 블록입니다. figure_qa와 같은 PNG 묶음을 만들고, 시안 1-4-3과 1-5-5(둘 다 세로 변형 있음)에 돌려 그림마다 PNG 13장이 나오는 것을 확인했어요.

```bash
F=vol1-llm/ch04/figures/1-4-4.svg       # 검수할 본문 그림 SVG
case "$F" in */figures/*) Q="${F%/*}/_render/qa" ;; *) Q="${TMPDIR:-/tmp}/figqa" ;; esac
V="${F%.svg}.v.svg"; [ -f "$V" ] || V=

# 1. 자동 lint (출력 SVG면 도구와 상관없이 figkit lint, C는 figlib lint도)
.venv/bin/python assets/svg-parts/_build/figkit.py lint "$F" $V

# 2. 컬러(2배), 흑백, 휴대폰 328. 세로 변형은 360도 한 장 더
.venv/bin/python assets/svg-parts/_build/figkit.py preview "$F" $V -o "$Q" >/dev/null
[ -n "$V" ] && node scripts/svg_to_png.mjs "$V" "$Q/$(basename "${V%.svg}").w360.png" --width 360 >/dev/null

# 3. 제1, 제2색약(check_palette.py 행렬)과 다크 모드 카드(7.3절 값)
.venv/bin/python - "$Q" "$(basename "${F%.svg}")" <<'EOF'
import sys, numpy as np
from pathlib import Path
from PIL import Image
sys.path.insert(0, "scripts")
from check_palette import CVD, to_lin, from_lin
q, fid = Path(sys.argv[1]), sys.argv[2]
for p in [q / f"{fid}.png", q / f"{fid}.v.png"]:
    if not p.exists():
        continue
    im = Image.open(p).convert("RGB")
    a = np.asarray(im, dtype=float) / 255
    for v in ("protan", "deutan"):
        o = from_lin(to_lin(a) @ CVD[v].T)
        Image.fromarray(np.uint8(np.round(o * 255))).save(p.with_suffix(f".{v}.png"))
    w, h = im.size
    card = Image.new("RGB", (w + 36, h + 36), "#C9CDD3")
    card.paste(Image.new("RGB", (w + 32, h + 32), "#FFFFFF"), (2, 2))
    card.paste(im, (18, 18))
    page = Image.new("RGB", (w + 100, h + 100), "#1E2129")
    page.paste(card, (50, 50))
    page.save(p.with_suffix(".dark.png"))
EOF
ls "$Q" | grep "^$(basename "${F%.svg}")"
```

- 색약 시뮬레이션은 `check_palette.py`의 Machado(2009) 심도 1.0 행렬을 선형 sRGB에 적용합니다(style-guide 3.1절). 시안 보드 index.html의 `feColorMatrix`와 같은 값이에요. 제3색약은 팔레트 검사(3.3절)로 대신하므로 묶음에서 뺍니다(style-guide 6.11절).
- 다크 카드는 2배 PNG 기준이라 여백 8px이 16px, 테두리 1px이 2px로 그려집니다. 바탕 #1E2129는 근사값입니다(7.3절).
- 휴대폰 폭 PNG는 1배(폭 328 픽셀)입니다. 실제 휴대폰은 2~3배로 그리므로 이 PNG는 가장 엄격한 화면이에요. 여기서 읽히면 실제로도 읽힙니다.

## 3. 점검표 Q1~Q27

"자동"은 lint나 명령이 잡는 항목, "눈"은 PNG를 열어야 하는 항목입니다. 자동 항목도 경고가 났으면 PNG에서 실제 모습을 확인해요.

### 3.1 글자

| Q | 무엇을 보나 | PNG | 통과 기준 | 구분 |
|---|---|---|---|---|
| Q1 | 글자끼리, 글자와 선, 칩, 화살표의 겹침 | png, w328 | 0건. 글자가 선, 칩, 화살표 머리에 닿지 않음 | 자동(figkit "글자 겹침", S와 T) + 눈(M, C, 글자와 선) |
| Q2 | 잘림: 캔버스 끝, 상자 테두리, 줄바꿈 중간에서 끊긴 낱말. 칩 글자(단위 포함)가 칩 테두리에 닿거나 넘침 | png, 칩 자른 PNG | 0건. 상자 안 글자는 안쪽 여백 안. 칩 글자와 테두리 사이 4 이상 | 자동("상자 밖으로 넘침", "바깥 여백을 넘음", figure_qa FQ-CHIP) + 눈(칩은 1장 명령으로 잘라 2배로 엶) |
| Q3 | 최소 글자 크기 | w328 | SVG 크기는 14, 16, 20만(lint). 메시지에 필요한 글자가 아래 표의 수치 기준을 넘음. "읽힘" 같은 소감이 아니라 CSS px로 판정 | 자동(figure_qa FQ-W328, FQ-W328M, FQ-V 글자 목록) + 눈 |
| Q4 | 금지 기호, 글꼴에 없는 기호(네모 두부 글자) | png | 0건 | 자동(lint) + 눈(두부는 픽셀에서만 보임) |
| Q5 | 숫자 열 끝자리 정렬, 음수의 빼기 기호(−) | png | 같은 열 숫자의 오른쪽 끝이 한 x 값 | 눈 + 자동 경고("음수에 붙임표") |

Q3의 수치 기준은 style-guide 4.3절 계산을 따릅니다(화면 크기 = 글자 px × 표시 폭 ÷ 캔버스 폭).

| 캔버스 | 14 주석 | 16 라벨 | 판정 |
|---|---|---|---|
| 본문 640 → 328 | 7.2 CSS px | 8.2 CSS px | 메시지 정보는 16 이상으로 써야 통과. 14에만 있으면 세로 변형 대상(choose-type.md 5장 3번) |
| 세로 변형 360 → 328 | 12.8 CSS px | 14.6 CSS px | 모두 통과 |
| 세로 변형 420 이하 → 328 | 10.9 CSS px 이상 | 12.5 CSS px 이상 | 4.3절 권장 하한 |

- 판정은 수치로 적습니다. 검수 기록 w328 줄에는 "메시지 글자 16 → 8.2 CSS px, 통과"나 "값 라벨 14 → 7.2 CSS px, 세로 변형 필요"처럼 SVG 크기와 환산값을 함께 씁니다. 4장 1-4-8(옛 1-4-7) 첫 판은 값 라벨과 강조 라벨이 모두 14인데 기록이 "w328에서 읽힘"으로 통과시켜 reviewer 중대 지적(R1-G01)이 됐어요.
- 메시지 정보: 정본 값 라벨, 칩, 강조 라벨, 메시지 지시선 글, 그림이 증명하는 비교의 이름. 축 눈금, 머리줄, 보조 주석은 14여도 됩니다.
- `figure_qa.py`는 세로 변형이 없는 본문 그림에서 강조색, 600 이상, 칩 안 글자가 16 미만이면 FQ-W328M 경고를 냅니다. 굵기 500, ink-900 값 라벨처럼 기계가 못 가리는 메시지 글자도 있으니, FQ-V 참고 줄의 14 글자 목록을 보고 메시지 정보가 있는지 사람이 가립니다.

### 5.3 검수 기록 서식

장 `notes.md`(빌드 제외)에 그림마다 한 블록을 적습니다.

- 치수 줄은 기억이나 소스의 의도 값이 아니라 출력 SVG에서 읽은 값으로 적습니다(`patterns.md` 9.2절 두 번째 명령, 테두리 바깥 끝). 같은 열에 크기가 둘 이상 나오면 "어긋남 없음"이라 쓰지 않고 고침으로 돌립니다.
- 각 줄은 그 PNG를 연 뒤에 씁니다. lint 경고가 남았으면 경고 문구와 사유를 함께 적고, 경고와 맞지 않는 판정("어긋남 없음")을 적지 않습니다.
- 캔버스 높이가 패턴 기본보다 크면(예: P9 320 대신 480) 그 사유를 `note`에도 남깁니다. 패턴 표가 큰 캔버스를 허용하는 조건(P9는 하위 모듈 3개 이상)에 맞는지도 함께 적어요.
- 세련됨 줄은 대조한 시안 이름과 9장 12가지 가운데 어긋난 번호를 적습니다. 대조 시안이 검수 그림과 다른 종류일 수 있습니다(평가 금지 목록 때문에 S 그림을 1-4-3과 대조할 때 등). 그때는 design-rules 9장 표의 "시안에서 관찰한 값" 칸에서 같은 종류 그림(S는 1-4-4, C는 1-5-5 등)의 관찰값을 줄마다 확인합니다. 예를 들어 5번은 1-4-4의 "라벨 ink-600"을 검수 그림의 라벨 색, 굵기와 대조해요. 이 확인을 마친 뒤에만 "어긋남 없음"을 씁니다.

```markdown
- gray: 강조 띠가 가장 진하고 넓음. 키는 파선 띠로 갈림
- protan, deutan: 강조 파랑, 키 올리브로 바뀌나 면적과 파선으로 갈림
- w328: 칩 숫자 14 → 7.2 CSS px, 토큰 이름 16 → 8.2 CSS px. 칩이 메시지 정보라 세로 변형 사용(note 기록), 세로 변형은 12.8 CSS px
- dark: 카드 테두리 보임, 투명 구멍 없음
- 세련됨: 시안 1-4-4와 대조, 9장 12개 중 어긋남 없음
```

`figures.yml`의 `note`에는 한 줄만 덧붙입니다. 예: `QA 2026-10-14 통과(Q1~Q27), 경고 사유: Mermaid 배치 격자 3건`. 저자 확인이 있으면 `QA 저자 확인: Q24 R3 닮음 소견 notes.md 참고`처럼 남겨요.

## 6. reviewer가 이 점검표를 쓸 때

reviewer(CLAUDE.md 13장)도 같은 Q1~Q27을 씁니다. 다른 점은 다섯 가지입니다.

| 항목 | 작성자(making-figures) | reviewer |
|---|---|---|
| 대상 | 자기가 만든 그림 | 집필과 그림 제작에 참여하지 않은 그림만. 자기 그림이면 검수를 거절하고 보고 |
| PNG | 직접 만든 묶음 | 작성자의 PNG를 믿지 않고 같은 명령으로 다시 만들어 엶 |
| 고침 | 소스를 직접 고침 | 고치지 않음. Q 번호, 위치, 수정 제안만 검수 보고서에 적음 |
| 평가 축 | Q 항목 판정 | "사실 정확성"(Q20~Q23, Q27)과 "PM 독자 이해도"(Q10~Q12, Q17)를 따로 평가 |
| status | `reviewed`까지 올림 | 고침이 나오면 `rendered`로 내리라고 제안. 직접 `approved`를 쓰지 않음 |

PM 독자 이해도는 Q12를 독자 눈으로 다시 하는 것입니다. 캡션 없이 PNG만 보고 5초 안에 메시지를 말할 수 있는지, 정의되지 않은 기호(q, k, √d)가 앞 본문에 나왔는지를 봐요(제안).

## 7. 자주 놓치는 것

- PNG를 만들고 열지 않는 것. 묶음 명령의 `ls` 출력은 파일이 있다는 뜻일 뿐입니다.
- 컬러 PNG만 보고 gray와 색약 PNG를 건너뛰는 것. 강조가 색으로만 표시된 그림은 gray에서 바로 드러납니다.
- w328에서 "작지만 보인다", "읽힘"으로 넘기는 것. 메시지 정보가 14에만 있으면 Q3 표대로 고침이고, 기록에는 CSS px 수치를 씁니다(4장 R1-G01).
- 칩을 전체 PNG에서만 보고 넘기는 것. 칩 글자 넘침은 줄인 화면에서 안 보이니 잘라서 2배로 엽니다(4장 1-4-9).
- 패턴 그림을 "모양이 예쁘다"로 닫는 것. 패턴마다 무슨 뜻으로 읽히는지 적어 봅니다(3.8절 Q12, 4장 1-4-5).
- 그림 하나씩만 보고 장 대조판을 건너뛰는 것(4장 5번).
- `svg_to_png.mjs`가 tnum을 적용하지 않아 숫자가 Chrome보다 조금 좁게 그려진다는 점. 칩과 숫자 열이 많은 그림은 Chrome으로도 한 번 엽니다(chart-guide.md 7장).
- 세로 변형을 고친 뒤 원본의 숫자나 강조와 다시 맞추지 않는 것(Q18).
- lint 경고를 사유 없이 남기는 것. 경고는 오류가 아니지만, 기록에 사유가 없으면 고침으로 봅니다.
- 1-4-4처럼 accent가 칩과 띠 둘인 그림에서 하나만 확인하는 것. `accent` 필드에 적힌 대상을 모두 찾습니다.
- 3권 그림에서 로봇 닮음을 에이전트가 "통과"로 닫는 것. 소견을 적고 저자 확인으로 올립니다.
- 원고 그림의 PNG를 `figures/` 바로 아래에 만들어 커밋하는 것. `_render/qa/`에 둡니다.
