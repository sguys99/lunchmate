# 캡션, 대체 텍스트, 출처 (caption-alt)

그림 하나에 붙는 네 가지 글(캡션, 대체 텍스트, 출처 줄, 🔄 기준일)을 쓰고 `figures.yml`에 남기는 절차입니다. 렌더링과 시각 검수를 마친 뒤, 원고에 그림 줄을 넘기기 직전에 펼쳐 봅니다. 정본은 `docs/style-guide.md` 8장이고, 이 문서는 그것을 "무엇을 어떤 순서로 채우고 무엇으로 확인하나"로 압축했습니다. 값이 다르면 style-guide가 맞고, 이 문서를 고칩니다.

예시는 저자가 승인한 최종 시안 5장(`docs/style-board/final/figures.yml`)의 실제 값입니다. "고칠 예"는 같은 그림을 일부러 틀리게 바꾼 것이라 실제 기록에는 없어요.

## 목차

1. 두 스킬의 분담과 글의 분담
2. 캡션
3. 대체 텍스트
4. 출처 줄과 출처 종류
5. 🔄 그림의 기준일
6. figures.yml 한 항목 채우기
7. 점검 명령
8. 자주 하는 실수

## 1. 두 스킬의 분담과 글의 분담

### 1.1 making-figures와 writing-chapter

| 일 | 맡는 스킬 | 근거 |
|---|---|---|
| `figures.yml` 항목(메시지, 캡션 조각, alt, 출처, refresh, status) | making-figures | style-guide 8.6절 |
| 그림 소스 안의 `<title>`, `<desc>`(accTitle, desc 인자) | making-figures | 이 문서 3.4절 |
| 캡션 조립 결과와 원고 이미지 줄 한 줄을 만들어 넘기기 | making-figures | 8.6절 조립 규칙 |
| 이미지 줄을 `index.md`의 제자리에 넣고, 본문에서 "그림 1-4-3"으로 가리키기 | writing-chapter | box-markup.md 5장 |
| 앞뒤 문단의 해석, 비유가 틀리는 지점, 손계산 | writing-chapter | style-guide 6.8절 표 |

- 원고 줄의 서식(경로, `#fig:`, `alt="..."`, 작은따옴표)은 box-markup.md 5장과 style-guide 8.1절을 그대로 따릅니다. 이 문서는 서식을 다시 정하지 않아요.
- style-guide 8.6절은 원고에 들어간 글을 최종본, `figures.yml`을 사본으로 적습니다. 글을 고치는 순서의 기준(편집 원천)은 `figures.yml`입니다. 캡션과 alt를 바꿀 때는 `figures.yml` 항목을 먼저 고치고, 같은 회차에 원고 이미지 줄과 SVG `<desc>`를 같은 글로 바꿉니다(6.4절). 한쪽만 바꾸면 `check_figures.py` F11이 막습니다. 저자나 writing-chapter가 원고에서 먼저 고쳤다면 making-figures가 같은 회차에 `figures.yml`과 `<desc>`를 맞춥니다.
- 제안: 8.6절은 원고 줄 옮기기를 making-figures 몫으로, box-markup.md 5장은 writing-chapter 몫으로 적었습니다. 이 문서는 "making-figures가 줄을 만들고 writing-chapter가 넣는다"로 둘을 잇습니다.

### 1.2 무엇을 어디에 쓰나

그림 안 글자, 머리줄, 캡션, 대체 텍스트, 본문의 분담표는 design-rules.md 11장(원본 style-guide 6.8절)에 있습니다. 이 문서 쪽에서 덧붙일 것은 네 줄이에요.

| 글 | 한 줄 역할 | 이 문서 관점의 주의 |
|---|---|---|
| 머리줄 대상 이름 | 그림이 무엇에 관한 것인지(16자 이하 명사구) | 캡션 제목을 줄인 말. 제목과 따로 짓지 않음 |
| 캡션 | 무엇을 보여 주나 + 읽는 법 한 줄 | 숫자를 다 옮기지 않음. 출처와 기준일은 여기에만 |
| 대체 텍스트 | 그림을 못 보는 독자가 같은 결론에 닿게 하는 2~4문장 | 그림에 적힌 숫자를 모두 말로 옮길 수 있는 유일한 자리 |
| 본문 | 왜 그런지, 비유가 어디서 틀리는지 | 캡션과 대체 텍스트에 해석을 넣지 않음 |

## 2. 캡션

### 2.1 조립 규칙

`figures.yml`에는 조각만 적고, 문장은 조립 규칙이 만듭니다(8.6절).

```
"그림 " + id + ". " + title + ". " + reading
  + (caveat ? " " + caveat : "")
  + (refresh ? " 🔄 기준일: YYYY년 M월." : "")
  + (source.line ? " " + source.line : "")
```

| 조각 | 길이 | 문체와 형태 | 근거 |
|---|---|---|---|
| `title` | 40자 이하 | 명사구, 마침표 없이 적음(조립이 붙임) | 8.2절 |
| `reading` | 1문장, 70자 이하 | 습니다체, 마침표로 끝냄 | 8.2절 |
| `caveat` | 1문장, 70자 이하, 없으면 `null` | 습니다체. 원본과 달라진 점, 개념도, 가정값. `source.kind: own`이면 회사명, 모델명 없이 씀(2.2절) | 8.2절 |
| 셋의 합 | 120자 이하 | 넘으면 내용을 본문으로 옮김 | 8.2절 |

캡션은 해요체를 쓰지 않습니다. 캡션은 원고 어미 비율 계산에서 빠지지만, 시리즈 전체 캡션 말투를 하나로 맞추려고 습니다체로만 씁니다(8.2절).

### 2.2 제목과 읽는 법 쓰는 법

- 제목은 대상 이름입니다. 주장("~이 가장 큽니다")은 읽는 법과 지시선이 맡아요.
- 읽는 법은 "눈을 어디서 시작해 무엇을 비교하면 메시지가 보이나"를 씁니다. `message`를 그대로 옮기지 않고, 그 결론에 닿는 길을 씁니다.
- 순서어("첫 단계부터", "온도가 커질수록")를 쓰고 방향어("왼쪽 상자")를 피합니다. 가로 흐름이 EPUB 세로 변형에서 위아래로 바뀌기 때문이에요.
- 예외: 차트의 가로축처럼 세로 변형에서도 방향이 그대로인 축은 "왼쪽에서 오른쪽으로"를 써도 됩니다(style-guide 8.2절). 시안 1-5-5가 그렇게 썼습니다.
- 색 이름("파란 띠")으로 가리키지 않고, 라벨 글자나 개념 이름으로 가리킵니다. 흑백 인쇄와 다크 모드에서 틀린 말이 되기 때문입니다.
- 실측이 아니라 모양만 보여 주는 그림은 제목 끝에 "(개념도)", 한 장 요약은 "{장 핵심어} 한 장 요약"으로 씁니다.
- `source.kind: own`(정본으로 새로 그림)인 그림은 캡션과 대체 텍스트에 회사명, 제품명, 모델명을 쓰지 않습니다. 정본 값이 특정 제품의 공개값이어도 "한 대표 사례의 공개값"처럼 일반명으로 씁니다. 예: caveat "주기는 한 대표 사례의 공개값이며 제품마다 다릅니다." 이름을 밝혀야 하면 출처 줄(`data`, `adapted`)이 필요합니다. 그 키가 장 `references.yml`에 없으면 researcher 몫으로 보고합니다(4.3절, CLAUDE.md 8장 제품명 규칙).

### 2.3 좋은 예 (시안 실제 값)

| 그림 | title | reading | 왜 좋은가 |
|---|---|---|---|
| 1-4-3 M | 어텐션 계산의 네 단계 | 첫 단계부터 따라가면 '안'의 점수가 가중치로 바뀌고, 그 가중치로 값을 섞어 출력이 나옵니다. | 순서어로 시작해 세로 변형에서도 맞음. 숫자를 옮기지 않음 |
| 1-4-4 S | '안'이 다른 토큰을 보는 정도 | 띠가 굵을수록 가중치가 크고, 세 띠의 굵기를 합하면 쿼리 상자 한 변과 같습니다. | 시각 부호(굵기)가 무엇을 뜻하는지 알려 줌. caveat로 토큰 수를 줄인 사실을 밝힘 |
| 2-4-2 T | RRF로 합친 두 검색의 순위 | 문서마다 두 순위를 함께 보면, 한쪽 1위보다 두 검색 모두 상위인 문서가 점수가 높습니다. | 표를 읽는 단위(행)와 비교 대상을 정해 줌 |
| 1-4-8 요약 | 트랜스포머 한 장 요약 | 절 순서대로 읽으면 어텐션 부품들이 트랜스포머 블록으로 모이고, 그 대가와 다음 장의 질문이 이어집니다. | 요약 그림이 따르는 흐름(절 순서)을 한 문장으로 |

1-4-4의 caveat "계산을 보이려고 문장을 상자가, 안, 왔어요 세 토큰으로 줄였습니다."는 고객 문의 예문과 그림이 달라진 이유를 밝히는 전형적인 주의 문장입니다.

### 2.4 고칠 예

| 고칠 캡션 조각 | 무엇이 문제인가 | 고친 것 |
|---|---|---|
| title "'안'은 '왔어요'를 가장 많이 봅니다" | 제목에 주장을 씀. 메시지는 지시선과 읽는 법 몫 | "'안'이 다른 토큰을 보는 정도" |
| reading "파란 띠가 가장 굵습니다." | 색 이름, 결론만 있고 읽는 길이 없음 | "띠가 굵을수록 가중치가 크고, ..." |
| reading "왼쪽 상자에서 오른쪽 상자로 가면 가중치가 0.140, 0.284, 0.576이 됩니다." | 가로 흐름의 방향어, 숫자 나열(숫자는 alt 몫) | "첫 단계부터 따라가면 ..." |
| reading "온도가 커질수록 분포가 평평해져요." | 캡션에 해요체 | "... 분포가 평평해집니다." |
| title "온도에 따른 답변 첫 토큰의 확률(N5-2)" | 정본 ID는 `source.canon`에만 둠 | "온도에 따른 답변 첫 토큰의 확률" |
| caveat "이 그림에서 보듯 온도는 창의성을 조절하는 손잡이입니다." | 해석과 비유는 본문 몫. caveat는 달라진 점, 개념도, 가정만 | `null` |

## 3. 대체 텍스트

목표는 하나입니다. 대체 텍스트만 들은 독자가 캡션의 메시지와 같은 결론에 닿는 것이에요(8.3절).

### 3.1 형식과 문장 구조

| 항목 | 기준 |
|---|---|
| 분량 | 2~4문장, 전체 300자 이하, 문장마다 100자 이하 |
| 문체 | 습니다체만. 한 줄로, 줄바꿈 없음 |
| 넣지 않음 | 마크다운, `[@key]`, 굵은 글씨, 큰따옴표, 출처, "그림입니다", "이 그림은", "아래 그림", 캡션 복사, own 그림의 회사명과 모델명(2.2절), 그림과 설계서에 없는 하위 구성 |
| 이름 | 그림 라벨과 같은 말. 노드와 단계 이름, 입력 이름을 바꿔 읽지 않고, 라벨에 없는 구성(예: 센서가 무엇인지)을 덧붙이지 않음 |
| 용어 | 본문에서 이미 정의한 말만. 대체 텍스트에서 새 용어를 꺼내지 않음 |

| 순서 | 담을 것 | 시안 1-4-4의 문장 |
|---|---|---|
| 1 | 무엇을 어떤 형태로 | 토큰 '안'이 상자가, 안, 왔어요를 얼마나 보는지를 연결 띠의 굵기로 나타냈습니다. |
| 2~3 | 핵심 값과 관계 | 가중치는 상자가 0.140, 안 0.284, 왔어요 0.576이고 셋을 더하면 1입니다. |
| 마지막 | 캡션과 같은 결론 | 가장 굵은 띠가 왔어요로 이어져, '안'은 '왔어요'를 가장 많이 봅니다. |

### 3.2 숫자와 기호 읽기

- 숫자는 그림에 적힌 문자열 그대로 씁니다. 정본 값을 반올림하거나 새로 계산하지 않아요(8.3절). 0.576을 "약 0.58"이나 "57.6%"로 바꾸지 않습니다.
- 숫자는 "이름 값" 짝으로 붙여 씁니다("상자가 0.140, 안 0.284"). 값만 늘어놓으면 듣는 사람이 어느 값이 누구 것인지 놓쳐요.
- 큰 수는 정본 표기 그대로 한글 단위를 씁니다("128,000토큰이면 약 164억 쌍", 1-4-8).
- 수식 기호는 말로 풉니다. 시안 1-4-3은 ÷√2를 "루트 2로 나누면"으로 읽었습니다. 음수는 정본과 같은 마이너스 기호(−1)를 씁니다.
- 가정값이면 대체 텍스트에도 숫자 앞에 "가정"을 붙입니다.
- 숫자가 많으면 결론을 만드는 숫자를 고르고, 나머지는 그림 라벨에 남깁니다. 다만 고른 숫자 사이에 빠진 칸이 있다는 인상을 주지 않게 계열 단위로 고릅니다.
- 차트(C)는 핵심 숫자를 2~4개로 고릅니다(style-guide 8.3절). 세는 대상은 그림에서 값으로 읽히는 숫자(세로축 값, 칩)입니다. 계열 이름에 든 숫자(p = 0.95)와 가로축 조건(5단계, 온도 0.5)은 축과 비교 대상을 밝히는 말이라 세지 않습니다. 고르는 순서는 아래와 같아요.
  1. 칩을 단 정본 값(메시지가 기대는 값)
  2. 메시지 계열의 처음이나 끝 값(추세를 보이는 짝)
  3. 비교가 메시지면 맞수 계열의 같은 x 값 하나
  4. 여기까지 4개를 넘으면 뒤에서부터 덜어 내고, 덜어 낸 값은 그림 라벨에만 남깁니다.

### 3.3 색과 위치

대체 텍스트와 캡션에는 색 이름을 아예 쓰지 않습니다(style-guide 8.3절, 7장 명령이 검사). 선 종류와 위치만의 묘사도 그 뜻으로 바꿔 씁니다. 굵기, 길이처럼 값을 실어 나르는 시각 부호는 1-4-4처럼 그 뜻("굵기 = 가중치")과 함께 쓰면 됩니다.

### 3.4 SVG `<title>`, `<desc>`와 원고 alt

렌더링된 SVG는 `role="img"`, `aria-labelledby`로 `<title>`, `<desc>`를 가지며, 원고 `alt`와 이렇게 맞춥니다.

| SVG 요소 | 글 | 세로 변형(`.v.svg`) |
|---|---|---|
| `<title>` | `그림 {id} {머리줄 대상 이름}` (예: "그림 1-4-3 어텐션 계산 4단계") | 끝에 " (EPUB 세로 변형)"만 더함(5.11절) |
| `<desc>` | `figures.yml`의 `alt`와 글자 단위로 같음 | 원본과 같음 |

| 종류 | 어디에 적나 |
|---|---|
| M | `.mmd`의 `accTitle:`, `accDescr:` 줄(assets/mermaid/README.md) |
| S | figkit `Figure(desc=...)`, `<title>`은 자동 생성(figkit.py 독스트링) |
| C | figlib `save(fig, out, title=..., desc=...)` (시안 1-5-5.py) |
| T | 표 명세 yml의 `title:`, `desc:` (시안 2-4-2.yml) |

순서는 `figures.yml`의 `alt`를 먼저 확정하고, 그 문자열을 소스에 붙여 넣은 뒤 렌더링하는 것입니다. 소스 쪽에서 고치면 사본이 셋으로 갈라져요.

### 3.5 종류별 요령과 예시

| 종류 | 반드시 넣을 것(8.3절) | 시안 |
|---|---|---|
| M 흐름도 | 단계 수, 단계 이름을 순서대로(노드에 쓴 이름 그대로), 되돌아가는 고리가 있으면 그 조건 | 1-4-3 |
| S 공간 배치, 구조도 | 핵심 구성 요소 3~5개와 관계. 공간 부호(굵기, 거리)의 뜻. 구성 요소 이름은 상자 라벨 그대로 | 1-4-4 |
| C 차트 | 가로축과 세로축, 로그 눈금 여부, 비교 대상, 핵심 숫자 2~4개(3.2절 고르는 순서), 추세 | 1-5-5(첫 문장만 본보기, 아래) |
| T 표 | 행과 열이 무엇인지, 비교의 결론. 칸을 모두 읽지 않음 | 2-4-2 |
| 한 장 요약 | 묶는 개념 3~5개를 흐름 순서대로 | 1-4-8 |
| 데모 장면(3권) | "원격 조작", "자율", "배속" 표시 칸의 값 | (아직 없음) |

| 시안 | alt의 한 문장 | 짚을 점 |
|---|---|---|
| 1-4-3 M | 토큰 '안'의 어텐션 계산을 점수, 나누기, softmax, 가중합의 네 단계 흐름도로 나타냈습니다. | 첫 문장에 단계 수와 이름이 순서대로 다 있음. 이름은 노드 라벨 그대로(4장 원고판, 시안의 "크기 조정"을 원고 말 "나누기"로 바꿈) |
| 1-5-5 C | 같은 점수 2, 1, −1을 가진 답변 첫 토큰 후보 세 개의 확률을 온도 0.5, 1, 2에 걸쳐 선으로 이었습니다. | 고정 조건(점수)과 가로축(온도)이 첫 문장에. 이어서 후보별 추세 |
| 2-4-2 T | A는 1위와 2위로 0.03252, B는 3위와 1위로 0.03227, ... | 행 하나를 한 구절로. 마지막 문장이 "순서는 A, B, C, D입니다"로 결론 |
| 1-4-8 요약 | 순환을 버리고 ... 셀프 어텐션, 멀티헤드 어텐션, 위치 인코딩을 거쳐 ... 트랜스포머 블록에 닿습니다. | 표의 행을 다 읽지 않고 흐름 하나로 꿰었음 |

시안 1-5-5 alt는 세 후보의 값 9개를 모두 읽어 C 기준(핵심 숫자 2~4개)을 넘습니다. 첫 문장(고정 조건과 가로축)은 본보기로 쓰되 값 문장은 따르지 않습니다. 3.2절 순서로 고르면 이렇게 됩니다. "'죄송합니다'는 0.879에서 0.547로 줄고, 가장 낮은 '네'는 0.002에서 0.122로 늡니다." 칩 두 값(0.879, 0.547)과 맞수 계열의 처음과 끝 값으로 4개예요. 시안 기록을 이 방향으로 고칠지는 저자 확인 대상입니다(`docs/skill-trial-3.8.md` 4장).

표 그림의 행이 5개를 넘으면 결론에 필요한 행만 읽어요. 고칠 예 하나도 봐 두세요. "이 그림은 세 개의 파란 띠를 보여 줍니다. 가장 굵은 띠는 오른쪽에 있습니다."는 그림이라는 사실 알림, 색, 위치만 말하고 숫자와 결론이 없습니다.

## 4. 출처 줄과 출처 종류

### 4.1 결정표

`source.kind`를 먼저 고르면 출처 줄이 정해집니다(8.4절, 8.6절). 캡션 출처 줄은 머리말 낱말 네 가지(출처, 자료, 가정, 측정)로만 시작합니다.

| 그림의 근거 | `source.kind` | `refs` | `source.line`(캡션 끝) | `canon` |
|---|---|---|---|---|
| 정본 숫자나 개념으로 새로 그림 | `own` | 비움 | `null` | 쓴 정본 ID. 캡션과 alt에 회사명, 모델명 없음(2.2절) |
| 논문 그림을 참고해 새로 그림 | `adapted` | 1개 이상 | `출처: {논문 제목이나 저자} 논문 그림 {n}을 참고하여 재구성[@key].` | 있으면 |
| 출처 있는 수치로 그린 차트 | `data` | 1개 이상 | `자료: {자료 이름}의 수치로 재구성[@key].` | 보통 비움 |
| 가정값으로 그림 | `assumed` | 있으면 | `가정: {가정 내용}.` | 가정이 정본에 있으면 |
| 저자가 직접 측정 | `measured` | 있으면 | `측정: {조건}, 측정일 {YYYY}년 {M}월 {D}일.` | 비움 |
| 측정값 없이 모양만 보여 줌 | `concept` | 근거가 있으면 | 근거 자료가 있으면 `출처:`나 `자료:` 줄 | 비움 |
| 논문 그림을 참고했는데 출처 키가 장 `references.yml`에 아직 없음 | `adapted` | 비움(키 등록은 researcher) | `출처: {논문 제목이나 저자} 논문 그림 {n}을 참고하여 재구성[출처 필요: {key}].` 키는 설계서 그 장 "출처 키"의 이름 그대로 | 있으면 |
| 위와 같고 원 논문의 그림 번호도 확인하지 못함 | `adapted` | 비움 | `출처: {논문 제목이나 저자} 논문 그림을 참고하여 재구성[출처 필요: {key}, 그림 번호 확인].` 번호를 지어 넣지 않음 | 있으면 |
| 확인하지 못한 자료(논문도 키도 모름) | 근거에 맞게 | 비움 | `[출처 필요]` | |

- 정본으로 그린 그림(시안 5장 모두)은 출처 줄이 없습니다. 계산 방법의 출처는 본문이 `[@key]`로 이미 밝혔기 때문이에요(8.8절 보기 1).
- 출처 줄이 여럿이면 출처, 자료, 가정, 측정 순서로 한 문장씩 이어 씁니다.
- `[@key]`는 캡션에서는 출처 줄에만 쓰고, 대체 텍스트에는 쓰지 않습니다.
- 키가 장 `references.yml`에 없어도 출처 줄의 꼴은 버리지 않습니다. "출처:" 머리, "참고하여 재구성" 문구, 설계서의 출처 키를 그대로 두고 `[@key]` 자리만 `[출처 필요: {key}]`로 바꿉니다. researcher가 키를 등록하면 태그만 `[@key]`로 바꾸면 되고, 검수도 어느 논문인지 바로 알 수 있어요. 예: `출처: π0 논문 그림 1을 참고하여 재구성[출처 필요: black2024pi0].` 이 규칙은 writing-chapter `box-markup.md` 5장 출처 줄 표와 같습니다.

### 4.2 "참고하여 재구성" 문형

```
출처: 「Attention Is All You Need」 논문 그림 1을 참고하여 재구성[@vaswani2017].
```

- "참고하여 재구성"은 CLAUDE.md 10장 표현 그대로 씁니다. "인용", "발췌", "출처: 논문"으로 바꾸지 않아요.
- 그림 번호 n은 원 논문에서 확인한 번호만 씁니다. 확인하지 못했으면 줄을 지우지 않고 번호만 빼서 "논문 그림을 참고하여 재구성"으로 쓰고, 태그에 ", 그림 번호 확인"을 붙입니다. 예: `출처: π0 논문 그림을 참고하여 재구성[출처 필요: black2024pi0, 그림 번호 확인].` 키는 있는데 번호만 확인하지 못한 경우의 꼴은 아직 정해지지 않았으니 저자 확인으로 올립니다.
- 원본과 구조가 달라졌으면 `caveat`에 씁니다. 예: "원 논문 그림은 인코더-디코더 구조이고, 이 그림은 디코더 부분만 다시 그렸습니다."(1-4-6 설계)
- 외부 그림은 재사용하지 않고 모두 새로 그립니다. 재구성은 구조를 참고한다는 뜻이지 원본을 따라 그린다는 뜻이 아닙니다(CLAUDE.md 10장).

### 4.3 references.yml 키와 unverified

- `refs`의 키는 그 장 `references.yml`에 있어야 합니다. 없으면 researcher에게 넘기고, 이 스킬이 키를 새로 지어 넣지 않습니다.
- 에이전트가 찾은 출처는 `status: unverified`로 들어옵니다(CLAUDE.md 8장). 그림은 그 키로 렌더링까지 진행해도 됩니다.
- `refs`에 unverified 키가 있어도 `reviewed`까지는 올리고(style-guide 8.6절), `note`에 "출처 키 kwa2025metr unverified"처럼 적습니다. `approved`는 사람이 키를 확인한 뒤에만 둡니다.
- `[출처 필요]`나 `[출처 필요: {key}]`, `[출처 필요: {key}, 그림 번호 확인]`이 남은 그림은 `reviewed`로 올리지 않습니다(8.4절). 키가 없을 때 `[출처 필요: {key}]`의 key는 설계서 그 장 "출처 키"에 적힌 이름만 쓰고, 이 스킬이 새 키를 짓지 않습니다.

## 5. 🔄 그림의 기준일

설계서 그림 명세에 🔄가 붙은 그림만 해당합니다(8.5절, 6.10절).

| 항목 | 규칙 |
|---|---|
| 캡션 표기 | `🔄 기준일: 2026년 10월.` 월 단위. 자리는 읽는 법(과 caveat) 다음, 출처 줄 앞 |
| 값 | 해당 권 🔄 관리표의 기준 시점 그대로. 더 새 정보를 찾으면 원고 대신 관리표 갱신을 먼저 제안 |
| 측정 그림 | 기준일 대신 `🔄 측정: ..., 측정일 YYYY년 M월 D일.` 일 단위 |
| 그림 안 | 기준일을 넣지 않음(머리줄 포함) |
| 대체 텍스트 | 성능, 순위, 가격처럼 시점이 결론을 좌우하면 기준 시점을 넣음(6.8절 표) |
| `figures.yml` | `refresh.as_of`, `refresh.ledger`, `refresh.recheck`를 채움. `null`이 아니면 🔄 그림 |
| 출처 | 성능 수치를 보이는 🔄 그림은 출처 줄이 반드시 있음 |

`refresh` 예(8.6절, 2-10-5 보기):

```yaml
  refresh:
    as_of: "2026-10"
    ledger: "vol2 10장 / 10.6 METR 작업 시간 지평"
    recheck: "arXiv 2503.14499 최신판"
```

## 6. figures.yml 한 항목 채우기

### 6.1 절차

1. 설계서 그림 명세 행을 `spec`에 원문 그대로 옮기고 `id`, `vol`, `chapter`, `section`, `kind`를 채웁니다. `status: spec`.
2. 그리기 전에 `message`(40자 이하 습니다체 한 문장)와 `accent`를 정합니다(design-rules.md 2장).
3. 소스를 쓰면 `source_file`, `output_file`, `epub_variant`를 채우고 `status: source`. figkit은 desc 없이 저장하지 않고 figkit lint도 desc가 없으면 오류를 내니, 이때 alt 초안을 소스의 desc(M은 `accDescr`)에 넣어 둡니다.
4. 렌더링과 미리보기 확인을 마치면 `status: rendered`.
5. 시각 검수를 마친 뒤 이 문서 2~5장대로 `caption`, `alt`, `source`, `refresh`를 확정합니다. 확정한 `alt`를 소스의 desc에 옮겨 다시 빌드하고, SVG `<desc>`와 `alt`가 글자 단위로 같은지 7장 명령으로 확인해요.
6. 7장 명령과 시각 검수(qa-checklist.md)를 통과하면 `status: reviewed`. 조립한 이미지 줄을 writing-chapter에 넘깁니다. 규칙 예외(높이 초과, 선택 세로 변형, 재작도 사유)는 그때그때 `note`에 적어요.
7. 저자가 승인하면 `status: approved`. 이 값은 사람만 적습니다.

### 6.2 필드별 채우는 법 (시안 1-4-4에 주석)

스키마는 8.6절이 유일한 정본이고, 필드 이름은 그대로만 씁니다(`type`이 아니라 `kind`).

```yaml
- id: "1-4-4"            # 문자열. 파일명, #fig:, 캡션 번호, 머리줄 번호와 같음
  vol: 1
  chapter: 4
  section: "4.2"         # 그림이 처음 나오는 절. 요약 그림은 "한 장 요약"
  kind: S                # 설계서 명세 종류(choose-type.md 8장)
  spec: "고객 문의 예문에서 \"안\"이 다른 토큰을 보는 연결선. 선 굵기 = 가중치"   # 설계서 원문
  source_file: vol1-llm/ch04/figures/1-4-4.build.py   # 시안은 docs/style-board/final/
  output_file: vol1-llm/ch04/figures/1-4-4.svg
  message: "'안'은 '왔어요'를 가장 많이 봅니다"        # 40자 이하, 마침표 없이
  accent: "왔어요로 가는 연결 띠, 숫자 칩 0.576"      # 강조 대상과 칩
  role: 숫자             # 비유, 구조, 숫자, 요약 가운데 하나(6.6절)
  epub_variant: manual   # none, auto(Mermaid만), manual
  caption:
    title: "'안'이 다른 토큰을 보는 정도"             # 마침표 없이
    reading: "띠가 굵을수록 가중치가 크고, 세 띠의 굵기를 합하면 쿼리 상자 한 변과 같습니다."
    caveat: "계산을 보이려고 문장을 상자가, 안, 왔어요 세 토큰으로 줄였습니다."
  alt: "토큰 '안'이 상자가, 안, 왔어요를 ... '왔어요'를 가장 많이 봅니다."   # 3문장, 한 줄
  source:
    kind: own            # 4.1절 결정표
    refs: []             # own이면 비움
    line: null           # own이면 null
    canon: [N4-2]        # 쓴 정본 ID. 7장 명령이 숫자를 이 행과 대조
  refresh: null          # 🔄 그림만
  status: rendered       # spec → source → rendered → reviewed → approved
  note: "선 굵기 = 가중치를 ... 면(띠) 폭으로 그림. ..."
```

`message`는 마침표 없이, `reading`, `caveat`, `alt`는 마침표로 끝낸다는 점이 헷갈리기 쉬워요. 큰따옴표가 든 `spec`은 YAML 안에서 `\"`로 씁니다. `alt` 안에는 큰따옴표를 아예 쓰지 않습니다.

### 6.3 figures.yml 고치는 법(여러 에이전트가 동시에 일할 때)

`docs/figures.yml`은 세 권 그림 237개가 한 파일에 있는 공유 기록부입니다. 4장에서 그림 에이전트 여럿이 동시에 이 파일을 고치다가, 한 에이전트가 파이썬(yaml 읽고 쓰기)으로 파일 전체를 다시 써서 다른 에이전트의 갱신을 덮을 뻔했어요.

- 고칠 때는 Edit 도구로 맡은 ID 항목의 바뀐 줄만 바꿉니다. 새 항목도 Edit로 자리(같은 장의 번호 순서)에 끼워 넣어요.
- 파일 전체를 다시 쓰지 않습니다. Write 도구, `yaml.safe_load` 뒤 `yaml.dump`, sed나 스크립트의 전체 치환 모두 금지입니다. 따옴표, 줄 순서, 주석이 바뀌어 남의 항목까지 diff에 섞이고, 같은 때 고친 남의 갱신이 사라집니다.
- 맡지 않은 ID의 항목은 오탈자가 보여도 고치지 않고 보고합니다.
- Edit가 "파일이 바뀌었다"로 실패하면 다시 읽고 자기 줄만 다시 고칩니다. 덮어써서 해결하지 않아요.
- 고친 뒤 `check_figures.py`(F10, F11)로 그 장을 확인합니다. YAML 문법이 깨지면 모든 장의 검사가 멈춥니다.

### 6.4 캡션과 alt 바꾸기(원고와 같은 회차에)

원고 그림 블록과 `figures.yml`은 F11이 글자 단위로 대조합니다. 4장 R1 회차에서는 writer가 확정한 새 캡션을 원고에 넣지 못하고 기록부 문구 그대로 둔 채 그림 담당에게 넘겨야 했어요(notes.md "R1 반영 그림 인계"). 같은 일이 생기지 않게 순서를 정합니다.

1. 바꿀 글(캡션 제목, 읽는 법, 주의, 출처 줄, alt)을 확정안으로 받습니다. 원고 쪽 확정안은 writing-chapter가 인계표로 넘겨요.
2. `figures.yml` 그 ID 항목의 `caption`, `alt`, `source.line`을 Edit로 먼저 고칩니다(6.3절).
3. 같은 회차에 원고 이미지 줄을 2의 조립 결과(2.1절)로 바꿉니다. 원고 줄은 원래 writing-chapter 몫이지만, 캡션 동시 교체는 인계표에 적힌 확정안 그대로라면 그림 담당이 해도 됩니다. 인계표가 없으면 writing-chapter에 이미지 줄을 넘겨 같은 회차에 넣게 합니다.
4. alt가 바뀌었으면 소스의 desc(M은 `accDescr`)를 같은 글로 고치고 다시 빌드합니다(3.4절).
5. `check_figures.py --final 장`과 7장 명령으로 F11, desc와 alt 일치를 확인합니다. 셋(기록부, 원고, SVG) 가운데 하나라도 다르면 그 회차를 끝내지 않아요.

## 7. 점검 명령

원고에 이미지 줄이 들어간 뒤의 정식 판정은 두 스크립트입니다.

```bash
.venv/bin/python scripts/style_check.py vol1-llm/ch04/index.md   # 원고 그림 줄의 캡션 S20, 대체 텍스트 S21, 출처 줄 S22, 어미 S23, 색 이름 S24
.venv/bin/python scripts/check_figures.py vol1-llm/ch04          # 번호, 파일, 캡션과 alt 존재 F04, figures.yml 사본과 글자 단위 대조 F11
```

두 스크립트는 원고 쪽을 봅니다. 기록부 `figures.yml` 자체의 서식, alt 숫자와 정본 행 대조, SVG `<desc>`와 alt 일치는 아래 명령이 맡으므로, 이미지 줄을 넘기기 전(8, 9단계)에 이 명령을 돌려요. 한 항목마다 "통과"나 문제 목록을 한 줄로 찍습니다.

| 묶음 | 검사 항목 |
|---|---|
| 캡션 | 금지 기호 7종, 제목 40자, 읽는 법과 주의 각 70자, 셋의 합 120자 |
| 대체 텍스트 | 2~4문장, 300자, 문장당 100자, 큰따옴표, 캡션 복사 |
| 공통 | 금지어와 색 이름, alt 숫자가 `source.canon` 정본 행에 있는지, SVG `<desc>`가 alt와 같은지 |

```bash
Y=docs/style-board/final/figures.yml   # 실제 작업에서는 docs/figures.yml
.venv/bin/python -c 'import sys,re,yaml,html
B={0x2014,0x2015,0x2013,0xB7,0x318D,0x30FB,0x2022}
D={1:"vol1-llm",2:"vol2-agent",3:"vol3-physical-ai"}
NG=["그림입니다","이 그림은","아래 그림","다음 이미지","본문 참고","파란","빨간","초록","주황","보라","노란","회색"]
for f in yaml.safe_load(open(sys.argv[1],encoding="utf-8")):
    i,c,a=f["id"],f["caption"],f["alt"]; p=[]
    t,r,v=c["title"],c["reading"],c["caveat"] or ""
    for k,s in [("title",t),("reading",r),("caveat",v),("alt",a)]:
        if any(ord(x) in B for x in s): p.append(k+" 금지 기호")
    if len(t)>40: p.append("title %d자"%len(t))
    for k,s in [("reading",r),("caveat",v)]:
        if len(s)>70: p.append("%s %d자"%(k,len(s)))
    if len(t+r+v)>120: p.append("캡션 %d자"%len(t+r+v))
    S=[x for x in re.split(r"(?<=다\.)\s+",a.strip()) if x]
    if not 2<=len(S)<=4: p.append("alt %d문장"%len(S))
    if len(a)>300: p.append("alt %d자"%len(a))
    p+=["alt 문장 %d자"%len(x) for x in S if len(x)>100]
    p+=["금지어 "+w for w in NG if w in a+r+v]
    if f.get("kind")=="C" and len(set(re.findall(r"(?<![\d.])\d+\.\d+",a)))>4: p.append("후보: alt 소수 %d개(C는 결과값 2~4개, 계열 이름 숫자를 빼고 확인)"%len(set(re.findall(r"(?<![\d.])\d+\.\d+",a))))
    if chr(34) in a: p.append("alt 큰따옴표")
    if r in a: p.append("alt가 캡션 복사")
    row=" ".join(l for l in open("docs/design-vol%d-%s.md"%(f["vol"],D[f["vol"]].split("-",1)[1]),encoding="utf-8") for n in f["source"]["canon"] if l.startswith("| %s |"%n))
    if row: p+=["정본에 없는 숫자 "+n for n in re.findall(r"\d[\d,]*(?:\.\d+)?",a) if n.rstrip(",") not in row]
    try:
        d=re.search(r"<desc[^>]*>(.*?)</desc>",open(f["output_file"],encoding="utf-8").read(),re.S)
        if not d or html.unescape(d.group(1)).strip()!=a.strip(): p.append("SVG desc가 alt와 다름")
    except OSError: p.append("output_file 없음")
    print(i,"통과" if not p else p)' "$Y"
```

- 2026-10-14에 시안 기록부에 돌린 결과는 5개 항목 모두 "통과"입니다. 2026-10-15에 C 그림 alt 소수 개수 후보를 더했습니다. 1-5-5가 "후보: alt 소수 10개"(온도 0.5 포함, 결과값 9개)로 나오며, 저자 확인 대상입니다(3.5절 아래 문단). alt를 "이 그림은 파란 상자로 0.58을 보여 줍니다."로 바꾼 시험 항목에서는 1문장, 금지어 2개, 정본에 없는 숫자 0.58, desc 불일치를 모두 잡았습니다.
- 정본 대조는 alt 속 숫자가 설계서 7장 그 정본 행에 문자열로 있는지만 봅니다. "1", "2" 같은 작은 정수는 거의 늘 통과하므로 소수와 큰 수를 잡는 용도로 봐 주세요.
- 문장 나누기는 "다." 뒤 빈칸 기준입니다. 숫자 소수점(0.576)에서는 나뉘지 않습니다.
- 원고와의 글자 단위 대조는 `check_figures.py` F11 몫입니다. 스크립트를 못 쓸 때는 이미지 줄을 원고에서 `grep -F`로 찾아 확인해요.

## 8. 자주 하는 실수

- 소스의 `accDescr`나 `desc`를 먼저 고치고 `figures.yml`을 잊는 것. alt는 기록부에서 확정하고 소스로 복사합니다(3.4절).
- 대체 텍스트에서 정본 값을 반올림하거나 비율로 바꾸는 것("약 58%"). 그림 라벨 문자열 그대로 씁니다.
- 캡션 읽는 법에 메시지 문장을 그대로 붙여 넣는 것. 메시지는 지시선, 읽는 법은 그 결론에 닿는 길입니다.
- 정본으로 그린 그림에 "출처: 1권 설계서"나 정본 ID를 캡션에 적는 것. 근거는 `source.canon`에만 둡니다.
- "인용", "발췌"처럼 "참고하여 재구성"을 다른 말로 바꾸는 것, 확인하지 않은 그림 번호 n을 적는 것.
- 🔄 그림에서 그림만 갱신하고 캡션 기준일과 `refresh.as_of`를 그대로 두는 것.
- alt 안에 큰따옴표를 써서 원고 `alt="..."` 속성을 끊는 것. 인용은 작은따옴표('안')로 씁니다.
- `status`를 렌더링 직후 `reviewed`로 올리는 것. 7장 명령과 시각 검수, 출처 확인을 거친 뒤에 올립니다.
- own 그림의 caveat에 정본 값의 출처 회사나 제품 이름을 적는 것. "한 대표 사례의 공개값"으로 씁니다(2.2절).
- 노드나 단계 이름을 alt에서 다른 말로 풀어 쓰는 것, 라벨에 없는 하위 구성("영상, 관절 상태")을 alt에 덧붙이는 것.
- 차트 alt에 결과값을 계열마다 다 읽어 5개 이상이 되는 것. 3.2절 순서로 2~4개만 고릅니다.
