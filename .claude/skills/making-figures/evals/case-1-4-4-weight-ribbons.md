## 1. 이 사례를 고른 이유

명세는 "띠 폭 = 가중치"입니다(2026-10-15 저자 결정으로 "선 굵기"에서 고침). style-guide 5.5절은 선 굵기를 1, 1.5, 2.5, 4 네 단계로만 허용해서, 가중치를 선 굵기로 그리면 lint에 걸리거나 연속 값이 뭉개져요. 승인 시안은 선 대신 면(띠)을 쓰고 띠 폭을 가중치 × 80으로 잡아, 세 띠가 쿼리 상자 한 변 80을 빈틈없이 나눕니다. 과제 프롬프트는 여전히 "굵기"라고 말해요. 스킬이 이 말을 references(`patterns.md` P8, `choose-type.md` 3.3절)대로 띠 폭으로 그리는지가 첫째 시험입니다.

둘째 시험은 figkit 구조도의 정렬입니다. 세로 정렬선 3줄(48, 384, 520), 같은 크기 키 상자 3개, 칩 열 하나로 끝나는 시안의 밀도를 그대로 내는지 봐요. 러닝 예문을 세 토큰으로 줄였다는 caveat도 함께 확인합니다.

```
그림 1-4-4 그려 줘. 러닝 예문에서 '안'이 다른 토큰을 보는 연결선이고 굵기가 가중치야. 세로 변형이 필요하면 같이 만들어 줘.
```

### 5.3 정본 문자열과 금지 패턴

있어야 할 문자열(1권 N4-2 결과): `0.140`, `0.284`, `0.576`(칩 셋, `data-canon="N4-2"`), 토큰 라벨 `안`, `상자가`, `왔어요`.

| 패턴(정규식) | 이유 |
|---|---|
| `0\.14([^0-9]\|$)`, `0\.28([^0-9]\|$)`, `0\.58([^0-9]\|$)` | 정본 자릿수와 다름 |
| `57\.6`, `28\.4` | 백분율로 바꿈 |
| `N4-2` | 정본 ID 노출 |
| `주문`(주문한 포함), `아직` | 러닝 예문 전체 토큰을 그리면 정본에 없는 가중치를 지어내게 됨 |
| `stroke-width` 값이 1, 1.5, 2.5, 4 밖(예: 2.8, 5.7) | 선 굵기로 가중치를 그린 흔적. figkit lint가 오류로 잡음. 아래 `grep -o` 명령으로 값 종류를 셈 |

### 5.4 자동 판정 변수 줄

```bash
ID=1-4-4; D=vol1-llm/ch04/figures
MUST='안;;상자가;;왔어요;;0.140;;0.284;;0.576' \
BAN='0\.14([^0-9]|$);;0\.28([^0-9]|$);;0\.58([^0-9]|$);;57\.6;;28\.4;;N4-2;;주문;;아직' \
BOX='48,136,136,80;;384,88,120,48;;384,152,120,48;;384,216,120,48;;520,100,56,24;;520,164,56,24;;520,228,56,24' \
BOXV='16,136,72,80;;184,88,88,48;;184,152,88,48;;184,216,88,48;;280,100,56,24;;280,164,56,24;;280,228,56,24' \
TOL=8 KIND=S CANON=N4-2 EPUB=manual REFRESH=null
```

띠 폭은 아래 명령으로 따로 봅니다. 닫힌 띠 `path`의 출발점과 마지막 점을 읽어, 출발 변이 세로(가로 배치)면 y 차이, 가로(세로 배치)면 x 차이를 띠 폭으로 보고 가중치 × 80과 비교해요. 출발 x 값을 고정하지 않으므로 세로 변형(출발 x 88)과 위에서 아래로 흐르는 배치도 잡습니다. 띠를 하나도 못 찾으면 "실패"를 찍습니다.

```bash
for f in "$O/$D/$ID.svg" "$O/$D/$ID.v.svg"; do .venv/bin/python -c 'import re,sys
s=open(sys.argv[1],encoding="utf-8").read(); n=0
for d in re.findall(r"<path[^>]* d=\"(M[^\"]*Z)\"",s):
    p=[tuple(map(float,xy)) for xy in re.findall(r"(-?[\d.]+),(-?[\d.]+)",d)]
    if len(p)<4 or "C" not in d: continue
    (x0,y0),(x1,y1)=p[0],p[-1]
    w=abs(y1-y0) if abs(x1-x0)<0.5 else abs(x1-x0) if abs(y1-y0)<0.5 else None
    if w: n+=1; print(sys.argv[1].rsplit("/",1)[-1],"띠 폭 %.2f -> 가중치 %.3f"%(w,w/80))
print("띠",n,"개" if n else "실패: 띠 path 0개")' "$f"; done
```

시안 두 판에 돌리면 판마다 0.140, 0.284, 0.576이 나옵니다(2026-10-15 확인).

키 라벨 위계(H3, 9장 5번)는 아래 명령으로 봅니다. 토큰 이름(`상자가`, `안`, `왔어요`)과 글자가 같은 `<text>` 가운데 x가 가장 큰 것을 키 라벨로 보고(쿼리 "안"은 왼쪽), 굵기와 글자색을 토큰 값과 비교해요. 굵기가 없으면 400으로 봅니다. 라벨을 못 찾아도 "실패"를 찍습니다.

```bash
for f in "$O/$D/$ID.svg" "$O/$D/$ID.v.svg"; do .venv/bin/python - "$f" <<'EOF'
import re, sys, json, xml.etree.ElementTree as ET
ns = "{http://www.w3.org/2000/svg}"
ink = {k: v["hex"].lower() for k, v in json.load(open("assets/tokens/colors.json", encoding="utf-8"))["neutral"].items()}
want = {"왔어요": ("600", ink["ink-900"]), "상자가": ("400", ink["ink-600"]), "안": ("400", ink["ink-600"])}
st = lambda t, k: (re.search(k + r"\s*:\s*([^;]+)", t.get("style") or "") or [None, None])[1]
got = {}
for t in ET.parse(sys.argv[1]).getroot().iter(ns + "text"):
    name = "".join(t.itertext()).strip()
    if name in want and (name not in got or float(t.get("x", 0)) > float(got[name].get("x", 0))):
        got[name] = t
for name, (w, c) in want.items():
    t = got.get(name)
    if t is None:
        print("실패", sys.argv[1].rsplit("/", 1)[-1], name, "라벨 없음"); continue
    gw = str(t.get("font-weight") or st(t, "font-weight") or "400").strip()
    gc = str(t.get("fill") or st(t, "fill") or "").strip().lower()
    print("통과" if (gw, gc) == (w, c) else "실패", sys.argv[1].rsplit("/", 1)[-1], name, gw, gc, "(기대", w, c + ")")
EOF
done
```

시안 두 판에서는 여섯 줄 모두 통과입니다. 2회차 with_skill(라벨 셋 모두 400, ink-900)은 두 판 모두 세 라벨이 실패합니다(왔어요는 굵기, 나머지는 글자색, 2026-10-15 확인). 선 굵기 종류는 `grep -o 'stroke-width="[^"]*"' "$O/$D/$ID.svg" | sort | uniq -c`로 셉니다. 시안은 1, 1.5, 4 세 가지예요.

## 7. 설계서 확인 메모

1. 명세 문구는 "띠 폭 = 가중치"입니다. 2026-10-15 저자 결정으로 설계서 명세를 "선 굵기"에서 고쳐 시안, style-guide 6.12절과 맞췄어요(2026-10-13 결정 ⑤와 같음).
2. 토큰 분할: 설계서 6.3절은 러닝 예문 그림이 1-2-1의 분할을 따르라고 합니다. 분할은 2026-10-16에 정본 `docs/scenario-hanbit.yml`의 `vol1.token_split`(주문, 한, 상자가, 아직, 안, 왔어요)으로 고정했고, N4-2의 세 토큰 라벨(`상자가`, `안`, `왔어요`)은 이 분할과 글자가 같습니다. 이 사례는 그 세 토큰과 caveat를 기대합니다.
3. 정본 밖 값은 없습니다. 띠 폭 상수 80은 정본 값이 아니라 그리기 비율이라 칩이나 글자로 나오지 않아야 해요.
4. caveat와 4장 원고판(2026-10-17 확인): 4장 원고판 `docs/figures.yml` 1-4-4는 R2 제안 (e)로 caveat를 지우고(null), 세 토큰으로 줄였다는 사실을 원고 4.2절 본문이 맡습니다. 이 사례는 원고 문맥 없이 그림과 캡션만 만드는 과제라 caveat 기대(5.1절, A3)를 그대로 둡니다. 원고 본문이 같은 사실을 이미 말하는 실제 장 작업에서는 caveat를 비워도 되고, 그때는 캡션 정본인 `figures.yml`과 원고 그림 블록을 함께 고칩니다(`caption-alt.md` 6.4절). 입력 원고에 확정 캡션이 들어 있는 문제는 README 실행 방법 4번 주의를 봅니다.
