## 1. 이 사례를 고른 이유

3권 8장은 🔄 비중이 가장 높은 장이고, 3-8-1은 그 장의 첫 구조도입니다. 그림에 들어갈 주기(약 7~9 Hz, 200 Hz)는 정본 N8-1의 "입력과 가정" 칸에 있으면서 🔄 관리표 8.3행의 값이기도 해요. 그래서 두 규칙을 지키는지 시험하기 좋습니다. "칩을 달지 않고 보통 글자로 쓴다"(style-guide 6.5절)와 "회사명과 버전을 그림에 넣지 않는다"(CLAUDE.md 8장)입니다.

구도는 P9 입출력 블록인데, 모듈이 둘이고 모듈마다 입력이 따로 있어 패턴 표의 단일 블록과 다릅니다. 표준 열(x 24, 232, 456)을 지키며 두 줄로 쌓는 판단을 봅니다. 입력 넷과 출력 하나에 개념색을 몇 개 쓰는지(상한 3 + 강조), 로봇 실루엣을 넣지 않는 절제도 함께 봐요.

## 2. 과제 프롬프트

```
3권 8장 그림 3-8-1 이중 시스템 개념도 그려 줘. System 2랑 System 1이 잠재 표현으로 이어지고 각각 입력과 주기가 보이게. 세로 변형은 필요하면.
```

### 5.2 기대 구도 와이어프레임

본문 640 × 320. 열과 상자 크기는 `patterns.md` P9 표를 따른 제안값입니다. 입력 x 24 폭 160, 블록 x 232 폭 176, 출력 x 456 폭 160, 피치 64, 블록 높이 = 입력 묶음 높이입니다. 두 줄 사이 48은 P9 "열 사이 48(화살표와 라벨)"을 세로로 옮긴 값이에요.

```
640 x 320   x 24            184  232              408  456             616
y  24       그림 3-8-1 ------------------------------------- 이중 시스템의 두 모듈
y  56       [이미지 입력 160x48] --> +----------------+
                                    | System 2       |     (x 440~616 빈 곳:
y 120       [언어 지시 160x48]  --> | VLM, 느림       |      지시선 글 자리)
                                    | 약 7~9 Hz      |
y 168                               +-------+--------+
                                            |  잠재 표현 (accent, 라벨 x 328)
y 216                               +-------v--------+
y 224       [고속 센서 입력 160x48]->| System 1       | --> [액션 160x48]
                                    | 작은 정책, 빠름 |
y 280                               | 200 Hz         |
                                    +----------------+
```

| 항목 | 기대 값 | 허용 오차 | 근거 |
|---|---|---|---|
| 캔버스 | 640 × 320 | 0. 480은 블록 안 하위 모듈이 3개 이상일 때만 허용되고 이 그림은 모듈 둘이라 해당 없음. 잠재 표현을 상자 단으로 넣어 480으로 키우면 W1 실패 | P9 캔버스 행, style-guide 5.1절 |
| 입력 열 | x 24, 160 × 48. System 2 입력 둘(y 56, 120, 피치 64), System 1 입력 하나(System 1 상자 가운데 높이) | x, 폭, 높이 ±8. y는 사람 | P9 |
| System 2 | x 232, 176 × 112(입력 묶음 높이와 같게), y 56 | x, 폭 ±8 | P9 "블록 높이 = 입력 묶음" |
| System 1 | x 232, 176 × 64(이름 + 값 두 줄), y 216 | x, 폭 ±8. 높이를 System 2와 같은 112로 맞추면 320 안에 들어가지 않음(216 + 112 > 296) | P9 "모듈 둘 본문", style-guide 5.9절 |
| 잠재 표현 | System 2 아래 변 가운데(x 320)에서 System 1 위 변까지 수직 48, 라벨은 선 오른쪽 8 | 사람 | P9 열 사이 48 |
| 출력 | x 456, 160 × 48, System 1과 같은 행 | ±8 | P9 |
| 빈 곳 | x 440~616, y 56~200은 비움(지시선을 쓰면 글 자리) | 사람 | design-rules 9장 7번 |
| 아래 여백 | 가장 아래 요소 끝에서 캔버스 끝까지 24 이상(제안안은 40) | 자동(lint) | style-guide 5.2절 |
| 세로 정렬선 | 24, 232, 456(+ 라벨 328) | 5개 이하 | design-rules 9장 2번 |

세로 변형 360 × 472(만들 때). `patterns.md` P9 "모듈 둘 세로 변형" 값입니다. 1, 2회차의 156 × 48, x 188은 8의 배수가 아니어서 `figkit.box`가 오류를 냈습니다. 출력을 328로 넓히면 같은 열 입력 상자와 크기가 달라 lint 경고가 났어요. 그래서 2회차 실행이 고른 값(152 × 48, 사이 24, 출력 152)으로 P9와 이 표를 맞췄어요.

```
360 x 472   x 16            168 192            344
y  56       [이미지 입력 152x48] [언어 지시 152x48]
y 136       [System 2  VLM, 느림  약 7~9 Hz  328x64]
                                       |
y 232       [고속 센서 입력 152x48] [## 잠재 표현 152x48 ##]
y 312       [System 1  작은 정책, 빠름  200 Hz  328x64]
y 408       [액션 152x48]
```

| 항목 | 기대 값 | 허용 오차 |
|---|---|---|
| 캔버스 | 360 × 472 | 높이 ±48, 720 이하 |
| 두 칸 행 | x 16과 192, 152 × 48(사이 24) | ±8 |
| 모듈 상자 | x 16, 328 × 64 | ±8 |
| 출력 | x 16, 152 × 48(같은 열 입력 상자와 같은 크기) | ±8 |
| 잠재 표현 | 화살표 라벨 대신 System 1 입력 행의 상자로 둘 수 있음(본문과 표현이 달라도 강조 대상은 같아야 함, Q18) | 사람 |

와이어프레임 확인 기록: 두 판을 2026-10-14에 스크래치패드에서 빈 상자와 화살표로 그렸습니다. `scripts/svg_to_png.mjs`로 렌더링해 PNG를 열어 봤고, 저장소에는 남기지 않았습니다. 본문은 상자 6개와 라벨 하나로 부품 상한 7 안이고 오른쪽 위가 비어 균형이 맞았어요. System 2 상자는 입력 묶음 높이(112)를 맞추느라 아래쪽이 비는데, 주기 글자를 두 번째 줄에 두면 어색하지 않았습니다. 세로 변형은 잠재 표현을 상자로 바꿔야 화살표 라벨이 센서 입력 상자와 부딪치지 않았어요.

### 5.3 정본 문자열과 금지 패턴

정본 N8-1(3권 설계서 7장)의 입력과 가정 칸은 세 값입니다. Helix System 2 약 7~9 Hz와 System 1 200 Hz(figure2025helix), Helix 02 S0 1 kHz(figure2026helix02)예요. 결과 칸은 "System 2 한 번 갱신하는 동안 System 1은 약 22~29번 갱신"입니다.

있어야 할 문자열: `System 2`, `System 1`, `잠재 표현`, `약 7~9 Hz`, `200 Hz`, `VLM`, `액션`. 출력 라벨은 CLAUDE.md 7장 용어 규칙(2026-10-15 저자 결정)대로 "액션"이고, 옛 표기 "행동"은 금지 패턴입니다. 결과 값 `약 22~29번`은 선택이며, 쓰면 칩 1개(`data-canon="N8-1"`)까지 허용합니다.

| 패턴(정규식) | 이유 |
|---|---|
| `[0-9]Hz`, `[0-9]kHz` | SI 단위 앞 공백 누락(CLAUDE.md 9장) |
| `7 ?[-\u2013] ?9`, `7~9 ?Hz` 앞에 `약` 없음(`(^\|[^약] )7~9`) | 범위는 물결표, 정본 표기는 "약 7~9 Hz" |
| `8 ?Hz`, `(^\|[^0-9])9 ?Hz` 단독 | 범위를 한 값으로 줄임(3-8-2의 타임라인용 가정 8 Hz와 혼동) |
| `약 ?200 ?Hz` | 정본 N8-1 표기는 "약" 없는 `200 Hz` |
| `기준일` | 기준일은 캡션에만 씀(그림 안 금지) |
| `1 ?kHz`, `S0` | Helix 02의 S0 계층은 3-8-2(점선)와 8.3절 몫 |
| `Helix`, `Figure`, `GR00T`, `Gemini`, `π0` | 개념도와 그 캡션, alt에 회사, 모델명을 넣음. 이름은 본문과 3-8-4, 3-8-5 몫 |
| `관절`, `로봇 상태`, `손목` | 설계서가 "고속 센서 입력"으로만 적은 입력을 구체 센서로 바꿔 씀(7장 메모 3) |
| `7B`, `80M`, `10M` | 🔄 관리표의 모델 크기. 명세에 없음 |
| `N8-1` | 정본 ID 노출 |
| `22\.2`, `28\.6` | 결과를 "약 22~29번" 대신 계산 중간값으로 씀 |
| `행동(?! ?복제)` | 모델 출력 단위의 옛 표기. 출력 라벨, alt, 캡션 모두 "액션"(CLAUDE.md 7장). "행동 복제"는 다른 용어라 뺌 |

### 5.4 자동 판정 변수 줄

```bash
ID=3-8-1; D=vol3-physical-ai/ch08/figures
MUST='System 2;;System 1;;잠재 표현;;약 7~9 Hz;;200 Hz;;VLM;;액션' \
BAN='[0-9]Hz;;[0-9]kHz;;7 ?[-\u2013] ?9;;(^|[^약] )7~9;;(^|[^0-9~])[89] ?Hz;;1 ?kHz;;S0;;Helix;;Figure;;GR00T;;Gemini;;π0;;7B;;80M;;10M;;N8-1;;22\.2;;28\.6;;약 ?200 ?Hz;;기준일;;관절;;로봇 상태;;손목;;행동(?! ?복제)' \
CHIPBAN='Hz' \
BOX='24,*,160,48;;24,*,160,48;;24,*,160,48;;232,*,176,*;;232,*,176,*;;456,*,160,48' \
TOL=8 KIND=S CANON=N8-1 EPUB='manual|none' REFRESH=2026-10 VW=360 BH=320
```

`BH=320`은 W1(본문 320만)을 봅니다. P9는 하위 모듈 3개 이상일 때만 480을 허용합니다. `BOXV`는 비워 둡니다. 세로 변형은 구도 선택지가 넓어 W3을 사람 판정으로 봐요. `VW=360`은 W1 문구(세로 변형 폭 360)와 같은 값이고, 자동 블록도 이제 360만 통과로 봅니다. 이 그림에는 328에 안 들어가는 정본 숫자 묶음이 없어 400 예외(`svg-guide.md` 10장)에 해당하지 않아요. `관절`, `로봇 상태`, `손목`은 설계서에 없는 센서 구성을 라벨이나 alt에 붙인 경우를 잡습니다(7장 메모 3). `MUST`는 공백을 지우고 대조하므로 줄바꿈 없는 공백(U+00A0)을 쓴 "7~9 Hz"도 통과합니다.

## 7. 설계서 확인 메모

1. 주기 값은 설계서에 있습니다. 7장 N8-1 "입력과 가정" 칸(System 2 약 7~9 Hz, System 1 200 Hz)과 10장 🔄 관리표 8.3 Figure Helix 행이 같은 값입니다. 2026-10-15 저자 결정으로 정본 N8-1 표기("약 7~9 Hz", "200 Hz")가 정본이 되었고, 5장 8.2절 행과 그림 명세도 이 문자열로 맞췄습니다. 그래서 `약 200 Hz`는 C2 금지 패턴입니다.
2. 🔄 여부: 두 주기가 🔄 관리표 값이라 3-8-1은 🔄 그림입니다(2026-10-15 저자 결정, 그림 명세 3-8-1 행에 반영). `refresh`를 채우고 캡션에 기준일을 붙여야 하며, `refresh: null`은 Y1 실패입니다. caveat("제품마다 다르다")도 함께 둡니다.
3. 입력의 구체 구성: 설계서는 System 2 입력을 "장면과 지시", System 1 입력을 "고속 센서 입력"으로만 적었습니다. 센서가 로봇 상태인지 손목 카메라인지는 정해져 있지 않습니다. 그래서 라벨은 "고속 센서 입력"이고, 로봇 상태 개념색(회녹색) 대신 회색(ink) 상자로 둡니다(2026-10-15 저자 결정, 그림 명세 3-8-1 행).
4. 개념색 상한: 입력(이미지, 텍스트, 센서)과 출력(액션)에 모두 개념색을 쓰면 4개로 상한 3을 넘습니다. 센서 입력을 개념색 없는 회색 상자로 두어 개념색을 3개 이하로 맞춥니다(2026-10-15 저자 결정).
5. 출처: 정본으로 그린 그림이라 `source.kind: own`, 출처 줄 없음이 기본입니다. 장 `references.yml`이 비어 있어 `figure2025helix` 키를 캡션에 쓸 수 없어요(`caption-alt.md` 4.3절). 출처 줄이 필요하다고 보면 researcher 몫으로 보고하는 것이 기대 동작입니다.
6. 범위 밖 관찰: 3-8-2의 "System 2 갱신 8번"은 N8-1에 "타임라인 그림용 가정: System 2 8 Hz"로 추가되었습니다(2026-10-15 저자 결정). 3-8-2에서만 "가정 8 Hz"로 쓰고, 3-8-1에는 8 Hz가 나오지 않아야 합니다(C2).
7. 와이어프레임은 이 문서가 처음 정한 제안 치수입니다. 시험 결과가 P9 열을 지키면서 다른 행 배치를 고르면 W2(자동)는 통과하고, 구도의 좋고 나쁨은 H3에서 판정합니다.
8. 용어: 2026-10-15 저자 결정으로 모델 출력 단위는 "액션"입니다(CLAUDE.md 7장, 설계서 그림 명세 3-8-1 행도 "→ 액션"). 2회차까지의 산출물은 "행동"을 썼으므로 3회차부터 C1(`MUST`의 액션)과 C2(`BAN`의 행동)가 이를 가릅니다.
