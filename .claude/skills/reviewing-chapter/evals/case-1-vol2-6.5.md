# 평가 사례 1: 2권 6.5절 reviewer 검수와 확인 검수

`evals.json`의 `id: 1`(R1 전면 검수)과 `id: 2`(R2 확인 검수)에 대응하는 사례입니다. 실행 방법은 같은 폴더의 `README.md`에 있어요.

## 목차

1. 이 사례를 고른 이유
2. 과제 프롬프트
3. 입력 파일
4. R1 정답표
5. R2 정답표
6. 오탐으로 판정할 예
7. 설계서 확인 메모

---

## 1. 이 사례를 고른 이유

2권 6.5절은 writing-chapter 평가 사례 2와 같은 절이라, 두 스킬의 시험 결과를 이어 볼 수 있습니다. 정본 계산(N6-1, N6-2), 앞 권 가상 단가 인용, 뒤 장 용어, 그림 두 개가 한 절에 모여 있어 F, C, U, G, S 축이 모두 걸려요. 결함은 "고치면 끝나는" 수준으로만 심었기 때문에 기대 판정은 수정 후 통과이고, 고친 판(R2)으로 확인 검수와 통과까지 한 번에 봅니다.

## 2. 과제 프롬프트


R2(`id: 2`)
```
6.5절 확인 검수 부탁해. 고친 원고는 fixtures/case1-r2-vol2-6.5.md이고, 직전 보고서는 id 1의 출력, writer 반영 기록은 아래와 같아.
(5.1절의 반영 기록 표를 그대로 붙임)
```

## 4. R1 정답표

심은 결함 5개입니다. ID 번호는 검수자가 매기므로 축과 심각도, 범위로 대조합니다.

| 정답 | 위치 | 축 | 심각도 | 범위 | 근거 | 허용 범위 |
|---|---|---|---|---|---|---|
| K1 | 문단 3(📌 박스 뒤) "약 0.63, 곧 63%" | F | 치명 | 문장 | N6-1: p=0.95, 10단계 0.599. 설계서 ❗2 "약 60%" | 같은 문장의 "네 건 가까이"를 함께 지적해도 됨 |
| K2 | 문단 6 "입력 100만 토큰당 3달러 …로 계산하면(1권 2장)" | F 또는 C | 중대 | 문장 | CLAUDE.md 8장 가정 표지, 1권 N2-3 "가상 단가" | 축은 F, C 어느 쪽이어도 통과. 두 축에 두 번 세면 실패 |
| K3 | 문단 7 "HITL로 넘깁니다" | U | 중대 | 문장 또는 문단 | 2권 12장 신규 용어(사람의 승인 지점), 6장에서 정의 없이 씀. reader-profile 6.1절 유형 2 | 뒤 장 개념 예고 위반(B9)으로 C 축에 둬도 통과 |
| K4 | 그림 2-6-7 이미지 줄 | G | 중대 | 문장 | alt 속성 없음. CLAUDE.md 10장, box-markup 5장 | |
| K5 | 문단 6 "더 높은 비용을 가지고 있습니다" | S | 경미 | 문장 | reader-profile 6.1절 유형 5 직역투 | 중대로 올리면 실패 |

기대 판정

| 축 | 등급 |
|---|---|
| F | 수정 후 통과 |
| C | 수정 후 통과 또는 통과(K2, K3을 다른 축에 두었으면 통과) |
| U | 수정 후 통과(K3을 C에 두었으면 통과) |
| S | 통과 |
| L | 해당 없음 |
| G | 수정 후 통과 |
| 장 판정 | **수정 후 통과**. 치명 1, 중대 3, 경미 1 안팎. 재작성 조건 W1~W5 없음 |

그 밖에 보고서에 있어야 할 것
- 머리의 독립성 줄, 자동 검사 재실행 표, "reader 결과 없음" 표시
- 2권 완료 기준 행(사다리 위치, 시나리오 정본, 1권 참조, 제품 이름, 보안 수위, 1권 숫자)이 C 표에 있고, 절 검수라 해당 없는 행(10요소, 분량 등)은 "해당 없음"
- 출처 키(shinn2023reflexion)는 references.yml 상태에 따라 "보고"로 남김

## 5. R2 정답표

### 5.1 writer 반영 기록 (프롬프트에 붙이는 표)

```markdown
## 검수 반영 기록: R1 → R2

| ID | 심각도 | 조치 | 위치 | 한 줄 설명 |
|---|---|---|---|---|
| (K1의 ID) | 치명 | 반영 | 6.5 문단 3 | 0.599, 약 60%로. "네 건이 실패"로 |
| (K2의 ID) | 중대 | 반영 | 6.5 문단 6 | "1권에서 쓴 가상 단가"를 숫자 앞에 |
| (K3의 ID) | 중대 | 반영 | 6.5 문단 7 | "사람 담당자"로 바꾸고 12장 예고 |
| (K4의 ID) | 중대 | 반영 | 그림 2-6-7 줄 | 대체 텍스트 3문장 |
| (K5의 ID) | 경미 | 반영 | 6.5 문단 6 | "에이전트 쪽이 약 7배 비쌉니다" |
```

실행할 때는 괄호 안을 id 1 출력의 실제 ID로 바꿔 넣습니다.

### 5.2 기대 결과

| 항목 | 기대 |
|---|---|
| 직전 지적 상태 | K1~K5 모두 "닫힘" |
| 새 지적 | 문단 7 "이 넘김 규칙을 통해 비용의 상한이 정해집니다"가 직역투 경미로 R2- ID를 받음(새로 생긴 문장). 놓쳐도 판정에는 영향 없음 |
| 확인 범위 | 고친 문단과 앞뒤 한 문단만 다시 보고, 전면 검수를 하지 않음 |
| 장 판정 | **통과**. 치명 0, 중대 0 |

## 6. 오탐으로 판정할 예

아래를 치명이나 중대로 지적하면 그 판정 항목은 실패입니다.

| 원고 | 왜 맞나 |
|---|---|
| 📌 박스의 0.774, 0.358 | N6-1 정본 그대로 |
| 표의 3,000, 4,000, 5,000, 12,000, 75,000 | N6-2 조건에서 바로 나오는 값(설계서가 표로 쓰라고 함) |
| 0.225, 0.03, 0.255, 0.036, 약 7배 | N6-2 정본 |
| "이 값은 프롬프트 캐싱을 적용하지 않은 경우입니다" | 2권 7장 표 아래 주석 그대로 |
| 독립 가정의 한계 문단 | 설계서 E6-1 아래 문단 요구 |
| 그림 2-6-6 줄 | 캡션, alt, 번호 모두 서식대로 |
| 고정 비유 없음 | 난도 지도 `analogy: "없음"`. 비유가 없다는 이유로 지적하면 실패 |

## 7. 설계서 확인 메모

- K2는 2권에서 1권 가상 단가를 인용할 때 "가상 단가"와 "(1권 2장)"이 둘 다 필요하다는 해석입니다. 2권 7장 머리글도 "1권 N2-3의 가상 단가를 그대로" 쓴다고 했어요.
- K3의 HITL은 2권 설계서 12장 신규 용어입니다. 6장 🧭의 "실패 시 사람에게 넘기는 조건"은 일반어라 지적 대상이 아닙니다.
