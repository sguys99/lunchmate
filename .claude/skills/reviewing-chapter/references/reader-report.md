# reader 보고서 서식 (reader-report)

reader가 P1, P2, P3 페르소나로 원고를 읽고 쓰는 보고서입니다. 점검 항목과 표시 형식의 정본은 `docs/reader-profile.md` 9.3절이고, 이 문서는 그 형식에 보고서 틀과 읽는 순서를 더한 것이에요. 9.3절과 이 문서가 다르면 9.3절을 따르고 이 문서를 고칩니다.

## 목차

1. reader가 들고 읽는 것과 들지 않는 것
2. 읽는 순서
3. 지적 한 건의 형식
4. 보고서 뼈대
5. 채운 보기 (발췌)
6. 자주 하는 실수

---

## 1. reader가 들고 읽는 것과 들지 않는 것

reader의 가치는 "독자가 가진 것만 들고 읽는다"는 데 있습니다. 설계서나 정본을 보고 읽으면 빠진 전제가 저절로 채워져 막힘을 놓쳐요.

| 들고 읽음 | 들지 않음 |
|---|---|
| 그 페르소나의 프로필, 이미 아는 것, 모르는 것, 읽기를 멈추게 하는 것(`reader-profile.md` 2~4장) | 설계서의 장 설계, 정본 표, 비유 고정표 |
| 용어 단계표(5.2~5.5절)와 막히는 지점 목록(6장) | `references.yml`과 출처 원문 |
| 질문 틀(8.2절)과 난도 지도(`difficulty-map.yml`) | writer의 `notes.md`, `eli5.md`, 자가 점검 보고 |
| 그 페르소나의 읽기 경로에 있는 앞 장 원고 | 읽기 경로 밖 앞 장 원고(P3는 1권 2, 4, 9장과 3권 0장만) |
| `glossary.yml`: 어느 장에서 정의됐는지 찾는 데만 | glossary의 정의 문장으로 원고의 빈 정의를 메우기 |

## 2. 읽는 순서

1. 난도 지도에서 이 장의 개념과 절을 찾습니다. 지도에 오른 절이 우선이에요.
2. 지도 개념의 `personas` 첫 페르소나로 그 절을 먼저 읽고, 이어서 장 처음부터 끝까지 읽습니다.
3. 나머지 두 페르소나로 장 전체를 한 번씩 더 읽습니다. 페르소나마다 새로 읽고, 앞 페르소나의 표시를 보지 않아요.
4. 절마다 9.3절 점검표 12항목을 던집니다. 문단 하나에서 여러 항목이 걸리면 지적을 나눕니다.
5. 8.2절 질문 틀로 절마다 그 페르소나가 물을 질문 1~2개를 만들고, 본문이 답했는지 봅니다. 답하지 않았으면 "질문" 유형 의문으로 적습니다.
6. 집계하고 `verdict-rules.md` 4장으로 읽기 판정을 냅니다.

그림은 원고에 보이는 캡션과 대체 텍스트, 그리고 그림 PNG가 있으면 그것만 봅니다. 캡션 없이 그림만 보고 무엇을 말하는지 알 수 있는지가 독자 쪽 그림 점검이에요.

## 3. 지적 한 건의 형식

`reader-profile.md` 9.3절 표시 형식 그대로입니다. 9.3절이 ID 머리와 "같이 걸림" 표기를 함께 정해 둡니다.

```
R1-P1-04 [P1-용어-막힘] 6.5, 문단 7  (같이 걸림: P3)
인용: "실패하면 HITL로 넘깁니다"
이유: HITL이 무엇의 약자인지, 무엇을 넘기는지 앞에서 나오지 않음
제안: 처음 나올 때 풀어 쓰거나, 뒤 장 개념이면 예고로 돌리는 방향
```

| 칸 | 값 |
|---|---|
| ID | `R{회차}-{페르소나}-{번호}`. 페르소나마다 01부터(`verdict-rules.md` 1장) |
| 유형 | 용어, 다의어, 참조, 수식, 약어, 전제, 밀도, 직역, 비유, 질문, 길이 |
| 심각도 | 막힘(읽기를 멈춤), 걸림(다시 읽어야 이해함), 의문(이해했지만 질문이 남음) |
| 같이 걸림 | 같은 문장에서 다른 페르소나도 걸렸으면 적고, 지적은 하나로 둡니다 |
| 제안 | 고치는 방향 한 문장. 대체 문장은 쓰지 않아요 |

사실 판정을 하지 않는 방법: 숫자나 설명이 앞뒤로 맞지 않아 보이면 "틀렸다"가 아니라 "앞 문장의 0.2와 이 문장의 0.28이 같은 값인지 헷갈림"처럼 헷갈린 이유만 적고 "의문"으로 둡니다. 맞는지 틀린지는 reviewer가 F 축에서 정해요.

## 4. 보고서 뼈대

저장 위치는 `vol*/chNN/review/reader-r{N}.md`이고, 절 검수는 `reader-r{N}-s7.3.md`처럼 절 번호를 붙입니다(SKILL.md 9장).

```markdown
# reader 보고서: {권}권 {장}장 ({장 전체 | N.N절}) R{N}

- 대상: vol?-*/chNN/index.md / 범위 / 회차
- 검수자: reader / 검수일: YYYY-MM-DD
- 독립성: 집필, 그림, 자가 점검 참여 없음
- 읽은 순서: {지도 개념} 절을 {첫 페르소나}로 먼저, 이어서 P?, P?, P?
- 읽기 경로: P1 {읽은 앞 장}, P2 {…}, P3 {…} (`reader-profile.md` 1.1절. 요청 문구가 다른 경로를 주었으면 "요청과 다른 점: …" 한 줄)
- 확인 검수면: 직전 최상 절 막힘 ID마다 다시 읽은 페르소나와 닫힘 여부(1장 표의 "최상 절 막힘" 칸과 같은 내용)

## 1. 읽기 판정

| 항목 | 값 |
|---|---|
| 읽기 판정 | 통과 / 수정 후 통과 / 재작성 |
| 근거 | verdict-rules 4장 조건 (예: 최상 절 7.3 기준 독자 막힘 2) |
| 최상 절 막힘 | 절마다 개수. 0이 아니면 장 완료 전에 닫혀야 함(verdict-rules 3.6절 M1) |
```

## 5. 채운 보기 (발췌)

3권 7장 7.3절 시험 원고를 가정한 발췌입니다. Flow Matching은 난도 지도 최상 개념이고 `personas: [P1, P2, P3]`이라 P1로 먼저 읽었어요.

```markdown
## 1. 읽기 판정

| 항목 | 값 |
|---|---|
| 읽기 판정 | 수정 후 통과 |
| 근거 | 최상 절 7.3에 막힘 2(재작성 문턱 3 미만), 세 페르소나 공통 막힘 문장 0 |

## 2. 페르소나별 집계

| 페르소나 | 막힘 | 걸림 | 의문 | 가장 많이 걸린 유형 |
|---|---|---|---|---|
| P1 | 2 | 1 | 1 | 수식 |
| P2 | 0 | 1 | 0 | 직역 |
| P3 | 2 | 0 | 0 | 용어 |
| 합계(중복 제거) | 2 | 2 | 1 | |

## 4. 지적

### P1
R1-P1-01 [P1-용어-막힘] 7.3, 문단 3  (같이 걸림: P3)
인용: "모델은 각 지점의 속도장을 예측합니다"
이유: 속도장이 무엇인지 나오지 않아 '무엇을 예측하는지'를 놓침
제안: 숫자 하나짜리 예(지금 위치에서 어느 쪽으로 얼마나)로 먼저 보여 주는 방향

R1-P1-02 [P1-수식-막힘] 7.3, 문단 6  (같이 걸림: P3)
인용: "x(t+Δt) = x(t) + Δt × v(x, t)"
이유: 수식 앞에 말로 된 설명이 없고 뒤에 숫자도 없음
제안: 수식 앞에 한 문장 풀이, 뒤에 첫 두 걸음 숫자를 두는 방향

R1-P1-03 [P1-질문-의문] 7.3, 문단 8
인용: "10단계 뒤 0.28에 도착합니다"
이유: 앞 문단의 정답 위치와 이 숫자가 같은 값인지 헷갈림
제안: 도착값과 정답값의 관계를 한 문장으로 밝히는 방향
```

R1-P1-03은 reader가 "틀렸다"고 판정하지 않은 보기입니다. 실제로 값이 정본과 다른지는 reviewer가 F 축에서 정합니다.

## 6. 자주 하는 실수

- 설계서나 정본을 열어 보고 읽는 것. 막힘이 사라지는 게 아니라 안 보이게 됩니다.
- 세 페르소나를 한 번에 읽고 표시만 셋으로 나누는 것. P2가 아는 말을 P1도 아는 것처럼 읽게 됩니다.
- 대체 문장을 써 주는 것. reader의 제안은 방향 한 문장입니다(9.3절).
- "어렵다", "길다" 같은 느낌만 적는 것. 유형, 인용, 이유가 있어야 writer가 고칠 수 있습니다.
- 앞 장에서 정의된 말을 막힘으로 적는 것. 그 페르소나의 읽기 경로에 그 장이 있으면 참조 표시가 있는지만 봅니다. 참조 표시도 없으면 "참조" 유형입니다.
- 사실이 틀린 것 같다고 "치명"이나 "오류"라고 쓰는 것. reader에게는 그 낱말이 없습니다.
