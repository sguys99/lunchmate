# 심각도, 지적 ID, 판정 규칙 (verdict-rules)

reviewer와 reader 보고서가 같은 말로 지적하고 같은 규칙으로 판정하게 하는 기준입니다. 지적 하나하나가 writer의 작업 단위가 되므로, 심각도와 수정 범위를 먼저 정하고 판정은 그 개수와 범위로 기계적으로 냅니다. 판정에 감을 섞지 않으려는 것이에요.

## 목차

1. 지적 ID
2. 심각도와 수정 범위
3. reviewer 판정 규칙
4. reader 읽기 판정
5. reviewer와 reader 결과 합치기
6. 회차와 확인 검수
7. writer 반영 기록 서식
8. 문턱값의 지위

---

## 1. 지적 ID

```
R{회차}-{축}{두 자리 번호}        reviewer   예: R1-F03, R2-G01
R{회차}-{페르소나}-{두 자리 번호}  reader     예: R1-P1-04, R1-P3-11
```

| 자리 | 값 |
|---|---|
| 회차 | 1부터. 확인 검수마다 1씩 늘립니다 |
| 축 | C 완료 기준, F 기술 사실 정확성, U PM 독자 이해도, S 금지 기호 외 문체, L 서술 수위, G 그림 |
| 페르소나 | P1, P2, P3. 여러 페르소나가 같은 문장에 걸리면 처음 표시한 페르소나의 ID 하나로 쓰고 "페르소나" 칸에 모두 적습니다 |
| 번호 | 축(또는 페르소나)마다 01부터 |

규칙
- ID는 다시 쓰지 않습니다. 2회차에서 1회차 지적을 다시 말할 때는 원래 ID(R1-F03)를 그대로 쓰고, 새로 나온 지적만 R2-를 붙여요.
- reviewer가 reader 지적을 채택하면 새 U ID를 만들지 않고 reader ID를 U 축 표에 그대로 올립니다. writer가 찾아갈 ID가 하나여야 하기 때문입니다.
- 위치는 `절 번호, 문단 번호`로 적습니다. 문단은 절 제목 아래 본문 문단만 1부터 세고, 주석, 박스, 표, 그림 줄은 세지 않아요. 박스는 `4.2 📌 박스 2`, 표는 `6.5 표 1`, 그림은 `그림 1-4-3`처럼 따로 가리킵니다. 수식만 있는 줄은 한 문단으로 셉니다.

## 2. 심각도와 수정 범위

### 2.1 심각도 3단계

| 심각도 | 뜻 | 판별 질문 | 예 |
|---|---|---|---|
| 치명 | 독자가 틀린 것을 배우거나, 책에 실리면 해가 되는 문제 | 이대로 출간되면 정정 공지나 회수가 필요한가? | 정본과 다른 계산 결과, 시나리오 정본과 다른 값, 개념을 거꾸로 설명한 문장, 설계서 ❗와 정반대 주장, 존재를 확인 못 한 출처를 확정처럼 인용, 따라 할 수 있는 우회 절차, 지어낸 저자 경험 |
| 중대 | 완료 기준을 못 채우지만 국소 수정으로 고칠 수 있는 문제 | 완료 기준 체크리스트의 한 줄이 "아니요"가 되는가? | 정의 없는 C 단계 용어, "가정", "가상 단가" 표지 누락, 출처 키 누락, 🔄 기준일 누락, 대체 텍스트 누락, 앞 권 참조 표시 누락, 고유명사 허용 위치 위반, 대응 순서 위반, 계산은 맞지만 정본에 없는 숫자, reader 막힘(채택분) |
| 경미 | 기준은 채웠지만 더 좋아질 수 있는 문제 | 고치지 않아도 완료 기준은 모두 "예"인가? | 직역투 한 곳, 해요체 자리가 어색함, 리듬, 더 나은 예시 제안, reader 걸림과 의문(채택분) |

심각도와 따로 붙이는 꼬리표가 둘 있습니다. 둘 다 판정 개수에 넣지 않아요.

| 꼬리표 | 뜻 | 예 |
|---|---|---|
| 보고 | writer가 혼자 해소할 수 없어 넘기는 상태 기록 | unverified 출처 키, 그림 파일 미제작, `[출처 필요]` 잔존 수, 현장 노트 저자 답 대기 |
| 저자 확인 | 판정 기준이 없거나 사람만 정할 수 있음 | 로봇 닮음(Q24), 설계서끼리 충돌, 정본 값 자체의 의심, 문턱값 경계의 판단 |

### 2.2 수정 범위 3단계

| 범위 | 뜻 | 예 |
|---|---|---|
| 문장 | 한 문장 안에서 값, 낱말, 표지를 바꾸면 끝남 | 0.63을 정본 0.599로, "가상 단가" 추가 |
| 문단 | 한 문단을 다시 쓰거나 문단을 더해야 함 | 정의 없는 용어에 정의 문단 추가, 수위를 넘은 문단 걷어 내기 |
| 절 | 절의 흐름, 순서, 중심 설명을 다시 짜야 함 | 서사 단계 순서가 뒤바뀜, 절 전체가 따라 하기 절차로 짜임, 핵심 설명이 틀린 개념 위에 서 있음, 설계서 절 목차와 다른 내용 |

범위가 "절"인 지적은 심각도와 상관없이 재작성 조건이 됩니다(3.2절). 문장 단위 고침을 여러 번 해도 절의 뼈대가 틀리면 같은 문제가 되돌아오기 때문이에요.

### 2.3 경계에서 고르는 법

- 숫자가 틀렸으면 치명, 맞지만 정본에 없으면 중대입니다(CLAUDE.md 8장). 정본에 추가할 값인지는 "보고"로 따로 적습니다.
- 논문 설정값은 이렇게 가릅니다. 출처 claim(`value`, `what`)에 적힌 설정값과 claim이 적은 관계(원 논문의 512칸, 헤드 8개, "512 = 8 × 64")는 정본 밖 숫자가 아니라 출처 사실이라 지적하지 않고, `[@key]`와 그 자리 claim만 봅니다. 그 값으로 claim에 없는 새 계산(√64 = 8, 2,048 ÷ 512 = 네 배)을 만들었으면 "계산은 맞지만 정본에 없는 숫자"로 중대입니다(1권 4장 R1-F08은 기준이 없어 경미로 적었음).
- 인용 키가 있어도 그 자리 claim이 숫자나 주장을 받치지 않으면 출처 누락과 같게 봅니다. 숫자가 출처와 다르거나 주장이 claim보다 세면("층 수만 다르다") 치명입니다(1권 4장 R1-F01).
- 정의 없는 말은 C 단계면 중대, B 단계면 경미입니다(`reader-profile.md` 5.3, 5.4절).
- 성능 주장(3권 14.4절)의 조건 누락은 중대, 조건을 바꿔 써서 성능을 부풀렸으면 치명이에요.
- 서술 수위는 "그대로 따라 할 수 있는가"로 가릅니다. 따라 할 수 있으면 치명, 원리 수준인데 대응 순서만 틀렸으면 중대입니다.
- 두 등급 사이에서 망설이면 낮은 쪽으로 적고 "판단 근거"를 씁니다. 근거 없는 의심은 심각도 대신 "확인 요청"(F 축)으로 남깁니다.

### 2.4 두 축에 걸치는 지적

한 문제는 지적 하나, ID 하나로 적고 **주 축 한 곳에서만** 셉니다. 다른 축 표에는 ID 칸을 "→ R1-F01 참조"로 시작하는 참조 행만 두고 개수에 넣지 않아요. 화살표로 시작해야 ID 중복 검사에 걸리지 않습니다. 같은 문제를 두 번 세면 W2, W3 개수가 부풀어 맞는 원고가 재작성으로 갈 수 있기 때문입니다.

주 축은 "고치려면 무엇을 바꿔야 하는가"로 고르고, 둘 이상 맞으면 표의 위쪽을 고릅니다.

| 순서 | 주 축 | 이럴 때 | 예 |
|---|---|---|---|
| 1 | L | 따라 할 수 있는 절차, 대응 순서처럼 수위가 문제 | 공격 절차 단계가 숫자 목록으로 있음 |
| 2 | F | 값, 개념, 출처, 표지처럼 사실과 정본이 문제 | 정본과 다른 값, "가상 단가" 표지 누락 |
| 3 | G | 그림 파일이나 원고의 그림 줄이 문제 | 대체 텍스트 누락, 캡션과 그림 숫자 불일치 |
| 4 | U | 정의, 참조, 전제처럼 독자가 읽다 멈추는 것이 문제 | 뒤 장 용어를 정의 없이 씀 |
| 5 | S | 자동 검사 밖 문체 | 직역투 |
| 6 | C | 위 어느 축에도 맞지 않는 완료 기준 미충족 | 장 도입 질문에 답이 없음, 분량 |

- C 축 표의 완료 기준 행은 주 축 지적 ID를 "미충족 R1-F01"처럼 가리킵니다(`reviewer-report.md` 2장).
- 주 축을 다르게 골랐더라도 한 번만 셌다면 판정은 같습니다. 평가 사례가 축을 둘 중 하나로 허용하는 이유예요.
- reader 지적과 reviewer 지적이 같은 원인이면 5장 "병합"으로 대표 ID 하나만 셉니다.

## 3. reviewer 판정 규칙

### 3.1 축별 등급

축마다 그 축의 지적만 세어 아래 3.2~3.4절을 같은 순서로 적용합니다. 해당 문단이 없는 축(예: 서술 수위)은 "해당 없음"이에요. U 축은 5장 규칙으로 reader 지적을 넣은 뒤에 셉니다.

### 3.2 재작성 (하나라도 맞으면)

| 번호 | 조건 | 비고 |
|---|---|---|
| W1 | 범위 "절" 지적이 1개 이상 | 심각도 무관 |
| W2 | 치명이 장 전체 5개 이상(절 검수면 3개 이상) | 축을 합쳐 셈 |
| W3 | 한 절에 치명과 중대가 합쳐 8개 이상 | 밀도 기준. 절 검수도 같음 |
| W4 | 장 도입 질문 3개 가운데 본문이 답하지 않는 질문이 2개 이상 | C 축 |
| W5 | reader 읽기 판정이 "재작성"이고 reviewer가 그 근거 지적을 기각하지 않음 | 4장, 5장 |

### 3.3 수정 후 통과

재작성 조건에 걸리지 않고, 치명이나 중대가 1개 이상이거나 3.6절 M1이 남아 있으면 수정 후 통과입니다. 치명이 있어도 문장, 문단 범위로 고칠 수 있으면 여기에 듭니다.

### 3.4 통과

치명 0, 중대 0이고 3.6절 완료 조건을 채우면 통과입니다. 경미는 개수와 상관없이 판정에 넣지 않고 목록으로 넘겨요. "보고"와 "저자 확인"도 판정에 넣지 않지만, 장 완료(저자 승인) 전에는 모두 닫혀야 합니다.

### 3.5 장 판정

장 판정은 축별 등급 가운데 가장 나쁜 것입니다(재작성 > 수정 후 통과 > 통과). W2, W3처럼 축을 합쳐 세는 조건은 장 판정에서 한 번 더 봅니다. 보고서에는 장 판정과 함께 그 등급을 만든 조건 번호(예: "수정 후 통과: F 치명 1, C 중대 2", "수정 후 통과: M1 7.3 막힘 1")를 적어요.

### 3.6 완료 조건 M1: 최상 개념 절 막힘 0

난도 지도에서 "최상" 개념이 있는 절에 reader 막힘이 하나라도 남아 있으면, 다른 축이 모두 통과여도 장 판정은 통과가 될 수 없고 **최소 수정 후 통과**입니다(`reader-profile.md` 10.1절, 저자 확정). 막힘이 3개 이상이면 4장 (a)를 거쳐 W5로 재작성이에요.

| 상태 | M1에서 |
|---|---|
| 채택, 병합 | 남아 있음. 확인 검수에서 "닫힘"이 될 때까지 통과 불가 |
| 기각 | 원고의 정의나 참조 위치를 "4.1절 문단 2"처럼 댈 수 있을 때만 닫힌 것으로 봅니다. 이유가 "읽기 경로 밖"이면 기각할 수 없고 채택합니다 |
| 하향 | 최상 절 막힘은 경미로 낮추지 않습니다 |

- 최상 절 막힘을 확인 검수에서 닫을 때는 reader가 같은 페르소나로 그 문단과 앞뒤 한 문단을 다시 읽어 막힘이 없다고 적어야 합니다. reviewer 혼자 "닫힘"으로 바꾸지 않아요.
- reader 보고서가 없으면 M1을 판정할 수 없으므로, 장 판정이 통과여도 "M1 미확인"을 적고 사이클 ⑥을 닫지 않습니다(5장 마지막 원칙과 같음).
- 같은 회차 reader 보고서를 reviewer가 받지 못했으면(동시 실행) "M1 미확인"으로 내고, 메인 에이전트가 reader 보고서의 닫힘 기록을 보고 M1을 닫습니다. 절차는 `SKILL.md` 4장이에요. 확인 검수는 reader를 먼저 끝내는 순서가 기본입니다.

## 4. reader 읽기 판정

reader는 사실을 판정하지 않으므로 등급은 "읽을 수 있는가"만 말합니다. 셀 때는 문장 하나에 여러 페르소나가 걸려도 지적 하나로 셉니다.

| 등급 | 조건 |
|---|---|
| 재작성 | (a) 난도 지도 "최상" 개념이 있는 절에서 그 개념의 기준 독자 막힘이 3개 이상, 또는 (b) 한 절에서 세 페르소나가 모두 막힌 문장이 2개 이상, 또는 (c) 장 전체 막힘이 15개 이상 |
| 수정 후 통과 | 재작성 조건 미만이고 막힘이 1개 이상(최상 개념 절의 막힘 1~2개 포함) |
| 통과 | 막힘 0. 걸림과 의문은 개수와 상관없이 목록으로 |

기준 독자는 `reader-profile.md` 1.1절 표와 난도 지도의 `personas` 첫 페르소나입니다. "최상 절 막힘 0"은 `reader-profile.md` 10.1절의 제안을 저자가 장 완료 조건으로 확정한 것이에요. reviewer 쪽에서는 3.6절 M1로 장 판정에 들어갑니다.

## 5. reviewer와 reader 결과 합치기

reviewer는 reader 보고서의 지적을 하나씩 셋 중 하나로 분류해 U 축 표에 올립니다.

| 분류 | 언제 | U 축에서 |
|---|---|---|
| 채택 | 원고를 다시 읽어도 같은 자리에서 걸림 | 아래 변환표의 심각도로 셈 |
| 병합 | 같은 원인을 가진 다른 지적이 이미 있음(reviewer 지적이나 다른 reader 지적) | 대표 ID 하나로 셈, 나머지 ID는 "병합 → R1-F02"로 남김 |
| 기각 | reader가 놓친 정의나 참조가 원고에 실제로 있음 | 세지 않음. 기각 이유를 한 줄로(예: "4.1절 문단 2에 정의, 참조 표시 있음"). 지적이 그 페르소나의 읽기 경로 밖 장의 개념에서 나왔다는 것은 기각 이유가 아닙니다. 경로 밖 장을 가리키면 한 문장 상기가 필요하기 때문이에요(`writing-chapter/references/self-check.md` B12, 3.6절과 같음) |

심각도 변환표

| reader 표시 | 기본 | 올리는 경우 |
|---|---|---|
| 막힘 | 중대 | 막힌 이유가 틀린 설명이면 F 축 치명으로 옮기고 reviewer가 근거를 붙임 |
| 걸림 | 경미 | 같은 문단에서 두 페르소나 이상 걸림, 또는 최상 개념 문단이면 중대 |
| 의문 | 경미 | 의문이 장 도입 질문이나 🧭 "개발자에게 물어볼 질문"과 같은데 본문이 답하지 않으면 중대(C 축 질문 답 항목과 병합) |

합치는 원칙
- 장 판정은 reviewer가 냅니다. reader 읽기 판정은 W5로, 최상 절 막힘은 3.6절 M1로 들어갑니다.
- reviewer는 reader 지적을 근거 없이 낮출 수 없습니다. 기각과 하향에는 이유를 적어요.
- 기각한 reader 지적도 보고서에 남겨 둡니다. 같은 기각이 여러 장에서 반복되면 독자 프로파일이나 reader 지시를 고칠 신호이기 때문입니다.
- reader 보고서가 없으면 U 축은 reviewer 혼자 평가하고 "reader 결과 없음"을 적습니다. 이 경우 장 판정이 통과여도 사이클 ⑥은 reader 검수 뒤에 닫습니다.

## 6. 회차와 확인 검수

| 직전 판정 | 다음 회차 | 범위 |
|---|---|---|
| 수정 후 통과 | 확인 검수 R{N+1} | 직전 치명, 중대 지적 ID 전부와 고친 문단 앞뒤 한 문단. 새로 보이는 문제도 적되 R{N+1} ID로. 최상 절 막힘이 있었으면 그 문단만 reader 확인 읽기(3.6절) |
| 재작성 | 전면 검수 R{N+1} | 처음과 같은 전 범위, reader도 다시 |
| 통과 | 없음 | 저자 검토로 |

확인 검수에서 지적 ID마다 상태를 하나 붙입니다.

| 상태 | 뜻 |
|---|---|
| 닫힘 | 반영됐고 새 문제가 없음 |
| 남음 | 반영 안 됐거나 부분 반영. 원래 심각도로 다시 셈 |
| 이견 수용 | writer 이견이 타당. 닫힘과 같게 셈 |
| 저자 확인 | writer와 reviewer 의견이 갈려 저자 결정이 필요. 판정에서 빼고 저자 검토로 넘김 |

확인 검수 판정은 "남음"과 새 지적만으로 3장 규칙을 다시 적용한 결과입니다. 같은 지적이 두 회차 연속 "남음"이면 보고서 요약에 따로 적어 저자에게 알립니다.

## 7. writer 반영 기록 서식

writer는 reviewer 보고서를 고치지 않고 `vol*/chNN/notes.md` 끝에 아래 표를 붙입니다. 확인 검수자는 이 표를 보고 어디부터 볼지 정해요.

```markdown
## 검수 반영 기록: R1 → R2

| ID | 심각도 | 조치 | 위치 | 한 줄 설명 |
|---|---|---|---|---|
| R1-F01 | 치명 | 반영 | 6.5 문단 3 | 0.63을 N6-1의 0.599로, 문장 끝 "약 60%"로 |
| R1-P1-02 | 중대 | 반영 | 6.5 문단 7 | 12장 용어 대신 "사람에게 넘기는 조건", 12장 예고 한 줄 |
| R1-G01 | 중대 | 반영 | 그림 2-6-7 줄 | 대체 텍스트 3문장 추가 |
| R1-S01 | 경미 | 반영 안 함 | 6.5 문단 4 | 정의 문단이라 습니다체 유지가 맞다고 판단 |
| R1-F04 | 보고 | 해당 없음 | references.yml | researcher 확인 대기 |
```

조치 값은 반영, 부분 반영(무엇을 남겼는지 설명), 반영 안 함(경미만 허용), 이견(근거 필수), 해당 없음(보고, 저자 확인)입니다. 치명과 중대에 "반영 안 함"을 쓰면 확인 검수에서 "남음"으로 셉니다.
