# 평가 사례 1: 1권 4장 장 리서치

`evals.json`의 `id: 1`에 대응하는 사례입니다. 실행 방법과 공통 판정 명령은 같은 폴더의 `README.md`에 있어요.

## 1. 이 사례를 고른 이유

1권 4장은 시리즈 기준 샘플이라 리서치도 가장 먼저 돌아갑니다(tasks.md 5장 첫 작업). 출처 키 5개가 모두 설계서 마스터 목록에 있고 ✅ 4개와 ◐ 1개가 섞여 있어, 서지를 서지 마스터에 한 번만 적고 장 파일에는 키와 `claims`만 두는 구조와, 상태 기호를 `check`로 옮기는 규칙을 함께 시험하기 좋습니다. 학회 연도와 arXiv 연도가 다른 키(`he2016`), 해설 자료(`alammar2018`), 키가 없는 사례 후보 2개, 그리고 🔄 행이 없는 장이라는 점도 한 번에 들어 있습니다.

## 2. 과제 프롬프트

```
1권 4장 리서치 해 줘. references.yml 채우고 🔄 항목도 확인해 줘.
```

## 3. 입력 파일

| 파일 | 볼 곳 |
|---|---|
| `CLAUDE.md` | 8장, 13장 |
| `docs/design-vol1-llm.md` | 5장 "4장"(메타 🔄 비중 낮음, 절 목차, 🏭 사례 후보, 그림 1-4-6 명세, 출처 키), 7장 N4-1~N4-3, 9장 관리표, 11장 머리말과 11.2절 |
| `vol1-llm/ch04/references.yml` | 머리 주석 두 줄과 `references: []` |
| `docs/references-master.yml` | 머리 주석과 `entries: []`. 실행 전에 `outputs/docs/`로 복사 |
| `vol1-llm/ch04/index.md` | 자리 표시만 있음. 원고 없음 |
| `vol1-llm/ch04/notes.md` | 없음. 새로 만들어야 함 |

## 4. 기대 산출물

| 파일 | 내용 |
|---|---|
| `docs/references-master.yml` | 설계서 키 5개의 서지 항목(키 알파벳 순서), 필요하면 새 키 항목 |
| `vol1-llm/ch04/references.yml` | 설계서 키 5개의 `key`와 `claims`(설계서 순서), 필요하면 새 키 |

## 5. 기대 결과

판정 열의 "자동"은 grep, python 한 줄로 판정할 항목, "사람"은 grader가 읽고 판정할 항목입니다.

### 5.1 서식

| # | 기대 | 판정 |
|---|---|---|
| Y1 | `references-schema.md` 9장 점검 명령(서지 마스터와 장 파일)의 마지막 줄이 `OK` | 자동 |
| Y2 | 장 파일 머리 주석 두 줄이 그대로 있고 최상위 키가 `references` 하나 | 자동 |
| Y3 | 서지 마스터의 모든 항목이 `status: unverified`, `verified_by: null`, `verified_at: null` | 자동 |
| Y4 | `what`, `conditions`, `note`, `notes.md` 리서치 보고에 금지 기호 7종이 0개 | 자동 |
| Y5 | 장 파일 항목에 `key`, `claims`, `note` 밖의 필드(서지 필드)가 없고, 모든 키가 서지 마스터에 있음 | 자동(점검 명령) |

### 5.2 키와 서지

| # | 기대 | 판정 |
|---|---|---|
| K1 | `research-report.md` 7장 키 대조 명령의 "빠짐"과 "마스터 없음"이 0줄. 키 5개(vaswani2017, alammar2018, he2016, ba2016, su2021)가 철자 그대로 있음 | 자동 |
| K2 | 설계서 키 5개의 순서가 설계서 "출처 키" 줄 순서와 같음(원고가 없으므로) | 자동 |
| K3 | 서지 마스터 `vaswani2017`: `kind: paper`, `tier: 1`, `id: "arXiv:1706.03762"`, `url`이 `https://arxiv.org/abs/1706.03762`, `venue`에 NeurIPS, `year: 2017` | 자동 |
| K4 | 서지 마스터 `he2016`: `year: 2016`, `venue`에 CVPR, `note`에 arXiv 초판 2015 언급 | 자동 |
| K5 | 서지 마스터 `alammar2018`: `kind: explainer`, `tier: 3`. 게시 연도를 페이지에서 확인하지 못했으면 `note`에 그렇게 적음 | 자동(kind, tier) / 사람(note) |
| K6 | 설계서 ✅ 키 4개는 원문을 다시 열었으면 `check: matched`와 그날의 `accessed`, 못 열었으면 `matched`와 `2026-10-12`에 대조 방법 `note`. ◐인 `alammar2018`은 열어서 제목과 저자를 확인했을 때만 `matched` | 사람 |
| K7 | arXiv 주소가 모두 `/abs/` 꼴이고 `/pdf/`가 없음 | 자동 |
| K8 | 장 파일 `claims`에 `where: "1-4-6"`이 있으면 `locator`가 원 논문 그림 번호이거나 `"확인 못 함"`. 지어낸 그림 번호가 없음 | 사람 |

### 5.3 사례 후보와 새 키

설계서 4장 사례 후보는 ① 트랜스포머가 여러 분야로 퍼진 확산 사례(각 사례 출처 필요) ② 검색 엔진의 BERT 적용 공식 발표입니다. 둘 다 마스터 목록에 키가 없습니다.

| # | 기대 | 판정 |
|---|---|---|
| C1 | 사례 후보 ①, ②가 보고서 키 표 또는 "찾지 못함"에 모두 나옴 | 사람 |
| C2 | 새 키를 넣었다면 `kind: official`(개발사 블로그) 같은 알맞은 종류이고, `url`이 실제로 연 발행 주체 도메인 주소이며, 보고서 "새 키 제안" 표에 설계서 서식 인용과 상태 기호, 넣을 절(1권 12.2절)이 있음 | 사람 |
| C3 | 새 키 이름이 `references-schema.md` 6장 꼴(기관명 + 연도 + 주제어)이고 영문 소문자, 숫자, 하이픈만 씀 | 자동 |
| C4 | 열지 못한 사례 출처는 서지 마스터와 장 파일 어디에도 없고 "찾지 못함"에 찾아본 곳과 `[출처 필요: ...]` 권고가 있음 | 사람 |
| C5 | 후보 밖 사례를 새로 고르지 않음 | 사람 |

## 6. 실패로 판정할 예

- 기억으로 채운 BERT 검색 발표 주소나 날짜가 서지 마스터에 있는데, 실행 기록에 그 페이지를 연 흔적이 없음
- `check: matched`를 받은 항목을 `status: verified`로 올림
- `alammar2018`을 숫자 근거로 `claims`에 연결함
- 설계서 9장에 4장 행을 추가하거나 설계서 11장 표에 새 키 행을 직접 넣음
- `he2016`의 `year`를 2015로 적음
- 장 파일 항목에 `title`, `year`, `status` 같은 서지 필드를 복사함

## 7. 설계서 확인 메모

- 1권 설계서 11장 머리말: ✅는 "2026년 10월 12일 서브 에이전트가 arXiv 초록 페이지 또는 공식 페이지에서 저자, 제목, 연도를 대조함"입니다. 그래서 다시 열지 못했을 때의 `accessed` 기본값이 `2026-10-12`예요.
- writing-chapter `box-markup.md` 3.3절 예시는 사례 ②를 `[출처 필요: 검색 엔진 개발사 2019년 10월 공식 블로그]`로 시연합니다. 이 리서치가 그 태그를 풀 키를 제안할 수 있는지가 C2의 요지입니다.
