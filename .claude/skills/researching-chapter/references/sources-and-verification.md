# 출처 우선순위와 대조 절차 (sources-and-verification)

출처를 고르는 기준과, 고른 출처가 실제로 있고 원고가 쓰려는 내용을 정말 담고 있는지 확인하는 절차입니다. 근거는 CLAUDE.md 8장, 계획서 11장, 각 권 설계서 출처 마스터 목록의 상태 정의예요.

## 목차

1. 출처 우선순위
2. 무엇을 찾는가: 수집 목록 만들기
3. 존재 대조: 종류별 확인 방법
4. 내용 대조: 사실과 숫자
5. 언론 숫자의 교차 확인
6. 판정이 갈릴 때
7. 기록하지 않는 것
8. 도구와 접근 실패

---

## 1. 출처 우선순위

CLAUDE.md 8장의 순서는 원 논문 > 개발사 공식 문서와 블로그 > 저명한 해설 자료 > 언론(수치는 교차 확인)입니다. 이 스킬은 이 순서를 서지 마스터의 `tier` 1~4로 적습니다(`references-schema.md` 4.1절). CLAUDE.md 목록에 이름이 없는 종류는 이렇게 둡니다. 사양, 법령, 표준, 판결 원문, 주장의 원전 도서는 원 논문과 같은 1단계, 기관 보고서는 공식 발표와 같은 2단계, 교재는 해설과 같은 3단계입니다.

| tier | 무엇 | 쓸 수 있는 일 | 쓰면 안 되는 일 |
|---|---|---|---|
| 1 | 원 논문, 사양 원문, 법령과 판결 원문, 표준 문서, 주장의 원전 도서 | 개념 설명, 수치, 연도, 최초 제안 | 원문에 없는 해석을 원문 탓으로 돌리기 |
| 2 | 개발사와 발행 주체의 공식 블로그, 문서, 보도자료, 모델 카드, 데이터시트, 가격 페이지, 기관 보고서 | 제품 사양, 출시일, 가격, 회사 발표 수치("발표 기준") | 회사 발표 수치를 독립 측정처럼 쓰기 |
| 3 | 저명한 해설(강의, 교재, 해설 블로그) | 설명 순서와 비유의 참고, 더 읽을거리 | 숫자와 연도의 근거 |
| 4 | 언론, 2차 해설, 로펌 뉴스레터 | 상위 출처가 다루지 않는 사건 사실(계약, 배치, 소송 경과) | 교차 확인 없는 숫자, 상위 출처가 있는 사실 |

고르는 규칙

1. 같은 사실을 담은 출처가 여럿이면 tier가 낮은 숫자(1에 가까운 쪽)를 고릅니다. 보도에서 처음 알게 된 사실이라도 그 보도가 인용한 원문을 찾아 원문을 키로 씁니다.
2. 같은 tier 안에서는 발행 주체에 가까운 쪽, 그다음 판이 최신인 쪽을 고릅니다. 다만 🔄 항목이 아닌 개념 설명은 초판의 문제의식을 인용하는 편이 서사 프레임 ①(태동 배경)에 맞아요.
3. 법령, 규정, 표준은 공식 등재처(국가법령정보센터, EUR-Lex, ISO 공식 페이지)가 tier 1이고, 그 해설은 tier 4입니다. 1권 설계서가 `eu-ai-omnibus-2026`을 "2차 자료로만 확인 ⚠"로 둔 이유가 이것입니다.
4. 시장 전망과 가격은 발표 기관의 원문(tier 2)을 찾습니다. 원문이 유료라 열 수 없으면 기관의 공개 요약이나 보도자료를 쓰고, 그것도 없으면 `check: secondary`로 둡니다.
5. 모델 성능은 원 논문이나 공식 발표에서 조건과 함께 가져옵니다. 리더보드는 기준일을 함께 적고 🔄 항목으로 다룹니다.

## 2. 무엇을 찾는가: 수집 목록 만들기

장 리서치는 "좋은 자료 모으기"가 아니라 "원고가 쓸 사실마다 근거 하나씩 붙이기"입니다. 그래서 찾기 전에 수집 목록을 먼저 만듭니다. 목록 칸은 `research-report.md` 3장 표와 같아요.

수집 목록에 넣을 것(해당 권 설계서에서)

| 설계서 위치 | 넣을 것 |
|---|---|
| 5장 그 장의 "출처 키" 줄 | 모든 키 |
| 같은 장의 절 목차 "핵심 내용" 칸 | 괄호 안 키(예: 3권 7.3절의 `lipman2022flow`, `black2024pi0`)와 "출처 필요", "집필 시 조사"로 적힌 사실 |
| 같은 장의 "🏭 사례 후보" | 후보마다 받칠 사실과 숫자. 키가 없으면 새 키 후보 |
| 7장 숫자 정본 | 이 장 행 가운데 출처 키가 붙은 값(예: 3권 N7-3의 `black2024pi0`) |
| 🔄 관리표(1권 9장, 2, 3권 10장) | "위치" 칸에 이 장 절 번호가 있는 행 |
| 출처 마스터 목록 | 위 키들의 행과 상태 기호, 설명 |
| 그림 명세 | "논문 그림을 참고하여 재구성"할 그림(예: 1권 1-4-6) |

- 설계서에 없는 사실을 원고에 넣자고 먼저 제안하지 않습니다. 원고 내용은 설계서가 정하고, 이 스킬은 근거만 붙입니다.
- 원고가 이미 있으면 `[출처 필요]` 태그와 `[@key]` 가운데 `references.yml`에 없는 키도 목록에 넣습니다(writing-chapter `self-check.md` 명령 G-2, G-3).

출처를 찾지 않는 것. 아래는 근거가 출처가 아니라 정본이나 설명 장치라 목록에 넣지 않고, 원고에 표지가 있는지만 봅니다.

| 대상 | 원고에서 확인할 것 |
|---|---|
| 정본 손계산 숫자(설계서 7장) | `<!-- canon: ... -->` 주석 |
| 한빛로지스 장면과 값 | `scenario-hanbit.yml` 값 |
| 설계서가 정한 설명용 예문과 그 값(1권 3.1절과 4.4절 "5월 3일/3월 5일") | 예문이 한빛로지스 값으로 읽히지 않고, `check_canon`에 걸리면 사유를 적은 `check_canon: ignore` 표지(writing-chapter `box-markup.md` 1장) |
| 설명을 위해 단순화한 가정(4.4절 "5", "월", "3", "일" 네 토큰 분할) | "설명을 위해 … 나눈다고 해 봅시다"처럼 가정임을 밝힌 문장. 실제 토크나이저 분할을 받칠 출처를 찾지 않습니다 |

## 3. 존재 대조: 종류별 확인 방법

존재 대조는 "이 자료가 이 제목, 이 저자, 이 연도로 정말 있다"를 확인하는 일입니다. 기억이나 검색 결과 요약만으로는 대조로 치지 않아요. 존재하지 않는 논문이나 잘못된 연도가 책에 실리는 사고는 대개 기억에서 시작되기 때문입니다.

| 종류 | 열 곳 | 맞춰 볼 칸 | 흔한 함정 |
|---|---|---|---|
| arXiv 논문 | `https://arxiv.org/abs/{id}` 초록 페이지 | ID, 제목, 저자 목록, 초판 날짜, 최신판 번호와 날짜 | 판이 바뀌며 제목이 바뀜(`edge2024graphrag`, `kwa2025metr`). PDF 주소를 url로 씀 |
| 학회, 저널 논문 | 출판사 페이지(DOI가 가리키는 곳), ACL Anthology, CVF Open Access, 학회 proceedings | DOI, 학회명과 연도, 쪽 | arXiv 연도와 학회 연도가 다름(`he2016`, `sennrich2016`) |
| 공식 블로그, 문서 | 발행 주체 도메인의 페이지 | 제목, 게시일, 저자(있으면), 주소 | 게시일이 없는 페이지(`morganstanley-openai`는 "게시일 미표기, 접근일 기록"). 다시 쓰여 내용이 바뀐 페이지 |
| 사양 | 사양 공식 사이트의 판별 페이지 | 판 이름(날짜형 판은 날짜), 변경 기록 | 최신판과 원고가 설명하는 판이 다름 |
| 법령, 규정 | 국가법령정보센터, EUR-Lex | 법령 번호, 제정일, 시행일, 조문 번호 | 보도의 날짜와 관보 날짜가 다름. 행정 방침과 부칙을 섞음(1권 9장 AI 기본법 행) |
| 표준 | ISO, ANSI 등 표준 기구 공식 페이지 | 번호, 판, 단계(초안, 발행, 개정 중) | "폐지됐다"는 2차 서술(3권 10장 ISO/TS 15066 행) |
| 판결 | 법원, 재판소 공식 판결문 목록 | 사건명, 법원, 선고일 | 보도의 요약과 판결문 내용이 다름 |
| 기관 보고서 | 기관 공식 사이트의 보고서나 보도자료 | 제목, 발표일, 수치와 그 기준 연도 | 다른 해의 전망치를 섞음 |
| 저장소, 모델 카드 | 공식 조직 계정의 저장소, 모델 카드 | 조직명, 공개일, 라이선스, 판 | 비공식 복제 저장소 |

대조가 끝나면 서지 마스터 항목에 `check: matched`, `accessed`에 연 날짜를 적습니다. 어느 방법으로 대조했는지 `note`에 한 줄 남기면 사람 확인이 빨라져요(예: "arXiv 초록 페이지로 대조").

## 4. 내용 대조: 사실과 숫자

존재를 확인한 뒤에는 원고가 쓰려는 사실이 원문 어디에 있는지 찾습니다. 찾은 위치를 `claims.locator`에 적어요.

1. 사실 문장: 원문에서 같은 뜻의 문장을 찾습니다. 해설 자료가 덧붙인 해석이 원문에 없으면 원문 키로 받치지 않습니다.
2. 숫자: 원문 숫자를 단위까지 그대로 `value`에 옮깁니다. 반올림, 환산, 합산은 하지 않습니다. 원고에서 계산이 필요하면 정본 추가 제안으로 돌립니다(CLAUDE.md 8장 숫자 규칙).
3. 숫자의 조건: 하드웨어, 데이터, 설정, 측정 방법, 시도 수, 성공 횟수, 일반화 칸, 재생 속도, 원격 조작 여부 가운데 원문에 있는 것을 `conditions`에 적습니다. 원문에 없는 칸은 "공개되지 않음"으로 적어요. 3권은 데모 장면의 조작 방식과 배속을 특히 확인합니다.
4. 정본과 대조: 이 장 정본(설계서 7장)이 같은 숫자를 쓰면 원문 값과 정본 값이 같은지 봅니다. 다르면 고치지 말고 보고서 "설계서와 다른 점"에 올립니다.
5. 원 논문 그림: 다시 그릴 그림이 참고할 원문 그림 번호를 확인합니다. 판마다 그림 번호가 바뀔 수 있어 `version`도 함께 적어요.
6. 모델과 제품 서술: "최고", "최초", "가장"이 붙은 주장은 원문이 그렇게 말해도 "○○가 발표했다"로만 옮길 수 있게 `what`을 씁니다(CLAUDE.md 8장, 모델명은 계보의 대표 사례).

## 5. 언론 숫자의 교차 확인

`tier: 4` 출처의 숫자는 그대로 쓰지 않습니다. 아래 순서로 확인하고 결과를 장 파일의 `claims.crosscheck`와 서지 마스터 `note`에 남깁니다.

1. 원문 찾기: 보도가 인용한 회사 발표, 보고서, 논문을 찾습니다. 찾으면 그 원문을 키로 쓰고 보도는 `claims.crosscheck`로 내립니다.
2. 원문이 없으면 독립 보도 하나 이상: 서로 다른 매체가 같은 숫자를 실었는지 봅니다. 한 보도를 다른 매체가 옮겨 실은 것은 독립이 아니에요. 기사 안의 인용 출처가 같으면 하나로 셉니다.
3. 숫자가 갈리면 쓰지 않음: 매체마다 숫자가 다르면 어느 쪽도 고르지 않고 보고서 "판정이 갈림"에 둘 다 적습니다.
4. 결과 기록: 원문 확인이면 `check: matched`, 독립 보도 둘 이상이면 `check: secondary`와 `claims.crosscheck` 두 칸 이상, 하나뿐이면 `check: secondary`에 `note: "단일 보도, 교차 확인 실패"`를 붙입니다. 단일 보도 숫자는 원고에 쓰지 말라고 보고서에 적어요.

설계서 선례

- 2권 `uber2024querygpt`: 흔히 인용되는 "월 14만 시간 절감"은 Uber 원문 수치가 아니라서 쓰지 않음. 이런 판정은 `note`에 그대로 남깁니다.
- 2권 관리표 A2A 행: 일부 2차 자료의 "2025년 12월 합류"가 공식 발표와 어긋나 쓰지 않음. 공식 발표가 2차 자료를 이깁니다.
- 2권 `anthropic2024contextual`: 감소 수치를 2차 자료로만 확인해 ⚠. 원문 블로그를 열어 수치가 있으면 `matched`로 올릴 후보예요.

## 6. 판정이 갈릴 때

| 상황 | 처리 |
|---|---|
| 원문과 설계서 값이 다름 | 원문 값을 `claims.value`에 적고, 보고서 "설계서와 다른 점"에 설계서 수정안으로 올림. 설계서와 정본은 고치지 않음 |
| 원문 최신판과 초판이 다름(제목, 수치) | 원고가 설명하는 판을 `version`에 적고, 다른 점을 `note`에. 🔄 항목이면 갱신 제안 |
| 공식 발표끼리 다름(블로그와 문서) | 더 늦게 갱신된 공식 문서를 우선하고 둘 다 보고 |
| 공식 발표와 보도가 다름 | 공식 발표를 따르고, 보도 숫자는 쓰지 말라고 `note`에 적음 |
| 원문은 있으나 열 수 없음(유료, 접근 차단) | `check: unchecked` 또는 `secondary`, `note`에 사유. 사람 확인 요청 목록 앞쪽에 둠 |
| 같은 키로 다른 자료를 가리키는 것 같음 | 키를 고치지 않고 보고. 키 이름은 설계서가 정함 |

## 7. 기록하지 않는 것

- 존재를 확인하지 못한 논문, 링크, 수치(CLAUDE.md 8장). 기억에 있는 arXiv 번호, 주소, 숫자라도 열어 보지 못했으면 적지 않습니다.
- 검색 결과 요약에만 나오고 원문에서 찾지 못한 숫자.
- 원문에 없는 해석, "업계 최고", "현재 가장" 같은 비교 서술.
- 긴 직접 인용. 요지만 우리말로 적습니다.
- 사람이 확인했다는 표시. `status: verified`는 사람만 씁니다.

기록하지 않은 대신 무엇을 찾으려 했고 어디까지 갔는지를 보고서 "찾지 못함"에 남깁니다. 다음 사람이 같은 검색을 되풀이하지 않게 하려는 것입니다.

## 8. 도구와 접근 실패

- 웹 검색과 웹 페이지 열기 도구가 있으면 그것으로 원문을 엽니다. 검색 결과 목록은 원문으로 가는 길일 뿐이에요.
- 웹 도구가 없거나 막히면 존재 대조를 할 수 없습니다. 이때는 설계서 행을 옮기는 일(초기화)만 하고, 모든 새 항목을 `unchecked`로 두고, 보고서 첫 줄에 "웹 접근 불가로 대조하지 못함"을 적습니다.
- arXiv 초록 페이지가 막히면 arXiv 목록 API(`export.arxiv.org/abs/{id}`)나 학회 페이지를 시도합니다. 그래도 안 되면 2권 설계서처럼 "검색 결과로 대조"라고 `note`에 적고 `check: unchecked`로 둡니다.
- 대조에 쓴 페이지 주소는 서지 마스터 `url` 또는 장 파일 `claims.crosscheck`에 남깁니다. 주소 없이 "확인함"만 적으면 사람이 다시 찾아야 해요.
