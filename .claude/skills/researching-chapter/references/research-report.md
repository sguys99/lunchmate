# 리서치 보고서 서식 (research-report)

리서치 결과를 메인 에이전트와 저자에게 넘기는 서식입니다. 보고서는 장 폴더 `notes.md` 끝에 붙이고, 같은 내용의 요약을 응답으로 돌려줍니다. writer는 이 보고서를 보고 어느 사실에 `[@key]`를 붙이고 어느 사실을 `[출처 필요]`로 남길지 정하고, 저자는 "사람 확인 요청"만 보고 확인을 시작할 수 있어야 해요.

## 목차

1. 놓는 곳과 머리 줄
2. 요약 수치
3. 키 표
4. 새 키 제안
5. 찾지 못함
6. 설계서와 다른 점
7. 키 대조 명령
8. 🔄 재확인 결과
9. 사람 확인 요청
10. 응답 요약
11. 채운 예시

---

## 1. 놓는 곳과 머리 줄

- 파일: `vol*/chNN/notes.md`. 없으면 만들고, 있으면 끝에 붙입니다. writing-chapter의 입력 메모, 절 개요, 자가 점검 보고가 같은 파일에 있으므로 다른 절을 고치지 않아요. 파일이 있으면 Write로 전체를 쓰지 않고 Edit로 끝에 붙인 뒤, `grep -c '^## ' notes.md`가 쓰기 전보다 줄지 않았는지 확인합니다. 1권 4장 리서치에서 노트를 통째로 새로 써 writer의 절 개요가 지워진 일이 있었어요.
- 머리 줄: `## 리서치 보고 (YYYY-MM-DD)`. 같은 장을 다시 리서치하면 새 머리 줄로 덧붙이고 앞 보고는 지우지 않습니다.
- 장 폴더가 없는 작업(관리표 전체 재확인, 여러 장 초기화)은 보고서를 응답에 직접 적고, 파일로 남길 곳을 메인 에이전트에게 묻습니다.

머리 줄 바로 아래 범위 줄

```markdown
- 작업: 장 리서치 / 🔄 재확인 / 초기화 / 키 몇 개 확인
- 대상: 1권 4장 (설계서 5장 "4장", 11.2절, 9장 관리표)
- 읽은 입력: (파일과 절 번호)
- 웹 접근: 가능 / 불가(불가면 이 보고의 모든 check는 unchecked)
```

## 2. 요약 수치

```markdown
| 항목 | 수 |
|---|---|
| 장 파일 항목 | 7 (서지 마스터 check: matched 5, unchecked 1, secondary 1) |
| 서지 마스터에 새로 넣은 항목 | 2 |
| claims 위치 확인 못 함 | 1 |
| 새 키 제안(설계서 마스터 목록 밖) | 1 |
| 찾지 못함 | 1 |
| 설계서와 다른 점 | 1 |
| 🔄 행 | 0 (이 장 관리표 행 없음) |
| 사람 확인 요청 | 3 |
```

## 3. 키 표

수집 목록(`sources-and-verification.md` 2장)의 모든 줄이 이 표에 한 번씩 나옵니다. writer는 "원고에서" 칸을 보고 인용 방식을 정해요.

```markdown
| 키 | 쓰일 곳 | tier | check | 원고에서 | 비고 |
|---|---|---|---|---|---|
| vaswani2017 | 4.1, 1-4-6 | 1 | matched | [@vaswani2017] | 그림 1-4-6 참고 원문 그림 번호 확인 |
| alammar2018 | 더 읽을거리 | 3 | unchecked | 더 읽을거리만 | 숫자 근거로 쓰지 않음 |
| (사례 ①) | 4장 사례 | - | 찾지 못함 | [출처 필요: ...] 유지 | 5장 참고 |
```

"원고에서" 칸의 값

| 값 | 뜻 |
|---|---|
| `[@key]` | 인용해도 됨. `status: unverified`이므로 장 완료 전 사람 확인 필요(writing-chapter `box-markup.md` 6장) |
| `[@key], 발표 기준` | 회사나 기관 발표 수치. 원고에 "○○ 발표 기준"을 붙여야 함 |
| 더 읽을거리만 | 본문 사실의 근거로 쓰지 않음 |
| `[출처 필요: 찾을 곳]` 유지 | 존재나 내용을 확인하지 못함. 태그 안에 찾을 곳을 적어 줌 |
| 쓰지 않음 | 확인 결과 사실이 아니거나 원문 수치가 아님(예: `uber2024querygpt`의 "월 14만 시간") |

## 4. 새 키 제안

설계서 출처 마스터 목록에 없는 출처를 서지 마스터(`docs/references-master.yml`)와 장 파일에 넣었으면 여기 올립니다. 설계서 목록이 서지 마스터와 1:1로 대응해야 하므로(1권 설계서 11장 머리말), 저자가 승인하면 메인 에이전트가 설계서 표에 행을 넣습니다. 승인 전에도 서지 마스터 항목은 `status: unverified`로 남겨 두고, 거절되면 메인 에이전트가 두 파일에서 지웁니다.

```markdown
| 키 | 설계서 표에 넣을 인용 (설계서 서식 그대로) | 상태 기호 | 넣을 절 | 쓸 곳 |
|---|---|---|---|---|
| (새 키) | (저자, "제목", 매체, 연도. 주소) | ✅ | 1권 12.2절 | 4장 사례 ② |
```

- 인용 칸은 설계서 표 서식(`저자, "제목", 매체/학회, 연도. URL`)을 그대로 따릅니다.
- 상태 기호는 `check` 값을 거꾸로 옮깁니다(matched ✅, unchecked ◐, secondary ⚠).
- 존재를 확인하지 못한 출처는 새 키로 제안하지 않고 5장으로 보냅니다.

## 5. 찾지 못함

```markdown
| 무엇 | 쓰일 곳 | 찾아본 곳과 방법 | 결과 | writer에게 |
|---|---|---|---|---|
| (사실이나 숫자) | 4장 사례 ① | (검색어, 연 페이지) | 원문 미발견 / 보도 1건뿐 / 숫자 불일치 | [출처 필요: (찾을 곳)] 유지, 또는 후보 ②로 교체 권고 |
```

- 찾아본 곳을 구체적으로 적습니다. 다음 리서치가 같은 길을 되풀이하지 않게 하려는 것이에요.
- 사례 후보가 출처를 못 찾으면 설계서의 다른 후보를 권하되, 후보 밖 사례를 새로 고르지는 않습니다(writing-chapter `chapter-template.md`, 사례 후보 규칙).

## 6. 설계서와 다른 점

원문을 대조하다 설계서 값(마스터 목록 서지, 정본 숫자, 장 설계의 사실 서술)과 다른 점을 찾으면 적습니다. 설계서는 고치지 않고 수정안만 올립니다(CLAUDE.md 2장).

```markdown
| 설계서 위치 | 설계서 값 | 원문 값 | 근거 | 수정안 | 영향 |
|---|---|---|---|---|---|
| 2권 12.1절 edge2024graphrag | (설계서 셀) | (원문) | [@키] 위치 | (바꿀 셀) | 원고, 그림, 정본 중 해당 |
```

## 7. 키 대조 명령

보고 전에 설계서 "출처 키" 줄, 장 파일, 서지 마스터, 원고 `[@key]`가 서로 맞는지 `scripts/check_references.py`로 확인합니다. 저장소 루트에서 돌려요.

```bash
.venv/bin/python scripts/check_references.py vol1-llm/ch04   # 이번 장(서식 점검과 키 대조를 함께)
.venv/bin/python scripts/check_references.py                 # 전체: 미사용 마스터 항목(REF-X01)까지
```

| 출력 규칙 ID | 뜻 | 보고서에서 |
|---|---|---|
| `REF-D01` 빠짐 | 설계서 줄에 있는데 장 파일에 없음 | 5장 찾지 못함에 설명 |
| `REF-D02` 추가 | 설계서 줄에 없는데 장 파일에 있음 | 4장 새 키 제안이나 키 표 비고에 설명(절 목차, 정본, 앞 권 키) |
| `REF-C03` 마스터에 없음 | 장 파일에 있는데 서지 마스터에 없음 | 0줄이어야 함. 서지 마스터에 항목을 넣거나 장 파일에서 뺌 |
| `REF-X01` 미사용 | 서지 마스터에 있는데 어느 장 파일도 쓰지 않음(인자 없이 돌릴 때만) | 지울지, 다른 장 리서치를 기다릴지 보고서에 적음 |
| `REF-D03` 순서 | 장 파일의 설계서 키 순서가 설계서 줄과 다름 | 원고가 없으면 설계서 순서로 고침. 원고가 있으면 첫 인용 순서가 맞는지 확인 |
| `REF-D04` | 설계서에서 그 장의 출처 키 줄을 찾지 못함 | 설계서 장 제목 꼴이나 "출처 키" 줄 확인 |
| `REF-B01` | 원고 `[@key]`가 장 파일에 없음(오류) | 장 파일에 키를 넣거나 writer에게 알림 |

요약 줄 끝이 `OK`이고 종료 코드가 0이면 오류가 없는 것입니다. REF-D와 REF-X는 경고라 종료 코드에 영향이 없으니 줄을 직접 읽어요.

- 2권과 3권은 경로만 바꿉니다(`vol2-agent/ch06`). 2권과 3권 0장처럼 "출처 키" 줄이 "없음"이면 설계서 키가 0개로 잡힙니다.
- 장 파일이 비어 있으면(`references: []`) 설계서 대조를 건너뛰고 REF-I02 정보만 냅니다. 예전 손 명령은 이때 설계서 키를 모두 "빠짐"으로 냈어요. 초기화 직후 빠진 키 목록이 필요하면 설계서 그 장의 "출처 키" 줄을 직접 봅니다.
- 절 목차 칸에만 있는 키(예: 3권 7.3절 `lipman2022flow`)와 정본 행의 키는 설계서 "출처 키" 줄에 없어서 "추가"(REF-D02)로 나옵니다. 수집 목록과 눈으로 대조하고 키 표 비고에 출처 위치를 적어요.
- "미사용"은 초기화가 덜 된 동안 정상으로 나올 수 있습니다. 장 리서치 보고에는 이번 장 키와 관계있는 줄만 옮깁니다.
- 서식 규칙(REF-M, REF-C)의 뜻은 `references-schema.md` 9장 표에 있습니다.
- 스크립트를 못 쓸 때는 설계서 그 장의 `**출처 키**` 줄(`grep -n "출처 키" docs/design-vol1-llm.md`)과 `grep -n "key:" vol1-llm/ch04/references.yml`를 나란히 놓고 눈으로 대조합니다.
## 8. 🔄 재확인 결과

`refresh-proposal.md` 4장의 요약표와 제안 카드를 여기 붙입니다. 이 장 행이 없으면 "이 장 🔄 행 없음(관리표 ○장 확인)" 한 줄만 적습니다.

## 9. 사람 확인 요청

저자가 확인할 것을 급한 순서로 적습니다. 이 목록이 tasks.md 4.4절 "👤 출처 원문 확인"의 입력이 됩니다.

순서

1. `check: secondary`이면서 원고나 정본 숫자를 받치는 키
2. 정본 숫자(설계서 7장)를 받치는 키
3. 장 파일 `claims.locator`가 `"확인 못 함"`인 줄
4. 법령, 규정, 판결, 표준(날짜와 조문이 틀리면 피해가 큼)
5. `check: unchecked`인 나머지
6. `check: matched`인 나머지(원문 한 번 열어 보기)

`check`와 `status`는 서지 마스터 값을 씁니다. 사람이 확인해 `verified`로 올리는 곳도 서지 마스터 항목이에요.

```markdown
| 순서 | 키 | 확인할 것 | 열 곳 |
|---|---|---|---|
| 1 | gxo-digit-2025 | "10만 개 이상" 수치와 기간 | 회사 공식 발표 |
```

## 10. 응답 요약

메인 에이전트에게 돌려주는 응답은 아래 다섯 줄을 넘지 않게 씁니다. 자세한 내용은 `notes.md`에 있으니 응답에서 되풀이하지 않아요.

```markdown
1권 4장 리서치를 마쳤습니다. 장 파일 항목 7개(서지 마스터 check: matched 5, unchecked 1, secondary 1), 모두 status: unverified입니다.
새 키 제안 1개, 찾지 못함 1개(사례 ①, [출처 필요] 유지 권고), 설계서와 다른 점 1건이 있어요.
🔄: 이 장 관리표 행 없음.
사람 확인 요청 3건은 notes.md "리서치 보고 (2026-10-15)" 9절에 있습니다.
```

## 11. 채운 예시

1권 4장을 리서치했다고 가정한 보고서 뼈대입니다. 서지는 설계서 11.2절 값이고, 사례 줄은 "찾지 못한 경우"를 시연하려고 꾸민 결과예요. 실제 리서치 결과가 아닙니다.

```markdown
## 리서치 보고 (2026-10-15)

- 작업: 장 리서치
- 대상: 1권 4장 (설계서 5장 "4장", 11.2절, 9장 관리표)
- 읽은 입력: CLAUDE.md 8장, 설계서 5장 4장 절, 7장 N4-1~N4-3, 9장, 11.2절, vol1-llm/ch04/references.yml(빈 목록), docs/references-master.yml(빈 목록)
- 웹 접근: 가능

### 요약 수치
| 항목 | 수 |
|---|---|
| 장 파일 항목 | 5 (서지 마스터 check: matched 4, unchecked 1, secondary 0) |
| 서지 마스터에 새로 넣은 항목 | 5 |
| claims 위치 확인 못 함 | 0 |
| 새 키 제안 | 0 |
| 찾지 못함 | 1 |
| 설계서와 다른 점 | 0 |
| 🔄 행 | 0 (1권 9장에 4.x 위치 행 없음) |
| 사람 확인 요청 | 5 |

### 키 표

### 🔄 재확인 결과

| 순서 | 키 | 확인할 것 | 열 곳 |
```
