## 2. with_skill 실패 항목과 원인

### W2 본문 단계 상자 치수(실측 x 96, 폭 200, 기대 x 88, 폭 240)

- 현상: 단계 이름을 줄이고 연산 문구(÷ √d, d = 2, softmax, 합 = 1, Σ 가중치 × v)를 뺐습니다. 뒤 처리가 "최장 줄 글자 폭 + 32"로 폭을 잡아(`mermaid-guide.md` 5장) 200이 됐습니다.
- 원인: 지시 부족(주). `patterns.md` P1은 폭 240을 적지만, Mermaid에서는 폭이 문구로 정해진다는 사실과 이어 주지 않습니다. 검사 누락(부). lint는 같은 역할 상자끼리의 크기만 보고, 패턴 기준 폭과는 대조하지 않습니다.
- 고칠 곳: `patterns.md` P1 "열" 행, `mermaid-guide.md` 2장 예시(1-4-3 일곱 노드 전체), `qa-checklist.md` Q2.

### A2 [사람] 대체 텍스트 단계 이름

- 현상: 이름이 '내적 점수, 루트 2로 나누기, softmax, 가중합'으로, 기대(점수, 크기 조정, softmax, 가중합)와 다릅니다. 노드 이름 변경이 alt로 옮겨졌습니다.
- 원인: 지시 부족(주). "노드 이름은 설계서, 원고, 용어집 용어를 쓴다"는 규칙이 없습니다. 예시 부족(부). `caption-alt.md` 161행 예가 형식 예로만 읽히고, 원고가 비었을 때 기댈 단계 이름표도 없어요.
- 고칠 곳: `SKILL.md` 5단계, `caption-alt.md` 2장, `patterns.md` P1 부록.

## 5. 그림 세련됨 개선 제안(저자 확인 대상)

- 정렬: 단계 열 x 96과 입력 행 x 106, 291로 왼쪽 끝이 10px 어긋납니다. 쿼리 상자 왼쪽 끝을 단계 글자 시작점에 맞추면 정렬선이 하나 줄어요.
- 여백: 폭 200에 "[0.707, 1.414, 2.121]"이 거의 꽉 차 안쪽 여백이 좁습니다. 240으로 돌아가면 오른쪽 빈 열과의 비율도 시안처럼 안정됩니다.
- 위계: "이름 굵게 + 연산 보통 + 값 줄"의 세 층이 연산 문구를 빼면서 두 층으로 줄었고, d = 2 같은 정본 근거도 그림에서 사라졌습니다.
- 표기 일관성: '쿼리 q'는 소문자인데 '키 K', '값 V'는 대문자입니다. 토큰 하나의 벡터이므로 q, k, v 소문자로 맞추고, 토큰 목록은 괄호로 묶는 편이 낫습니다.
- 색 절제: 개념색은 띠에만, 강조는 한 곳에만 있어 잘 지켰습니다. 유지하면 됩니다.

## 6. 평가 자체에 대한 메모

1. mermaid-sample 계열 파일이 정답 노드 글자를 담고 있습니다. 사례 2는 `figkit-sample.build.py`도 같은 방식으로 점검할 필요가 있습니다.
2. `check_figures --root`가 index.md가 없어 멈춥니다. README 2단계에 링크 단계를 넣어야 합니다.
3. H3는 "같은 역할 상자끼리 같은 크기"만 봐서, 시안보다 40px 좁은 상자도 통과합니다. "시안과 단계 이름, 연산 문구가 같은가"를 더하면 변별력이 올라갑니다.
4. F2의 S 재현 명령은 산출 파일을 제자리에서 덮어씁니다. 해시가 다르면 제출본이 사라지므로 임시 경로로 출력하는 편이 안전합니다.
