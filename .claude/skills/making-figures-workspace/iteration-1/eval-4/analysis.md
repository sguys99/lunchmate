## 3. 스킬 실행의 판단 두 가지

### 3.1 강조를 잠재 표현 상자에 둔 판단

기대와 맞습니다. 사례 md 5.1절의 "accent tint 상자" 안이고, 컬러와 gray, 색약 PNG 모두에서 강조가 한 곳에 남았어요(H2 통과). 대신 상자 한 단이 늘어 캔버스가 480이 됐습니다. P9의 480 조건(하위 모듈 3개 이상)에 해당하지 않고 note에 사유도 없습니다. 본문은 accent 화살표와 600 라벨로 320을 지키고, 상자 표현은 세로 변형에서만 쓰는 쪽이 와이어프레임 의도에 가깝습니다.

### 3.2 source.kind를 own으로 둔 판단

기대와 맞습니다. 7장 메모 5대로 refs를 비우고 line을 null로 두었으며, figure2025helix 키가 없다는 사실을 note와 notes.md로 보고했습니다. 기준선은 data와 [@figure2025helix]를 넣었어요. 다만 스킬 실행은 caveat에 "Figure Helix"를 적어 출처를 캡션으로 다시 들여왔고, 이것이 C2 실패입니다. caveat 기대 문구는 "주기는 한 대표 사례의 공개값이며 제품마다 다릅니다."입니다.

## 4. 그림의 세련됨 개선 제안

1. 정렬: 센서 입력을 48 높이로 되돌리면 세 입력이 P9 피치 64에 맞습니다.
2. 여백: 480 캔버스의 아래 여백이 약 88로 비어 있습니다. 320으로 줄이거나 위아래 여백을 맞추는 편이 낫습니다. 모듈 상자도 아래 약 40이 비어요. System 1은 176 × 64 두 줄로 줄일 수 있습니다.
3. 위계: 결과 자리인 행동 라벨이 ink-600이라 흐름의 끝이 약합니다. ink-900으로 올리는 안을 검토할 만해요. 주기 글자를 500으로 올리면 느림, 빠름과 값이 짝으로 읽힙니다.
4. 색 절제: 개념색을 띠에만 쓴 점은 좋습니다. 다만 강조가 상자, 지시선, 끝점 세 군데에 나뉘므로 지시선은 ink-600으로 낮추는 편이 낫습니다.
5. 세로 변형: 입력이 오른쪽에서 왼쪽으로 들어와 읽는 방향이 뒤집힙니다. 위에서 아래로 "입력 행, System 2, 센서와 잠재 표현 행, System 1, 행동" 순서로 쌓는 것을 제안합니다.

## 5. 수정 제안 우선순위

1. caption-alt.md 3장, 4.3절: own 그림의 캡션과 alt에서 회사명, 모델명 금지(C2, 두 실행 공통)
2. design-rules.md 11장, patterns.md P9 표: 하위 구성 금지, 입출력 상자 160 × 48 고정(W2, H3, H7의 뿌리)
3. figkit.py lint, qa-checklist.md 3.2절: 같은 role 상자 크기 경고(H3)
4. patterns.md P9 세로 변형, svg-guide.md 10장: 모듈 둘 예시, 폭 400 제한(W1, W3)
5. qa-checklist.md 5.3절: 검수 기록의 치수는 SVG 실측값으로, 480 사유는 note에(H7)
