# 칼럼 서식과 다듬기 규칙

저자 답을 `.box-field` 칼럼으로 옮기는 규칙입니다. 박스 마크업의 정본은 `writing-chapter/references/box-markup.md` 3.4절이고, 여기서는 그 안에 들어갈 글의 분량, 구조, 화자, 다듬기 범위를 정합니다.

## 목차

1. 박스 서식
2. 근거 단위와 근거 주석
3. 분량과 구조
4. 화자와 문체
5. 다듬기에서 해도 되는 일과 안 되는 일
6. 점검표
7. 다듬기 예시(가상의 연습용 답변)

---

## 1. 박스 서식

```markdown
::: {.box-field}
🛠 현장 노트: {주제}

<!-- source: interview.md 저자 답, 다듬은 날 YYYY-MM-DD -->

{문단 1}
<!-- 근거: Q1-1, Q1-2 -->

{문단 2}
<!-- 근거: Q2-1 -->

{마지막 문단}
<!-- 근거: Q3-1 -->
:::
```

- 제목 줄의 `{주제}`는 설계서 후보 주제를 명사구로 줄인 것입니다(예: "어텐션 비유가 통한 순간과 엇나간 순간"). 저자 답의 중심이 후보와 달라졌으면 답에 맞춰 줄이고 다듬기 기록에 적습니다.
- `source` 주석은 `box-markup.md` 3.4절 서식 그대로입니다.
- `근거` 주석도 `box-markup.md` 3.4절 서식에 들어 있습니다. 출간 빌드에서 주석은 사라지므로 남겨 둬요. reviewer가 "답에 없는 문장"을 찾을 때 이 주석으로 대조합니다.

## 2. 근거 단위와 근거 주석

근거 단위는 "질문 번호 + 답 안의 순서"입니다. `Q2-3`은 질문 2의 답에서 세 번째 문장(목록이면 세 번째 항목)을 뜻해요. 순서는 `_private/interviews/`의 날 답에서 세고, 날 답 원문은 고치지 않습니다. `interview.md` 답 칸의 일반화한 답은 날 답 문장 하나를 번호 하나로 옮기므로(`interview-format.md` 3장), 커밋된 파일만 보는 reviewer도 `Q2-3`을 일반화한 답 3번으로 대조할 수 있어요.

- 칼럼의 모든 문단은 근거 주석을 하나 이상 가집니다.
- 근거 주석이 없는 문장은 두 종류만 허용합니다. 장 본문과 잇는 연결 문장(5장 표의 "해도 되는 일" 4번)과, 문단을 잇는 접속 한 구절입니다.
- 저자가 구술한 답을 에이전트가 받아 적었으면 날 답 파일의 "받은 방식" 칸에 `구술, 에이전트 받아 적음`을 적고 같은 규칙을 씁니다.

## 3. 분량과 구조

| 항목 | 기준 | 근거 |
|---|---|---|
| 쪽수 | 0.5~1쪽(확정) | 계획서 6장 표(0.5~1쪽), 1권 설계서 3.4절(1쪽) |
| 문단 수 | 2~5문단 | `box-markup.md` 3.4절 |
| 글자 수 | 공백 포함 약 590~1,180자 | 0.5~1쪽을 쪽수 환산 기준(tasks.md P7, `scripts/page_estimate.yml` 쪽당 1,178자, 2026-10-17 1권 4장 보정)으로 옮긴 값입니다. 박스 테두리와 제목 줄 여백은 뺀 글자만의 분량이에요. 조판 엔진(D7)이 정해져 계수를 다시 재면 이 값도 다시 계산합니다 |
| 문장 길이 | 60자 내외, 100자 초과 금지 | CLAUDE.md 6장 |

구조는 질문 3개의 역할(`question-design.md` 2장)을 따릅니다.

| 문단 | 할 일 | 주로 쓰는 근거 |
|---|---|---|
| 1 | 상황: 어떤 현장에서 무엇을 하던 중이었나. 일반화한 배경 한두 문장 | Q1 |
| 2~3 | 사건과 판단: 무엇이 예상과 달랐고, 무엇을 보고 알아챘고, 무엇을 바꿨나 | Q1, Q2 |
| 마지막 | 독자에게 건넬 것: PM, PO가 비슷한 상황에서 먼저 확인할 것 | Q3 |

저자 답에 "독자에게 건넬 것"이 없으면 마지막 문단을 지어내지 말고, 질문 3을 다시 묻거나 칼럼을 장면과 판단까지만 씁니다.

## 4. 화자와 문체

화자 규칙은 저자 확인을 거쳐 확정했습니다(2026-10-15). 설계서에는 시점을 정한 곳이 없고, 계획서는 현장 노트를 "저자 실무 경험 칼럼"(6장 표), "저자가 직접 쓰거나 구술한 내용을 바탕으로"(13.2절 ⑦)라고만 적었기 때문이에요.

| 항목 | 규칙(확정) | 이유 |
|---|---|---|
| 시점 | 저자 1인칭 단수("저는", "제가") | 저자 경험 칼럼이라는 성격이 분명하고, 현장 들여다보기(1인칭 금지)와 바로 구별됩니다 |
| 1인칭 빈도 | 문단당 1회 안팎. 문장마다 주어로 넣지 않음 | 주어를 반복하면 회고록처럼 읽힙니다 |
| 복수 1인칭 | "저희", "저희 팀", "우리 회사", "우리 팀"은 쓰지 않고 "함께 일하던 팀"처럼 | 소속을 짐작하게 합니다(G2) |
| 소속과 경력 | 회사명, 정확한 경력 연수와 연도는 쓰지 않음 | 머리말 저자 소개에만 싣습니다(G2, G18) |
| 상대 | "고객사", "현업 담당자"처럼 역할로 | G14 |
| 독자 호칭 | 마지막 문단에서만 "여러분"이나 생략형으로 말 걸기 | 본문 해요체 쓰임과 같음 |

문체는 원고 규칙(CLAUDE.md 6장, `writing-chapter/references/style-rules.md`)을 그대로 씁니다. 칼럼은 경험을 들려주는 글이라 본문보다 해요체가 많아도 됩니다. 칼럼 하나의 해요체 비율은 절 단위 경고 기준인 5~40% 안에 두고, 목표 비율 15~25%는 장 전체로 맞춥니다.

- 사실과 경과는 습니다체: "문서의 절반 가까이가 스캔본이었습니다."
- 느낌, 정리, 독자에게 건네는 말은 해요체: "그때부터 문서 목록을 먼저 달라고 해요."
- 금지 기호, 굵은 글씨 규칙, 숫자 표기는 본문과 같습니다. 굵은 글씨는 칼럼 전체에 1회 이하로 둡니다.
- 용어는 이 시리즈 표기로 바꿉니다(예: 답의 "미세조정" → "파인튜닝", "튜닝" → 문맥에 맞는 시리즈 용어). 장 본문에서 정의된 용어만 쓰고, 아직 정의 전인 용어는 쉬운 말로 풉니다.

## 5. 다듬기에서 해도 되는 일과 안 되는 일

| 해도 되는 일 | 안 되는 일 |
|---|---|
| 1. 답의 순서를 문단 구조(3장)에 맞게 재배열 | 답에 없는 일화, 장면, 대화 더하기 |
| 2. 구어, 군말, 반복을 문어로 정리 | 답에 없는 수치, 기간, 규모 더하기(규모어도 원래 값에서만) |
| 3. 일반화 규칙(`generalization.md`) 적용 | 답에 없는 감정("뿌듯했습니다", "막막했습니다") 더하기 |
| 4. 장 본문과 잇는 한 문장("4.2절의 도서관 검색 비유로 말하면") | 답에 없는 교훈, 결론, 일반론 더하기 |
| 5. 용어를 시리즈 표기로 바꾸기 | 저자의 판단을 더 단정적이거나 더 겸손하게 바꾸기 |
| 6. 긴 문장을 나누기, 짧은 문장을 잇기 | 공개가 애매한 내용(G16, G17)을 에이전트 판단으로 넣기 |
| 7. 답 안의 서로 다른 질문 답을 한 문단에 합치기 | 답에 없는 저자 경력, 직함, 경험 연수 추가(답에 있어도 정확한 연수는 G18대로) |

애매하면 "저자가 이 문장을 읽고 '나는 이렇게 말한 적 없다'고 할 수 있는가"를 물어요. 그럴 수 있으면 지웁니다.

## 6. 점검표

- [ ] 박스 첫 줄이 `🛠 현장 노트: `로 시작하고 `source` 주석이 있다
- [ ] 모든 문단에 `<!-- 근거: ... -->` 주석이 있고, 가리키는 답이 실제로 있다
- [ ] 2~5문단, 문장 100자 이하, 금지 기호 0
- [ ] 해요체 비율이 5~40%이고 사실 서술은 습니다체다
- [ ] 1인칭은 단수("저는", "제가")만, 문단당 1회 안팎. "저희", "우리 회사", "우리 팀"은 0개
- [ ] `generalization.md` 5장 체크리스트를 통과했다
- [ ] 5장 "안 되는 일"에 해당하는 문장이 없다
- [ ] 한빛로지스 세계관이 섞이지 않았다
- [ ] `interview.md` 답 칸에 일반화한 답을 날 답과 같은 번호로 채웠고, 원래 값은 `_private/interviews/`에만 있다
- [ ] `interview.md`의 상태를 `칼럼 초안`으로 바꾸고 다듬기 기록과 일반화 목록, 저자에게 확인할 것을 원래 값 없이 채웠다

## 7. 다듬기 예시(가상의 연습용 답변)

아래 답은 스킬 시험용으로 지어낸 **가상의 연습용 답변**입니다. 저자의 실제 경험이 아니며, 원고나 `interview.md`에 옮기지 않습니다. 고유명사도 모두 가상입니다. 실제 날 답이라면 이 원문은 `_private/interviews/`에만 있고, 커밋되는 파일에는 아래 일반화한 답과 칼럼만 들어갑니다.

가상의 연습용 답변(2권 3장 질문 1)

> 음 그게 가나다전자 품질팀 과제였는데요, 2024년 3월쯤 시작했고, 모델은 처음에 별 문제 없었어요. 근데 규정집이 스캔본이 4,300장이 넘었고 표가 이미지로 박혀 있어서 OCR을 라마솔루션 걸 썼는데 표가 다 깨졌어요. 결국 7개월 중에 5개월을 문서 정리에 썼어요.

`interview.md` 답 칸에 옮기는 일반화한 답(형식 예시)

> 1. 한 제조 고객사의 품질 부서 과제였고, 모델은 처음에 별 문제가 없었습니다.
> 2. 규정집이 수천 장의 스캔본이었고 표가 이미지로 들어 있어, 외부 문자 인식 솔루션을 썼더니 표가 모두 깨졌습니다.
> 3. 결국 과제 기간의 대부분을 문서 정리에 썼습니다.

다듬은 문단(형식 예시)

> 한 제조 고객사의 사내 규정 검색 과제였습니다. 모델 쪽은 처음부터 큰 문제가 없었어요. 막힌 곳은 문서였습니다. 규정집이 수천 장의 스캔본이었고, 표가 이미지로 들어 있어 외부 문자 인식 솔루션을 거치자 표가 모두 깨졌습니다. 결국 과제 기간의 대부분을 문서 정리에 썼습니다.
> `<!-- 근거: Q1-1, Q1-2, Q1-3 -->`

바뀐 것: 고객사명(G1), 시기(G9, G10), 장수(G12), 벤더명(G3), 기간 비율 "7개월 중 5개월"(G9, G11)이 규모어 "대부분"으로 바뀌었습니다. 답에 없는 문장("막막했습니다", "그때 배운 교훈은")은 더하지 않았어요. "막힌 곳은 문서였습니다"는 Q1-1(모델은 문제없음)과 Q1-2(표가 깨짐)를 잇는 정리 문장이라 근거 안에 있습니다. 답의 문장은 세 개라 근거 단위도 Q1-1~Q1-3이고, 일반화한 답의 번호 1~3과 같습니다. 일반화한 답에서도 원래 값은 모두 빠졌어요.
