# 일반화 규칙

저자 답을 칼럼으로 옮길 때 고유명사와 수치를 일반화하는 규칙입니다. 근거는 CLAUDE.md 11장("고객사명, 회사명, 프로젝트명, 로봇 모델명, 금액, 기간, 수치는 일반화"), 1권 설계서 16.1절, 3권 설계서 B8과 Q4("회사명, 로봇 모델명, 수치 없이")입니다.

일반화는 두 곳에 씁니다. B단계에서 `_private/interviews/`의 날 답을 `interview.md` 답 칸의 일반화한 답으로 옮길 때, 그리고 그 답을 칼럼으로 다듬을 때예요(`interview-format.md` 1장). 원래 값은 날 답 파일에만 남고, 커밋되는 파일에는 일반화한 값만 들어갑니다.

목표는 두 가지입니다. 독자가 고객사나 저자의 소속, 특정 과제를 짐작할 수 없게 하는 것, 그리고 일반화한 뒤에도 이야기의 교훈이 남게 하는 것이에요.

## 목차

1. 기본 원칙
2. 규칙표(범주, 바꾸기 전, 바꾼 뒤)
3. 일반화하면 이야기가 무너질 때
4. 점검 명령(grep)
5. 체크리스트

---

## 1. 기본 원칙

- 범주를 지우지 말고 한 단계 위로 올립니다. "자동차 부품 2차 협력사"는 "한 제조 고객사"로 올리고, 아예 지워 "어떤 곳"으로 만들지 않습니다. 업종 감각은 독자에게 쓸모가 있기 때문이에요.
- 조합으로도 특정되지 않게 합니다. 업종, 지역, 시기, 규모가 한 문장에 함께 있으면 하나씩은 일반적이어도 고객사를 짐작할 수 있습니다. 한 문단에 이 넷 가운데 둘까지만 남깁니다.
- 숫자는 규모어로 바꿉니다. 정확한 값 대신 자릿수 감각("수십 개", "수천 장", "몇 배")이나 방향("눈에 띄게 줄었다", "절반 가까이")만 남깁니다.
- 일반화는 답의 사실을 흐리게 할 뿐 바꾸지 않습니다. "3개월"을 "수개월"로는 바꾸지만 "1년 가까이"로 바꾸지 않습니다. 규모어는 원래 값을 포함해야 합니다.
- 공개 정보는 일반화 대상이 아닙니다. 논문, 공개 오픈소스, 공개 발표처럼 출처가 있는 사실은 일반화하지 않고 출처 키를 붙입니다. 다만 그것이 "어느 고객사가 무엇을 썼다"를 드러내면 고객사 쪽을 일반화합니다.
- 한빛로지스 정본 숫자(설계서 7장)와 헷갈릴 숫자는 칼럼에 두지 않습니다. 칼럼은 실제 현장 이야기이고, 정본은 가상 시나리오이기 때문이에요.

## 3. 일반화하면 이야기가 무너질 때

정확한 수치 차이가 교훈의 핵심인 경우가 있습니다(예: "예상의 몇 배"가 곧 요점인 1권 2장 토큰 비용 이야기). 이때 규칙을 어기지 말고 두 안을 저자에게 보여 줘요.

| 안 | 쓰는 법 | 예(가상) |
|---|---|---|
| 규모어 안 | 배수나 자릿수만 남김 | "견적의 몇 배가 나왔습니다" |
| 구조 안 | 숫자 대신 원인 구조를 남김 | "출력이 길어지고 재시도가 겹치면서, 견적서에 없던 비용 항목이 생겼습니다" |

저자가 정확한 수치를 남기겠다고 하면, 그 수치가 고객사나 과제를 특정하지 않는지 한 번 더 묻고 저자 결정과 날짜를 다듬기 기록에 적습니다. 그래도 정본처럼 보이지 않게 "제 경우에는" 같은 한정어를 붙여요.

## 4. 점검 명령(grep)

원고를 저장하면 `style_check.py`가 `.box-field` 박스 안에서 아래 명령 1~7과 같은 후보를 S33 경고로 알려 줍니다(`.venv/bin/python scripts/style_check.py vol1-llm/ch04/index.md`). 명령 8(남은 고유명사 후보 대조)은 사람 몫이라 스크립트가 보지 않아요. 아래 명령은 박스만 떼어 후보를 한꺼번에 보고 싶을 때나 스크립트를 못 쓸 때 씁니다. 출력은 후보일 뿐이라 한 줄씩 직접 판단합니다. 남겨도 되는 예는 "질문 3개", 절 번호 "4.2절", 출처 키 `[@key]` 안의 연도 같은 것입니다.

```bash
F=vol1-llm/ch04/index.md
BOX="${TMPDIR:-/tmp}/box-field.md"
awk '/^::: \{\.box-field\}/{p=1} p{print} p&&/^:::$/{exit}' "$F" > "$BOX"

# 1. 숫자 전부(절 번호와 [@key] 안은 사람이 걸러 냄)
grep -nE '[0-9]' "$BOX"

# 2. 금액, 화폐
grep -nE '[0-9,]+ ?(원|만 ?원|억|달러|불)|\$|₩|USD|KRW' "$BOX"

# 3. 기간, 날짜
grep -nE '[0-9]+ ?(개월|달|주|주일|일간|년|년간|분기)|20[0-9]{2}|(작년|올해|지난해|상반기|하반기)' "$BOX"

# 4. 비율, 성능 수치
grep -nE '[0-9.]+ ?(%|퍼센트|배|점)' "$BOX"

# 5. 회사 표지, 사람 호칭
grep -nE '\(주\)|㈜|주식회사|Inc\.|Corp|Co\.,|Ltd|부장|차장|과장|팀장|대표|이사|CTO|CEO|[가-힣]님' "$BOX"   # "대표 사례" 같은 일반어도 걸리므로 눈으로 거름

# 6. 라틴 대문자 고유명사 후보(모델명, 제품명). [@key]는 제외
grep -noE '\b[A-Z][A-Za-z0-9-]{1,}\b' "$BOX" | grep -v '@'

# 7. 따옴표 안 이름 후보(프로젝트명, 시스템명)
grep -nE "(프로젝트|시스템|포털|플랫폼) ?['\"‘“]" "$BOX"

# 8. 답 칸의 고유어가 칼럼에 남았는지: 답에서 뽑은 후보 단어를 하나씩 대조
#    (날 답 원문은 _private/interviews/에만 있으므로 아래 W에 후보를 직접 넣음)
#    박스와 함께 interview.md 전체도 대조합니다. 일반화한 답, 일반화 목록, 확인할 것에도 0이어야 합니다
I=vol1-llm/ch04/interview.md
for W in "후보1" "후보2"; do printf "%-12s 박스 %s, interview.md %s\n" "$W" "$(grep -cF -- "$W" "$BOX")" "$(grep -cF -- "$W" "$I")"; done
```

8번은 자동으로 만들 수 없는 단계입니다. 날 답 파일을 읽으며 고유명사, 숫자, 기간 표현을 모두 뽑아 W 목록에 넣고, 칼럼과 `interview.md`에서 모두 0이 되는지 봅니다. W 목록은 명령줄에서만 쓰고 파일이나 보고서에 남기지 않아요. 0이 아닌 단어는 2장 규칙표로 다시 바꿔요.

## 5. 체크리스트

- [ ] G1~G15에 해당하는 표현이 칼럼에 남지 않았다(4장 명령 1~8)
- [ ] G16, G17에 해당하는 내용은 칼럼에 없고 "저자에게 확인할 것"에 원래 값 없이 올렸다
- [ ] G2, G18: 저자 소속 회사명과 정확한 경력 연수, 연도가 칼럼에 없다
- [ ] G6: 공개 계보 모델명은 저자가 허락한 기록이 없으면 "공개 VLA 모델"로 바꿨다
- [ ] `interview.md` 전체(일반화한 답, 다듬기 기록, 확인할 것)에 원래 고유명사와 숫자가 없다(4장 명령 8)
- [ ] 한 문단에 업종, 지역, 시기, 규모 가운데 셋 이상이 함께 있지 않다
- [ ] 규모어는 원래 값을 포함한다(부풀리거나 줄이지 않았다)
- [ ] 일반화 목록에 원래 고유명사와 숫자를 옮겨 적지 않았다
- [ ] 공개 출처가 있는 사실에는 `[@key]`를 붙였고, 그 키가 `references.yml`에 있다
- [ ] 한빛로지스 정본 숫자나 세계관이 칼럼에 섞이지 않았다
