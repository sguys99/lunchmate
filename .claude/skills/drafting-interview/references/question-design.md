# 질문 설계 가이드

좋은 인터뷰 질문은 저자가 "그때 그 장면"을 떠올리게 하고, 그 장면이 장의 학습 목표와 이어지게 합니다. 질문이 추상적이면 답도 일반론이 되고, 일반론은 본문과 겹쳐 칼럼이 할 일이 사라져요.

## 목차

1. 좋은 질문의 기준 5가지
2. 질문 3개의 역할 배치
3. 점검표 8항목
4. 장별 예시(좋은 질문과 고칠 질문)
5. 자주 하는 실수

---

## 1. 좋은 질문의 기준 5가지

| 기준 | 뜻 | 확인 방법 |
|---|---|---|
| 일화를 끌어냄 | 특정한 한 번의 상황(누구에게, 무엇을 하다, 무엇이 일어났나)을 묻습니다 | "한 번", "그때", "처음" 같은 말이 있고 "보통", "일반적으로"가 없다 |
| 경험으로 답할 수 있음 | 문헌을 찾아야 답할 수 있는 질문이 아닙니다 | 저자가 자료를 열지 않고 말로 답할 수 있다 |
| 학습 목표와 이어짐 | 답이 그 장의 개념(절 번호)을 현장에서 다시 보여 줍니다 | 머리표 "연결 학습 목표"에 절 번호가 있다 |
| 열린 질문 | 예/아니요나 하나의 정답으로 끝나지 않습니다 | "무엇", "어떻게", "어느", "왜"로 묻는다 |
| 공개해도 안전함 | 이름, 금액, 정확한 수치를 요구하지 않고, 답이 그대로 실려도 큰 문제가 없게 묻습니다 | "얼마였나요", "어느 회사" 같은 말이 없다 |

## 2. 질문 3개의 역할 배치

세 질문은 칼럼의 문단 구조(`column-format.md` 3장)와 짝을 이룹니다. 저자가 세 질문에만 답해도 칼럼 뼈대가 서도록 배치해요.

| 질문 | 역할 | 칼럼에서 쓰일 자리 | 묻는 꼴 |
|---|---|---|---|
| 1 | 장면 | 1~2문단: 어떤 상황이었고 무엇이 일어났나 | "○○했던 때 하나를 떠올려 주세요. 무엇이 예상과 달랐나요?" |
| 2 | 판단 | 2~3문단: 무엇을 보고 알아챘고 무엇을 바꿨나 | "그때 무엇을 보고 ○○라고 판단하셨고, 그 뒤 무엇을 바꾸셨나요?" |
| 3 | 독자에게 건넬 것 | 마지막 문단: PM, PO가 비슷한 상황에서 먼저 확인할 것 | "같은 상황의 PM이 첫 회의에서 확인해야 할 것을 하나 고른다면 무엇인가요?" |

후보 주제가 "A, 또는 B" 꼴이면 질문 1을 둘로 갈라 저자가 고르게 합니다. 질문 2, 3은 고른 쪽에 모두 맞게 씁니다.

## 3. 점검표 8항목

질문 하나마다 8항목을 모두 통과시킵니다. 하나라도 걸리면 고쳐 쓰고, 고칠 수 없으면 다른 각도로 다시 만듭니다.

| # | 항목 | 걸리는 예 |
|---|---|---|
| Q1 | 한 문장, 100자 이하인가 | 질문 두 개를 "그리고"로 이은 문장 |
| Q2 | 예/아니요로 끝나지 않는가 | "~해 보신 적 있나요?", "~가 더 낫던가요?" |
| Q3 | 답을 미리 정해 두지 않았는가 | "역시 데이터 정리가 가장 힘드셨죠?" |
| Q4 | 저자의 경험을 넘겨짚지 않는가(후보 주제에 있는 경험만 전제) | 후보에 없는 "강의하실 때", "팀장으로서" |
| Q5 | 이름, 금액, 정확한 수치를 요구하지 않는가 | "그 과제 규모가 얼마였나요?" |
| Q6 | 장 학습 목표 또는 절 하나와 이어지는가 | 장 주제와 무관한 경력 일반 질문 |
| Q7 | 세 질문이 서로 겹치지 않고 2장의 세 역할을 나눠 맡는가 | 세 질문이 모두 "어려웠던 점" |
| Q8 | 본문이나 🏭 사례 박스가 이미 답하는 내용을 다시 묻지 않는가 | "어텐션은 왜 길이의 제곱으로 느나요?"(4.6절 내용) |

## 4. 장별 예시(좋은 질문과 고칠 질문)

설계서의 실제 후보 주제로 만든 예시입니다. 질문만 있고 답은 없습니다. 답은 저자만 씁니다.

### 4.1 1권 4장: 어텐션을 설명할 때 통했던 비유와 오해를 낳은 비유

후보 주제: 비전공 동료나 수강생에게 어텐션을 설명할 때 잘 통했던 비유와 오히려 오해를 낳았던 비유(1권 설계서 5장 4장).

| # | 좋은 질문 | 역할 |
|---|---|---|
| 1 | 비전공 동료나 수강생에게 어텐션을 설명하다가 상대 표정이 확 풀렸던 순간 하나를 떠올려 주세요. 그때 어떤 비유를 썼나요? | 장면 |
| 2 | 반대로 비유 때문에 상대가 엉뚱하게 이해했던 때, 무엇을 듣고 그 오해를 알아채셨고 설명을 어떻게 바꾸셨나요? | 판단 |
| 3 | 이 책은 Q, K, V를 도서관 검색(검색어, 색인표, 책 내용)으로 설명하는데, 현장에서 써 보신 비유와 비교하면 어느 지점에서 독자가 걸려 넘어질 것 같나요? | 독자에게 건넬 것 |

고칠 질문

| 고칠 질문 | 걸린 항목 | 고친 질문 |
|---|---|---|
| 어텐션 비유로 도서관 검색이 좋다고 생각하시나요? | Q2, Q3 | 위 3번 |
| 어텐션을 설명할 때 어떤 비유가 좋나요? | 기준 "일화를 끌어냄"(일반론을 묻는 질문) | 위 1번 |
| 강의를 몇 번 하셨고 수강생은 몇 명이었나요? | Q5, Q6 | 묻지 않음 |

### 4.2 1권 2장: 토큰 비용 예측이 빗나간 경험

후보 주제: 생성형 AI 과제 견적에서 토큰 비용 예측이 빗나갔던 경험(언어, 출력 길이, 재시도 횟수 같은 숨은 변수).

| 좋은 질문 | 역할 |
|---|---|
| 견적 때 잡은 토큰 비용과 실제 사용량이 크게 어긋났던 과제 하나를 떠올려 주세요. 어긋난 것을 처음 알아챈 순간은 언제였나요? | 장면 |
| 어긋남의 원인을 언어, 출력 길이, 재시도 가운데 무엇으로 좁히셨고, 다음 견적부터 계산 방식을 어떻게 바꾸셨나요? | 판단 |
| 견적서를 받은 PM이 "토큰 수 가정"에서 꼭 물어봐야 할 한 가지는 무엇인가요? | 독자에게 건넬 것 |

고칠 질문: "예상보다 몇 배 더 나왔나요?"는 Q5에 걸립니다. 배수는 일반화 대상이라 답을 받아도 실을 수 없어요. "어긋남이 얼마나 컸는지 규모로만 말씀해 주세요"처럼 물을 필요도 없습니다. 크기는 저자가 스스로 말하면 그때 규모어로 바꿉니다.

### 4.3 2권 3장: 문서 파싱에 시간이 더 들었던 경험

후보 주제: 사내 문서 RAG 구축에서 모델보다 문서 파싱과 정리에 시간이 더 들었던 경험(스캔본, 표, 버전이 섞인 규정집).

| 좋은 질문 | 역할 |
|---|---|
| 사내 문서 RAG를 만들며 "모델이 아니라 문서가 문제구나" 하고 깨달은 장면 하나를 들려주세요. 어떤 문서였나요? | 장면 |
| 스캔본, 표, 버전이 섞인 규정집 가운데 가장 손이 많이 간 것은 무엇이었고, 처리 순서를 어떻게 정하셨나요? | 판단 |
| RAG 일정을 잡는 PM이 착수 전에 문서 쪽에서 먼저 확인해야 할 것은 무엇인가요? | 독자에게 건넬 것 |

### 4.4 3권 6장: 데모 영상을 볼 때 먼저 확인하는 세 가지

후보 주제: 데모 영상을 볼 때 저자가 가장 먼저 확인하는 세 가지(재생 속도, 시도 횟수, 원격 조작 여부).

후보 주제가 이미 "세 가지"를 정해 두었으므로 질문은 그 세 가지를 확인하게 된 계기와 쓰임새를 묻습니다. 세 가지를 다시 고르게 하면 Q3에 걸려요.

| 좋은 질문 | 역할 |
|---|---|
| 이 세 가지를 먼저 확인하게 된 계기가 된 영상이나 시연 하나를 떠올려 주세요. 그때 무엇을 보고 그렇게 정하셨나요? | 장면 |
| 재생 속도, 시도 횟수, 원격 조작 여부 가운데 영상만 보고 판단하기 가장 어려운 것은 무엇이고, 그럴 때 어떻게 확인하시나요? | 판단 |
| 로봇 데모를 처음 보고 보고서를 써야 하는 PM에게 영상 아래 표시 줄 말고 따로 물어봐야 할 것이 있다면 무엇인가요? | 독자에게 건넬 것 |

이 장은 서술 수위 규칙(CLAUDE.md 12장)이 적용되는 3권입니다. 특정 회사 데모를 깎아내리는 답을 유도하지 않도록 질문에 회사명이나 제품명을 넣지 않아요.

### 4.5 3권 9장: 텔레오퍼레이션 데이터 수집 계획

후보 주제: 시니어케어, 가사 지원 작업을 위해 텔레오퍼레이션으로 조작 데이터를 모으는 계획을 세우며 정한 기준(시연자, 다양성, 실패 시연 처리).

| 좋은 질문 | 역할 |
|---|---|
| 수집 계획을 세우다가 "이 기준을 안 정하면 데이터가 쓸모없어지겠다" 싶었던 순간은 언제였나요? | 장면 |
| 시연자, 다양성, 실패 시연 처리 가운데 팀 안에서 의견이 가장 갈린 기준은 무엇이었고, 어떻게 정리하셨나요? | 판단 |
| 데이터 수집 예산을 승인하는 PM이 계획서에서 가장 먼저 봐야 할 줄은 무엇인가요? | 독자에게 건넬 것 |

## 5. 자주 하는 실수

- 질문에 본문 용어를 정의 없이 넣기: 저자는 알지만 질문을 다시 읽을 때 장 맥락을 잊었을 수 있습니다. 용어 옆에 절 번호를 붙여 둡니다.
- 후보 주제를 질문 3개로 쪼개기만 하기: 세 질문이 모두 장면을 물으면 칼럼에 판단과 교훈이 빠집니다. 2장 역할 배치를 지킵니다.
- 대답하기 부담스러운 질문을 첫 번째에 두기: 실패, 갈등을 묻는 질문은 2번 자리에 둡니다. 첫 질문이 가벼워야 답이 길어집니다.
- "답하기 어려우면" 칸을 비우기: 저자가 질문 하나를 건너뛰어도 칼럼이 서도록 대안 질문을 꼭 둡니다.
