# interview.md 서식과 날 답 보관

장 폴더의 `interview.md`는 저자와 에이전트가 함께 쓰는 작업 파일입니다(CLAUDE.md 3장). 빌드 대상은 아니지만 저장소에 커밋됩니다. 그래서 저자의 날 답(고객사명, 회사명, 금액, 기간, 수치가 섞일 수 있는 원문)은 이 파일에 두지 않고, git이 무시하는 `_private/interviews/`에만 둡니다.

## 목차

1. 두 파일의 역할
2. 누가 어느 칸을 쓰는가
3. interview.md 서식
4. 날 답 파일 서식
5. 상태 값
6. 공개 가능 여부 값
7. 채운 예시 머리표(1권 4장)

## 1. 두 파일의 역할

| 파일 | 커밋 | 담는 것 | 담지 않는 것 |
|---|---|---|---|
| `vol*/chNN/interview.md` | 함 | 머리표, 질문 3개, 일반화한 답, 공개 점검, 상태, 다듬기 기록, 일반화 목록, 저자에게 확인할 것 | 날 답 원문, 원래 고유명사와 숫자 |
| `_private/interviews/vol{권}-ch{NN}.md` | 하지 않음(저장소 루트 `.gitignore`의 `/_private/`) | 저자 날 답 원문, 받은 날과 받은 방식 | 질문 설계, 칼럼 |

파일 이름 규칙입니다.

| 대상 | 공개 파일 | 날 답 파일 |
|---|---|---|
| 1권 4장 | `vol1-llm/ch04/interview.md` | `_private/interviews/vol1-ch04.md` |
| 2권 3장 | `vol2-agent/ch03/interview.md` | `_private/interviews/vol2-ch03.md` |
| 3권 맺음말 | `vol3-physical-ai/epilogue-interview.md` | `_private/interviews/vol3-epilogue.md` |

지킬 것입니다.

- 날 답 파일을 만들거나 고치기 전에 무시 설정을 확인합니다. 아래 명령이 둘 다 실패하면 날 답을 쓰지 않고 멈춘 뒤, `.gitignore`에 `/_private/`를 더해 달라고 사용자에게 알립니다. 에이전트가 `.gitignore`를 직접 고치지는 않아요.

```bash
grep -qxE '/?_private/?' .gitignore && echo "ignore 설정 있음"
git check-ignore -q _private/interviews/vol1-ch04.md && echo "git이 무시함"   # git 저장소일 때
```

- 원래 값은 날 답 파일 밖으로 옮기지 않습니다. `interview.md`, `index.md`, `notes.md`, 사용자 응답, 보고서, 커밋 메시지 모두 해당합니다. 저자와 특정 문장을 짚어야 하면 "날 답 질문 2의 다섯 번째 문장"처럼 위치로 가리켜요.
- 저자가 날 답을 `interview.md` 답 칸에 바로 적었으면, 다른 일보다 먼저 그 원문을 날 답 파일로 옮기고 답 칸을 일반화한 답으로 바꿉니다. 옮긴 사실은 다듬기 기록에 "날 답 이동"으로 적고, 원문이 이미 커밋됐는지는 사용자에게 확인을 부탁합니다.
- 날 답 파일은 저자 소유입니다. 에이전트는 저자가 구술한 답을 받아 적을 때만 씁니다. 받아 적은 뒤에는 고치지 않아요.

## 2. 누가 어느 칸을 쓰는가

| 칸 | 쓰는 사람 | 비고 |
|---|---|---|
| 머리표(권, 장, 후보 주제, 주제 근거, 연결 학습 목표, 날 답 위치) | 에이전트 | A단계 |
| 질문 1~3, 이 질문으로 얻고 싶은 것, 답하기 어려우면 | 에이전트 | A단계 |
| 날 답(날 답 파일) | 저자 | 저자가 구술하면 에이전트가 받아 적을 수 있고, 이때 받아 적었다고 표시합니다 |
| 답(`interview.md`의 일반화한 답) | 에이전트 | B단계. 날 답을 `generalization.md` 규칙으로 일반화한 것이고, 저자가 확인합니다 |
| 공개 점검 체크 | 저자 | 에이전트는 체크하지 않습니다 |
| 상태 | 에이전트와 저자 | 5장 표의 "바꾸는 사람"을 따릅니다 |
| 다듬기 기록, 일반화 목록 | 에이전트 | B, C단계. 원래 고유명사와 숫자는 적지 않습니다 |
| 저자에게 확인할 것 | 에이전트 | 원래 값 없이 위치와 범주로 적습니다. 저자가 답하면 줄을 지우지 않고 "답:"을 붙입니다 |

## 3. interview.md 서식

````markdown
# {N}장 현장 노트 인터뷰

<!-- 설계서 {N}장 현장 노트 후보 주제로 저자 인터뷰 질문 3개를 적는다(CLAUDE.md 11장). 이 파일은 커밋된다. 날 답은 머리표의 날 답 위치에만 둔다 -->

| 항목 | 값 |
|---|---|
| 권, 장 | {권}권 {N}장 {장 제목} |
| 후보 주제 | {설계서 "🛠 현장 노트 후보" 문구 그대로} |
| 주제 근거 | `docs/design-vol{권}-*.md` 5장 {N}장 "🛠 현장 노트 후보" |
| 연결 학습 목표 | {설계서 학습 목표 가운데 이 주제와 닿는 부분, 관련 절 번호} |
| 상태 | 답변 대기 |
| 공개 가능 여부 | 미확인 |
| 날 답 위치 | `_private/interviews/vol{권}-ch{NN}.md`(커밋하지 않음) |
| 마지막 갱신 | YYYY-MM-DD |
````

서식에서 지킬 것입니다.

- 질문 머리는 `## 질문 1. ` 꼴로 씁니다. 평가와 검사 명령이 `^## 질문 [1-3]\. `으로 질문 수를 셉니다.
- 답 칸 머리는 `### 답` 하나로 고정합니다. A단계에서는 답 칸에 HTML 주석 한 줄 말고는 아무것도 두지 않아요.
- B단계에서 채우는 일반화한 답은 아래 꼴입니다. 날 답의 문장 하나가 번호 하나이고, 번호는 날 답의 문장 순서와 같습니다. 그래서 칼럼의 `<!-- 근거: Q2-3 -->`은 날 답과 일반화한 답 어느 쪽에서도 같은 문장을 가리킵니다(`column-format.md` 2장).

```markdown
### 답

(일반화한 답, 날 답 받은 날 YYYY-MM-DD, 일반화한 날 YYYY-MM-DD)

1. 한 제조 고객사의 사내 규정 검색 과제였습니다.
2. 모델 쪽은 처음에 큰 문제가 없었습니다.
3. (뺌: 공개 여부 확인 필요, G16. "저자에게 확인할 것" 1번)
```

- 칼럼에 쓰지 않을 문장(G16, G17처럼 공개 여부 문제)도 번호는 남기고 내용은 "(뺌: 사유, 규칙 번호)"로 둡니다. 번호가 밀리면 근거 주석이 엉뚱한 문장을 가리키기 때문이에요.
- 일반화 목록과 저자에게 확인할 것에는 원래 고유명사와 숫자를 적지 않습니다. 원래 값은 날 답 파일에만 있어야 민감 정보가 커밋되지 않습니다.
- 3권 맺음말 "저자의 마지막 현장 노트"의 공개 파일은 `vol3-physical-ai/epilogue-interview.md`, 날 답 파일은 `_private/interviews/vol3-epilogue.md`입니다. 서식은 같고, 머리표 "권, 장" 칸에 "3권 맺음말"을 씁니다.

## 4. 날 답 파일 서식

```markdown
# {권}권 {N}장 날 답 (커밋 금지)

<!-- _private/ 아래 파일이라 git이 무시한다. 원래 값은 이 파일에만 둔다. 공개 파일: vol{권}-*/ch{NN}/interview.md -->

| 항목 | 값 |
|---|---|
| 받은 날 | YYYY-MM-DD |
| 받은 방식 | 저자 작성 / 구술, 에이전트 받아 적음 |

## 질문 1 답

{저자 원문 그대로}

## 질문 2 답

## 질문 3 답
```

- 질문 문장은 옮기지 않습니다. 질문의 정본은 공개 파일 하나뿐이에요.
- 저자가 답을 고쳐 다시 주면 원문을 덮어쓰지 않고 `## 질문 1 답 (YYYY-MM-DD 수정)`처럼 아래에 더합니다. 일반화한 답과 근거 주석은 최신 답 기준으로 다시 맞춥니다.

## 5. 상태 값

| 상태 | 뜻 | 바꾸는 사람 | 다음 단계 |
|---|---|---|---|
| (없음) | 장 폴더 골격만 있음 | 에이전트 | A |
| 답변 대기 | 질문 3개가 있고 날 답이 아직 없음 | 에이전트 | 저자 답 |
| 답변 받음 | 날 답 파일에 저자 답이 있음. `interview.md` 답 칸은 아직 비어 있음 | 저자, 또는 구술을 받아 적은 에이전트 | B |
| 칼럼 초안 | 답 칸에 일반화한 답이, `.box-field`에 다듬은 칼럼이 있고 저자 확인 전 | 에이전트 | 저자 확인 |
| 저자 승인 | 저자가 칼럼을 승인함 | 저자만 | 끝(사이클 ⑦) |
| 대체 | 저자가 현장 들여다보기로 바꾸기로 함. 사유와 결정자를 머리표 아래 한 줄로 적음 | 저자 결정을 받아 에이전트 | C |
| 대체 출처 대기 | 대체를 정했지만 쓸 출처 키가 없어 출처 요청 중 | 에이전트 | researcher, 그 뒤 C |
| 들여다보기 초안 | 현장 들여다보기 해설이 있고 저자 확인과 출처 확인 전 | 에이전트 | 저자 확인 |

`저자 승인`과 `대체`의 결정은 에이전트가 스스로 적지 않습니다. 대화에서 저자가 분명히 말했을 때만 그 문장을 근거로 적어요(예: `대체: 2026-10-15 저자 결정, 사유 "보안 정책상 공개 어려움"`).

## 6. 공개 가능 여부 값

| 값 | 뜻 | B단계 진행 |
|---|---|---|
| 미확인 | 저자가 아직 정하지 않음 | 진행하되 칼럼 초안을 보여 줄 때 공개 점검 체크를 부탁합니다 |
| 공개 가능(일반화 조건) | 일반화하면 실어도 됨 | 진행 |
| 일부 공개 | 질문 번호나 내용 일부만 공개 가능 | 공개 가능한 답만 근거 단위로 씀 |
| 공개 불가 | 실을 수 없음 | 멈춤. C단계로 갈지 저자에게 묻습니다 |

## 7. 채운 예시 머리표(1권 4장)

A단계를 마친 직후의 모습입니다. 질문 문장은 `question-design.md` 4장 예시를 그대로 썼어요.

```markdown
| 공개 가능 여부 | 미확인 |

```
