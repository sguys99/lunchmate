## 2. 번들 요약 (gzip, 추정)

- **새 의존성 없음.** 세 안 모두 NumberFlow(`RollingNumber`, `DeadlineCountdown`, 약 5.6 KB, 투표 화면에서만), Lucide 아이콘, 공용 Badge, Avatar(Base UI Avatar, 수 KB), CSS 전환(`@starting-style`)만 씁니다.
- **확정 축하는 canvas-confetti 없이** DESIGN.md 7장대로 display 세리프 한 줄 페이드 + 1위 바 차오름입니다(세 안 공통, +0).
- **투표방은 홈 첫 로드 밖**(`/poll/[code]`)이라 홈 200 KB 예산과 무관합니다. 투표방 자체 첫 로드는 앱 셸 + NumberFlow + 화면 코드로, 세 안 차이는 1 KB 안팎으로 봅니다. 실제 값은 T7.5 선택 뒤 `pnpm build`로 재서 `docs/design/bundle-log.md`에 남깁니다.
- Realtime(Supabase 채널)은 세 안이 같으므로 비교에서 뺐습니다(T7.16에서 측정).

## 3. 공통으로 지킨 것

- **틀**: 앱 셸 하단 탭(투표 활성), 머리줄은 뒤로(이름 "투표 목록으로") + 공유 + 방장만 ⋯(이름 "투표 관리 더 보기", 메뉴 "링크 복사", "투표 취소하기" → 그 자리 확인 상자, POLL-12). 데스크톱 1280은 좌 리스트 + 우 지도 자리(후보 핀, 1위나 확정 핀만 올리브).
- **올리브 면 버튼은 화면에 하나**: 안 찍음 "투표하기"(안 고르면 꺼진 모양 "후보를 골라 주세요"), 찍음 "선택 바꾸기"(테두리) + 참여자는 "투표 취소"(글자) / 방장은 "지금 결정하기"(primary). 방장이 안 찍었을 때는 "투표하기"(primary) + "결정하기"(테두리). 결정은 확인 상자("지금 마감할까요?")를 한 번 거칩니다.
- **득표 바**: DESIGN.md 5장 그대로, 트랙 `vote-bar-track` 8px, 1위만 `vote-bar`(올리브), 나머지 `chart-3`, 숫자는 NumberFlow + tabular-nums. 처음 보일 때와 값이 바뀔 때 slow(520ms) emphasized로 차오릅니다(축소 모드 즉시).
- **카운트다운**: 공용 `DeadlineCountdown`(role="timer", 매초 읽지 않고 이름에 남은 시간 문장). 첫 렌더는 같은 폭 자리.
- **실시간**: 평소 머리줄에 초록 점 + "실시간"(스크린 리더 "득표가 실시간으로 갱신됩니다"), 끊기면(`?live=lost`) 위아래 헤어라인 한 줄 "실시간 연결이 끊겼습니다. 다시 연결하는 중입니다." + "다시 연결". 다른 사람 표는 `role="status"`로 "새싹 님이 투표했습니다"를 읽습니다(`?sim=on`).
- **기피 경고(POLL-13)**: 배지 "못 먹는 분 있음"(warning, 유일한 의미 색) + 목록 아래 caption 한 줄 "참여자 중 이 식당 음식을 피하는 분이 있습니다. 누구인지는 알리지 않습니다."
- **할인 배지(DEAL-05)**: 후보에 "할인"(제보 출처) + "제보". 제휴 배지는 두지 않습니다. 카드 배지 최대 2개(pickBadges 그대로, C 타일은 1개).
- **이름 해석 실패(T0.16, T5.12a)**: 그림 자리는 점선 빈 원, 이름 "후보 2" + "카카오맵에서 보기"(새 창, `place_url`). 득표와 고르기는 그대로 됩니다.
- **비로그인 미리보기(POLL-05)**: 제목, 후보 이름, 카운트다운, 참여 인원만. 득표는 숨기고 "득표는 참여한 뒤에 보입니다." 하단 "로그인하고 투표하기"(primary) + "로그인하면 이 투표로 돌아옵니다."(D-08 문장과 같은 말).
- **후보 제안(POLL-07)**: 참여자는 목록 아래 "후보 제안" 글자 버튼(후보 고르기 시트는 T7.2와 같은 시트, 시안은 알림만) → "제안을 보냈습니다. 방장이 승인하면 후보에 들어갑니다." 방장은 "제안받은 후보" 점선 줄 + 거절(글자) / 승인(테두리). 5곳이면 "후보는 5곳까지 담을 수 있습니다."
- **동점(POLL-08)**: 방장은 "2곳이 동점입니다 / 직접 고를까요, 룰렛에 맡길까요?" + 동점 후보를 눌러 "○○으로 정하기"(primary) 또는 "룰렛에 맡기기"(테두리). 룰렛은 그냥 골라줘 R1 리듬(60 → 260ms, 2초)으로 동점 후보를 번갈아 비추다 멈춥니다(축소 모드는 바로 결과). 참여자는 "방장이 동점을 정하는 중입니다."
- **결과(POLL-09)**: 맨 위 "오늘 점심은 여기로 정했어요."(display 세리프, slow 페이드), 정해진 방식 한 줄("마감 시각에 정해졌습니다." / "방장이 마감했습니다." / "동점이라 룰렛으로 정했습니다."), 확정 식당, 득표 결과, "참여한 분 모두의 방문 기록에 후보로 담았습니다. 내일 어땠는지 묻습니다."(AC-POLL-5), 하단 "길찾기"(primary) + "결과 공유"(테두리, 이미지는 T7.4).
- **못 들어가는 방**: 만료(POLL-11) "마감된 투표입니다", 인원 초과 "참여 인원이 가득 찼습니다", 방장 취소 "방장이 투표를 취소했습니다"(copy-guide 4.7 문장). 공용 EmptyState + 그림.
- **4상태**: 로딩은 머리 + 후보 줄(B는 카드) 뼈대, 빈 상태는 득표 0인 방("아직 투표한 사람이 없습니다. 먼저 골라볼까요?" 한 줄 + 바 0), 오류는 투표방 불러오기 실패(공용 ErrorState + 다시 시도), 투표 전송 실패(`fail=vote`)는 "투표를 보내지 못했습니다. 고른 곳은 그대로 있습니다." + "다시 보내기", 오프라인은 마지막 득표를 보이고 "오프라인입니다. 마지막으로 받은 득표입니다. 연결되면 투표할 수 있습니다." + 꺼진 주 버튼.
- **접근성**: axe 검사 240건 통과(`e2e/a11y-g7-poll.spec.ts`, 3안 × 18쿼리 + 투표한 뒤 + 방장 취소 확인 × 라이트, 다크 × 모바일, 데스크톱). 후보 목록은 `radiogroup` 안에 목록(ul)을 두는 구조(listitem 규칙). 후보 고르기는 `radiogroup`/`radio`(복수면 `group`/`checkbox`), 후보 이름과 득표 수가 이름에 들어갑니다. 확인 상자는 열리면 첫 버튼으로 포커스, 방장 메뉴는 Esc로 닫히고 버튼으로 포커스가 돌아갑니다(실제 구현은 Base UI Menu). 모든 전환은 `motion-safe:`로 꺼집니다.
