# 7단계 회식 모드 비교 자료 (T7.3 → ⛔ T7.5)

> ⛔ T7.5 선택 게이트에서 사용자에게 보여 줄 자료입니다. 회식 모드 시안 하나(또는 조합)를 고르고 아래 5절 안건을 함께 정합니다.
> 비교하는 것은 **조건을 받는 흐름**(한 장 / 한 질문씩 / 결과 먼저)과 **후보 5곳과 근거를 보여 주는 그릇**(번호 목록 / 비교표 / 지도 띠 + 목록)입니다. 근거 표시 규칙과 4상태 문구는 세 안이 같습니다(3절).
> 캡처는 2026-11-01 dev 서버(3102)에서 찍었습니다. 번들 수치는 `pnpm build` 없이 의존성으로 추정한 값입니다(2절).
> 시안 라우트: `/design-lab/party/<a|b|c>`. 쿼리 규약(`src/features/design-lab/party/params.ts`):
> `?state=ready|loading|empty|error|offline`, `?view=form|results`(A, B 단계, C는 늘 결과), `?q=1|2|3|4`(B 질문),
> `?edit=people|budget|room|alcohol`(C 조건 고치기 칸), `?few=on`(5곳 미만, 2곳), `?cold=on`(근거 대부분 정보 없음), `?active=1..5`(고른 후보, 지도 핀 강조, B는 펼친 줄).
> 관련 요구사항: PRD PARTY-01~05, 4.4 흐름, REC-10(홈 진입점), POLL-01(후보 2~5), 10.2 `party_searched`, copy-guide 4.2, 4.3, 4.8, tasks T7.25~T7.28.

## 2. 번들 요약 (gzip, 추정)

- **새 의존성은 없습니다.** 세 안 모두 공용 Slider(Base UI), Chip(Base UI ToggleGroup), Lucide 아이콘, CSS 전환만 씁니다. C만 Checkbox(Base UI)를 더 씁니다.
- **홈 첫 로드 영향은 세 안 모두 0입니다.** 회식 모드는 홈의 "회식 모드" 글자 링크(REC-10, 이미 있음)로 들어가는 별도 경로라 홈 묶음에 들어가지 않습니다.
- 회식 화면 자체 묶음(추정): Slider 약 6~8 KB, ToggleGroup 약 3 KB, Checkbox 약 3 KB(C만), 화면 코드 약 4~6 KB. A와 B는 약 +13~17 KB, C는 약 +16~20 KB.
- 실제 화면의 지도는 지도 탭과 같은 `MapProvider`를 동적 import합니다. **C는 모바일에서도 첫 화면에 지도 띠가 있어 지도 SDK를 바로 불러옵니다**(A, B는 데스크톱 오른쪽 칸에서만). 지도 SDK 몫은 지도 탭과 같고 캐시를 공유합니다.
- `pnpm build`로 잰 값은 T7.5 선택 뒤 `docs/design/bundle-log.md`에 남깁니다.

## 3. 공통으로 지킨 것

- **틀**: 투표 탭 안 화면(하단 탭 "투표" 활성). 머리는 뒤로(이름 "투표로 돌아가기") + 눈썹 "회식 모드" + 세리프 title + 고정 안내 한 줄 "회식은 저녁 기준, 도보 15분 안에서 찾습니다."(PARTY-02, copy-guide 4.8). 데스크톱 1024px 이상은 좌 리스트(최대 460) + 우 지도 2단(홈 D1, 지도 B와 같은 틀).
- **지도 자리**: 회사 핀(마름모) + 도보 15분 점선 원 + 번호 핀 1~5. 목록 줄 앞의 번호 원과 핀이 같은 모양(28px 원, 고르면 올리브 면)이라 둘을 눈으로 잇습니다. 고른 핀은 이름 알약이 붙습니다(지도 B의 "고른 마커" 문법).
- **후보 한 곳 = 카테고리(잉크 색) + 식당명 + 숫자 3칸(도보 분 | 1인 가격대 | 만족 %) + 근거 줄.** 숫자 칸은 DESIGN.md 숫자 규칙(라벨 위, 숫자 아래, 1px 세로선)을 numeric-md 크기로 씁니다. 가격 제보가 없으면 카테고리 저녁 추정가에 "1인 추정" 라벨(T5.13 `EstimateMark`와 같은 뜻), 후기 3건 미만이면 "후기 적음".
- **근거 표시 3단계 (PARTY-03, 04)**: 색에만 기대지 않게 모양이 모두 다릅니다.
  - 제보로 확인: 올리브 원 안 흰 체크. `3.2만 원대 제보 6건`, `룸 있음 제보 4건`, `단체석 제보 3건`, `술집`.
  - 카테고리로 추정: 점선 원 안 회색 체크. `2.5만 원대, 카테고리 추정`, `고기, 저녁 주류 흔함`.
  - 정보 없음: 회색 가로줄 + `정보 없음, 네이버 플레이스에서 확인`(밑줄 링크, 새 탭, 이름은 "○○ 네이버 플레이스에서 확인").
  - 근거 줄 앞에는 조건 라벨(1인 예산, 룸/단체석, 주류)을 고정 폭 칸에 둬서 다섯 곳의 근거가 세로로 맞습니다. 끈 조건(룸, 주류)은 줄을 만들지 않습니다. 맨 아래 "표시 뜻" 한 줄(제보로 확인 / 카테고리로 추정 / 정보 없음).
- **고르는 규칙(시안 목업, 실제는 T7.27, 안건 2~5)**: 하드 필터는 주류(카페, 분식, 샐러드, 패스트푸드 제외)와 예산(가격 제보가 있고 예산을 넘을 때만, 홈 추천과 같은 규칙). 룸/단체석은 하드 필터가 아니라 **순서에만** 씁니다(PRD 축소안). 순서는 제보로 확인된 조건 수 → 추천 점수. 할인은 쓰지 않습니다(AC-DEAL-2). 목업은 `src/features/design-lab/party/mock.ts`의 순수 함수라 실제 화면으로 그대로 옮길 수 있습니다(단위 테스트 5건).
- **4상태와 예외**
  - 로딩: 목록 자리 번호 원 + 막대 4줄 뼈대 × 5, 지도는 회사와 원만. `aria-busy` + "회식 후보를 찾는 중입니다".
  - 0곳: 빈 상태 "도보 15분 안에 조건에 맞는 곳이 없습니다 / 1인 예산을 조금 올려볼까요?" + "예산 바꾸기"(이때만 주 버튼, 하단 투표 버튼은 숨김).
  - 5곳 미만(2곳): 목록 아래 테두리 상자 "조건에 맞는 곳이 2곳뿐입니다 / 1인 예산을 조금 올려볼까요?" + "예산 바꾸기"(보조). 투표는 2곳으로도 만들 수 있습니다(POLL-01).
  - 오류(카카오 재시도 1회 뒤): "식당 정보를 불러오지 못했습니다 / 잠시 후 다시 시도해 주세요." + 다시 시도 + "네이버 지도에서 주변 식당 보기"(PRD 12장, copy-guide 4.3).
  - 오프라인: 결과 자리는 "인터넷에 연결되어 있지 않습니다 / 연결되면 회식 후보를 찾아 드립니다.", 조건 입력 화면은 입력을 그대로 두고 찾기 버튼 위 한 줄 "연결되면 후보를 찾을 수 있습니다." + 버튼 `aria-disabled`.
  - 콜드 스타트(근거 60% 넘게 추정이나 정보 없음): 목록 위 왼쪽 선 한 덩어리 "아직 제보가 적은 동네입니다 / 정보 없음은 네이버 플레이스에서 확인해 주세요. 다녀온 뒤 남긴 태그가 다음 회식의 근거가 됩니다."
- **장소 데이터 규칙**: 식당 이름, 카테고리, 거리는 카카오 세션 값으로만 그립니다. 네이버 플레이스 링크는 이름으로 그 자리에서 만들고 저장하지 않습니다. 조건(인원, 예산, 토글)만 기기에 남길지가 안건 6입니다.
- 접근성: axe 검사 **140건 통과**(3안 × 첫 화면, 결과, 콜드, 5곳 미만, 4상태, 결과 오프라인 + B 질문 2~4와 오프라인, C 고치기 칸 3종과 핀 고름 × 라이트, 다크 × 모바일, 데스크톱, `e2e/a11y-g7-party.spec.ts`). 지도 핀은 버튼(`aria-pressed`, 이름 "1 달빛 이자카야"는 숨은 글자로, 보이는 글과 이름이 어긋나지 않게), 근거 아이콘은 비교표 칸에서 숨은 글자 "충족 / 추정 / 정보 없음"을 함께 읽습니다. 포인트 컬러 면 버튼은 화면에 하나(하단 찾기 또는 투표 만들기, 빈 상태에서는 "예산 바꾸기"). 모든 전환은 `motion-safe:`/`motion-reduce:`로 꺼집니다.

## 6. 품질 메모

- **고른 안을 구현할 때 고칠 것**
  - C 지도 띠: 390 × 844에서 1번 식당명이 첫 화면 아래 끝에 걸립니다. 띠 높이 160 → 136이나, 스크롤하면 띠가 접히는(sticky 축소) 방식을 검토합니다.
  - C 고치기 칸: 열릴 때 칸 제목으로 포커스, Esc로 닫기, 적용 뒤 문장의 그 낱말로 포커스 복귀(시안 미구현).
  - B를 처음 질문으로 쓰면: 질문 바뀜 포커스 이동, 두 줄 고르기를 Base UI Radio(화살표 키)로.
  - 지도 핀 위치는 시안 고정값입니다. 실제는 지도 B의 `MapProvider` 마커(도보 분 알약) 대신 **번호 알약**을 쓸지 정해야 합니다(지도 탭과 문법이 갈림, 안건 아님, 구현 때 확인).
  - 근거 링크 "네이버 플레이스에서 확인"은 이름 검색 URL(`map.naver.com/p/search/<이름>`)입니다. 카카오 `place_url`과 함께 "카카오맵에서 보기"도 둘지 구현 때 확인합니다.
