## 2. 번들 요약 (gzip, 추정)

- 새 의존성은 없습니다. 세 안 모두 공용 Chip(Base UI ToggleGroup), Lucide 아이콘, CSS 전환만 씁니다.
- **홈 첫 로드 영향은 세 안 모두 0에 가깝게 만들 수 있습니다.** 묻는 띠는 D1 그대로이고, 선택 입력 부품(가격 칩, 태그, 글 칸, 공개 범위)은 "가격, 태그 남기기"(A, B)나 한 탭(C)을 누른 뒤 동적 import로 불러옵니다. 이 묶음은 ToggleGroup 포함 약 **+4~6 KB**로 추정합니다(누른 뒤 로드).
  - C는 한 탭 직후 바로 첫 질문을 보여야 해서, 띠가 화면에 보인 뒤 유휴 시간에 미리 불러와야(prefetch) 누른 순간 빈 칸이 생기지 않습니다. 홈 첫 로드 예산에는 들어가지 않지만 홈 세션의 전송량은 A, B보다 조금 큽니다.
- **B: 시안은 CSS 틀, 실제는 Base UI Drawer.** 모달 시트라 tasks 2.4절대로 Drawer를 누른 뒤 지연 로딩합니다. 로그인 유도 시트(D-08)와 같은 덩어리를 공유하면 추가는 거의 없고, 처음 쓰는 경우 Drawer 몫(`g4-comparison.md` 2절 기준 약 +33.7 KB 묶음 안)이 누른 뒤 붙습니다.
- **A, C: 0.** 띠 안에서 펼치거나 바꾸므로 시트가 없습니다. A의 신고 메뉴를 실제 구현에서 Base UI Menu로 바꾸면 상세에서 그만큼(수 KB) 늘어납니다.
- `pnpm build`로 잰 값은 T6.4 선택 뒤 `docs/design/bundle-log.md`에 남깁니다.

## 3. 공통으로 지킨 것

- **띠는 D1 그대로**: 그림 36 + "어제 간 소담밥상, 어땠어요?" + 안 갔어요 / 👍 👎(44px, 이름 "좋았어요", "별로였어요"). 한 탭이면 고마움 한 줄로 접히고 누른 버튼 대신 그 줄로 포커스가 갑니다. 안 갔어요에는 선택 입력을 권하지 않습니다(FB-05).
- **가격은 칩이 기본입니다.** 이 식당의 추정가(카테고리 추정, T5.13)를 천 원 단위로 맞춰 가운데 두고 1천 원씩 벌린 칩(3~4개) + "직접". 칩 하나 누르면 끝이라 한 탭 원칙을 지키고, 직접 입력은 숫자 키패드(`inputMode="numeric"`)에 오른쪽 "원". 칩 이름은 "9천 원", "1만 1천 원"(`shortWon`). 추정가 근거 한 줄 "이 식당 추정 가격은 9천 원입니다."
- **태그 8종**(혼밥 OK, 15분 컷, 웨이팅 적음, 룸 있음, 단체석, 가성비, 양 많음, 조용함), 여러 개. 선택은 칩 테두리 1.5px 올리브(면 틴트 없음, DESIGN.md 칩).
- **한 줄 후기 100자**: 글자 수 `0/100`를 칸 안 오른쪽 아래에 두고(`aria-describedby`), 100자에서 더 받지 않습니다.
- **공개 범위 기본 공개**(FB-03): 칩 둘 "공개 / 나만 보기"(늘 하나는 골라짐). 바로 아래 **집계 포함 고지 한 줄을 늘** 둡니다: "나만 보기를 골라도 가격, 만족 여부, 태그는 이름 없이 식당 집계에 들어갑니다."(PRD 11.2, T6.28). 공개면 앞에 "닉네임과 방문 월만 함께 보입니다."를 붙입니다. 화면 문구에서는 "👍" 대신 "만족 여부"로 썼습니다(이모지가 쉼표 사이에서 어색하게 떠서, 안건 8).
- **상세에서 쓸 때는 한 탭 답을 맨 앞에서 묻습니다**(띠를 거치지 않았으므로). 답을 고르기 전에는 "남기기"가 `aria-disabled`입니다. 방문 기록이 함께 생긴다는 한 줄 "다녀왔다면 방문 기록도 함께 남습니다."(FB-06).
- **삭제는 한 번 더 묻습니다**(FB-07): "후기를 지울까요? / 가격, 만족 여부, 태그도 식당 집계에서 빠집니다. 방문 기록은 남습니다." + "지우기"(destructive 테두리) / "그대로 두기".
- **이름 해석 실패(`?state=error&fail=name`)**: 띠 그림 자리에 빈 원과 수저, 질문 "어제 가신 곳은 어땠어요?", 글자 버튼 줄에 "카카오맵에서 보기"(`place_url`, 새 탭). 한 탭은 그대로 됩니다. 글자 버튼이 둘 이상이면 360px에서 세 줄로 쌓여서, 띠 폭 전체를 쓰는 둘째 줄로 내렸습니다(세 안 공통, `__360-error-name`). 상세는 D-10 규칙(제목 "이름을 불러오지 못했습니다", 주 버튼 "카카오맵에서 보기")을 따릅니다.
- **4상태**: 로딩은 띠도 같은 높이(64) 뼈대. 빈 상태는 "물을 식사가 없는 날"(FB-04)이라 띠가 없고 추천은 정상. 오류는 "보내지 못했습니다" + "다시 보내기"(고른 답은 화면에 남음, 스크린 리더에 "고른 답은 이 화면에 남아 있습니다."). 오프라인은 D1대로 띠를 숨기고, 상세는 "후기 쓰기"를 끄고 "연결되면 후기를 쓸 수 있습니다." 한 줄, 다른 사람 후기 자리는 "연결되면 후기를 불러옵니다."
- **비공개 후기 텍스트는 목업에도 다른 사람 목록에 없습니다**(AC-FB-2). 내 후기의 공개 범위는 머리줄에 "10월 방문, 공개 / 나만 보기"로만 보입니다.
- **신고 시트는 T6.3 몫**이라 진입점만 두었고, 누르면 스크린 리더에 "신고 화면은 제보 시안(T6.3)에서 정합니다."만 알립니다.
- 접근성: axe 검사 216건 통과(3안 × 17쿼리 + 좋았어요 누른 뒤 × 라이트, 다크 × 모바일, 데스크톱, `e2e/a11y-g6-feedback.spec.ts`). 아이콘 버튼은 모두 이름이 있습니다(`좋았어요`, `별로였어요`, `후기 쓰기 닫기`, `500원 내리기`, `500원 올리기`, `이전 단계`, `점심탐험가 후기 더 보기`). 칩 묶음은 `role="group"` + 제목으로 이름을 받습니다. 제목 단계는 홈 띠 안 h2, 상세와 시트 안 h3. 모든 전환은 `motion-safe:`/`motion-reduce:`로 꺼집니다. 포인트 컬러 면 버튼은 화면에 하나(A, C는 하단 길찾기, B는 시트가 떠 있는 동안 시트의 "남기기" 하나이고 뒤 화면은 `inert`).

## 6. 캡처에서 본 품질 메모 (선택과 무관하게 구현 때 고칠 것)

- **B 시트 높이**: 390 × 844에서 한 줄 후기와 공개 범위가 스크롤 아래에 있습니다. 하단 "남기기"는 고정이라 누를 수 있지만, 고지 한 줄이 처음에 안 보입니다. 스테퍼와 칩 사이 간격을 줄이거나 태그 격자 행 높이를 40으로 두는 정도로 한 화면에 넣어 볼 만합니다.
- **B 시트의 칩을 누른 뒤 스크롤 위치**: "나만 보기"를 누르면 시트 안이 아래로 스크롤된 채 남습니다(`__compose-filled`). 실제 Drawer에서는 스크롤 영역과 하단 버튼 사이에 위 그림자 대신 1px 선만 둡니다(시안과 같음).
- **A 펼침 높이**: 가격 칩 5개가 2줄이 됩니다. 칩을 4개(직접 포함)로 줄이면 390에서 1줄이 됩니다.
- **C 자동 넘김 지연 220ms**: 고른 칩이 보인 뒤 넘어가도록 둔 값입니다. 축소 모드에서도 같은 대기(움직임이 아니라 대기)입니다.
- **테두리 버튼 클래스**: 공용 `buttonClass()`(cn 없는 이어 붙이기)는 기본 `border-transparent`와 variant의 `border-border`가 겹쳐 테두리 버튼이 투명해질 수 있습니다. 시안은 `cn(buttonClass(...))`로 감쌌습니다. 공용 함수 쪽 점검이 필요합니다(오류 화면 등 다른 사용처 확인).
- 상세 화면은 D-10 본문(숫자 3칸, 접힘 행)을 생략한 틀이라, 구현 때 "내 후기"는 D-10의 "내 방문 기록 한 줄" 아래, 다른 사람 후기는 접힘 행 "후기" 안에 넣습니다.
