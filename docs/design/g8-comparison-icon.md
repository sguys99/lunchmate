# 8단계 앱 아이콘과 스플래시 비교 자료 (T8.1 ⛔ 선택)

> ⛔ T8.1 선택 게이트에서 보여 줄 자료입니다. 아이콘 시안 하나(또는 조합)를 고르고 5절 안건을 함께 정합니다. PNG 생성과 매니페스트 교체는 T8.2에서 합니다.
> 한 시안 페이지 안에 아이콘이 실제로 쓰이는 자리를 모두 모았습니다: (1) 홈 화면(iOS 60px, 둥근 사각 마스크, 밝은/어두운 배경화면), (2) 크기별 원본 512, 192, 180, 48, (3) 안드로이드 maskable 마스크 4종과 지름 80% 안전 원, (4) 파비콘 16, 32px(브라우저 탭 모형), (5) OG 이미지 왼쪽 위 24px 기호(D-17 안건 12), (6) 스플래시(iOS 시작 이미지 라이트/다크, 안드로이드 background_color), (7) 스플래시에서 첫 화면으로 넘어가는 전환.

## 2. 번들과 생성 비용

- **새 의존성 없음, 앱 번들 영향 0.** 시안 코드는 `/design-lab` 안에만 있습니다. 스플래시 전환 흉내는 CSS 전환(Motion 0)입니다.
- 아이콘 원본은 SVG 컴포넌트 하나(`src/features/design-lab/app-icon/art.tsx`, 4안 합쳐 약 7 KB 소스). 실제 파일로 내보내면 SVG 파비콘은 안마다 0.4~0.9 KB입니다(B는 글자를 패스로 바꾸면 약 1.5 KB).
- T8.2 산출물 추정: PNG 아이콘 5장(192, 512 any와 maskable, apple 180) 합쳐 약 15~30 KB, iOS 시작 이미지는 기기 크기마다 1장씩이라 라이트/다크 합쳐 20~30장, 장당 10~25 KB(단색 바탕 + 작은 그림이라 압축이 잘 됨). 시작 이미지는 `media` 조건이 맞는 1장만 내려받습니다.

## 3. 공통으로 지킨 것

- **안전 원**: 모든 그림이 중심 지름 80% 원 안에 듭니다(W3C maskable 규격). 그래서 한 그림을 iOS 둥근 사각, 안드로이드 원형, 스쿼클, 물방울 어디에 넣어도 잘리지 않습니다(마스크 섹션의 붉은 점선).
- **크기별 세부 3단계**: full(96px 이상) 잔선 포함, small(40~95) 잔선 빼고 선 굵게, tiny(40 미만, 파비콘과 OG 기호) 따로 다듬은 최소 형태. 일러스트 `strokeWidthFor`와 같은 생각입니다(큰 크기 그림을 그냥 줄이지 않음).
- **색은 생성 상수만**: 앱 아이콘은 기기 테마와 무관하게 늘 같은 색이어야 해서 CSS 변수(다크에서 바뀜) 대신 `sharePalette`(`pnpm tokens`가 DESIGN.md color.light에서 만든 생성 상수)를 씁니다. 하드코딩 색 0, `pnpm lint`(check-css-colors 포함) 통과. 다크 틀은 `.dark` 범위 + 토큰입니다.
- **올리브 한 군데**: OG 기호는 글자색 한 가지(단색)로 그렸습니다. 색 그대로 넣으면 OG의 올리브(제목 밑 선, 1위 바)와 겹쳐 두 군데가 됩니다(D-17 "올리브는 이미지마다 한 군데", OG 섹션 "비교: 색 그대로 넣으면").
- **4상태 매핑**: 아이콘 페이지에는 데이터가 없어서 상태를 뜻으로 옮겼습니다.
  - `loading` = 스플래시를 멈춘 모습(첫 화면이 그려지기 전).
  - `empty` = **해당 없음.** 아이콘에는 "없음" 상태가 없어 안내 한 줄과 기본 화면을 그대로 보여 줍니다.
  - `error` = 잘못 만든 경우: maskable이 아닌 아이콘을 안드로이드 원형 런처가 흰 원 안에 작게 줄여 넣은 모습과 올바른 모습 비교.
  - `offline` = 오프라인 첫 화면(T8.3)에 들어갈 아이콘 자리(아이콘 48 + "연결이 끊겼습니다" + 자동 새로고침 안내).
- **다크 모드**: 페이지 전체 다크 캡처 + 페이지 안 어두운 배경화면, 어두운 탭, 다크 스플래시 틀. "라이트"로 이름 붙인 틀은 페이지 테마와 무관하게 늘 밝게 그렸습니다(tokens.css에 `.light` 범위 선택자가 없어 생성 상수 색을 직접 검).
- **모션**: 스플래시가 사라지고 첫 화면이 보이는 순간을 180ms 페이드로 흉내 냈습니다("다시 보기" 버튼, 자동 재생 없음, `motion-reduce`면 즉시). 바탕을 앱 배경과 같은 색으로 두면 번쩍임 없이 그림만 옅어집니다. **앱 안에 스플래시 오버레이를 새로 만들자는 뜻은 아닙니다**(안건 8).
- **문구**: `src/copy/design-lab-app-icon.ts`(금지 문자 0, 설명은 습니다체).

## 6. 품질 메모

- 아이콘 그림은 viewBox 100 하나에 크기별 세부 단계를 넣었습니다. 크기를 바꾸면 선 굵기와 잔선이 자동으로 바뀌므로 T8.2 생성 스크립트는 크기마다 같은 컴포넌트를 렌더하면 됩니다.
- C의 앞 카드에는 바탕색 테두리를 둘러 뒤 카드 선과 떨어져 보이게 했습니다. 512에서 앞 카드 위 모서리와 뒤 카드 선이 맞닿는 곳이 있어 고르면 T8.2에서 회전각(지금 16도)이나 앞 카드 높이를 1~2 단위 조정합니다.
- B의 글자는 웹 글꼴(마루 부리 Regular, KS X 1001 서브셋)로 그립니다. 글꼴이 늦게 오면 대체 세리프로 그려지므로 PNG 생성은 `document.fonts.ready` 뒤에 찍어야 하고, SVG 파일은 글자를 패스로 바꿔야 합니다.
- 페이지 안 "라이트" 틀은 다크 페이지에서도 밝게 보이도록 생성 상수 색을 직접 걸었습니다. tokens.css가 `.dark`만 아무 요소에 걸 수 있어서입니다(공유 확인 화면과 같은 처리).
- shots 스크립트는 경로의 쿼리를 파일 이름에 넣지 않습니다. `?tone=olive` 캡처가 기본 캡처를 덮어써서 이름을 바꾸고 기본을 다시 찍었습니다. 쿼리 변형을 자주 찍는다면 스크립트에 쿼리 슬러그를 넣는 개선이 필요합니다(이번에는 고치지 않음).
- `[실기기]` 확인이 필요한 것: iOS Safari 홈 화면 추가 후 아이콘과 시작 이미지(라이트/다크), 안드로이드 Chrome 설치 후 스플래시와 원형 런처 마스크, 카카오톡 인앱 브라우저에서 파비콘 표시. Claude가 대신 확인하지 못했습니다.
