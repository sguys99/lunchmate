# 7단계 투표 만들기 비교 자료 (T7.2 → ⛔ T7.5)

> ⛔ T7.5 선택 게이트에서 사용자에게 보여 줄 자료입니다. 투표 만들기 흐름 하나(또는 조합)를 고르고 아래 5절 안건을 함께 정합니다.
> 비교하는 것은 **투표방이 생기기까지의 흐름**입니다: 빠른 투표(POLL-02, 오늘 카드 3장), 상세에서 한 곳(투표에 추가), 회식 후보 5곳(PARTY-05)에서 시작해 제목, 마감, 방식, 후보를 정하고 친구에게 보내기(POLL-03)까지. 투표방 화면 자체는 T7.1, 링크 미리보기 실제 모양은 T7.4가 정합니다.
> 캡처는 2026-11-01 dev 서버(3102)에서 찍었습니다. 번들 수치는 `pnpm build` 없이 의존성으로 추정한 값입니다(2절).
> 시안 라우트: `/design-lab/poll-create/<a|b|c>`. 쿼리 규약(`src/features/design-lab/poll-create/params.ts`):
> `?state=ready|loading|empty|error|offline`, `?state=error&fail=save|limit|share`, `?flow=home|compose|pick|share|edit`,
> `?step=1|2|3`(B), `?entry=home|detail|party`, `?clock=noon|late`(목업 현재 시각 11:05 / 11:45), `?field=deadline|title|candidates|mode`(C의 edit).
> 관련 요구사항: PRD POLL-01, POLL-02, POLL-03, POLL-04(미리보기에 식당 이름 없음), PARTY-05, MOD-05(하루 10개), REC-10(홈 진입점), 10.2 `poll_created`, `poll_link_shared`, `poll_candidate_added`, tasks T7.6(기준점), T7.11~T7.13.

## 2. 번들 요약 (gzip, 추정)

- 새 의존성은 없습니다. 세 안 모두 공용 Chip(Base UI ToggleGroup), Lucide 아이콘, CSS 전환만 씁니다. NumberFlow와 Motion은 쓰지 않습니다.
- **홈 첫 로드 영향은 세 안 모두 0입니다.** 홈에 늘어나는 것은 이미 있는 진입점 글자 버튼 둘(`today-screen.tsx` Entries, `pollEntry` 플래그)뿐이고, 시트는 누른 뒤 지연 로딩합니다.
- **시트 묶음**: Base UI Drawer(로그인 유도 시트, 후기 시트와 공유, `g4-comparison.md` 2절 기준 약 +33.7 KB 묶음 안) + 이 화면 부품 약 +5~7 KB(후보 줄, 마감, 방식, 보내기). 카카오 JS SDK 공유는 "카카오톡으로 보내기"를 누를 때 받습니다(T7.13).
- **C는 누르는 순간 서버에 만들고 보내기 시트를 바로 보여야 해서**, 진입점이 화면에 보이거나 손이 닿으면(hover, focus, touchstart) 시트 묶음을 미리 받아야 빈 프레임이 생기지 않습니다(그냥 골라줘 결과 패널과 같은 방식, DESIGN.md 5장). 홈 첫 로드 예산 밖이지만 홈 세션 전송량은 A, B보다 조금 큽니다.
- `pnpm build`로 잰 값은 T7.5 선택 뒤 `docs/design/bundle-log.md`에 남깁니다.

## 3. 공통으로 지킨 것

- **진입점은 지금 홈 그대로**: 대안 카드 아래 밑줄 글자 버튼 "친구랑 정하기", "회식 모드"(REC-10, T5.23). 시안에서는 "회식 모드"를 누르면 회식 모드의 "이 후보로 투표 만들기"(PARTY-05)를 흉내 내 후보 5곳으로 엽니다. 상세 더 보기의 "투표에 추가"는 `?entry=detail`로 봅니다(눈썹 "정담국밥에서").
- **기본값 (POLL-01)**: 제목 "수요일 점심"(회식은 "수요일 회식"), 마감 30분 뒤(회식은 오늘 18:00), 한 곳만. 빠른 투표 후보는 오늘 카드 3장 그대로.
- **마감 빠른 선택**: 점심 "10분 뒤 / 30분 뒤 / 11:30 / 직접". **11:30이 지났거나 10분 안이면 그 칩 대신 "1시간 뒤"**(`?clock=late`, 칩 아래 "11:30이 지나 1시간 뒤를 대신 보여 줍니다."). 회식 "1시간 뒤 / 오늘 18:00 / 내일 12:00 / 직접". 직접은 `<input type="time">` 5분 단위, 지금부터 10분 뒤부터. 칩 아래 한 줄이 늘 절대 시각을 말합니다("11:35에 마감합니다.", `tabular-nums`, aria-live).
- **후보 2~5곳**: 개수는 "3/5". 1곳이면 "후보를 한 곳 더 넣어 주세요."(만들기 꺼짐, `aria-disabled`), 5곳이면 넣지 않은 줄이 50%로 꺼지고 "후보는 5곳까지입니다. 하나를 빼면 더 넣을 수 있습니다." 같은 곳은 두 번 넣지 않습니다.
- **후보 줄**: 일러스트 40 + 이름 label + 메타 caption "국밥/탕 | 도보 4분 | 9천 원대"(카테고리 잉크 색, 1px 세로선, 문자 구분자 없음) + 빼기 아이콘 44. 넣기 목록은 오른쪽 원 32(넣음은 1.5px 올리브 테두리 + 체크, 면 틴트 없음, DESIGN.md 칩 규칙). 즐겨찾기, 최근 간 곳은 DB의 `place_id`를 세션 이름으로 보여 줍니다(T5.12a).
- **카카오 데이터 규칙**: 만들 때 서버로 가는 것은 `place_id`, `place_url`, 순서와 투표방 설정(제목, 끼니, 마감, 방식, 기준점, 반경)뿐입니다(T7.6). 이름, 좌표, 카테고리, 거리는 화면에만 있습니다.
- **후보 이름 기준(기준점, T7.6)**: "후보 이름 기준 회사 핀 근처" + "기준 바꾸기"(지도에서 점 찍기) + "친구 화면에서 후보 이름을 이 위치 주변에서 찾습니다. 현위치는 쓰지 않습니다." 한 줄.
- **보내기 (POLL-03)**: 성공 표시(원 32 `success-surface` + 체크, slow 페이드) + "투표방을 만들었어요" heading 세리프 + "11:35까지 표를 받습니다. 친구에게 링크를 보내 주세요." → **친구에게 보이는 미리보기**(2:1 면에 "런치메이트", 제목, "후보 3곳, 11:35 마감", 아래 링크 한 줄. 식당 이름과 카테고리는 넣지 않음, POLL-04) + "미리보기에는 식당 이름이 나오지 않습니다. 이름은 링크를 연 뒤에 보입니다." → **"카카오톡으로 보내기"(올리브 면, 화면에 하나)** + "다른 앱으로"(Web Share) + "링크 복사"(누르면 체크와 "복사함", 스크린 리더 "링크를 복사했습니다.") + "투표방으로 가기" 글자 버튼.
- **4상태와 실패**: 로딩은 같은 자리 후보 줄 뼈대("후보를 불러오는 중입니다"). 빈 상태는 점선 상자 "넣을 후보가 아직 없습니다" + "지도에서 고르기"(만들기 꺼짐). 만들기 실패는 하단 줄 위 안내 "투표방을 만들지 못했습니다 / 고른 내용은 그대로 있습니다." + 버튼이 "다시 만들기"로(토스트만으로 알리지 않음, 자동 재시도 1회 뒤). **하루 한도(MOD-05)** "오늘 만들 수 있는 투표를 모두 만들었습니다 / 투표방은 하루 10개까지 만들 수 있습니다. 내일 다시 만들 수 있습니다." + "진행 중인 투표 보기", 만들기 꺼짐. **공유 실패** "카카오톡을 열지 못했습니다 / 링크를 복사해 대화방에 붙여 넣어 주세요." + 링크 복사가 주 버튼. 오프라인 "연결되면 만들 수 있습니다 / 고른 내용은 이 화면에 남아 있습니다."(만들기 꺼짐). 오류 글자만 `destructive`, 빨간 면 없음.
- **시트**: 모달 바텀시트(위 라운드 28, 손잡이, 딤 32%, 뒤 화면 `inert`, 제목 포커스, Esc, 닫히면 연 버튼으로 포커스 복귀). 데스크톱은 가운데 대화상자(최대 448). 하단 고정 줄 위 1px 선.
- 접근성: axe 검사 180건 통과(3안 × 12~14쿼리 + 열고 닫기 포커스 × 라이트, 다크 × 모바일, 데스크톱, `e2e/a11y-g7-poll-create.spec.ts`). 넣기 토글은 `aria-pressed`, 이름은 보이는 글자 + sr-only "후보에 넣기"(label-content-name-mismatch를 피해 aria-label을 쓰지 않음). B의 마감 큰 칸은 `radiogroup`/`radio`. 모든 전환은 `motion-safe:`로 꺼집니다. 목업 규칙 단위 테스트 9건(`poll-create-lab.test.ts`: 11:30 대체, 회식 칩, 직접 입력 하한, 만들 수 있는 조건, 쿼리).

## 6. 품질 메모

- C의 로딩(만드는 중)은 지금 후보 줄 뼈대라, 구현에서는 항목 줄 4개 뼈대 + 보내기 버튼 자리 뼈대로 바꿉니다.
- 시트 안 넣기 목록(A 펼침, B 1단계)은 즐겨찾기가 많으면 길어집니다. 구현에서 그룹마다 3개 + "더 보기"로 자릅니다.
- 포커스 복귀: 뒤 화면이 `inert`가 되면 연 버튼이 포커스를 잃어서, 누를 때 연 버튼을 기억해 두고 닫힐 때 다음 프레임에 돌려줍니다(`rememberOpener`). 실제 구현은 Base UI Drawer의 `finalFocus`로 같은 결과를 냅니다.
- 이름 해석 실패(T5.12a) 후보 줄: 이 화면의 후보는 모두 방장 세션에서 고른 곳이라 이름이 있습니다. 즐겨찾기, 최근 간 곳 중 이름을 못 찾은 곳은 넣기 목록에서 빼고(투표방 후보 이름이 순번으로 보이는 것을 막음) 나 탭에서 다룹니다.
- 미선택 시안 코드는 T7.5 뒤 구현을 마치고 지우고, 캡처와 이 문서는 남깁니다. axe 검사는 고른 안만 `e2e/a11y.spec.ts` 7단계 루프로 옮깁니다.
