> 캡처는 2026-10-31 dev 서버(3150)에서 찍었습니다. 번들 수치는 같은 날 `next build` + `scripts/bundle-report.mjs --route` 기준입니다(2절).
> 시안 라우트: `/design-lab/map/<a|b|c>` (쿼리 `?state=loading|empty|error|offline`, `?select=<식당 id>`, `?snap=peek|half|full`, `?filter=open`, `?moved=1`, `?map=naver`).
> 관련 요구사항: PRD MAP-01~06, PLACE-01~04(시트 안 내용), tasks T5.26~T5.32. 함께 볼 기록: `docs/design-decisions.md` D-05(홈 D1, 데스크톱 좌 리스트 + 우 지도), D-07(온보딩 지도 위 시트, 회사 핀 모양).

## 0. 세 안이 공통으로 한 것

- **지도는 MapProvider 경유.** 시안 지도는 `MapProvider` 인터페이스(`src/lib/map/types.ts`)를 그대로 구현한 목업 공급자(`src/features/design-lab/map/shared/lab-map-provider.ts`)입니다. 화면 코드는 `load → createMap → addMarker / addCircle / fitBounds / panTo` 순서로 실제 지도와 같은 길을 탑니다. 마커는 `addMarker`에 빈 DOM 요소를 넘기고 그 안을 React 포털로 그립니다(T5.27에서 네이버 구현체에 그대로 쓰는 방식). `?map=naver`를 붙이면 같은 화면이 실제 네이버 지도로 뜹니다(키와 도메인 등록 필요, 캡처는 목업).
- **목업 데이터.** 기존 가상 식당 12곳 + 서로 60m 안에 모인 "먹자골목" 3곳(클러스터 시연). 위치는 회사 핀에서 도보 분에 맞는 거리(도보 분 x 67 ÷ 1.3 m)에 놓았습니다. 카카오 데이터는 쓰지 않고 아무것도 저장하지 않습니다(CLAUDE.md 7장).
- **기준 위치와 반경 원(MAP-01)**: 온보딩과 같은 올리브 회사 핀 + 도보 10분 원(점선). 첫 화면은 원 전체가 "위 겹침(칩)과 아래 시트 사이 보이는 칸"에 들어오게 맞춥니다.
- **클러스터(MAP-02)**: 골목 세 곳이 한 마커로 묶이고, 누르면 그 자리로 다가가며 펼쳐집니다. 실제 구현은 네이버 MarkerClustering(T5.27).
- **필터(MAP-03)**: 카테고리(펼쳐 고름), 1만 원 이하, 도보 5분 안, 👍 상위(80% 이상), 즐겨찾기. 지도와 목록이 바로 바뀝니다. 0곳이면 "필터 모두 풀기" 빈 상태.
- **이 지역에서 다시 찾기(MAP-05)**: 사용자가 지도를 끌거나 방향키로 옮긴 뒤에만 나타납니다(코드가 옮긴 것은 제외).
- **데스크톱(MAP-06)**: 1024px 이상에서 좌 460 칸(시트 내용이 리스트가 됨) + 우 지도, 하단 탭은 좌 칸 아래. 홈 D1, 온보딩 B와 같은 틀입니다.
- **4상태**: 로딩(지도 자리 스켈레톤 + 목록 스켈레톤), 빈 상태(원 안 0곳, "15분까지 넓히기" 주 버튼), 오류(**지도 로딩 실패 시 목록 보기로 자동 전환, T5.32**: 실패 안내 + "지도 다시 불러오기" + 같은 목록, 식당을 고르면 목록 안에서 요약이 펼쳐짐), 오프라인(지도 자리 안내 + 시트에 오프라인 블록).
- **시트 끝까지 열림**은 식당 상세 시안(T5.2)이 채울 "상세 내용 자리"(점선 칸 네 개)만 두었습니다. 반쯤 열림 요약(카테고리, 식당명, 숫자 3칸, 이유, 길찾기 + 자세히)도 T5.2 결정을 따라 바뀝니다.
- **모션(모두 CSS, Motion 없음)**: 시트는 놓으면 slow 300 `enter`(오버슈트 없음), 끄는 동안은 손가락을 바로 따름. 지도 맞춤과 고른 식당으로 이동은 slow 300 `standard`. 마커 선택은 fast 180. 축소 모드면 모두 즉시.
- **접근성**: 마커는 버튼(이름, 카테고리, 도보 분을 읽음, `aria-pressed`), 지도는 방향키로 이동, 같은 식당을 시트 목록에서도 고를 수 있음(지도 조작의 대체 수단). 시트 손잡이는 버튼(누르면 한 단계 올림, 끝까지면 내림, 바뀐 높이를 `aria-live`로 알림). 식당을 고르면 요약 제목으로 초점. 터치 영역 44 이상. axe(WCAG 2.1 AA + best-practice) 위반 0: 3안 x 9쿼리 x (390, 1280 라이트와 다크, 360 라이트), 360/390/1280 가로 넘침 0.

## 2. 번들 요약 (gzip)

- **세 안이 거의 같습니다.** 라우트 첫 로드 A 234.1, B 233.7, C 236.2 KB(차이 2.5 KB 안). 지도 목업 공급자, 시트, 목록 행, 칩(Base UI Toggle), 상태 블록을 함께 쓰고 세 안 모두 모션이 CSS입니다(Motion 없음). C만 필터 시트(Base UI Drawer)를 "필터"를 누른 뒤 따로 받습니다(지연 청크 약 +23.1 KB).
- 지도 탭(`/map`)은 홈 첫 로드 예산(200 KB) 대상이 아닙니다. 실제 구현에서는 목업 공급자 대신 네이버 SDK(외부 스크립트, 번들 밖)가 들어오고, 시안 틀(`DesignScope`)의 Motion 약 30 KB는 빠집니다.
- 근사값입니다. 모듈 단위로 귀속하지 않고 청크 차이(파일 gzip)로 봤습니다. `/today`는 같은 빌드에서 172.8 KB.

## 4. 바텀시트 구현 방식 메모

시안 시트는 **지도 칸 안의 절대 위치 요소 + 포인터 끌기 + CSS 전환**으로 만들었습니다(`shared/map-sheet.tsx`). 지도 시트는 늘 떠 있는 비모달 시트라 Base UI Drawer(포털, `fixed` 뷰포트, 열고 닫는 모달 중심)보다 이 방식이 하단 탭 위에 자연스럽게 앉고, 데스크톱에서는 같은 요소가 좌 칸이 됩니다. 번들 증가도 없습니다. 모달인 필터 시트(C)는 Base UI Drawer를 누른 뒤 지연 로딩했습니다. 실제 구현 방식은 5절 안건 3으로 묻습니다.

## 6. 캡처에서 본 품질 메모 (선택과 무관하게 구현 때 고칠 것)

- 고른 마커 아래 이름 알약(A)과 펼친 알약(B, C)이 이웃 마커를 가립니다. 고른 마커만 위로 올리는 처리는 했고(z-index), 실제 구현은 `MarkerHandle`에 `setZIndex`를 더해야 합니다(지금 인터페이스에 없음, T5.27).
- 회사 핀과 가장 가까운 식당(2분) 마커가 겹칩니다. 기준점 둘레 약 30m는 마커를 살짝 밀어내거나 회사 핀을 작게(점 + 링) 하는 방법을 T5.26에서 봅니다.
- 오프라인 상태는 지도 칸에 "지도를 불러올 수 없습니다" 한 줄만 둡니다. 세션 메모리에 이미 받은 목록이 있으면 목록을 흐리게 보여 줄지 T5.32에서 정합니다(카카오 데이터는 세션 메모리만, 저장 금지).
- 다크 모드 목업 지도의 건물과 길 색은 시안용 변수(`--lab-road`, `--lab-building`)입니다. 실제 네이버 지도 다크 스타일은 T5.26에서 따로 확인합니다.
- 반쯤 열림 요약의 숫자 3칸, 버튼 줄은 T5.2 상세 시안 결정을 따라 바꿉니다(가격 "추정" 표기 위치 포함).
- `[실기기]` 시트 끌기와 지도 끌기의 제스처 충돌(iOS Safari, 카카오톡 인앱)은 확인하지 못했습니다. 구현 뒤 실기기 확인 항목입니다.
