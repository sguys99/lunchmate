## 2. 번들 요약 (gzip, 추정)

- 나 탭은 홈(`/today`)과 랜딩(`/`) 첫 로드 밖이라 **홈 200 KB 예산 판단 요소가 아닙니다.**
- **세 안 모두 새 의존성 0.** 카테고리 일러스트, 앱 셸, 상태 컴포넌트, 설정 줄(`features/me/parts`), 화면 설정(`DisplaySettings`)을 그대로 씁니다. 모션은 CSS 전환과 이미 들어 있는 `tw-animate-css` 클래스뿐이고 Motion, NumberFlow, Drawer를 쓰지 않습니다.
- 시안 고유 코드(gzip, 소스 기준): A 약 4.3 KB, B 약 5.0 KB, C 약 5.0 KB + 공용 조각 약 8.7 KB(기록 줄, 즐겨찾기, 다시 안 갈 곳, 내 후기, 상태). 실제 화면은 이 중 고른 안 하나 + 공용 조각만 들어갑니다.
- B의 달력은 한 달 칸(최대 42칸)마다 일러스트 SVG(약 1~1.6 KB 마크업)를 그려 **DOM이 세 안 중 가장 큽니다**(10월 기준 그림 15개). 첫 로드 JS가 아니라 렌더 비용입니다.
- `pnpm build`로 잰 값은 T6.4 선택 뒤 `docs/design/bundle-log.md`에 남깁니다.

## 3. 공통으로 지킨 것

- **카카오 값은 저장하지 않고 그때그때 찾습니다.** 기록, 즐겨찾기, 다시 안 갈 곳, 내 후기는 DB의 `place_id`와 `place_url`만 가진 행이고(`supabase/migrations/20261031120000_t5_14_*`), 이름과 카테고리는 T5.12a 순서(세션 메모리 → 기준점 주변 FD6 매칭 → 미해결)로 붙입니다. **미해결 줄**은 그림 대신 점선 원 + 핀, 이름 대신 **날짜나 순번**("10월 22일 점심에 간 곳", "저장한 식당 7", "10월 22일에 남긴 후기") + **카카오맵 링크**입니다. 기본 화면에도 미해결이 1~2줄 섞여 있고, `?names=fail`은 전부 실패한 경우(위에 안내 한 줄)입니다. 카테고리도 카카오 값이라 미해결 줄은 C의 "자주 간 종류" 집계에서 빠집니다.
- **HIS-01 네 가지**(날짜, 끼니, 출처, 내 평가)를 모든 기록 줄에 둡니다. 메타 줄은 문자 구분자 없이 1px 세로선("점심 | 추천에서"), 평가는 👍/👎 아이콘 + 스크린 리더 이름, 안 갔어요는 글자, 평가가 없으면 "평가 없음".
- **확인 전 방문**(status `candidate`, 길찾기만 누르고 답이 없는 곳)은 점선 "확인 전" 표시 + 그 줄 아래 **"다녀오셨나요?" 세 답**(👍, 👎, 안 갔어요, FB-01과 같은 세 가지, 3개 이하). 답하면 한 줄 결과("기록했습니다.", 안 갔어요면 "추천 점수에는 쓰지 않습니다.")로 바뀝니다. 홈 띠(FB-04: 하루 1회, 48시간)가 묻지 않은 곳을 여기서 늦게라도 정리할 수 있습니다.
- **즐겨찾기 해제**는 별 토글(`aria-pressed`), 끈 줄은 흐리게 남아 다시 누르면 되돌립니다. **다시 안 갈 곳 해제**는 "해제" 버튼 → "다시 추천에 넣었습니다." + "되돌리기". **내 후기**는 수정(6단계 후기 입력 시트로) / 삭제(그 자리 확인 "이 후기를 지울까요? 지우면 식당 집계에서도 빠지고 되돌릴 수 없습니다.", PRD 11.4).
- **비공개 후기**는 "나만 보기"(자물쇠)로 표시하고 목록 아래에 "나만 보기 후기는 글만 숨깁니다. 가격, 👍, 태그는 식당 집계에 익명으로 들어갑니다."(PRD 11.2) 한 줄. 내 후기 화면은 본인만 보므로 비공개 글도 보입니다.
- **설정은 그대로 둡니다.** 4단계 설정 줄(사무실, 예산과 거리, 못 먹는 음식, 요즘 이게 땡겨요, 화면, 계정, 약관)을 같은 컴포넌트(`SettingsSection`, `SettingsLinkRow`)로 옮겼습니다. A는 머리줄 "설정" 아이콘 버튼 뒤 하위 화면, B와 C는 같은 페이지 아래쪽입니다. 화면 설정은 줄 하나로 접었습니다(안건 5).
- **4상태**: 로딩은 같은 자리 스켈레톤(A 날짜 칸 줄, B 달력 칸, C 숫자 3칸과 막대). 빈 상태(첫 방문)는 그릇 세 개가 점선 위에 놓인 그림 + "아직 다녀온 곳이 없습니다" + 쌓이는 방법 3단계 + "첫 점심을 기록해 볼까요?" + **오늘 추천 보기**(화면의 유일한 primary). 오류는 "기록을 불러오지 못했습니다" + 다시 시도, **설정 줄은 그대로**(설정은 따로 오는 데이터). 오프라인은 연결 전 기록을 보이고 위에 안내 한 줄, 해제와 수정과 답하기는 `aria-disabled`.
- **로그인 꺼짐 둘러보기**(`?auth=off`, AUTH-07): 지금 `/me`의 ComingSoon과 같은 말투("로그인하면 기록이 쌓입니다 / 로그인은 곧 열립니다") + 오늘 추천 보기(보조) + **그 안의 흐린 미리보기**(A 주간 줄, B 빈 달력, C 숫자 3칸, `inert` + `aria-hidden`) + 화면 설정(이 기기 저장).
- **긴 목록**: 처음엔 몇 개만, "더 보기"/"지난 기록 더 보기"(실제는 다음 페이지 요청, `?more=on`이 펼친 상태). 끝까지 보면 "처음 기록까지 모두 봤습니다."
- **데스크톱(1280)**: 앱 셸 2단 그대로(좌 리스트 + 하단 탭, 우 지도). 오른쪽 지도에 해당 기록 핀(A 이번 주, B 이번 달 + 고른 날 강조, C 즐겨찾기와 이번 달). 핀 이름도 세션 메모리 값이라 미해결 곳은 핀이 없습니다.
- 접근성: axe 검사 132건 통과(3안 × 11쿼리 × 라이트, 다크 × 모바일, 데스크톱, `e2e/a11y-g6-me.spec.ts`). 아이콘 버튼은 모두 이름이 있고(설정, 좋았어요, 별로였어요, ○○ 즐겨찾기, 이전 달, 다음 달, 뒤로), 탭은 `tablist`/`tab`/`tabpanel` + 좌우 화살표, 달력 칸은 보이는 날짜를 숨기고 "10월 24일 금요일, 홍운각 점심 좋았어요" 전체를 읽습니다. 모든 전환은 `motion-reduce:`로 꺼집니다. 포인트 컬러 면 버튼은 세 안 모두 빈 상태의 "오늘 추천 보기" 하나뿐이고 평소 화면에는 없습니다(올리브는 B 고른 날 테두리, 하단 탭 막대).

## 6. 캡처에서 본 품질 메모 (선택과 무관하게 구현 때 고칠 것)

- **미해결 후기 줄**("10월 22일에 남긴 후기")은 오른쪽 날짜와 같은 날짜가 두 번 보입니다. 후기 목록에서는 대체 이름을 "남긴 후기 3"처럼 순번으로 바꾸는 편이 낫습니다.
- **B 달력 그림 22~26px**는 icon 변형이라도 국밥과 한식처럼 그릇 모양이 비슷한 종류는 구분이 어렵습니다. B를 고르면 그림 대신 색 점(카테고리 ink) + 이름 첫 글자도 비교해 봅니다.
- **B 고른 날 테두리**(primary 1.5px)는 확인 전 점선 원과 겹치면(10월 30일) 원이 둘로 보입니다. 고른 날은 테두리 대신 날짜 밑줄로 바꾸는 안도 있습니다.
- **C 첫 방문 숫자 칸**("0번 / 평가 3개부터 / 아직 없음")은 빈 상태 그림 위에 있어 정보가 겹쳐 보입니다. 기록 0건이면 숫자 칸을 숨기는 편이 낫습니다.
- **오프라인에서 비활성 버튼**은 투명도 50%만으로 표시됩니다. 실제 구현은 누르면 "연결되면 할 수 있습니다" 토스트를 띄웁니다.
- 공용 문구 파일(`src/copy/design-lab-me.ts`)은 해요체 비율 검사 대상(25~40%) 밖입니다(디자인 랩). 실제 `src/copy/me.ts`로 옮길 때 비율을 다시 맞춥니다.
- 다크 모드는 세 안 모두 대비와 경계가 정상입니다(axe color-contrast 통과).
