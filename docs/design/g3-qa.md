## 4. 축소 모드, 햅틱, axe

### 축소 모드 (`prefers-reduced-motion: reduce`)

`document.getAnimations()`로 실행 중인 전환과 애니메이션(길이 0 제외)을 셌다. 홈 4안 × 룰렛 r1, r2, r3(로드, 다시 뽑기, 다음, 그냥 골라줘 직후와 300ms 뒤), 랜딩 3안(로드, B 다시 뽑기, C 스크롤 두 번).

| 대상 | 결과 |
| --- | --- |
| 홈 A, B, C, D (다시 뽑기, 다음, 스와이프 버튼) | 실행 중 모션 0 |
| 그냥 골라줘 r1, r2 | 연출 없이 바로 결과, 모션 0 |
| 그냥 골라줘 r3 | 고침 전 600ms 선 전환 1건(보이지 않는 무대) → 고친 뒤 0 |
| 랜딩 A, B(다시 뽑기), C(장면 등장, 득표 바, 취소선) | 모션 0 (landing.css의 reduce 미디어 쿼리) |

### 햅틱 (T3.3 보고 처리)

- 바꾼 것: "그냥 골라줘"와 결과의 "다른 곳"을 **누르는 순간** `tap`. 연출 중 화면을 눌러 **건너뛰면** 그 누름 안에서 `select`. 연출이 끝나 결과가 정해지는 순간(타이머)에는 진동하지 않는다.
- 근거: `src/lib/haptics` 규칙은 "제스처 핸들러 안에서만, 타이머와 효과 안에서는 부르지 않는다". 타이머 진동은 sticky activation 덕에 Android Chrome에서 대개 울리지만, 규칙이 막는 패턴이고 백그라운드 탭과 권한 정책에서 조용히 무시되어 기기마다 결과가 달라진다. 결과 확정은 시각 전환과 status 안내가 이미 알리고, 진동은 보조 신호라 빠져도 정보가 사라지지 않는다. 누름에 붙은 진동이 가장 예측 가능하다.
- 축소 모드에서는 `haptic`이 스스로 건너뛴다(기존 동작).
