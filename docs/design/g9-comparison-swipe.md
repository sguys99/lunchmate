## 3. 공통 판정 규칙 (`gesture.ts`, 단위 테스트 14개)

- **시작**: 화면 좌우 가장자리 24px 안에서 시작한 손가락은 받지 않는다(iOS Safari의 가장자리 "뒤로 가기"). 지도 캔버스, 가로 스크롤 줄(필터 칩), 나 안쪽 탭 줄, 입력칸, 슬라이더도 받지 않는다(`data-swipe-ignore`, 가로로 넘치는 `overflow-x: auto` 요소 자동 판정).
- **방향 잠금**: 처음 10px 동안 기다렸다가, 가로 이동이 세로의 1.5배를 넘을 때만 가로로 본다. 세로면 그 손가락은 버리고 브라우저 스크롤에 맡긴다(받는 요소 `touch-action: pan-y`라 세로 스크롤은 늘 브라우저가 한다).
- **넘어가기**: 폭의 30% 이상 밀었거나, 같은 방향으로 0.5px/ms 이상 빠르게 40px 이상 튕겼을 때. 밀었다가 되돌리며 놓으면 제자리.
- **방향**: 왼쪽으로 밀면 다음 탭(오늘 → 지도 → 투표 → 나), 오른쪽은 이전 탭. 양 끝은 1/4만 따라오다 48px에서 멈춘다.
- **눌림 방지**: 가로로 민 뒤 바로 이어지는 click은 막는다(손가락 밑 카드, 링크가 눌리지 않게).
- **접근성**: 하단 탭은 그대로라 스와이프만 있는 조작이 아니다. 옮긴 뒤 "<탭> 탭으로 옮겼습니다." 알림(실제 앱은 Next 경로 알림 + 페이지 제목). 축소 모드면 움직임 없이 바로 바뀐다.
- **데스크톱**: 실제 구현은 터치와 펜만 받는다(마우스, 트랙패드 가로 스크롤은 받지 않음, 하단 탭 그대로). 시안은 PC에서 시험할 수 있게 마우스도 받는다.

## 4. 번들 요약 (gzip, 추정)

**홈 `/today` 첫 로드 200.2 KB, 예산 201 KB(여유 0.8 KB).** 세 안 모두 판정 규칙과 포인터 훅이 약 1.0~1.3 KB라 첫 로드에 넣으면 예산을 넘습니다. 그래서 **첫 화면이 뜬 뒤(유휴 시간) 따로 받는** 방식으로 구현합니다. 받기 전(첫 1초 남짓)의 손가락은 무시됩니다. 새 의존성은 없습니다(Motion `m`도 쓰지 않고 CSS transform, opacity 전환만).

- **A**: 규칙 + 훅 + 옆 탭 표시 약 +1.6 KB(지연 로드). 홈 첫 로드 0.
- **B**: 규칙 + 훅 + 가장자리 알약 약 +1.5 KB(지연 로드). 홈 첫 로드 0.
- **C**: 탭 막대 렌즈와 말풍선 약 +1.2 KB(지연 로드). 하단 탭은 모든 화면의 레이아웃에 있으므로 역시 첫 로드 밖으로.

## 6. 안건 (고를 때 함께 정할 것)

1. **안 선택**: A / B / C / 조합(예: B + C). Claude 기본안은 **B 단독**(본문 밀림 없이).
2. **기준값**: 넘어가는 거리 폭의 30%, 튕김 0.5px/ms 이상 + 40px 이상, 가장자리 제외 24px, 방향 잠금 1.5배. 기본안 그대로(베타에서 잘못 넘어감 제보가 있으면 조정).
3. **처음 안내**: A, B는 안내 없이 둘지, 처음 한 번 토스트("좌우로 밀어 탭을 옮길 수 있습니다.")를 띄울지. C는 막대 위 안내 한 줄이 필요하다. 기본안: A, B는 안내 없음(하단 탭이 주 경로이고, 스와이프는 아는 사람의 지름길).
4. **진동**: 넘어가는 순간 진동은 넣지 않는다(`src/lib/haptics` 규칙: 탭 이동에는 쓰지 않음, iOS는 미지원).
5. **분석 이벤트**: PRD 10.2절에 없으므로 새 이벤트를 만들지 않는다(쓰임새를 보려면 PRD에 먼저 추가하는 안건으로 따로 올림).
6. **구현 범위**: 실제 앱은 `(app)` 레이아웃의 본문 칸에 스와이프 영역을 두고 `router.push(탭 href)`로 옮긴다. 탭 화면 안의 열린 바텀시트, 대화상자 위에서는 받지 않는다. 투표방 `/poll/[code]`처럼 탭 첫 화면이 아닌 하위 화면에서는 끈다(뒤로 가기와 헷갈리지 않게).
