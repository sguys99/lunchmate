## 2. 번들과 생성 비용

- **앱 JS 번들 증가 0.** 투표 OG는 서버 라우트(`/api/og/poll/[code]`)가 그리는 PNG라 클라이언트로 가는 코드가 없습니다. 시안 코드는 `/design-lab` 라우트 핸들러 안에만 있습니다.
- 글꼴은 지금 KS X 1001 woff 두 개 그대로(새 파일 없음). 그릇 그림은 `icon-art.ts`의 SVG 문자열과 랜딩 공용 부품 `OgBigBowl` 재사용, 함수 번들 증가는 수 KB 이하.
- PNG 크기(dev 렌더, 짧은/긴): A 43/61 KB, B 56/64 KB, C 45/55 KB, D 53/61 KB. 모두 카카오와 X 권장 한도(수 MB) 안. 생성 시간은 지금과 같은 수준(그림 한 장 추가).

## 3. 공통으로 지킨 것

- 1200 x 600(D-17 안건 2), 늘 라이트 팔레트, 색은 `sharePalette` 생성 상수만(하드코딩 색 0, `pnpm lint` 통과), 올리브는 이미지마다 한 군데(A 제목 밑 선 / B, C, D 그릇 선. B, C, D 결과 그림은 득표 바를 빼서 한 군데 유지).
- 왼쪽 위 단색 그릇 기호 24 + "런치메이트"(`OgBrand`, D-18 안건 6), 오른쪽 위 종류 라벨, 글자는 좌우 88 안쪽(B, D 오른쪽 그릇은 72 안쪽, 1.91:1 자르기에서 원 가장자리만 조금 잘림).
- **표시 정보는 지금 범위 그대로**: 브랜드, 종류 라벨, 제목 + 행동 유도("어디로 갈까요?" / 결과 "정해졌어요"), 후보 수, 마감(결과는 참여 수, 1위 표 수). 인원이나 참여자 수를 초대 그림에 새로 넣지 않았습니다. 식당 이름과 카테고리 없음(CLAUDE.md 13장, T0.16-4).
- 행동 유도 문장은 새 문구를 만들지 않고 `shareCopy.og.inviteHeadline`에서 제목 자리만 뗀 꼬리를 씁니다(`art.test.ts`로 같은 문장인지 검사).
- 글꼴 범위: 시안이 쓰는 글과 목업 제목, 마감 표기를 KS X 1001로 그릴 수 있는지 테스트(`art.test.ts`). 사용자 제목은 지금처럼 `isOgDrawable`로 판정해 밖 글자가 있으면 끼니 기본 문구(emoji 목업에서 확인, 빈 칸 글자 없음).
- 4상태와 다크 모드: OG 이미지는 정적 한 장이라 로딩, 빈, 오류, 오프라인 상태가 없습니다(열 수 없는 방 그림은 지금 A 그대로 두고 고른 안에 맞춰 구현 때 정리). 다크는 앱 테마가 아니라 **어두운 채팅방 위 모습**으로 확인했습니다. 모션 없음.

## 6. 품질 메모

- 카카오톡 말풍선과 채팅 배경색은 근사치 틀입니다. 실제 카카오톡(라이트, 다크) 피드 말풍선 표시, 캐시 갱신(`OG_ART_VERSION` 3으로 올려 `?v=`가 바뀌는지)은 `[실기기]` 확인 항목이며 Claude가 대신 확인하지 못했습니다.
- X 큰 카드 왼쪽 아래 제목 띠는 X 표시 방식을 흉내 낸 것입니다. C는 아래 숫자 줄이 띠에 가려집니다.
- 긴 제목은 B, D에서 `lineClamp: 2`, C에서 두 줄까지로 막았습니다. 20자 최대 제목에서 잘림 없이 들어감을 확인했습니다(공백 적은 20자 제목은 구현 때 한 번 더 확인).
- 공용 부품(`src/features/landing/og-art.tsx`의 `OgBrand`, `OgBigBowl`, `ogRow`, `ogCol`, `ogSerif`)은 import만 했고 바꾸지 않았습니다. D의 숫자용 그릇은 시안 파일 안에서 `bowlMarkup`으로 따로 만들었습니다.
- 선택 뒤 할 일: 고른 그림을 `src/features/poll/share/og-art.tsx`로 옮기고 `OG_ART_VERSION`을 "3"으로, 열 수 없는 방 그림 정리, `src/features/design-lab/og-poll/`, `src/app/design-lab/og-poll/` 삭제(캡처와 이 문서는 남김), design-decisions에 기록, 보내기 화면 미리보기(D-15 안건 13)가 같은 그림을 쓰는지 확인.
