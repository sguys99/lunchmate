# 6단계 제보와 신고 입력 비교 자료 (T6.3 → ⛔ T6.4)

> ⛔ T6.4 선택 게이트에서 사용자에게 보여 줄 자료입니다. 제보와 신고 입력 시안 하나(또는 조합)를 고르고 아래 5절 안건을 함께 정합니다. 피드백 카드(T6.1)와 나 탭(T6.2)은 각자의 비교 문서에서 따로 봅니다.
> 캡처는 2026-10-31 dev 서버(3102)에서 찍었습니다. 번들 수치는 `pnpm build` 없이 의존성과 기존 측정값(`docs/design/bundle-log.md`)으로 추정한 값입니다(2절).
> 시안 라우트: `/design-lab/report/<a|b|c>`. 쿼리 규약(`src/features/design-lab/report/params.ts`):
> `?flow=deal|deal-check|wait|place|review-report`(어느 입력), `?phase=form|dup|done|ended|cooldown`(흐름 안 단계), `?error=limit|banned-word`(하루 한도, 금칙어),
> `?state=loading|empty|error|offline`(4상태, error는 보내기 실패), `?kind=closed|price|wrong`(정보 제보 종류), `?target=review|deal`(신고 대상), `?step=1..4`(C 질문 단계), `?menu=open`(더 보기 메뉴).
> 관련 요구사항: PRD DEAL-01~05, AC-DEAL-1~3, PLACE-05, PLACE-07, PLACE-08, MOD-01~05, 10.2 이벤트. 함께 볼 기록: `docs/design-decisions.md` D-09(지도 시트), D-10(식당 상세: 접힌 "지금" 행, 할인 고지 두 줄, 더 보기 안 제보 3종, 안건 11 후기 신고 진입점).

## 0. 세 안이 공통으로 한 것

- **배경은 D-10 식당 상세 그대로.** 요약(그림, 이름, 이유, 숫자 3칸, 배지) + 접힘 행(가격, 만족도, 후기, 지금) + 하단 고정 줄(길찾기, 즐겨찾기, 더 보기)을 실제 부품(`features/place/detail/parts`의 `Fold`, `CompactNumbers`, `PriceScale`, `TenMeter`, 실제 `PlaceMoreMenu`)으로 그렸습니다. 모바일은 홈 위 상세 시트를 끝까지 연 모양, 데스크톱은 좌 상세 + 우 지도(핀)입니다.
- **진입점은 세 안이 같습니다.** 할인 등록은 더 보기 메뉴 "정보가 다른가요?" 묶음 맨 위 **"할인 정보 알리기"**(제보 3종 위) + "지금" 행 할인 목록 아래 글자 버튼. 식당 정보 제보 3종은 D-10대로 더 보기 메뉴. 후기 신고는 후기 머리줄 오른쪽 작은 더 보기(이름 "OO 후기 신고", D-10 안건 11 기본안). 할인 신고는 할인 줄 오른쪽 깃발 버튼(이름 "이 할인 정보 신고").
- **웨이팅 3버튼(바로 입장, 조금 기다려요, 줄 길어요)은 D-10 "지금" 행 안 그대로**이고, 버튼 아래 "줄 길어요는 점심 피크에 추천 순서를 조금 낮춥니다."(PLACE-08을 사용자에게 밝힘, 원칙 3)를 한 줄 두었습니다.
- **할인 표시(DEAL-02)**: 할인 하나 = 유형(caption) + 출처 배지 `제보`(Badge neutral + Tag 아이콘, 스크린 리더 "사용자 제보") + 내용 + "3일 전 제보, 11월 5일까지" + (있으면) 얇은 세로선 뒤 "평일 점심" + 아직 해요/끝났어요 + 확인 수. 목록 끝에 **고지 두 줄**("사용자가 제보한 정보라 실제와 다를 수 있습니다." + "할인 정보는 추천 순서에 쓰지 않습니다.", D-10 안건 12). 등록 폼에도 같은 두 줄(C는 첫 질문 아래 둘째 줄)을 둬서 **할인이 추천에 영향을 주지 않는다는 것(원칙 6)을 제보하는 순간에도** 보입니다.
- **할인 등록 필드(DEAL-01)**: 유형 칩 5개(점심특선, 할인, 오픈, 기념 이벤트, 해피아워, 기타, 필수) → 내용 60자(필수, 글자 수 `0/60`, 유형별 예시 placeholder) → 언제까지(칩 3일, **7일 기본 선택**, 2주, 30일 + 날짜 "11월 7일까지") → 요일과 시간(선택, 기본 "언제든"). 시간대는 시각 입력 대신 점심(11~15시), 오후(15~17시), 저녁(17시부터) 칩입니다(안건 6).
- **중복 병합(DEAL-04)**: 유형을 고르는 순간 같은 식당 같은 유형 제보가 있으면 "이미 제보된 정보가 있습니다 / 같은 내용이면 아직 해요로 확인할까요?" + 기존 제보 + 주 버튼 **"아직 해요로 확인"**, 글자 버튼 "다른 내용이라 새로 남기기". 세 안은 이 안내를 보여 주는 자리만 다릅니다(3절). `?phase=dup`.
- **한 탭 결과**: 웨이팅을 누르면 고른 버튼에 체크 + `aria-pressed`, 나머지는 `aria-disabled`, "12시 54분부터 다시 알릴 수 있습니다."(30분 1회, copy-guide 4.12). 상세 배지와 "지금" 요약도 방금 값으로 바뀝니다. 아직 해요/끝났어요는 토글 버튼(`aria-pressed`), 끝났어요를 누르면 그 줄이 흐려지고 "끝났다고 알렸습니다. 3명이 알리면 숨겨집니다."(AC-DEAL-3). 세 안 모두 **되돌리기**가 있습니다.
- **식당 정보 제보(PLACE-05)**: 종류(문 닫았어요, 가격이 달라요, 정보가 틀려요)를 고르면 종류별 **선택** 세부(문 닫음: 아예 닫았어요, 다른 곳으로 옮겼어요, 오늘만 쉬어요 / 가격: 1인 가격 숫자 / 정보: 이름, 위치, 전화번호, 음식 종류 여러 개). 자유 글은 받지 않습니다(안건 9). 문 닫음에는 "서로 다른 세 분이 알리면 추천에서 뺍니다."(MOD-03).
- **후기 신고(MOD-01)**: 사유 5개(광고, 스팸 / 욕설, 비방 / 개인정보 / 허위 / 기타) 라디오, 사유마다 한 줄 설명, 기타는 선택 입력 100자. **할인 신고**(`?target=deal`)는 "광고성, 허위"를 맨 위에 두고 광고, 스팸과 허위를 그 하나로 합쳤습니다(DEAL-04, 안건 10). 아래에 "신고한 분은 알리지 않습니다. 세 분이 신고하면 바로 가리고 검토합니다."(MOD-02). 보낸 뒤 그 후기는 신고한 사람에게 "신고한 후기입니다. 나에게는 가려 둡니다. [보기]"로 바뀝니다(안건 11).
- **오류 상태**: 하루 한도(`?error=limit`)는 **입력 칸 대신** "오늘은 할인 제보를 더 남길 수 없습니다 / 하루 10건까지입니다. 내일 다시 알려 주세요. 이미 있는 정보에는 아직 해요를 누를 수 있습니다."(신고, 정보 제보는 30건 문구). 금칙어(`?error=banned-word`)는 칸 테두리 `destructive` + 칸 아래 "쓸 수 없는 표현이 있습니다. 표현을 바꿔 다시 보내 주세요."(`role="alert"`, 어떤 낱말인지는 알려 주지 않음) + 주 버튼 비활성, 고치면 바로 풀림. 보내기 실패(`?state=error`)는 버튼 위 "보내지 못했습니다 / 입력한 내용은 그대로 두었습니다." + 주 버튼이 "다시 보내기". 오프라인은 맨 위 안내 + 주 버튼 "연결되면 보낼 수 있습니다"(`aria-disabled`), 쓰던 내용은 유지. 로딩(`?state=loading`)은 한도와 중복을 불러오는 동안 칸 모양 스켈레톤(스피너 없음). 빈 상태(`?state=empty`)는 할인과 웨이팅 제보 0건: "아직 알려진 할인 정보가 없습니다." + "최근 30분 동안 웨이팅 제보가 없습니다." + 같은 진입 버튼.
- **카카오 값 저장 없음.** 제보에 실리는 카카오 값은 `place_id`뿐이고 이름, 주소는 화면 표시용 세션 값입니다(CLAUDE.md 7장). 금칙어, 한도, 30분 제한은 서버 판정이라는 가정으로 그렸습니다.
- 접근성: axe(WCAG 2.1 AA + best-practice) **264건 통과**(3안 × 21~24쿼리 × 라이트, 다크 × 모바일, 데스크톱, `e2e/a11y-g6-report.spec.ts`). 360/390/1280 가로 넘침 0. 모든 아이콘 버튼에 이름, 칩 묶음은 `aria-labelledby`, 사유는 `fieldset` + `legend` 라디오, 오류는 `role="alert"`, 결과 줄은 `role="status"`, 글자 수는 "60자 중 N자"로 읽힘. 포인트 컬러 면 버튼은 화면에 하나(시트를 띄운 A, C는 뒤 상세의 길찾기가 딤 아래 `inert`).

## 2. 번들 요약 (gzip, 추정)

- 세 안 모두 **홈(`/today`)과 랜딩(`/`) 첫 로드 밖**입니다. 제보와 신고는 상세를 연 뒤 버튼을 눌러야 열리므로 홈 200 KB 예산 판단 요소가 아닙니다. 폼 코드(칩, 입력, 라디오, 문구)는 세 안 모두 수 KB이고 상세를 연 뒤 지연 로딩할 수 있습니다.
- **A 한 장 시트: 상세 시트 안에서는 약 0, 지도 시트에서는 Drawer 약 +22~27 KB.** 홈 "상세"는 이미 Base UI Drawer를 지연 로딩하므로(D-10) 제보 시트는 같은 청크를 다시 씁니다(중첩 Drawer). 지도 탭 상세는 D-09 직접 구현 시트라 제보 시트를 처음 열 때 Drawer 청크가 붙습니다(`bundle-log.md` 2026-10-28 Drawer 묶음 약 27 KB, 2026-10-30 로그인 A Drawer와 Dialog 21.7 KB). 결과 알림은 Sonner 토스트(첫 토스트 때 약 9.6 KB, `LazyToaster`, 앱의 다른 토스트와 공유).
- **B 제자리 펼침: 약 0.** 시트도 토스트도 쓰지 않습니다. 칩 묶음(Base UI ToggleGroup)과 입력은 지도 필터와 온보딩에 이미 있는 부품입니다.
- **C 한 질문씩: A와 같은 Drawer 비용(상세 시트 안 약 0, 지도 시트 약 +22~27 KB), 토스트 0.** 완료도 시트 안에서 보여 줍니다.
- 고른 뒤 `pnpm build` + `next analyze`로 잰 값은 T6.4 기록 뒤 `docs/design/bundle-log.md`에 남깁니다.

## 4. 담는 그릇 구현 메모

- A, C 시트는 `components/ui/drawer.tsx`(Base UI Drawer)를 그대로 썼습니다. 홈 "상세"가 이미 Drawer라 실제로는 **시트 위 시트(중첩 Drawer)** 가 됩니다. Base UI Drawer는 중첩을 지원하지만 뒤 시트가 살짝 밀려나는 모양과 딤 두 겹을 구현 때 확인해야 합니다([확인 필요], Base UI 문서 `drawer.md` 중첩 절). 지도 탭 상세(D-09 직접 구현 시트)에서는 일반 Drawer 하나입니다.
- 데스크톱 시트 딤은 좌 칸(40%)에만 깔았습니다(`min-[64rem]:w-2/5`). 지도 칸은 계속 보입니다.
- B의 "하단 줄 바뀜"은 상세 하단 고정 줄(`PlaceDetailActions`)에 모드를 하나 더 두는 일입니다. 지도 시트 반쯤 높이에서는 펼친 입력이 거의 안 보이므로 B를 고르면 입력을 열 때 시트를 끝까지 올려야 합니다.

## 6. 캡처에서 본 품질 메모 (선택과 무관하게 구현 때 고칠 것)

- **접힘 행 안 `sr-only`가 문서 높이를 늘림**: `Fold` 내용 칸은 `overflow-hidden`이지만 `position: relative`가 아니라서, 안쪽 `sr-only`(absolute) 요소의 기준 상자가 칸 밖이 되어 접힌 상태에서도 아래로 빈 스크롤이 생겼습니다(시안에서 "지금" 행 아래 약 130~230px). 시안은 행 내용을 `relative`로 감싸 고쳤습니다. 실제 `features/place/detail/parts.tsx`의 `Fold` 안쪽 칸에도 `relative`를 넣는 것이 안전합니다(지금 실제 상세에서는 재현되지 않음, 확인 화면 `/design-lab/place/live?view=inline` 높이 정상).
- **창 스크롤은 `scrollIntoView` 대신 `window.scrollTo`**: 펼친 자리로 갈 때 `scrollIntoView`가 접힘 칸(overflow hidden)까지 밀 수 있어 창만 스크롤했습니다.
- **요일 칩 7개**: 칩 44px + 간격 6px이면 390 폭(본문 342px)에서 "일"이 다음 줄로 떨어져 간격을 4px로 줄였습니다. 360에서는 두 줄이 됩니다(허용).
- **A 토스트 되돌리기**는 키보드 사용자에게 닿기 어렵습니다. A를 고르면 결과를 상세 안에도 남겨야 합니다(B 방식과 같아짐).
- **C 질문 전환 때 초점**: 시안은 질문을 `key`로 다시 그려 등장 효과만 줍니다. 구현 때는 새 질문 제목으로 초점을 옮깁니다.
- **더 보기 메뉴 펼침(`?menu=open`)은 axe 목록에서 뺐습니다.** 실제 `PlaceMoreMenu`(Base UI Menu, 모달)가 열리면 바깥을 `aria-hidden`과 포커스 가드로 가려 axe가 region, aria-hidden-focus를 보고합니다. D-10 구현 그대로의 동작이라 이번 시안 문제는 아닙니다(캡처만 남김).
- **T6.1 피드백 시안과 겹침**: T6.1 캡처에 `report-menu`, `report-expand`가 있어 후기 신고 진입을 그쪽에서도 다룬 것으로 보입니다. 후기 신고 사유 화면은 이 문서 기준으로, 진입점(후기 머리줄 더 보기)은 두 문서를 함께 보고 하나로 정합니다.
