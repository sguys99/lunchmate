# G9 홈 한 화면 맞춤 시안 비교 (T9.10, 2026-11-02)

> ⛔ 선택 게이트. 사용자가 고르기 전에는 구현하지 않는다. 시안 코드는 커밋하지 않은 상태로 둔다.

## 1. 문제

- 실기기(iPhone, Safari와 Chrome) 보이는 영역은 약 390 x 664. 지금 홈은 문서 높이 819~856px이라 대안 두 곳과 "친구랑 정하기, 회식 모드"를 보려면 180~215px 스크롤해야 한다(프로덕션 측정, 아래 캡처).
- 세로를 쓰는 곳: 머리 세 줄(칩, 날짜, 30px 제목) 약 170px, 큰 카드 약 330px(위아래 24 여백, 두 줄 세리프 이름, 이유, "왜 추천했나요?" 줄, 따로 떨어진 "상세 ..." 줄, 숫자 줄), 하단 행동 줄 73px + 탭 64px(화면의 약 21%).

## 2. 세 시안

공통: 실제 앱 셸(AppShell, 고정 하단 탭)과 실제 홈 부품(LocationChip, MealToggle, CardArt, CategoryCaption, NumberGrid, NumberValue, AltTile, TodayActionBar, 상태 카드)을 목업 데이터로 다시 조합했다. 머리는 세 시안 모두 두 줄(칩 + 끼니 / 제목 heading 22px + 날짜)로 같고, 카드 구조만 다르다. "왜 추천했나요?"는 이유 줄 자체를 펼치기 버튼으로 바꿨고(접근성 이름에 "왜 추천했나요?" 포함), 같이 정하기 두 진입점은 "또는 이 두 곳" 제목 줄 오른쪽으로 올렸다.

## 3. Claude 추천

**A**. 지금 구조와 길찾기 위치(엄지 영역)를 그대로 두고, 두 줄 머리, 상세를 윗줄로, 이유 줄 펼치기, 같이 정하기를 대안 제목 줄로 옮기는 것만으로 390x664와 360x640에 들어간다. 번들 영향이 거의 없어 /today 예산(현재 여유 0.3 KB)에도 안전하다. B의 인라인 숫자 줄은 A가 빡빡하다고 느껴지면 나중에 섞을 수 있는 선택지로 남긴다(조합 예: A + B의 대안 목록). C는 탭 높이가 전 화면에 걸리고 주 버튼이 위로 올라가 한 손 원칙과 부딪혀 추천하지 않는다.

고를 때 함께 정할 안건:

1. 머리 제목 크기 30 → 22px(세 시안 공통). 세리프 제목의 존재감이 줄어든다.
2. "왜 추천했나요?" 별도 줄을 없애고 이유 줄이 펼치기(세 시안 공통).
3. 같이 정하기 진입점을 "또는 이 두 곳" 줄 오른쪽 작은 글자로(세 시안 공통). 눈에 덜 띈다.
4. 큰 카드 그림 크기: A는 80px 고정(D-05 안건 6의 152px 예외를 홈 한 화면 우선으로 바꿈), C는 96/80px.
