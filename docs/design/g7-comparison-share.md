## 2. 번들과 생성 비용 (추정, gzip)

- **새 의존성 없음.** 서버 OG는 Next 내장 `next/og`(Satori + resvg wasm), 결과 공유 이미지는 canvas 2D 직접 그리기입니다.
- **홈과 투표방 첫 로드 영향 0.** 결과 공유 그리기 모듈(`share-canvas.ts`, 약 3 KB)은 결과 화면에서 "결과 공유"를 누른 뒤 동적 import합니다. 글꼴은 앱이 이미 쓰는 동적 서브셋(`public/fonts/v1`)을 `document.fonts.load`로 기다려 쓰므로 추가 전송은 이미지에 든 글자 조각 몇 개뿐입니다.
- **html-to-image류와 비교**: DOM을 SVG foreignObject로 복제하고 웹 글꼴을 base64로 인라인하는 방식이라 라이브러리(약 4~10 KB)보다 실행 비용이 큽니다(글꼴 조각 수십 개 인라인, iOS Safari foreignObject 글꼴 누락 이슈). canvas는 그릴 것이 글 다섯 줄, 바 하나, 그림 하나라 직접 그리는 쪽이 가볍고 결과가 결정적입니다.
- **서버 OG 글꼴(함수 번들, 클라이언트 0)**: Satori는 woff2를 못 읽어 woff로 다시 만들었습니다. 마루 부리 Light KS X 1001 **279,128 B**, Pretendard Medium KS X 1001 **208,240 B**(`src/features/design-lab/share/fonts/`, OFL 라이선스 동봉, fontTools `pyftsubset` 4.68로 기존 KS X 1001 글자 범위를 그대로 사용).
- **서버 OG 생성 시간**: dev 서버에서 첫 요청 약 1.2초(컴파일 포함), 이어서 0.2~0.5초. PNG 40~48 KB.
- **결과 공유 이미지**: 1080 x 1080 PNG 75~110 KB(카카오 업로드 제한 5MB의 2% 남짓).
- `pnpm build` 실측은 T7.5 선택 뒤 구현 때 `docs/design/bundle-log.md`에 남깁니다.

## 3. 공통으로 지킨 것

- **식당 이름은 서버 이미지에 없습니다**(T0.16-4). 서버 OG 라우트는 쿼리에서 이름과 카테고리를 읽지도 않습니다(`ogQuery`가 넣지 않음). 카테고리도 카카오 값이라 서버 OG에 일러스트를 넣지 않았습니다(B의 돌은 후보 수만 나타냄).
- **크기: 서버 OG 1200 x 600 (2:1).** 카카오 운영진 답변(2025-12-12, DevTalk "Og:image 800X400 으로 설정해도 링크 썸네일 잘리는 현상" https://devtalk.kakao.com/t/og-image-800x400/147559)에 따르면 허용 비율은 **1:1, 2:1, 4:3**이고 그 밖이면 "가장 상징적인 콘텐츠를 자동 crop"합니다. 일반 OG 관례 1200 x 630(1.91:1)은 범위 밖이라 잘릴 수 있어 2:1로 맞췄고, 해상도가 낮으면 흐리다는 같은 답변에 따라 800 x 400의 1.5배로 그렸습니다. 거꾸로 1.91:1로 자르는 다른 서비스(페이스북, 슬랙 등)에서는 좌우 약 27px씩 잘리므로 글자를 좌우 72~88px 안쪽에만 둡니다("안전 영역 보기" 토글, 붉은 점선).
- **결과 공유 이미지 1080 x 1080 (1:1)**: 카카오톡 공유 피드 템플릿 허용 비율(1:1) 안이고 인스타그램 피드에도 그대로 맞습니다.
- 카카오 공식 문서(메시지 템플릿 공통, https://developers.kakao.com/docs/ko/message-template/common): 이미지 파일 최대 5MB, 기본 템플릿 1장, 최소 200 x 200, **이미지 업로드 API로 올린 이미지는 100일 보관**. 스크랩(og:image) 비율과 자르기 규칙은 공식 문서에 없어 DevTalk 답변을 근거로 썼습니다. JS SDK `Kakao.Share.uploadImage({ file: FileList })`는 `ImageInfos.original.url`을 돌려줍니다(https://developers.kakao.com/sdk/reference/js/release/Kakao.Share.html).
- **이미지는 늘 라이트 팔레트**입니다. og:image에는 테마가 없고, 저장한 이미지는 어디서 열릴지 모릅니다. 샌드 바탕이 어두운 채팅방에서도 말풍선 안 밝은 카드로 읽힙니다(1절 어두운 채팅방 캡처).
- **색은 DESIGN.md 토큰에서 계산**: OG와 canvas는 CSS 변수를 못 읽어 `palette.ts`가 DESIGN.md 프런트매터를 읽어 oklch를 sRGB 16진으로 바꿉니다(하드코딩 색 0, `pnpm lint` 통과). 실제 구현은 `pnpm tokens` 생성 상수로(안건 5).
- **서체**: 제목과 식당명은 마루 부리 Light 300, 숫자와 라벨은 Pretendard 500(DESIGN.md 3장). 올리브(`primary`)는 이미지마다 한 군데만: A는 제목 밑 짧은 선(초대) 또는 1위 득표 바(결과), B는 1위 돌 테두리와 바, C는 떼는 쪽 숫자.
- **문구**: 이미지 안 값 구분은 문자 대신 간격과 1px 선. 제목(사용자 입력)과 식당 이름 뒤에 조사를 붙이지 않으려고 "목요일 점심, 정해졌어요"처럼 쉼표로 이었습니다(안건 6). 공유 템플릿 문구 제안은 `src/copy/design-lab-share.ts`의 `kakao`(금지 문자 0).
- **긴 값**: 제목은 20자, keep-all, 최대 2줄. 결과 이미지의 식당 이름은 한 줄이면 크게(A 140, B 124, C 112), 넘치면 한 단계 작게 두 줄, 그래도 넘치면 말줄임. 캡처 `__share-image-party.png`.
- **4상태**: 로딩은 OG 자리와 공유 이미지 자리에 같은 비율 스켈레톤. 빈 상태(진행 중)는 "아직 결과가 없습니다" + 초대 링크만 보낼 수 있다는 안내. 오류는 "결과 이미지를 만들지 못했습니다" + 다시 만들기(링크 공유는 그대로). 오프라인은 카카오톡 보내기를 `aria-disabled`로 막고 "이미지 저장은 지금도 할 수 있습니다." 공유 버튼 줄은 상태마다 `aria-disabled`.
- 접근성: axe 74건 통과(3안 × 6쿼리 × 라이트, 다크 × 모바일, 데스크톱 + OG 라우트 PNG 1200 x 600 확인, `e2e/a11y-g7-share.spec.ts`). 이미지마다 alt("런치메이트 투표 초대, 후보 3곳, 12:30 마감", 결과 공유는 이름과 표 수 포함). 작게 보기 미리보기는 장식 `alt=""`. 저장, 공유 결과는 `role="status"`.

## 6. 품질 메모

- Satori에서 `<>` 조각 안의 자식은 flex gap이 먹지 않아 A 숫자 칸 사이가 붙었던 것을 고쳤습니다(조각 대신 실제 div, 세로선에 좌우 여백). 실제 구현에서도 OG 컴포넌트에는 조각을 쓰지 않습니다.
- Satori의 `wordBreak: keep-all`과 `lineClamp: 2`가 동작합니다(긴 회식 제목 확인). 20자 제목은 76~84px에서 두 줄 안에 듭니다.
- canvas 이름 크기는 "한 줄이면 크게, 두 줄이면 한 단계 작게"로 정했습니다. 처음에는 두 줄도 큰 크기로 그려 A의 축하 문장과 숫자, C의 날짜가 겹쳤습니다(`__share-image-party.png`로 확인 후 수정).
- canvas 글꼴: 앱의 웹 글꼴 목록이 아직 없는 첫 방문이면 `faces.css`를 붙이고 `document.fonts.load`로 이름 글자 조각을 기다린 뒤 그립니다. 기다리지 않으면 대체 서체로 그려집니다(실제 구현에서도 유지).
- 일러스트는 화면의 `<CategoryIllustration>`을 숨긴 채 렌더하고 svg를 직렬화해 CSS 변수를 16진 값으로 바꾼 뒤 그립니다. react-dom/server를 쓰지 않아 서버 컴포넌트 제약이 없습니다.
- 말풍선 모형은 앱 토큰으로 흉내만 냈습니다(실제 카카오톡 색이 아님). 어두운 채팅방은 tokens.css의 `.dark` 범위 선택자로 페이지 테마와 무관하게 어둡게 그립니다. 처음에는 `.dark`를 figure에 걸어 밝은 페이지 위 캡션이 다크 색(대비 2.07)이 되던 것을 axe가 잡아 패널 안으로 옮겼습니다.
- `[실기기]` 확인이 필요한 것: 카카오톡 실제 말풍선에서의 2:1 표시와 잘림, 어두운 채팅방, iOS Safari Web Share 파일 공유(`navigator.canShare({ files })`), 카카오톡 인앱 브라우저에서 `a[download]` 저장 동작(인앱은 다운로드를 막는 경우가 있어 길게 눌러 저장 안내가 필요할 수 있음). Claude가 대신 확인하지 못했습니다.
