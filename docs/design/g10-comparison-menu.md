## 2. 번들 요약 (gzip, 추정)

**홈 `/today` 첫 로드가 지금 199.9 KB로 예산 200 KB까지 0.1 KB 남았습니다**(T10.15 메모 푸시 뒤, lunchmate-b4 세션 측정). 홈 카드를 바꾸는 안은 다른 곳에서 덜어 내야 들어갑니다.

- **새 의존성 없음.** 세 안 모두 기존 입력 클래스, Chip, Base UI Drawer, CompactNumbers, 상태 컴포넌트, Lucide 아이콘만 씁니다. Motion(`m`)은 쓰지 않습니다.
- **A**: 홈 카드 숫자 칸 분기 약 +0.2~0.3 KB + 홈 집계 응답에 1위 메뉴(이름, 가격, 제보 수) 필드. 상세 청크 +약 1 KB, 피드백 시트 청크 +약 1 KB. **홈 예산 초과 → 덜어 낼 곳 필요.**
- **B**: 홈 카드 메뉴 줄 약 +0.2 KB + A와 같은 홈 집계 필드. 상세 청크 +약 1.5 KB(검색형 목록), 피드백 청크 +약 1.5 KB. **홈 예산 초과 → 덜어 낼 곳 필요.**
- **C**: **홈 0.** 상세 청크 +약 1.5 KB(메뉴판, 줄 펼침), 피드백 청크 +약 1.5 KB(항목 줄 + 작은 시트, Drawer 덩어리 재사용). 메뉴 집계는 상세를 열 때만 읽어 홈 요청도 그대로입니다.
- 실제 값은 구현 뒤 `pnpm build`의 bundle-report로 재서 `bundle-log.md`에 남깁니다.

## 3. 공통으로 지킨 것

- **입력**: 메뉴 이름 한 줄 `input`, 늘 빈 칸에서 시작. 카카오 장소명이나 카테고리 이름 미리 채우기, 붙여 넣기 버튼, 자동 완성 없음. 자리표시자는 일반 예시 "예: 김치찌개". 20자(코드 포인트, 넘으면 빨간 수 + 한 줄, 보내기 꺼짐). NFC, 공백 한 칸, 앞뒤 공백 제거(`normalizeMenuName`), 같은 메뉴 판정은 공백 지운 비교 키(`menuKey`, 테스트). 이미 제보된 메뉴 칩, 목록은 우리 DB 집계라 미리 보여도 됩니다.
- **가격**: FB-02와 같은 500원 단위 스테퍼(1천~10만 원). 제보 메뉴를 고르면 그 메뉴 가격 중앙값에서 시작. 알려주기는 메뉴와 가격 둘 다 필수, 피드백은 메뉴를 고를 때만 가격 필수(만족만으로도 저장).
- **보이는 집계**: 메뉴별 가격 중앙값과 제보 수, 제보 많은 순 3개. 제보한 사람은 어디에도 없습니다. 홈 카드(A, B)는 제보 2건 이상인 1위 메뉴만(안건 2).
- **추천 점수에 쓰지 않음**: 카드의 메뉴는 표시 전용. 가격 하드 필터는 지금처럼 `reviews.price_krw`.
- **올리브 버튼은 화면에 하나**: 상세는 길찾기, 피드백 시트는 저장, 알려주기 시트(별도 층)는 알려주기. C 메뉴판 안 "알려주기"는 상세 길찾기가 있어 보조 버튼.
- **제보 없음**: 세 안 같은 내용("아직 알려진 메뉴가 없습니다." + "처음으로 알려 주시면 다음 사람이 메뉴를 보고 고를 수 있습니다." + 알려주기 + 네이버 플레이스에서 전체 메뉴 보기). 홈 카드는 지금 그대로.
- **상태 문구**: 실패 "보내지 못했습니다. 쓴 내용은 그대로 있으니 다시 눌러 주세요.", 금칙어 기존 `moderationCopy.banned`, 한도 "오늘은 메뉴를 20번 알려 주셨습니다. 내일 다시 알려 주세요.", 오프라인 "인터넷에 연결되어 있지 않아 메뉴를 남길 수 없습니다. 연결되면 다시 시도해 주세요.", 결과 "메뉴를 알려 주셔서 고맙습니다." 금지 문자 0(`pnpm lint:copy`).

## 6. 설계안 (초안, 마이그레이션 파일은 선택 뒤에 만듦)

### 6.1 스키마: `public.menu_reports`

| 열 | 형 | 규칙 |
| --- | --- | --- |
| id | uuid pk | `gen_random_uuid()` |
| user_id | uuid | `default auth.uid()`, `auth.users on delete cascade` |
| place_id | text | `^[0-9]{1,20}$` (favorites와 같은 검사) |
| place_url | text | 카카오 장소 링크 형식 검사(favorites와 같은 식) |
| menu_name | text | 1~20자(코드 포인트), 앞뒤 공백과 제어 문자 없음, 연속 공백 없음 |
| menu_key | text | 트리거가 채움: 공백 제거 + lower. 사용자가 넣지 않음 |
| price_krw | integer | 1000~100000, 500원 단위 |
| source | text | `feedback` / `detail` |
| review_id | uuid null | `reviews(id) on delete cascade`(후기를 지우면 함께 지움, MENU-01). source=feedback일 때만 |
| hidden_at, hidden_reason | | 관리자 숨김(`admin`), 신고 누적은 MENU-05 |
| created_at | timestamptz | `now()` |

- 제약: `unique (user_id, place_id, menu_key, kst_day)`(같은 메뉴 하루 1회), 1인 하루 20건 버킷 `menu_reports`(`private.consume_daily_quota`), 금칙어 트리거(`private.reject_banned_text`, T10.3b), 정지 사용자 차단(`private.block_suspended_writer`).
- RLS: select/insert/delete는 본인 행만, update 없음(고치려면 지우고 다시). anon 권한 없음.
- 집계 함수 `public.place_menus(place_ids text[])`: security definer, 최근 180일, 숨김 제외, menu_key별 대표 이름(가장 많이 쓴 표기), 가격 중앙값, 제보 수, 최근 제보 월, 장소마다 상위 3개. 비로그인도 부름(상세는 비로그인도 봄). user_id 반환 없음(AC-MENU-1).
- 관리자: `admin_hide_menu_report`, `admin_merge_menu_key(place_id, from_key, to_key)`(T8.5 처리 이력에 남김).
- 탈퇴: cascade, `account_residue`가 자동으로 셈. 처리방침 수집 항목에 "메뉴 제보(메뉴 이름, 가격)" 추가(T10.16g).

### 6.2 테스트

- RLS 3역할(본인, 타인, 비로그인): 타인 원본 행 0, 비로그인 insert 거절, 집계 함수에 user_id 없음, 숨긴 행 집계 제외, 금칙어와 한도 거절(AC-MENU-1).
- 추천 점수 미반영: 같은 시드에서 메뉴 집계 유무로 결과가 같다(AC-MENU-2).
- 입력: 이름 칸 빈 시작, 카카오 이름 미리 채움 없음(AC-MENU-3), 피드백 칩 탭 수(AC-MENU-4, E2E).
