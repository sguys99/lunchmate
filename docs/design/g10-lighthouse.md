# G10 성능 재측정: AC-REC-4 원인과 Lighthouse (T10.9)

> 2026-11-02 KST. 기준 커밋 21f0b9a(= origin/main, 배포 중인 프로덕션) + 작업 트리(아래 2절 최적화).
> 빌드와 측정은 모두 scratchpad 복사본(`git archive` + `pnpm install --offline`)에서 `VERCEL_ENV=production NEXT_PUBLIC_DESIGN_LAB=false pnpm build && next start`로 했다. 본 폴더 `.next`와 dev 서버(3102)는 건드리지 않았다.

## 0. 요약

- **AC-REC-4 원인**: T9.10(D-25 홈 압축, 상한, 프로필 사진)이 아니다. 9ac5118(T6.11, 2026-11-01)이 카드 앞에 **우리 DB 집계(place_stats) 서버 액션 왕복**을 직렬로 넣으면서 +0.31초 늘었다(4.66 → 4.97초). 그 뒤 커밋들은 ±0.05초 안이다.
- **고친 것**: 늘어난 왕복을 없애는 대신(카드를 집계 없이 먼저 내면 카드가 바뀌는 동작 변화) 앞쪽 대기를 줄였다. 카카오 SDK를 HTML 머리의 preload 힌트로 첫 로드 JS와 나란히 받고, 집계 읽기 청크를 화면 진입 때 미리 받는다. 화면, 문구, 동작 변화 없음. 첫 로드 JS 변화 없음(`/` 178.8 KB, `/today` 199.7 KB).
- **결과**: Regular 3G 첫 방문 카드 중앙값 **mobile 4.99 → 4.50초, desktop 4.93 → 4.46초**(같은 날, 같은 기계, 3회). 5회 반복 측정은 4.94 → 4.41~4.46초. 여유 약 0.5초. Fast 4G LCP도 2.96 → 2.39초로 2.5초 안에 들어왔다.
- **Lighthouse(모바일, 3회 중앙값)**: 로컬 `/today` 86 → **88**, 나머지는 그대로(`/` 97, `/login` 97, `/terms` 98, `/offline` 99, `/map` 81). 접근성은 모두 96 이상.
  배포된 프로덕션(최적화 전 코드)은 `/` 99, `/today` 88, `/login` 99, `/terms` 100, `/offline` 100, **`/map` 89**. 성능 85, 접근성 90 기준을 로컬 `/map`(81)만 못 넘고, 프로덕션은 모두 넘는다.

## 3. Lighthouse 재측정 (T10.9)

### 3.1 조건

T8.10(g8-lighthouse.md 1절)과 같다. Lighthouse 13.5.0(npx 캐시), 로컬 Chrome headless(`--headless=new`), 기본 모바일 프리셋(simulate, RTT 150ms, 1.6 Mbps, CPU 4x), 비로그인 첫 방문, 위치 권한 없음, `*posthog*`, `*sentry*`, `*ingest*` 차단, 페이지마다 3회 중앙값.

### 3.3 기준 미달과 판단

- **성능 85 미달은 로컬 `/map` 81 하나**. 프로덕션 `/map`은 **89**(LCP 3.8초)로 기준을 넘는다. 차이는 로컬 `next start`(압축 gzip, HTTP/1.1, 서버 렌더 시간 포함)와 Vercel CDN(brotli, HTTP/2, 정적 껍데기 캐시)이다. 같은 이유로 프로덕션은 모든 페이지가 로컬보다 0~8점 높다.
  - 판단: D-21(로컬 81 수용, 배포 후 재검토)의 재검토 조건은 **실측으로 충족**된다. 사용자에게 닿는 값은 프로덕션 89이므로 `/map`은 85 기준 통과로 보고, g8-lighthouse.md 4절의 동작이 바뀌는 85 후보(지도 SDK 늦게 받기, 하단 탭 프리페치 미루기)는 하지 않는 것을 권한다. 결정 기록(design-decisions D-21 후속)은 사용자 확인 뒤 남긴다.
- **접근성 90 미달 없음**. `/`, `/login` 96은 네이버 로그인 버튼 흰 글자 대비(`color-contrast`, 브랜드 예외 G3 안건 7, g8-a11y-audit I3)로 T8.10과 같다.
- 권장사항 96(`/today`, `/map`)은 `geolocation-on-start`(진입 때 위치 요청, 10초 원칙 제품 결정), SEO 63(`/today`, `/login`, `/offline`, `/map`)은 `robots: { index: false }`로 일부러 막은 결과다. T8.10과 같다.
- `/today` 88은 위치 안내 상태의 값이다. 카드 상태 LCP는 2.1절(Fast 4G 2.39초).

## 4. 남은 것
