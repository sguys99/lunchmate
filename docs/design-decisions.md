# 디자인 결정 기록 (design-decisions.md)

> 선택 게이트(⛔)에서 사용자가 고른 시안과 그 이유를 남기는 기록입니다. 절차는 `docs/tasks.md` 2.3절, CLAUDE.md 6.1절을 따릅니다.
> 이 파일에 기록된 결정이 있어야 해당 화면을 구현할 수 있습니다. 새 항목은 아래에 날짜순으로 추가하고, 기존 항목은 고치지 않습니다(바뀌면 새 항목으로 "변경" 기록).

## 기록 양식

복사해서 쓰십시오.

```markdown
### D-NN. <게이트> <화면 또는 컴포넌트>

- 게이트/화면: G1 디자인 시스템 | G3 오늘(홈) | T4.0 온보딩 ... (작업 ID 함께)
- 날짜: YYYY-MM-DD
- 비교한 시안: A <한 줄 의도> / B <한 줄 의도> / C <한 줄 의도>
- 선택안: A | B | C
- 조합 지시: (예: "B 배치 + A의 카드 스와이프 모션", 없으면 "없음")
- 이유: 사용자가 말한 선택 이유 (원문에 가깝게)
- Claude 추천과 차이: 추천안, 추천과 다르게 고른 경우 그 점
- 캡처 경로: docs/design/shots/<화면>/ (390px, 1280px, 라이트, 다크)
- 비교표: tasks.md 2.3절 양식 표를 붙이거나 위치를 링크
- 후속 작업: 구현 작업 ID, 미선택 시안 코드 삭제 여부 (삭제 커밋)
```

- 날짜: 1차 2026-10-29(비교 자료) → 선택 2026-10-29, 2차 2026-10-30
- 비교한 시안 (1차): A 스와이프 스택 <한 장씩 넘기며 숫자(도보 28px)로 판정> / B 피크 캐러셀 <그림과 이름 먼저, 옆 카드가 살짝 보임> / C 세로 3단 비교 <세 곳 숫자를 같은 열로 비교, 열 최선만 진하게> / D 오늘의 한 곳 + 대안 2곳 <앱이 1순위를 크게 권하고 이유를 이름 바로 아래에>
- 1차 선택: D. 사용자 원문 "홈은 D가 좋은데 어제간 곳 어땠는지 물어보는 항목을 추가해줘. 랜딩은 B. 내 의견 반영해서 다시 시안 만들어."
- 비교한 시안 (2차, D 수정안, 2026-10-30): D1 머리 아래 한 줄 띠 <제목 바로 아래 헤어라인 띠 한 줄로 묻고 답하면 고마움 한 줄로 접힘> / D2 큰 카드 위 질문 카드 <같은 폭 얇은 카드로 묻고 답하면 카드가 사라짐> / D3 먼저 묻기 <어제 간 곳이 있는 날은 첫 화면이 질문, 답하거나 미루면 추천으로>
- 선택안: **D1** (사용자 원문 "홈 D1", 2026-10-30)
- 조합 지시: D(오늘의 한 곳 + 대안 2곳) + 어제 피드백을 첫 화면에 → 2차 D1. 2차 세 안 공통으로 D의 약점을 고침: 길찾기, 그냥 골라줘, 다시 뽑기를 하단 탭 위 고정 행동 줄로 내림(길찾기 위치 0.62 → 0.85, 390 x 844), 대안 두 줄을 나란히 놓인 작은 카드 두 장으로 바꾸고 만족 %를 더함
