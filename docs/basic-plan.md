## 1. 개요

런치메이트는 "오늘 뭐 먹지?"를 10초 안에 끝내 주는 **모바일 우선 웹앱(PWA)** 이다. 회사 위치·예산·거리·기피 음식을 한 번 설정하면 끼니마다 인근 식당을 추천하고, 먹은 뒤 남긴 짧은 피드백으로 추천이 내 입맛에 맞춰진다. 동료를 초대해 투표로 점심·회식 장소를 정할 수도 있다.

- **대상**: 구내식당 없는 직장인(점심·저녁 외식), 회식 장소를 정해야 하는 총무·팀장, 회사 근처 맛집이 궁금한 신규 입사자
- **핵심 가치**
  - 결정 피로 감소: 선택지를 3개로 좁힘
  - 실패 확률 감소: 내 피드백 + 다른 사용자 후기·가격
  - 합의 비용 감소: 친구 초대 투표로 "아무거나"를 끝냄
  - 이동 마찰 제거: 지도 확인 → 네이버 지도 길찾기 한 번에
- **포지셔닝**: 맛집 "검색" 앱이 아니라 "결정" 앱
- **공개 범위**: 일반 공개 서비스 (약관·개인정보·위치정보·신고 기능까지 출시 범위에 포함)

### 3.2 친구 초대 투표 상세

**흐름**

1. 방장이 투표방을 만든다: 제목(예: "금요일 팀 점심"), 끼니, 마감 시각, 후보 식당(추천 결과에서 2~5곳 선택 또는 직접 검색), 복수 선택 허용 여부.
2. 초대 링크(`/poll/{초대코드}`)를 **카카오톡 공유** 또는 휴대폰 공유창(Web Share API)으로 보낸다. 링크 복사도 제공.
3. 친구가 링크를 열면 투표방 미리보기(제목, 후보 수, 마감 시각)를 먼저 보여준다.
4. 투표하려면 카카오·네이버·구글 로그인. 로그인 후 원래 투표방으로 자동 복귀한다.
5. 투표 결과는 실시간으로 갱신된다(Supabase Realtime).
6. 마감 시각이 되거나 방장이 "결정"을 누르면 1위 식당을 확정하고, 참여자 모두에게 결과 카드와 길찾기 버튼을 보여준다. 동점이면 방장이 고르거나 룰렛으로 정한다.
7. 확정된 식당은 참여자 전원의 방문 기록 후보로 들어가고, 다음 접속 때 피드백을 요청한다.

**규칙**

- 1인 1표(복수 선택 허용 시 후보별 1표), 마감 전까지 변경 가능
- 참여 인원 최대 30명, 초대 링크는 마감 후 24시간 지나면 만료
- 방장만 후보 추가·삭제·마감 가능, 참여자는 "후보 제안" 가능
- 투표방은 초대 링크를 가진 사람만 볼 수 있음 (검색·목록 노출 없음)

**기술 포인트**

- 카카오톡 공유: Kakao JavaScript SDK 공유 기능, 카카오 앱에 Vercel 도메인 등록 필요
- 링크 미리보기: Vercel에서 투표방별 Open Graph 이미지 동적 생성(제목·후보 수·마감 시각)
- 로그인 후 복귀: OAuth redirect URL에 투표방 경로를 담아 처리
- 보안: 투표·후보 테이블은 RLS로 "참여자만 읽기/쓰기"

### 3.3 회식 모드 상세

| 조건 | 입력 방식 | 데이터 출처 |
| --- | --- | --- |
| 인원 | 숫자 (2~40) | 사용자 입력 |
| 1인 예산 | 슬라이더 | 후기 제보 가격 |
| 룸·단체석 | 토글 | 사용자 태그 제보 |
| 주류 | 토글 (술집·고깃집 가중치 상향) | 카카오 카테고리 |
| 시간대 | 저녁 고정, 거리 허용치 자동 확대(도보 15분) | 설정 |

결과는 후보 5곳 리스트로 보여주고, "이 후보로 투표 만들기" 버튼으로 바로 친구 초대 투표로 넘어간다. 룸·단체석 정보는 초기에 비어 있으므로 상세 화면에 "네이버 플레이스에서 확인" 링크를 함께 둔다.

## 4. 놓친 요구사항 보완 (반영 완료)

1. **가격 데이터**: 장소 API는 메뉴 가격을 주지 않는다. 식후 피드백의 "실제 1인 가격"으로 식당별 가격대를 만들고, 데이터가 없으면 카테고리 평균 추정값에 "추정" 배지를 붙인다.
2. **영업시간·브레이크타임**: 상세 화면에서 네이버 플레이스 링크로 확인, "문 닫았어요" 제보 누적 시 추천 제외.
3. **중복 회피**: 최근 2~3일 먹은 식당·카테고리는 점수 감점.
4. **위치 권한 거부**: 현위치를 못 받으면 기본 사무실로 자동 전환.
5. **혼밥·빠른 식사 태그**: "혼밥 OK", "15분 컷", "웨이팅 적음", "룸 있음", "단체석" 태그를 피드백으로 수집.
6. **일반 공개 서비스 필수 요소**: 이용약관, 개인정보처리방침, 위치정보 이용약관, 회원 탈퇴·데이터 삭제, 후기 신고, 문의 채널.
7. **남용 방지**: 후기·투표 생성 빈도 제한(rate limit), 금칙어 필터.
8. **분석**: 추천 수락률, 다시 뽑기 횟수, 피드백 응답률, 투표 완료율을 이벤트로 수집(PostHog 또는 Vercel Analytics).

## 5. 기술 검토 요약

| 항목 | 확인 결과 | 결정 |
| --- | --- | --- |
| 네이버 지역 검색 API | 한 번에 최대 5건 | 식당 목록 수집에는 사용하지 않음 |
| 네이버 Web Dynamic Map | 브라우저 동작, 서비스 도메인 등록, 무료 이용량은 대표 계정 한정 | 지도 표시에 사용, 사용량 한도·알림 설정 |
| 네이버 지도 앱 URL Scheme | `nmap://route/walk` 등으로 도보·대중교통·자동차 길찾기, `appname` 필수 | 길찾기 버튼에 사용 |
| 카카오 로컬 API | 음식점(FD6) 반경 검색, JS SDK로 브라우저 호출 가능 | 식당 후보 주 데이터원 |
| 카카오 결과 저장 정책 | 캐싱 포함 저장 금지, 실시간 호출만 허용 | 장소 ID와 사용자 생성 데이터만 저장 |
| GitHub Pages | 정적 호스팅만 가능 | 공유 미리보기·서버 함수 때문에 **Vercel로 변경** |

**출시 전 확인 필요**

- 카카오 장소 데이터를 네이버 지도 위에 표시하는 것이 양사 약관상 허용되는지. 불가하면 지도를 카카오맵으로 바꾸고 길찾기만 네이버 지도 앱으로 연결한다.
- 일반 공개 서비스이므로 위치기반서비스사업 신고 대상인지. 현위치를 서버에 저장하지 않는 구조로 시작하고, 출시 전 방송통신위원회 기준을 확인한다.
- 카카오 로그인에서 이메일 등 추가 동의 항목이 필요하면 카카오 비즈 앱 전환이 필요할 수 있다. MVP는 닉네임·프로필 사진만 받는 것을 기본으로 한다.

## 7. 추천 로직과 피드백 학습

MVP는 설명 가능한 점수 합산 방식으로 시작하고, 피드백으로 카테고리 선호 가중치를 자동 갱신한다.

**처리 순서**

1. **후보 수집**: 선택한 사무실 또는 현위치 기준, 허용 도보 거리 반경으로 카카오 음식점(FD6) 검색 (최대 45곳)
2. **하드 필터**: 기피 음식 카테고리 → 다시 안 갈 곳 → 폐업 제보 누적 → 예산 초과(제보 가격이 있을 때만) 순서로 제거
3. **점수 계산**

   ```
   S = w_d·D + w_p·P + w_b·B + w_c·C − w_r·R
   ```

   - D: 거리 점수 (가까울수록 1)
   - P: 내 카테고리·식당 선호도
   - B: 예산 적합도
   - C: 다른 사용자 평판 (👍 비율, 후기 수로 보정)
   - R: 최근 먹은 곳·카테고리 반복 패널티
4. **무작위성**: 상위 10곳 안에서 점수 비례 샘플링 (다시 뽑기가 매번 같지 않게)
5. **다양성 제약**: 뽑힌 3장 중 같은 카테고리는 최대 2장. 샘플링하면서 적용한다(PRD 7장)
6. **설명 생성**: 카드마다 "도보 약 6분, 지난주 👍한 한식" (기여도 상위 2요소)

**피드백 반영**

- 👍 → 식당·카테고리 선호도 상승, 👎 → 하락. 최근 피드백에 더 큰 가중치(지수 감쇠)
- 다시 뽑기 3번 연속 → 해당 후보들에 약한 부정 신호
- "요즘 이게 땡겨요" 카테고리 선택 시 일주일간 가중치 상향
- 투표에서 이긴 식당은 참여자 모두에게 약한 긍정 신호
- (2단계) 날씨 나쁨 → 거리 가중치 상향
- (3단계) 협업 필터링: 취향이 비슷한 사용자가 👍한 식당 가산점

## 9. 화면 구성과 디자인 방향

### 9.1 화면 구조

하단 탭 4개: **오늘 · 지도 · 투표 · 나** (기록은 '나' 안에 배치). 데스크톱은 좌측 리스트 + 우측 지도 2단 레이아웃.

| 화면 | 핵심 요소 |
| --- | --- |
| 랜딩 (비로그인) | 한 줄 가치 제안, 추천 체험 버튼, 카카오·구글로 시작하기 |

| 오늘 (홈) | 끼니 자동 전환(00:00~14:59 점심, 15:00~ 저녁, KST), 사무실 전환 칩, 추천 카드 3장 스와이프, 다시 뽑기, "친구랑 정하기" 버튼, 회식 모드 진입 |

| 식당 상세 (바텀시트) | 도보 분, 가격대(제보/추정), 👍 비율, 태그, 공개 후기, 길찾기, 네이버 플레이스 링크, 투표에 추가 |

### 9.2 디자인 원칙

- **톤**: 따뜻하고 편안한 미니멀. 따뜻한 밝은 배경 + 흙빛 계열 단일 포인트 컬러 하나만 사용 (최초안 토마토 레드에서 변경, `docs/design/preferences.md`)
- **타이포**: Pretendard 단일 서체, 도보 분·가격 같은 숫자를 크게
- **결정 중심**: 한 화면 선택지 3개 이하, 리스트보다 카드
- **모션**: 카드 스와이프, 다시 뽑기 셔플, 바텀시트 스프링, 투표 득표 바 애니메이션 정도만
- **한 손 조작**: 주요 버튼은 화면 하단 1/3, 터치 영역 최소 44px
- **다크 모드** 지원, 접근성 대비 4.5:1 이상
- **컴포넌트**: shadcn/ui + Lucide 아이콘, 디자인 토큰(색·간격·라운드)을 먼저 정의

- 리포 루트 `CLAUDE.md`에 이 계획서의 결정 표, 데이터 모델, 디자인 원칙을 요약해 둔다.

## 12. 수익화 전략

### 12.1 원칙

- **추천과 광고를 분리한다.** 광고·스폰서 여부는 추천 점수(7장)에 절대 반영하지 않는다. 추천 카드 3장 안에 광고를 섞지 않는다. 신뢰가 서비스의 핵심 자산이다.
- **결정 흐름을 방해하지 않는다.** 오늘(추천)·지도·투표방·투표 초대 페이지에는 일반 광고 배너를 넣지 않는다.
- **광고는 항상 '광고' 또는 '제휴'로 표시한다.**
- **사용자에게도 쓸모 있는 광고를 우선한다.** 일반 배너보다 근처 식당 할인·쿠폰이 낫다.

### 12.2 단계별 전략

| 단계 | 시점(목표) | 수익 모델 | 내용 |
| --- | --- | --- | --- |
| 1. 무광고 | 출시 후 약 6개월 | 없음 | 깔끔한 경험으로 사용자와 후기·가격 데이터 확보 |
| 2. 제한적 네이티브 배너 | 활성 사용자가 쌓인 뒤 | 광고 네트워크 (카카오 애드핏 우선, 구글 애드센스 대안) | 기록·월간 리포트·설정 화면에만 앱 톤에 맞춘 광고 카드 1장 |
| 3. 식당 스폰서·점심 쿠폰 | 특정 지역 사용자가 충분해진 뒤 | 노출비, 쿠폰 사용 건당 수수료, 사장님 페이지 월 구독 | 추천 카드와 분리된 "근처 제휴 식당" 1칸, 한가한 시간대 타임딜, 식당이 가격·메뉴·영업시간·룸 정보 직접 관리 |
| 4. 회식 예약 연결 | 회식 모드 사용이 늘어난 뒤 | 예약 건당 수수료, 제휴 할인 | 투표로 확정된 식당을 바로 예약. 초기에는 네이버 예약 링크, 제휴 식당은 직접 예약 |
| 5. B2B | 회사 그룹 사용이 늘어난 뒤 | 회사 단위 연 구독 | 사내 맛집 지도, 관리자 통계, 식대·모바일 식권 가맹점 연동 |
| 보조. 프리미엄 구독 | 3단계 AI 기능 출시와 함께 | 사용자 월 구독 | AI 자연어 추천 무제한, 상세 월간 리포트, 광고 제거 |

### 12.3 광고 배치 규칙

### 12.4 지역 집중 전략

광고·제휴 영업은 동네 단위로 한다. 첫 집중 지역은 서울로 확정했다(PRD Q10). 서울 안에서 직장인이 밀집하고 구내식당 없는 회사가 많은 권역(예: 강남, 여의도, 성수, 종로·광화문) 중 한 곳을 골라 사용자를 먼저 모으고, 그 동네 식당에 "이 반경 직장인 몇 명이 매일 쓴다"는 숫자로 스폰서·쿠폰 영업을 시작한다.

### 12.5 측정 지표

- 광고: 노출 수, 클릭률, 광고 화면 이탈률(광고가 경험을 해치는지 확인)
- 스폰서·쿠폰: 쿠폰 노출 대비 사용률, 제휴 식당 재방문율, 식당 재계약률
- 예약: 회식 투표 확정 대비 예약 전환율
- 신뢰 지표: 추천 수락률이 광고 도입 전후로 떨어지지 않는지

### 12.6 수익화 전 확인 사항

- 카카오·네이버 API 상업적 이용 조건(광고와 함께 표시, 사용량 과금)을 수익화 시점에 다시 확인
- 쿠폰 판매나 예약·결제 대행을 하면 통신판매업 신고 등 전자상거래 관련 요건 확인
- 광고 네트워크 심사 기준(콘텐츠 양, 개인정보처리방침 게시) 충족
