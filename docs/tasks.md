## 0. 이 문서 사용법

### 0.1 표기

| 표기 | 뜻 |
| --- | --- |
| `- [ ]` | 미착수 또는 진행 중 |
| `- [x]` | 완료 (완료 기준 충족 후에만 체크) |
| ⛔ **선택 게이트** | Claude Code가 결과물을 보여주고 **멈추는 지점**. 사용자가 고르기 전에는 다음 작업으로 넘어가지 않습니다 |
| ❓ | 사용자 답변이 필요한 작업 |
| `(REC-03)` | 관련 PRD 요구사항 ID |
| `[실기기]` | Claude가 대신 확인할 수 없는 항목. 사용자가 휴대폰으로 확인 후 체크 |

### 0.2 작업 ID와 커밋 규칙

- 작업 ID는 `T{단계}.{번호}` 형식입니다. 예: `T5.12`
- 커밋 메시지에 PRD ID와 작업 ID를 함께 적습니다. 예: `feat(REC-05, T5.18): 다시 뽑기 셔플 모션`
- PRD ID가 없는 작업(준비, 디자인 시스템, 공통 기반 등)은 작업 ID만 적습니다. 예: `design(T1.4): 시안 A Terracotta Table`, `chore(T0.23): Vitest 설정`
- 작업을 끝낸 커밋에서 이 문서의 체크박스도 함께 체크합니다. 체크만 따로 커밋하지 않습니다.
- 1장 진행 현황 표는 단계가 끝날 때마다 갱신합니다.

### 0.3 Claude Code 세션 시작 문장 예시

```
tasks.md에서 다음 미완료 작업부터 진행해줘. 시작 전에 관련 PRD ID와 AC를 요약하고,
선택 게이트를 만나면 멈춰서 비교표와 함께 선택을 요청해줘.
```

## 2. 공통 규칙

### 2.1 작업 완료 기준 (DoD)

모든 기능 작업은 아래를 만족해야 체크합니다. (CLAUDE.md 10장 요약)

- [ ] 관련 PRD AC 통과 (테스트 또는 수동 확인 기록)
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm lint:copy` 통과
- [ ] 390px, 1280px, 다크 모드 확인
- [ ] 로딩(스켈레톤), 빈 상태, 오류, 오프라인 4상태 구현
- [ ] 분석 이벤트 연결 (PRD 10.2절 이름 그대로)
- [ ] 새 테이블은 RLS 정책과 3역할(본인, 타인, 비로그인) 테스트 포함

### 2.2 프론트엔드 문구 규칙 (필수)

화면에 보이는 모든 텍스트(UI, 토스트, 오류, OG 이미지, 메타 설명, 카카오톡 공유 문구, 약관 외 안내문)에 적용합니다.

**금지 문자**

| 금지 | 대신 쓰는 것 |
| --- | --- |
| Em dash `—`, en dash `–`, 가로줄 `―` | 쉼표, 마침표, 괄호. 범위는 `~` (예: 11:30~13:00) |
| 중간점 `·`, `・`, `‧` (키워드 나열) | 쉼표 `,`, "와/과", 슬래시 `/` |

- 카드 메타 정보 줄(도보 분, 가격, 👍 비율)은 문자 구분자 대신 **레이아웃 간격(gap)이나 얇은 세로 구분선**으로 나눕니다. 가운뎃점 모양의 장식 요소도 쓰지 않습니다.
- 한 문장 안에서 이을 때: `도보 약 4분, 1인 9천 원대`, `룸 있음/단체석`, `한식과 국밥`

**해요체와 습니다체 비율 3:7**

| 문체 | 비중 | 쓰는 곳 |
| --- | --- | --- |
| 습니다체 | 약 70% | 상태 안내, 결과, 설명, 오류, 빈 상태 설명, 정책 고지, 권한 안내 |
| 해요체 | 약 30% | 질문, 제안, 피드백 요청, 축하처럼 말을 거는 순간 |
| 비율에서 제외 | | 버튼, 탭, 칩, 라벨 같은 명사형 문구 (예: "길찾기", "투표 만들기"), 약관 본문(습니다체 100%) |

예문

| 상황 | 문체 | 예문 |
| --- | --- | --- |
| 추천 이유 | 명사형 | 도보 약 4분, 지난주 👍한 국밥 |
| 피드백 요청 | 해요체 | 어제 간 정담국밥, 어땠어요? |
| 빈 상태 | 습니다체 + 해요체 | 도보 10분 안에 조건에 맞는 식당이 없습니다. 15분까지 넓혀볼까요? |
| 오류 | 습니다체 | 식당 정보를 불러오지 못했습니다. 잠시 후 자동으로 다시 시도합니다. |
| 권한 | 습니다체 | 현위치를 쓰려면 위치 권한이 필요합니다. 지금은 기본 사무실 기준으로 추천합니다. |
| 투표 마감 | 습니다체 | 투표가 마감되었습니다. 1위는 정담국밥입니다. |
| 확정 축하 | 해요체 | 오늘 점심은 여기로 정했어요. |
| 할인 안내 | 습니다체 | 사용자가 제보한 정보라 실제와 다를 수 있습니다. |
| 온보딩 | 혼합 | 회사 위치부터 알려 주세요. 이 위치를 기준으로 근처 식당을 찾습니다. |

(예문의 식당 이름은 모두 가상입니다.)

**자동 검사**: T2.3의 `pnpm lint:copy`가 금지 문자를 오류로, 문체 비율을 리포트로 보여줍니다. 비율은 화면 단위가 아니라 도메인 문구 파일 단위로 25~40% 해요체를 허용 범위로 봅니다.

세부 예문, 금지 표현, 숫자 표기, `src/copy` 작성법은 `docs/copy-guide.md`(T2.1)를 봅니다.

### 2.3 디자인 시안 절차 (3안 이상)

CLAUDE.md 6.1절을 따르되 **시안 수는 3안 이상**으로 합니다.

1. 같은 요구사항으로 **방향이 분명히 다른** 3안 이상을 `src/app/design-lab/<화면>/{a,b,c}`에 만듭니다. 색만 바꾼 변형은 시안이 아닙니다.
2. 각 시안은 4상태, 다크 모드, 목업 데이터, 핵심 모션을 포함합니다.
3. `pnpm shots`로 캡처하고 아래 비교표를 붙여 선택을 요청한 뒤 멈춥니다.
4. 선택 결과를 `docs/design-decisions.md`에 기록한 뒤에만 구현합니다.
5. 구현 후 미선택 시안 코드는 삭제하고, 캡처와 기록은 남깁니다.

**사용 규칙**

- 효과마다 "결정을 빠르게 하거나 상태를 더 잘 알려주는가"를 비교표에 적습니다. 장식만을 위한 효과는 넣지 않습니다.
- 홈 첫 화면에서 동시에 움직이는 효과는 2개 이하로 둡니다.
- 라이브러리를 추가할 때마다 `docs/design/bundle-log.md`에 증가량을 기록하고, 큰 의존성은 사용자에게 먼저 묻습니다 (CLAUDE.md 9장).
- 모든 모션은 `prefers-reduced-motion`에서 즉시 상태 변화로 대체합니다.
- 스와이프 조작에는 항상 이전/다음 버튼을 함께 둡니다.
- 분석/관측 SDK(PostHog, Sentry 클라이언트)는 홈 초기 번들에 넣지 않고 첫 렌더 이후 로딩합니다. posthog-js는 약 104KB(gzip)라 그대로 넣으면 홈 200KB 예산을 넘깁니다 (T0.27).
- 클라이언트 입력 검증은 `zod/mini` 사용을 검토합니다(`zod` 전체는 약 89KB gzip). 서버 재검증은 `zod`를 씁니다 (T0.27).
- 번들 증가량은 `pnpm analyze`(`next analyze`, Turbopack 내장)로 측정합니다. `@next/bundle-analyzer`는 Webpack 전용이라 쓰지 않습니다 (T0.27).
