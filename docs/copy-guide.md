# 문구 가이드 (copy-guide.md)

> 화면에 보이는 모든 글을 쓰는 기준입니다. 규칙의 정본은 `docs/tasks.md` 2.2절이고, 이 문서는 그 규칙을 화면 유형별 예문, 금지 표현, 숫자 표기법, `src/copy` 작성법으로 풀어 씁니다(T2.1).
> 목소리는 `DESIGN.md` 8장(시안 B "Quiet Stone": 짧고 낮은 목소리, 느낌표를 거의 쓰지 않음)을 따릅니다. 두 문서와 이 문서가 다르면 tasks.md 2.2절과 DESIGN.md가 우선하고, 이 문서를 고칩니다.
>
> - **적용 범위**: UI, 토스트, 오류, 빈 상태, OG 이미지, 메타 설명, 카카오톡 공유 문구, 매니페스트, 약관 외 안내문. 약관 본문은 습니다체 100%.
> - **적용 제외**: 문서(`docs/`, `*.md`) 서술, 코드 주석, 로그. 문서 서술의 중간점은 그대로 둡니다.
> - 예문의 식당 이름(정담국밥, 스시오, 소담식당 등)은 모두 가상입니다.

## 1. 금지 문자

| 금지 | 대신 쓰는 것 | 예 |
| --- | --- | --- |
| Em dash `—`, en dash `–`, 가로줄 `―`, figure dash `‒` | 쉼표, 마침표, 괄호. 범위는 `~` | `11:30~13:00`, `후보 2~5곳` |
| 중간점 `·` `・` `‧` `･`, 수식 점 `∙` `⋅` | 쉼표, "와/과", 슬래시 `/` | `한식과 국밥`, `룸 있음/단체석`, `도보 약 4분, 1인 9천 원대` |

- 하이픈 `-`, 마이너스, 물결 `~`는 허용합니다.
- 카드 메타 줄(도보 분, 가격, 👍 비율)은 문자 구분자를 넣지 않고 **레이아웃 간격(gap)이나 얇은 세로선**으로 나눕니다. 가운뎃점 모양의 장식 요소도 쓰지 않습니다. 그래서 메타 값은 한 문자열로 이어 붙이지 않고 값마다 따로 둡니다(7.3절).
- 소스에 `\u00B7`, `&middot;`, `&mdash;`처럼 이스케이프로 써도 `pnpm lint:copy`가 잡습니다.

## 2. 문체: 습니다체 7, 해요체 3

### 2.1 쓰임새

| 문체 | 비중 | 쓰는 곳 | 예 |
| --- | --- | --- | --- |
| 습니다체 | 약 70% | 상태 안내, 결과, 설명, 오류, 빈 상태 설명, 정책 고지, 권한 안내 | `식당 정보를 불러오지 못했습니다.` |
| 해요체 | 약 30% | 질문, 제안, 피드백 요청, 축하, 행동 부탁처럼 말을 거는 순간 | `15분까지 넓혀볼까요?` |
| 비율에서 제외 | | 버튼, 탭, 칩, 라벨, 배지, 추천 이유 같은 명사형. 약관 본문(습니다체 100%) | `길찾기`, `투표 만들기`, `도보 약 4분, 지난주 👍한 국밥` |

- **한 덩어리 안의 조합**: 사실은 습니다체로 먼저 말하고, 이어지는 제안만 해요체로 묻습니다. `도보 10분 안에 조건에 맞는 식당이 없습니다. 15분까지 넓혀볼까요?`
- **부탁 문장**(`~해 주세요`)은 해요체로 셉니다. 오류 안내 끝에 다음 행동을 부탁할 때 씁니다. `연결을 확인한 뒤 다시 시도해 주세요.`
- **판단이 애매하면** "사용자에게 말을 거는가, 상태를 알리는가"로 고릅니다. 말을 걸면 해요체, 알리면 습니다체입니다.
- 비율은 화면이 아니라 **도메인 문구 파일 단위**로 봅니다(해요체 25~40%). 오류 위주 파일처럼 도메인 성격상 범위를 벗어나면 억지로 맞추지 말고 파일 머리 주석에 이유를 적습니다.

### 2.2 목소리 (DESIGN.md 8장)

- **짧고 낮게.** 한 문장은 25자 안팎, 길어도 40자를 넘기지 않습니다. 문장이 둘이면 두 번째는 다음 행동입니다.
- **느낌표는 거의 쓰지 않습니다.** 확정 축하도 마침표로 끝냅니다. `오늘 점심은 여기로 정했어요.`
- **사실 먼저, 꾸밈은 빼고.** 숫자와 근거가 형용사보다 설득력이 있습니다. `가까운 맛집`보다 `도보 약 3분, 👍 92%`.
- 존댓말 수준은 "~합니다/~해요/~해 주세요"까지. "~하십시오", "~하시기 바랍니다"는 쓰지 않습니다.
- 사용자는 이름이나 호칭으로 부르지 않습니다(`OO님` 없음). 주어가 필요하면 생략하거나 "내"를 씁니다(`내 선택`, `내 기록`).

### 2.3 문장 부호와 띄어쓰기

- **제목(title)은 마침표 없이**, 설명(body)은 마침표로 끝냅니다. 질문은 `?`로 끝냅니다. 토스트는 한 줄 제목으로 보고 마침표를 붙이지 않습니다.
- 버튼, 탭, 칩, 라벨, 배지에는 문장 부호를 붙이지 않습니다.
- 보조 용언은 "~해 보다"만 붙여 쓰고(`넓혀볼까요`, `골라볼까요`, `검색해보세요`, tasks.md와 DESIGN.md 예문 기준), "~해 주다"는 띄어 씁니다(`다시 시도해 주세요`, `알려 주세요`, 기존 `src/copy` 기준).
- 숫자와 단위: 한글 단위 명사는 띄우고(`9천 원`, `1.2만 원`), 아라비아 숫자 바로 뒤 단위는 붙입니다(`9,000원`, `4분`, `3곳`, `5표`).

## 3. 숫자 표기법

숫자는 정보 위계의 주인공입니다. 화면에서는 항상 `tabular-nums`(고정폭 숫자)로 그리고, 카드의 숫자 3개는 Pretendard 500, 28px로 둡니다(DESIGN.md 9장). 숫자를 문자열로 만드는 일은 컴포넌트가 아니라 `src/lib/format`이 맡습니다.

| 대상 | 표기 | 규칙 | 포매터 |
| --- | --- | --- | --- |
| 도보 시간 | `도보 약 4분` | 직선거리 × 1.3 ÷ 67m/분, 올림, 최소 1분. 추정값이므로 "약"을 뺄 수 없습니다 | `formatWalkDistance`(거리), `walkMinutesFromMeters`(숫자만) |
| 1인 가격대 | `1인 9천 원대`, `1.2만 원대`, `1천 원 미만` | 천 원 단위 내림. 카드 메타에서는 "1인"을 생략하고 `9천 원대`만 둡니다 | `formatPriceBand`, `formatPerPersonPriceBand`, `priceBandParts`(숫자와 단위 분리) |
| 금액 요약 | `1.2만 원`, `1만 원` | 예산 슬라이더, 회식 1인 예산처럼 "대"가 붙지 않는 값 | `formatShortWon` |
| 정확한 금액 | `9,000원` | 사용자가 입력한 실제 가격, 메뉴 가격. 천 단위 쉼표 | `formatWon` |
| 👍 비율 | `👍 87%` | 반올림 정수, 👍와 숫자 사이 공백 하나. 후기 3건 미만이면 숫자 대신 `후기 모으는 중` | `formatThumbsUp`, `thumbsUpPercent` |
| 지난 시각 | `방금`, `12분 전`, `3시간 전`, `어제`, `3일 전`, `10월 28일` | 1분 미만 `방금`, 1시간 미만 분, 24시간 미만 시간, KST 달력 기준 어제, 2~6일 전, 7일 이상은 날짜(다른 해면 연도 포함). 공개 후기 방문 시기는 `10월`처럼 월까지만(PRD 11.2) | `formatRelativeTime` |
| 마감까지 | `마감까지 3:12` | 남은 분:초, 1시간 이상이면 `마감까지 1:05:12`. 초는 올림이라 마감 전에 0:00이 뜨지 않습니다 | `countdownUntil`(성분 분리), `formatCountdown` |
| 마감 시각 | `12:30 마감` | 24시간제, "오전/오후"를 쓰지 않습니다. KST 기준(`src/lib/time`) | 필요해지면 `src/lib/time`에 추가 |
| 범위 | `11:30~13:00`, `2~5곳`, `2~40명` | 물결만 씁니다. 대시 금지 | |
| 개수 | `후보 3곳`, `3명 참여`, `5표`, `제보 3건`, `1/3` | 단위는 곳, 명, 표, 건. 진행 표시는 슬래시 | |
| 큰 수 | `1,240명` | 천 단위 쉼표 | |

- 0은 숫자 대신 상태 문장으로 바꿉니다. `0표` 대신 `아직 투표한 사람이 없습니다.`
- 숫자와 단위를 크기가 다르게 그려야 하는 카드 숫자는 포매터가 값과 단위를 나눠 돌려주게 하고, 문자열을 잘라 쓰지 않습니다.

## 4. 화면 유형별 예문

예문은 `src/copy`에 옮겨 쓸 수 있는 형태로 적었습니다. `{N}`, `{식당}`은 함수형 문구의 인자입니다. 문체 열의 "명사"는 비율 제외 대상입니다.

### 4.1 홈 추천 카드와 추천 이유 (REC-06, REC-07, PRD 7장)

추천 이유는 **점수 기여도가 큰 요소 2개를 쉼표로 이은 명사형 한 줄**입니다. 할인, 제휴, 광고는 점수에 들어가지 않으므로 추천 이유에도 절대 쓰지 않습니다(제품 원칙 6).

| 상황 | 문체 | 예문 |
| --- | --- | --- |
| 가까움 + 선호 | 명사 | `도보 약 4분, 지난주 👍한 국밥` |
| 가까움 + 예산 | 명사 | `도보 약 3분, 예산 안 1인 9천 원대` |
| 요즘 땡김(SET-05) + 평판 | 명사 | `요즘 땡기는 일식, 👍 92%` |
| 반복 회피 + 거리 | 명사 | `최근 3일 안 먹은 중식, 도보 약 6분` |
| 콜드 스타트 | 명사 | `새로 찾은 곳, 도보 약 5분` |
| "왜 추천했나요?" 펼침 | 습니다체 | `회사에서 가장 가까운 곳 중 하나입니다.` / `지난주 좋았던 국밥과 같은 종류입니다.` / `최근 3일 동안 먹지 않은 종류입니다.` |
| 가격 추정 배지 설명 | 습니다체 | `제보된 가격이 없어 같은 종류 식당 기준으로 추정했습니다.` |
| 배지 | 명사 | `추정`, `제보`, `할인`, `못 먹는 분 있음` |
| 웨이팅 3단계 (PLACE-07) | 명사 | `바로 입장`, `조금 기다려요`, `줄 길어요` / `12분 전, 줄 길어요` |
| 카드 액션 | 명사 | `길찾기`, `상세`, `즐겨찾기`, `다시 안 갈래요`, `투표에 추가`, `다시 뽑기`, `그냥 골라줘` |
| 홈 하단 진입점 | 명사 | `친구랑 정하기`, `회식 모드` |
| 끼니 토글 | 명사 | `점심`, `저녁` |
| 연결 전 결과 표시 (APP-02) | 명사 | `연결 전 결과` |

### 4.2 빈 상태 (PRD 12장)

빈 상태는 "지금 상태(습니다체 title) + 다음에 할 수 있는 일(해요체 제안 또는 습니다체 설명) + 버튼 하나"입니다. 버튼 문구는 제안을 그대로 명사형으로 바꿉니다.

| 상황 | title | body | 버튼 |
| --- | --- | --- | --- |
| 반경 안 0곳 | `도보 10분 안에 조건에 맞는 식당이 없습니다` | `15분까지 넓혀볼까요?` | `15분까지 넓히기` |
| 필터 후 3곳 미만 | (카드는 있는 만큼) | `예산 조건을 풀면 4곳이 더 있습니다.` | `예산 조건 풀기` |
| 다시 뽑기 소진 | `주변 식당을 모두 보여드렸습니다` | `거리를 조금 넓혀볼까요?` | `20분까지 넓히기` |
| 투표 목록 없음 | `진행 중인 투표가 없습니다` | `오늘 카드 3장으로 바로 만들어볼까요?` | `빠른 투표 만들기` |
| 즐겨찾기 없음 | `아직 즐겨찾기한 식당이 없습니다` | `카드에서 별을 누르면 여기에 모입니다.` | |
| 방문 기록 없음 | `아직 기록이 없습니다` | `길찾기를 누른 식당이 여기에 쌓입니다.` | `오늘 추천 보기` |
| 상세 후기 없음 | `아직 후기가 없습니다` | `다녀오셨다면 첫 후기를 남겨볼까요?` | `후기 쓰기` |
| 득표 없음 | `아직 투표한 사람이 없습니다` | `먼저 골라볼까요?` | |
| 회식 후보 부족 | `조건에 맞는 곳이 2곳뿐입니다` | `1인 예산을 조금 올려볼까요?` | `예산 바꾸기` |

### 4.3 오류 (PRD 12장, APP-06)

오류는 **무엇이 안 됐는지(습니다체) + 다음 행동**입니다. 원인을 사용자 탓으로 돌리지 않고, 기술 용어와 오류 코드를 보여주지 않습니다. 카카오 장소 데이터는 저장하지 않으므로 "저장된 목록으로 추천" 같은 대체 동작을 약속하지 않습니다.

| 상황 | title | body | 버튼 |
| --- | --- | --- | --- |
| 카카오 API 오류, 한도 초과 (재시도 1회 후) | `식당 정보를 불러오지 못했습니다` | `잠시 후 다시 시도해 주세요.` | `다시 시도` / `네이버 지도에서 주변 식당 보기` |
| 위 상황 + 메모 있는 즐겨찾기 있음 | (위와 같음) | (위와 같음) | 보조: `즐겨찾기에서 고르기` |
| 네이버 지도 로딩 실패 | `지도를 불러오지 못해 목록으로 보여드립니다` | | `지도 다시 열기` |
| 장소 이름 못 찾음 (T0.16-2) | `이름을 불러오지 못했습니다` | | `카카오맵에서 보기` |
| 저장 실패 | `저장하지 못했습니다` | `연결을 확인한 뒤 다시 시도해 주세요.` | `다시 시도` |
| 주소 검색 결과 없음 | `주소를 찾지 못했습니다` | `건물명이나 도로명으로 검색해보세요.` | |
| rate limit (MOD-05) | `오늘은 후기를 더 남길 수 없습니다` | `하루 20개까지 남길 수 있습니다. 내일 다시 남겨 주세요.` | |
| 금칙어 (MOD-04) | `등록할 수 없는 표현이 있습니다` | `표현을 고친 뒤 다시 등록해 주세요.` | |
| 공통 오류 화면 (APP-06) | `화면을 표시하지 못했습니다` | `문제를 기록했습니다. 새로고침하면 대부분 해결됩니다.` | `새로고침` / `오늘 추천으로` |
| 404 | `찾는 페이지가 없습니다` | `주소가 바뀌었거나 사라진 페이지입니다.` | `오늘 추천으로` |

자동 재시도가 실제로 예약되어 있을 때만 `잠시 후 자동으로 다시 시도합니다.`를 씁니다. 하지 않을 일을 약속하지 않습니다.

| 느낌표, 물음표 겹침 | `정했어요!!`, `정말요?!` | `정했어요.` |
| 사과 과다 | `불편을 드려 대단히 죄송합니다` | 상태와 다음 행동: `저장하지 못했습니다. 다시 시도해 주세요.` |
| 사용자 탓 | `잘못 입력하셨습니다`, `올바르지 않은 주소입니다` | `주소를 찾지 못했습니다. 건물명으로 검색해보세요.` |
| 모호한 오류 | `오류가 발생했습니다` 한 줄 | 무엇이 안 됐는지 + 다음 행동 |
| 불확실한 말끝 | `~인 것 같아요`, `아마도` | 추정은 `추정` 배지와 `약`으로 표시 |
| 반말, 유행어 | `골라줘!`(시스템이 말할 때), `ㅋㅋ`, `가즈아`, `JMT` | 해요체 |
| 광고성 문구 | `할인 중이라 추천`, `제휴 맛집`, `지금 핫한 할인` | 할인은 배지와 고지만, 추천 이유에 넣지 않음 |
| 개인 노출 | `김OO 님이 못 먹는 음식`, `3명이 해산물을 피합니다` | `못 먹는 분 있음` (누구인지, 무엇인지 비공개) |
| 저장 오해 | `내 맛집 목록에 저장했습니다`(장소 정보를 저장하는 듯한 말) | `즐겨찾기에 담았습니다` |

참고: `그냥 골라줘`는 사용자가 앱에 하는 말을 버튼에 담은 것이라 예외로 둡니다(REC-12 기능명).

## 6. 화면을 쓸 때 체크리스트

1. 금지 문자(대시, 중간점)가 없습니다.
2. 상태를 알리면 습니다체, 말을 걸면 해요체입니다. 명사형 라벨에는 문장 부호가 없습니다.
3. 오류와 빈 상태에 다음 행동(버튼 또는 안내)이 있습니다.
4. 숫자는 `src/lib/format`을 거쳤고 `tabular-nums`로 그립니다. 범위는 `~`입니다.
5. 한 문장 40자 이하, 느낌표 없음, 장식 이모지 없음.
6. 추천 이유와 추천 근거에 할인, 제휴가 섞이지 않았습니다.
7. 서버 OG 이미지와 링크 미리보기에 식당 이름이 없습니다.
8. 아이콘만 있는 버튼에 aria-label이 있고, 그 문구도 `src/copy`에 있습니다.
9. `pnpm lint:copy`가 오류 없이 통과합니다.

## 7. `src/copy/<도메인>.ts` 작성 규칙 (T2.2)

### 7.1 파일 구조

- 도메인마다 파일 하나: `src/copy/<도메인>.ts`. 도메인 이름은 `src/features/<도메인>`과 맞춥니다(`rec`, `map`, `place`, `poll`, `party`, `feedback`, `deal`, `auth`, `onboarding`, `me`). 여러 화면이 함께 쓰는 문구(`다시 시도`, `닫기`, `취소`, 공통 상태 문구)는 `common.ts`, 메타 설명과 공유 문구는 `meta.ts`에 둡니다. 기존 `home.ts`는 T2.2에서 `rec.ts`로 합칠지 정합니다.
- 파일 머리 주석에 어떤 화면의 문구인지와 문체 메모를 한두 줄 적습니다. 해요체 비율이 25~40%를 벗어나는 이유가 있으면 여기에 적습니다.
- 내보내기는 `export const <도메인>Copy = { ... } as const;` 하나를 기본으로 합니다. 화면이 뚜렷이 나뉘면 `pollPreviewCopy`처럼 화면 이름을 붙여 나눕니다.
- 값은 문자열이나 문자열을 돌려주는 함수만 둡니다. JSX, 컴포넌트, 스타일, 비즈니스 로직은 넣지 않습니다.

```ts
// 투표 화면 문구. 상태와 결과는 습니다체, 동점 질문은 해요체 (docs/copy-guide.md 4.7절).
export const pollCopy = {
  actions: {
    vote: "투표하기",
    decide: "결정하기",
  },
  status: {
    participants: (count: number) => `${count}명 참여`,
    deadlineAt: (hhmm: string) => `${hhmm} 마감`,
  },
  closed: {
    title: "투표가 마감되었습니다",
    winner: (placeName: string) => `1위는 ${placeName}입니다.`,
  },
  states: {
    empty: {
      title: "진행 중인 투표가 없습니다",
      body: "오늘 카드 3장으로 바로 만들어볼까요?",
      action: "빠른 투표 만들기",
    },
  },
} as const;
```

### 7.2 키 이름

- camelCase, **화면 위치가 아니라 역할**로 짓습니다. `topText`보다 `title`, `button1`보다 `vote`.
- 같은 모양의 덩어리는 같은 키를 씁니다.
  - 상태 4종: `states.loading | empty | error | offline`, 각각 `title`(마침표 없음), `body`(마침표 있음), `action`(버튼). 로딩은 스크린리더용 `label`만 둡니다.
  - 버튼 묶음 `actions`, 배지 `badges`, 칩 `chips`, 토스트 `toasts`, 확인 대화상자 `confirm.{title, body, confirm, cancel}`.
  - 접근성 전용 문구는 끝에 `Label`을 붙입니다: `tabBarLabel`, `thumbsUpLabel`.
- `body`는 `title`을 되풀이하지 않고 다음에 일어날 일이나 할 일만 말합니다.

### 7.3 함수형 문구

- 숫자나 이름이 들어가는 문구는 함수로 씁니다: `(n: number) => string`. 인자 이름에 단위를 담습니다(`walkMinutes`, `minutesAgo`, `count`, `hhmm`, `placeName`).
- 숫자를 문자열로 바꾸는 일은 포매터가 먼저 하고, 문구 함수는 그 결과를 받는 편이 낫습니다. `waitingReport(minutesAgo, levelLabel)`처럼 단순 정수는 바로 받아도 됩니다.
- **조사가 붙는 자리에 이름을 넣지 않습니다.** 식당 이름은 받침 유무를 알 수 없으므로 `{이름}을/를`, `{이름}은/는` 대신 `1위는 {이름}입니다`, `어제 간 {이름}, 어땠어요?`처럼 조사가 필요 없는 자리에 둡니다. 어쩔 수 없으면 조사 유틸을 만들고 문구 함수 안에서만 씁니다.
- 0이나 없음은 별도 키로 둡니다(`noVotes`, `thumbsUpEmpty`). 함수 안에서 `n === 0` 분기로 다른 문장을 만들지 않습니다.
- 카드 메타처럼 값마다 따로 그리는 정보는 이어 붙인 문자열을 만들지 않습니다. 구분 문자 없이 컴포넌트가 간격으로 배치합니다.
- 컴포넌트에서 문구 조각을 `+`나 템플릿 문자열로 이어 새 문장을 만들지 않습니다. 필요한 문장은 함수형 문구 하나로 만듭니다.

### 7.4 컴포넌트에 직접 써도 되는 것

- 1~2단어 라벨(`다음`, `닫기`, `길찾기`)은 예외로 컴포넌트에 직접 써도 됩니다. 다만 두 곳 이상에서 쓰거나 aria-label로도 쓰면 `src/copy`로 옮깁니다.
- 식당 이름, 사용자 닉네임, 후기 본문처럼 **데이터**는 문구가 아니므로 `src/copy`에 두지 않습니다.
- 개발용 화면(design-lab, 스모크 페이지)도 같은 규칙을 따르지만, 비율 경고는 무시해도 됩니다.

## 8. `pnpm lint:copy` 사용법 (T2.3)

T0.31에서 금지 문자 검사를 만들었고, T2.3에서 문체 비율 리포트를 더해 완성합니다. 아래는 사양 수준의 설명이며, 세부 출력 형식은 `scripts/check-copy.ts` 구현을 따릅니다.

| 검사 | 결과 | 실패 여부 |
| --- | --- | --- |
| 금지 문자 (1장) | 파일:줄:열, 문자 이름, 고칠 방법 힌트 | **오류** (exit 1, pre-push 훅에서 푸시를 막음) |
| 문체 비율 | 파일별 해요체 비율. 문장 끝(`~니다.`, `~요.`, `~요?` 등)을 세고 명사형은 제외 | 25~40% 밖이면 **경고**(실패 아님) |

- **대상**: `src` 아래 `.ts`, `.tsx`(테스트와 `.d.ts` 제외, 주석 제외), `src/copy` 아래 `.json`, `public`과 `src/app`의 매니페스트, OG 이미지 alt 텍스트. `docs/`와 `*.md`는 검사하지 않습니다.
- **명령**
  - `pnpm lint:copy`: 금지 문자 검사와 파일별 해요체 비율 리포트를 함께 출력
  - `pnpm lint:copy -- --report`: 비율 리포트만 출력(항상 성공)
  - `pnpm lint:copy -- --json`: 결과를 JSON으로 출력(다른 도구 연결용)
  - `pnpm lint:copy -- src/copy/poll.ts`: 지정한 파일이나 폴더만 검사
- **예외 처리**: 꼭 필요한 경우(예: 금지 문자 자체를 다루는 코드) 바로 윗줄에 `// copy-lint-ignore-next-line <이유>`를 씁니다. 이유가 없으면 무시되지 않습니다. 화면 문구에는 쓰지 않습니다.
- **비율 경고가 뜨면**: 먼저 습니다체로 쓴 질문이나 제안이 없는지, 해요체로 쓴 상태 안내가 없는지 봅니다. 도메인 성격상 맞는 문체라면 파일 머리 주석에 이유를 남기고 그대로 둡니다.
- 커밋 전 `pnpm lint && pnpm typecheck && pnpm test && pnpm lint:copy`를 함께 돌립니다(CLAUDE.md 11장).
