### (1) 런치메이트 전체 구성

**현재 구현**
- 지도 화면은 **네이버 지도(NAVER Cloud Maps Web Dynamic Map)** 를 씁니다.
- 음식점 목록은 이용자 브라우저에서 카카오 `services.Places.categorySearch`(FD6)를 기준점(사무실 핀 또는 현위치)과 반경으로 **실시간 호출**해 얻고, 카드 3장과 네이버 지도 위 마커로 보여줍니다. 검색 한 번에 최대 3페이지(45건)까지 받습니다.
- 결과(장소명, 주소, 좌표, 카테고리, 전화번호)는 브라우저 탭 메모리에만 두고 DB, localStorage, 서버 캐시, 서비스 워커 캐시에 저장하지 않습니다. 서비스 워커는 앱 화면 파일만 캐시하고 `dapi.kakao.com` 등 카카오 도메인 요청에는 관여하지 않습니다.
- DB에는 즐겨찾기, 방문 기록, 다시 안 갈 곳, 식후 평가, 투표 후보에 **장소 ID(`id`)와 장소 URL(`place_url`)만** 저장합니다.
- 저장된 장소 ID의 이름은 (a) 같은 탭 메모리에 받아 둔 검색 결과, (b) 기준점 주변 FD6 실시간 재검색으로 ID 맞추기, (c) 둘 다 실패하면 "카카오맵에서 보기" 링크(저장된 `place_url`) 순서로 보여줍니다.
- 출처 문구나 카카오 로고는 따로 넣지 않았습니다.

**질문**
1. 네이버 지도 위에 카카오 로컬 검색 결과를 실시간으로 표시하고, 장소 ID와 장소 URL만 저장하는 이 구성이 운영정책에 맞는지 확인 부탁드립니다.
2. 이름을 찾기 위해 같은 기준점 주변을 다시 검색해 ID를 맞추는 방식(호출량을 늘리는 구조)에 문제가 없는지도 함께 여쭙니다.

**저희가 생각하는 답**
허용된다고 봅니다. 타사 지도와의 조합은 제한하지 않는다는 답변(https://devtalk.kakao.com/t/local-api-sdk/149943, https://devtalk.kakao.com/t/local-api/151645), 장소 ID와 URL은 저장 가능하다는 답변(https://devtalk.kakao.com/t/local-api/151645, https://devtalk.kakao.com/t/api-id/152228), 실시간 조회 매칭은 허용된다는 답변(https://devtalk.kakao.com/t/topic/151916), 출처 표기는 하지 않아도 된다는 답변(https://devtalk.kakao.com/t/api/150800)을 근거로 했습니다.

### (2) 이용자가 직접 쓴 메모 저장

**현재 구현**
- 아직 구현하지 않았습니다. 기능 플래그로 꺼 두었고 DB에 메모 칸도 만들지 않았습니다.
- 계획: 즐겨찾기에 이용자가 **빈 입력란에 직접 타이핑하는** 짧은 메모(예: "회사 앞 김치찌개")를 선택 입력으로 받아 장소 ID와 함께 저장합니다. 장소명을 미리 채우거나, 장소명을 붙여 넣는 버튼은 두지 않습니다.
- 용도: 카카오 장애나 이름 확인 실패 때 이름 대신 메모와 카카오맵 링크를 보여주는 것입니다.

**질문**
API 장소명은 저장하지 않고, 이용자가 빈 입력란에 직접 쓴 자유 텍스트만 장소 ID와 함께 저장하는 것이 허용되는지 여쭙니다. 이용자가 메모에 가게 이름을 직접 적는 경우도 포함해서 판단 부탁드립니다.

**저희가 생각하는 답**
이용자가 만든 콘텐츠라 허용될 것으로 기대합니다. 다만 이용자 입력 장소명 저장이 가능하다는 답변(https://devtalk.kakao.com/t/api/150888, 2026-07-28)과, 로컬 API 장소명은 저장할 수 없다는 답변(https://devtalk.kakao.com/t/1-id/152223, 2026-10-19) 사이에서 경계가 분명하지 않아 확인을 받고 싶습니다. 허용되지 않으면 메모 기능은 만들지 않겠습니다.

---

### (3) 같은 탭 안 메모리 보존

**현재 구현**
- 검색 결과는 TanStack Query의 메모리 캐시에만 둡니다. 결과를 다시 받지 않는 시간(staleTime) 5분, 화면을 떠난 결과를 메모리에서 지우는 시간(gcTime) 5분입니다. 브라우저 저장소에 남기는 플러그인은 쓰지 않습니다.
- 오늘 추천 화면 상태(카드 3장의 장소 ID, 이름, 좌표)는 메모리 전용 상태 저장소에 있어, **탭이 열려 있는 동안(새로고침 전까지)** 탭을 오가도 같은 카드가 유지됩니다. 새로고침하거나 탭을 닫으면 사라집니다.
- 탭이 열린 채 인터넷이 끊기면 메모리에 남은 카드를 "연결 전 결과" 표시와 함께 그대로 보여주고, 연결되면 다시 검색합니다. 앱을 새로 열었을 때 오프라인이면 장소 정보 없이 안내 화면만 보입니다.

**질문**
1. 이렇게 같은 탭 메모리에 결과를 들고 있는 것이 운영정책 제5조 제20호의 "사용자 환경을 개선하기 위한 목적"의 캐시로 인정되는지 여쭙니다.
2. 인정된다면 허용되는 보존 시간에 기준이 있는지(예: 탭이 열려 있는 동안, 또는 N분 이내) 알려 주시면 그에 맞추겠습니다.

**저희가 생각하는 답**
기기나 서버에 저장하지 않고 화면 표시를 위해 메모리에만 잠시 두는 것이므로 허용된다고 봅니다("실시간 호출하여 화면에 일시적으로 표시하는 구조는 허용", https://devtalk.kakao.com/t/local-api/151263). 다만 메모리 캐시를 직접 다룬 답변은 찾지 못해, 답변 전까지는 gcTime을 5분으로 짧게 잡아 두었습니다.

---

### (4) 투표방 기준점 좌표 저장

**현재 구현**
- 친구 투표방에는 후보 음식점의 장소 ID, 장소 URL, 추가한 사람, 순서만 저장하고 이름, 좌표, 카테고리, 거리는 저장하지 않습니다.
- 대신 투표방마다 **기준점 좌표와 반경(100~3000m)** 을 저장합니다. 기준점은 방장의 사무실 핀(방장이 지도에 직접 놓은 점) 또는 방장이 투표방을 만들며 지도에서 직접 찍은 점입니다. 카카오 검색 결과 좌표나 현위치는 기준점으로 쓰지 않습니다.
- 참여자 브라우저는 이 기준점 주변을 FD6로 실시간 검색해 후보의 장소 ID와 맞춰 이름과 거리를 보여줍니다. 못 찾으면 "후보 2" 같은 순번과 카카오맵 링크로 보여줍니다.

**질문**
기준점 좌표 자체는 이용자가 만든 값이지만, 후보 장소를 다시 찾기 위한 기준으로 쓰입니다. 이것이 장소 좌표의 우회 저장으로 보이는지 여쭙니다.

**저희가 생각하는 답**
카카오에서 받은 값이 아니고 장소 하나의 좌표도 아니므로 허용된다고 봅니다. 이용자가 지도에서 직접 찍은 핀 좌표를 저장하는 구조를 부정하지 않으신 답변(https://devtalk.kakao.com/t/sdk-poi/151294)도 참고했습니다.

---

### (5) 이용자가 공유하는 투표 결과 이미지

**현재 구현**
- 투표가 끝나면 이용자가 "결과 공유"를 누를 때 **브라우저 canvas에서** 결과 이미지(투표 제목, 확정 식당 이름, 득표 수, 카테고리 그림)를 그립니다. 식당 이름은 그 탭의 실시간 검색 결과에서 가져옵니다.
- 이미지는 저희 서버나 CDN으로 보내거나 보관하지 않습니다. 이용자가 고르면 기기에 저장, Web Share로 공유, 또는 카카오톡 공유(`Kakao.Share.uploadImage` 후 `sendDefault`)를 합니다.
- 링크 미리보기용 서버 OG 이미지에는 식당 이름을 넣지 않습니다(제목, 후보 수, 마감 시각, 결과 안내와 득표 수만).

**질문**
이용자 행동으로 만들어진 이 이미지가 카카오톡 대화방이나 이용자 기기에 남는 것이, 카카오에서 받은 데이터의 저장이나 제3자 제공(운영정책 제5조 제30호)에 해당하는지 여쭙니다.

**저희가 생각하는 답**
저희 서비스가 저장하거나 배포하지 않고 이용자가 화면을 공유하는 것에 가까우므로 허용된다고 봅니다. 해당하지 않는다면 지금 구조를 유지하고, 문제가 된다면 결과 이미지에서 식당 이름을 빼겠습니다.
